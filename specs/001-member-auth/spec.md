## User Scenarios & Testing *(mandatory)*

### User Story 1 - 이메일로 가입하고 인증하기 (Priority: P1)

방문자가 이메일·블로그 주소·비밀번호·닉네임을 입력하고 필수 약관 2개(이용약관, 개인정보 처리방침)에 동의해 가입한다. 가입 직후 로그인 상태가 되지만, 메일로 받은 인증 링크를 누르기 전에는 글쓰기·댓글·사진 업로드·좋아요·신고를 할 수 없다.

**Why this priority**: 계정이 없으면 블로그의 어떤 쓰기 기능도 쓸 수 없다. 이메일 가입은 외부 서비스 없이 시험할 수 있는 가장 기본 경로다.

**Independent Test**: 새 이메일로 가입 → 인증 전 글쓰기 시도(거부 + 인증 안내) → 메일의 링크 클릭 → 같은 글쓰기 시도(허용)로 확인한다.

**Acceptance Scenarios**:

1. **Given** 가입 화면, **When** 이메일 `kim755030@naver.com`을 입력하면, **Then** 블로그 주소 칸에 `kim755030`이 미리 채워지고 "가입 후 바꿀 수 없어요" 안내가 보인다.
2. **Given** 사용자가 블로그 주소 칸을 직접 고친 뒤, **When** 이메일을 다시 바꾸면, **Then** 주소 칸은 더 이상 자동으로 바뀌지 않는다.
3. **Given** 올바른 입력과 필수 약관 동의, **When** 가입하면, **Then** 계정이 만들어지고 인증 메일(24시간 유효, 한 번만 사용)이 발송되며 약관 종류·버전·동의 시각이 기록된다.
4. **Given** 필수 약관 중 하나라도 동의하지 않음, **When** 가입하면, **Then** 가입되지 않는다.
5. **Given** 인증 전 회원, **When** 글쓰기·댓글·사진 업로드·좋아요·신고를 시도하면, **Then** 계정 상태 때문에 거부되고 "인증 메일 다시 보내기" 안내가 보인다.
6. **Given** 인증 링크, **When** 처음 누르면 인증이 완료되고, **When** 같은 링크를 다시 누르거나 24시간이 지난 뒤 누르면, **Then** "링크가 만료됐어요" 안내와 재발송 버튼이 보인다.
7. **Given** 인증 메일 재발송, **When** 1분 안에 다시 요청하거나 하루 10번을 넘기면, **Then** 거부되고, 새 메일이 발송되면 이전 링크는 쓸 수 없다.
8. **Given** 이미 이메일로 가입된 주소, **When** 같은 이메일로 다시 가입하면, **Then** "이미 가입된 이메일이에요" 안내와 로그인·비밀번호 찾기 버튼이 보이고 계정은 하나뿐이다.
9. **Given** 그 이메일 계정이 탈퇴 유예 중, **When** 같은 이메일로 가입하면, **Then** "탈퇴 신청한 계정이 있어요. 로그인하면 복구할 수 있어요" 안내가 보인다.

### User Story 2 - 로그인·로그아웃 (Priority: P1)

회원이 이메일과 비밀번호로 로그인하고, 14일 동안 활동이 이어지면 로그인이 유지된다. 로그아웃하면 서버 로그인 상태와 브라우저에 남은 본인 임시 데이터가 모두 지워진다.

**Why this priority**: 가입한 사람이 다시 들어오고, 공용 PC에서 안전하게 나갈 수 있어야 서비스가 성립한다.

**Independent Test**: 로그인 → 쓰기 가능 확인 → 로그아웃 → 같은 쓰기 요청이 거부되고 브라우저 임시 글이 남아 있지 않은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 가입된 회원, **When** 올바른 이메일·비밀번호로 로그인하면, **Then** 보던 페이지(우리 사이트 안의 상대 경로만)로 돌아가고 마지막 로그인 일자가 기록된다.
2. **Given** 틀린 비밀번호 또는 없는 이메일, **When** 로그인하면, **Then** 둘 다 "이메일 또는 비밀번호가 올바르지 않아요"로 같은 안내를 받는다.
3. **Given** 같은 계정에 5번 연속 실패, **When** 다시 로그인하면, **Then** 15분 동안 "잠시 후 다시 시도해 주세요(약 15분)"로 거부된다.
4. **Given** 같은 IP에서 1분에 20번 넘게 로그인 시도, **When** 다음 시도를 하면, **Then** 거부된다.
5. **Given** 로그인한 회원, **When** 로그아웃하면, **Then** 홈으로 이동하고, 이후 쓰기 요청은 로그인 필요로 거부되며 브라우저의 본인 임시 데이터가 남지 않는다.
6. **Given** 마지막 활동 뒤 14일이 지남, **When** 다시 방문하면, **Then** 로그아웃된 상태다.
7. **Given** 정지된 계정, **When** 로그인하면, **Then** 로그인이 거부되고 정지 기간과 사유가 안내된다.
8. **Given** 동의 문구의 현재 버전이 회원이 동의한 버전과 다름, **When** 로그인하면, **Then** 다시 동의해야 서비스를 이어 쓸 수 있다.

### User Story 3 - Google·GitHub로 가입·로그인 (Priority: P2)

방문자가 Google 또는 GitHub로 계속하기를 누른다. 처음이면 가입 마무리 화면에서 닉네임·블로그 주소·약관 동의를 확인한 뒤에야 계정이 생기고, 이후에는 바로 로그인된다.

**Why this priority**: 공통 로그인 수단이지만 외부 서비스가 필요해 이메일 경로 다음에 검증한다.

**Independent Test**: 시험용 Google 계정으로 처음 로그인 → 마무리 화면에서 가입 → 로그아웃 → 다시 로그인하면 같은 계정인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 처음 소셜 로그인, **When** 인증이 끝나면, **Then** 계정을 만들지 않은 채 가입 마무리 화면이 보이고, 닉네임은 소셜 이름을 규칙에 맞게 정리해 미리 채운다(규칙에 안 맞으면 빈칸).
2. **Given** 가입 마무리 화면, **When** 블로그 주소를 보면, **Then** Google은 `go-`, GitHub은 `gi-` 접두어가 고칠 수 없는 글자로 붙어 있고 본문만 고칠 수 있다.
3. **Given** 마무리 화면에서 10분 넘게 머묾, **When** 가입을 완료하면, **Then** 소셜 인증을 다시 하도록 안내된다.
4. **Given** 소셜 가입 완료, **When** 계정이 생기면, **Then** 이메일 인증이 이미 끝난 상태다.
5. **Given** 이미 가입한 같은 소셜 계정, **When** 다시 로그인하면(소셜 쪽 이메일을 바꿨더라도), **Then** 기존 계정으로 로그인되고 새 계정이 생기지 않는다.
6. **Given** `kim755030@naver.com`으로 이메일 가입한 계정이 있음, **When** 같은 이메일의 GitHub 계정으로 처음 로그인하면, **Then** 별도의 새 계정(`gi-kim755030`)이 만들어진다.
7. **Given** GitHub에 인증된 대표 이메일이 없음, **When** 가입 마무리 화면에 오면, **Then** 이메일을 입력받고 이메일 가입과 같은 방식으로 인증한다.

### User Story 4 - 비밀번호 재설정 (Priority: P2)

비밀번호를 잊은 회원이 이메일을 입력해 재설정 메일을 받고 새 비밀번호를 정한다. 재설정하면 그 계정은 모든 기기에서 로그아웃된다.

**Why this priority**: 이메일 가입자가 계정을 되찾을 유일한 방법이며, 탈퇴 유예 회원의 복구에도 쓰인다.

**Independent Test**: 두 기기에서 로그인 → 재설정 메일로 비밀번호 변경 → 두 기기 모두 로그아웃되고 새 비밀번호로만 로그인되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 비밀번호 찾기 화면, **When** 가입된 이메일이든 아니든 입력하면, **Then** 화면에는 항상 "가입된 이메일이면 안내 메일을 보냈어요"가 보인다.
2. **Given** 이메일 가입 계정, **When** 재설정 메일을 요청하면, **Then** 30분 동안 한 번만 쓸 수 있는 링크가 그 이메일로 간다.
3. **Given** 같은 이메일로 소셜 계정만 있음, **When** 재설정을 요청하면, **Then** 메일에는 "이 이메일은 Google로 가입되어 비밀번호가 없어요" 같은 안내만 간다. 이메일 계정과 소셜 계정이 함께 있으면 재설정 링크와 소셜 계정 안내가 함께 간다.
4. **Given** 같은 이메일로 1분 안에 다시 요청하거나 하루 10번, 같은 IP로 1시간 20번을 넘김, **When** 요청하면, **Then** 거부된다.
5. **Given** 재설정 링크, **When** 규칙에 맞는 새 비밀번호를 저장하면, **Then** 그 계정의 모든 기기가 로그아웃되고 같은 링크는 다시 쓸 수 없다.

### User Story 5 - 가입할 때 블로그 주소 정하기 (Priority: P2)

가입하는 사람은 이메일 앞부분으로 만든 블로그 주소를 제안받고, 가입 전에 한 번 직접 고칠 수 있다. 가입 뒤에는 어떤 경로로도 바꿀 수 없다.

**Why this priority**: 블로그 주소는 영구 신원이라 가입 시점에 정확히 정해져야 한다. 가입 흐름 안에서만 의미가 있다.

**Independent Test**: 여러 이메일로 차례로 가입해 제안 주소와 중복 번호, 예약어·형식 거부, 동시 가입을 확인한다.

**Acceptance Scenarios**:

1. **Given** `kim755030@naver.com`(이메일), `kim755030@gmail.com`(Google), `kim755030@naver.com`(GitHub), **When** 차례로 가입하면, **Then** 주소는 `kim755030`, `go-kim755030`, `gi-kim755030`으로 겹치지 않는다.
2. **Given** `Kim.Min-Seo+blog@naver.com`, **When** 주소가 제안되면, **Then** `kim_min_seo`처럼 대문자와 `-`가 없다.
3. **Given** 이미 `kim755030`이 있음, **When** `kim755030@daum.net`으로 가입하면, **Then** `kim755030_2`가 제안된다.
4. **Given** 이메일 앞부분이 3자 미만이거나 영문·숫자가 없음, **When** 주소가 제안되면, **Then** `user_` + 숫자 6자리가 제안된다.
5. **Given** 예약어(`admin`, `go-admin` 포함)나 형식에 맞지 않는 주소, 금칙어가 든 주소, **When** 가입하면, **Then** 가입되지 않는다.
6. **Given** 두 사람이 같은 주소로 동시에 가입, **When** 처리되면, **Then** 한 명만 그 주소를 갖고, 늦은 쪽은 "방금 다른 분이 이 주소를 사용했어요"와 대안 주소를 안내받는다.
7. **Given** 가입한 회원, **When** 대문자로 된 주소(`/@Kim755030`)로 접속하면, **Then** 소문자 주소로 영구 이동한다.

### Edge Cases

- 비밀번호가 16자를 넘거나 공백·한글을 포함하거나, 이메일 `@` 앞부분을 포함하거나, 흔한 비밀번호 목록에 있으면 가입·재설정이 거부된다. 화면은 규칙별 충족 여부를 색만이 아니라 글자와 표시로 알린다.
- 이메일은 앞뒤 공백을 지우고 소문자로 바꿔 비교하므로 `Kim@X.com`과 `kim@x.com`은 같은 이메일 가입이다.
- 로그인 후 이동 주소가 외부 사이트를 가리키면 무시하고 홈으로 간다.
- 세션 저장소에 장애가 나면 인증·재설정 링크는 거부되고, 요청 횟수 제한은 통과시키며, 세션 조회 실패는 비로그인으로 처리해 공개 글 읽기를 유지한다.
- 같은 이메일로 소셜 계정을 처음 만들 때 기존 다른 수단 계정을 안내할지는 미결이다 (FR-022).
- 탈퇴 유예 회원이 로그인하면 복구 화면으로만 간다 (021-member-withdraw).

## Requirements *(mandatory)*

### Functional Requirements

**계정과 로그인 수단**

- **FR-001**: System MUST 이메일·Google·GitHub 세 가지 로그인 수단을 제공하고, 계정 하나에는 로그인 수단 하나만 둔다 (자동 합치기·계정 연결 없음).
- **FR-002**: System MUST 같은 로그인 수단(같은 이메일 가입, 같은 소셜 계정)으로는 동시에 요청해도 계정이 두 개 생기지 않게 한다. 로그인 수단이 다르면 이메일이 같아도 별도 계정이다.
- **FR-003**: System MUST 소셜 계정을 이메일이 아니라 소셜 서비스의 바뀌지 않는 고유 사용자 ID로 식별한다.

**이메일 가입·인증·동의**

- **FR-004**: 이메일 가입은 이메일(최대 254자, 공백 제거·소문자 저장)·블로그 주소·비밀번호·비밀번호 확인·닉네임·필수 약관 2개를 받아야 한다(MUST).
- **FR-005**: System MUST 필수 약관(이용약관, 개인정보 처리방침)에 동의하지 않으면 가입시키지 않고, 동의 종류·문구 버전·동의 시각을 가입과 함께 기록한다.
- **FR-006**: System MUST 로그인할 때 회원이 동의한 버전이 현재 문구 버전과 다르면 다시 동의를 받는다.
- **FR-007**: System MUST 이메일 가입 직후 24시간 유효·1회용 인증 링크를 보내고, 재발송은 1분에 1번·하루 10번으로 제한하며, 새 링크를 보내면 이전 링크를 무효로 한다.
- **FR-008**: System MUST 이메일 인증 전 회원의 로그인은 허용하되 글 작성·발행·댓글·사진 업로드·좋아요·신고는 계정 상태 사유로 거부하고 인증 메일 재발송을 안내한다.
- **FR-009**: 가입 화면은 이미 이메일 가입된 주소면 "이미 가입된 이메일이에요"를, 탈퇴 유예 계정이면 "탈퇴 신청한 계정이 있어요"를 보여야 한다(MUST). 이로 인한 가입 여부 노출은 감수한다.

**비밀번호**

- **FR-010**: System MUST 비밀번호를 8~16자, 영문·숫자·특수문자 각 1개 이상, 허용 문자만으로 제한하고, 이메일 `@` 앞부분이 들어간 것과 흔한 비밀번호 목록을 거부한다.
- **FR-011**: System MUST 비밀번호 원문을 저장하거나 기록에 남기지 않고 단방향 해시로만 보관한다.
- **FR-012**: System MUST 비밀번호 찾기 화면에서 가입 여부와 무관하게 같은 안내를 보여 주고, 메일은 그 이메일 주인에게만 보낸다. 메일에는 이메일 계정이면 30분 유효·1회용 재설정 링크를, 같은 이메일의 소셜 계정이 있으면 그 수단 안내를 담는다.
- **FR-013**: System MUST 재설정 요청을 같은 이메일 1분 1번·하루 10번, 같은 IP 1시간 20번으로 제한한다.
- **FR-014**: System MUST 비밀번호를 재설정하면 그 계정의 모든 로그인 세션을 끊는다.

**로그인·로그아웃**

- **FR-015**: System MUST 로그인 실패 시 이메일과 비밀번호 중 무엇이 틀렸는지 구분하지 않는 같은 문구를 보여 준다.
- **FR-016**: System MUST 같은 계정 5회 연속 실패 시 15분 잠그고, 같은 IP는 1분에 20회로 제한한다. 사용자 IP는 신뢰하는 프록시가 전달한 값만 인정해 위조 헤더로 제한을 우회할 수 없게 한다.
- **FR-017**: System MUST 로그인을 마지막 활동부터 14일 유지하고, 로그인할 때마다 새 세션 식별자를 발급하며, 로그인 성공 시각과 로그인 방식을 기록한다.
- **FR-018**: System MUST 로그인 뒤 원래 보던 우리 사이트 안의 페이지로만 돌려보낸다.
- **FR-019**: System MUST 정지된 계정의 로그인을 거부하고 정지 기간·사유를 안내한다.
- **FR-020**: System MUST 로그아웃하면 서버 세션을 지우고 브라우저에 남은 그 사용자의 임시 글·백업 데이터를 모두 지운 뒤 홈으로 보낸다. 로그아웃 뒤 쓰기 요청은 로그인 필요로 거부된다.

**소셜 가입**

- **FR-021**: System MUST 처음 소셜 로그인한 사람에게 가입 마무리 화면(닉네임·블로그 주소·약관 동의)을 반드시 거치게 하고, 마무리 전에는 계정을 만들지 않으며, 소셜 인증 정보는 10분만 보관한다. 소셜 가입 계정은 가입 시각에 이메일 인증된 것으로 본다. Google은 소셜 쪽에서 인증된 이메일만, GitHub은 인증된 대표 이메일만 쓰고 없으면 입력받아 인증한다.
- **FR-022**: 처음 소셜 로그인할 때 같은 이메일로 다른 수단의 계정이 이미 있으면 [NEEDS CLARIFICATION: 가입 마무리 화면에 "기존 계정으로 로그인 / 새 계정 만들기" 안내를 보여 줄지 (07 §10 F-1, 52 §11.2 미결)].

**블로그 주소 (가입 시)**

- **FR-023**: System MUST 이메일 `@` 앞부분으로 주소를 제안한다: `+` 뒤 버림, 소문자화, `.`·`-`를 `_`로, 허용 외 문자 제거, 연속 `_` 정리, 30자 자름, 3자 미만이면 `user_`+6자리 숫자, 수단별 접두어(이메일 없음·Google `go-`·GitHub `gi-`), 예약어·중복이면 비어 있는 첫 `_2`, `_3`….
- **FR-024**: System MUST 주소 형식을 "접두어(선택) + 본문 3~36자(영문 소문자·숫자·`_`, 처음과 끝은 영문 소문자나 숫자)"로 제한하고, 접두어는 가입 수단과 일치해야 하며 이메일 가입 주소에는 `-`가 들어갈 수 없다.
- **FR-025**: System MUST 예약어(접두어를 뺀 본문 기준)와 닉네임과 같은 금칙어 필터에 걸리는 주소를 거부한다.
- **FR-026**: 사용자는 가입 전에 제안 주소를 한 번 직접 고칠 수 있어야 하고(MUST), 입력이 잠시 멈추면 사용 가능 여부와 대안을 안내받는다(같은 IP 1분 30번 제한). 가입 요청 때 서버가 다시 검사한다.
- **FR-027**: System MUST 같은 주소로 동시에 가입해도 한 명에게만 주소를 주고, 가입 후에는 어떤 경로로도 주소를 바꿀 수 없게 한다.
- **FR-028**: System MUST 대문자가 섞인 블로그 주소 접속을 소문자 주소로 영구 이동시키고, 없는 주소는 찾을 수 없음으로 응답한다.

### Key Entities

- **회원 (member)**: 블로그 주인. 블로그 주소(영구), 닉네임, 상태(활동·정지·탈퇴), 권한을 가진다. 회원 = 블로그 하나.
- **로그인 수단 (auth_identity)**: 회원 하나에 하나. 수단 종류, 수단별 고유 식별값, 이메일, 이메일 인증 시각, 비밀번호 해시(이메일 가입만), 마지막 로그인 일자.
- **동의 기록 (member_agreement)**: 회원별 동의 종류(이용약관·개인정보·AI)마다 하나. 문구 버전과 동의 시각.
- **인증·재설정 링크, 실패·요청 횟수**: 만료 시간이 있는 임시 기록. 영구 데이터가 아니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 같은 이메일 가입이나 같은 소셜 계정으로 동시 요청을 포함해 100번 가입·로그인을 시도해도 계정은 정확히 1개다.
- **SC-002**: 로그아웃한 뒤 보낸 쓰기 요청의 100%가 거부되고, 브라우저에 그 사용자의 임시 데이터가 0건 남는다.
- **SC-003**: 인증 전 회원의 글쓰기·댓글·사진 업로드·좋아요·신고 요청은 100% 거부된다.
- **SC-004**: 8자 미만, 16자 초과, 영문·숫자·특수문자 중 하나라도 빠진 비밀번호로는 가입·재설정이 100% 실패한다.
- **SC-005**: 비밀번호를 재설정하면 그 계정의 다른 모든 기기에서 다음 요청부터 로그아웃 상태다.
- **SC-006**: 같은 계정으로 5회 연속 실패한 뒤 15분 동안 올바른 비밀번호로도 로그인되지 않는다.
- **SC-007**: 가입된 이메일과 가입되지 않은 이메일에 대해 로그인 실패·비밀번호 찾기 화면의 문구가 글자 하나까지 같다.
- **SC-008**: 인증·재설정 링크는 두 번째 사용과 만료 뒤 사용이 100% 거부된다.
- **SC-009**: 이메일·Google·GitHub가 같은 이메일 앞부분을 써도 블로그 주소가 겹치지 않고, 이메일에서 만든 주소에는 대문자와 `-`가 0건이다.
- **SC-010**: 같은 주소로 동시에 가입해도 그 주소를 가진 회원은 1명이고, 가입 뒤 주소를 바꾸는 경로가 0개다.
- **SC-011**: 예약어·형식 오류 주소로는 가입이 100% 실패하고, 대문자 주소 접속은 100% 소문자 주소로 이동한다.
- **SC-012**: 새 사용자의 90% 이상이 안내 없이 3분 안에 이메일 가입을 마친다.

## Assumptions

- 비밀번호 변경(로그인한 상태), 프로필 수정, 마지막 로그인 표시 화면은 [002-profile-nickname](../002-profile-nickname/spec.md)이 다룬다. 닉네임 형식·금칙어 규칙의 상세도 002를 따른다.
- 회원 탈퇴·복구 화면과 탈퇴 유예 회원의 로그인 후 흐름은 [021-member-withdraw](../021-member-withdraw/spec.md)가 다룬다.
- 소셜 프로필 사진 복사는 002가 다룬다. 이 spec은 가입 마무리 화면에 선택지를 보여 주는 것까지만 포함한다.
- AI 동의는 AI 태그 추천 spec이 다룬다. 이 spec은 필수 약관 2개만 다룬다.
- 네이버·카카오 로그인, 설정 화면의 "모든 기기에서 로그아웃" 버튼은 범위 밖(개인 확장)이다.
- 메일 발송 방식(개발용 대체 메일함, 배포 환경)은 구현 단계에서 정한다.
- 정지 처리 자체는 신고·숨김 spec이 다루고, 이 spec은 정지 계정의 로그인 거부만 다룬다.
- 권한 판정 순서와 응답 구분은 [42-permission-matrix.md](../../docs/42-permission-matrix.md)를 따른다.
