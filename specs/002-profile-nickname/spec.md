## User Scenarios & Testing *(mandatory)*

### User Story 1 - 닉네임 정하고 바꾸기 (Priority: P1)

회원은 가입할 때 닉네임을 정하고, 설정 화면에서 바꿀 수 있다. 닉네임은 2~10자의 완성형 한글·영문·숫자이고, 대소문자를 무시해 다른 사람과 겹칠 수 없으며, 금칙어·예약어를 쓸 수 없다. 바꾸면 30일 동안 다시 바꿀 수 없다.

**Why this priority**: 닉네임은 모든 글·댓글에 보이는 이름이다. 가입(001)과 프로필 수정이 같은 규칙을 써야 하므로 먼저 확정한다.

**Independent Test**: 여러 닉네임 후보로 사용 가능 확인·저장을 시도해 형식·중복·금칙어·예약어·30일 제한 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** `김민서`, `KimMinseo`, `dev2026`, **When** 저장하면, **Then** 허용된다.
2. **Given** `ㅋㅋ`, `김 민서`, `kim!`, 이모지, `12345`, 1자, 11자, **When** 저장하면, **Then** 각각 거부되고 형식 또는 "한글이나 영문을 1자 이상 넣어 주세요" 안내가 보인다.
3. **Given** 자음·모음이 분리된 형태로 붙여넣은 `김민서`, **When** 저장하면, **Then** 정상 닉네임으로 저장된다.
4. **Given** 다른 회원이 `Kim`을 사용 중, **When** `kim`이나 `KIM`으로 저장하면, **Then** "이미 사용 중인 닉네임이에요"로 거부되고 `KIM2`는 허용된다.
5. **Given** 두 사람이 같은 닉네임을 동시에 요청, **When** 처리되면, **Then** 한 명만 성공하고 다른 쪽은 "방금 다른 분이 이 닉네임을 사용했어요"를 본다.
6. **Given** `시1발`, `sh1t` 같은 변형 금칙어, **When** 저장하면, **Then** "사용할 수 없는 단어가 들어 있어요"로 거부되고 어떤 단어인지 알려 주지 않는다. `시발점`처럼 예외 목록의 단어는 허용된다.
7. **Given** `관리자김`, `admin123`, `Official`, **When** 저장하면, **Then** "사용할 수 없는 닉네임이에요"로 거부된다.
8. **Given** 닉네임을 바꾼 지 30일이 안 됨, **When** 설정 화면을 열면, **Then** 닉네임 칸이 비활성화되고 다음 변경 가능일이 보이며, 요청을 보내도 거부된다.
9. **Given** 가입 직후 처음 바꾸는 경우, **When** 저장하면, **Then** 허용된다(가입 때 정한 닉네임은 변경으로 세지 않는다).
10. **Given** 같은 닉네임으로 다시 저장, **When** 저장하면, **Then** 아무것도 바뀌지 않고 30일 제한도 시작되지 않는다. 대소문자만 바꾸면 변경으로 보고 제한이 시작된다.
11. **Given** 닉네임을 바꿈, **When** 다른 사람이 이전 닉네임으로 저장하면, **Then** 바로 허용된다.

### User Story 2 - 프로필 한 번에 저장하기 (Priority: P1)

회원이 설정 화면에서 닉네임·소개·프로필 사진을 고치고 [저장]을 한 번 누른다. 하나라도 규칙에 어긋나면 어떤 값도 바뀌지 않고 실패한 칸이 모두 표시된다. 블로그 주소와 이메일은 읽기 전용으로 보인다.

**Why this priority**: C-AUTH-2의 핵심이며 "본인만 수정", "부분 저장 없음"이 공통 완료 기준이다.

**Independent Test**: 올바른 닉네임과 200자를 넘는 소개를 함께 저장해 닉네임도 바뀌지 않았는지, 소개 오류가 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 설정 화면을 열면, **Then** 닉네임·소개(글자 수 표시)·프로필 사진은 고칠 수 있고, 블로그 주소·이메일·로그인 수단은 "변경할 수 없어요"로 읽기 전용이다.
2. **Given** 비회원, **When** 설정 화면에 들어가면, **Then** 로그인 화면으로 이동한다.
3. **Given** 여러 칸 중 하나가 규칙 위반, **When** 저장하면, **Then** 모든 칸이 그대로이고 실패한 칸마다 이유가 표시된다.
4. **Given** 닉네임 30일 제한 중, **When** 닉네임은 그대로 두고 소개만 바꿔 저장하면, **Then** 소개가 저장된다. 같은 요청에 닉네임 변경이 들어 있으면 전체가 실패한다.
5. **Given** 남의 프로필, **When** 어떤 방법으로든 수정하려 하면, **Then** 그런 경로가 없다(수정 대상은 항상 로그인한 본인).
6. **Given** 두 기기에서 동시에 저장, **When** 처리되면, **Then** 나중에 저장한 쪽이 반영된다.
7. **Given** 프로필 저장 성공, **When** 목록·글 상세·댓글을 보면, **Then** 바뀐 닉네임·사진이 바로 보인다.
8. **Given** 이메일 인증 전 회원, **When** 닉네임·소개를 저장하면, **Then** 허용된다.

### User Story 3 - 소개 쓰기 (Priority: P2)

회원이 블로그 상단에 보일 짧은 소개를 쓴다. 글자만 쓸 수 있고 서식·자동 링크는 없다.

**Why this priority**: 블로그 상단에 공개되므로 안전한 표시가 중요하지만, 비워 둬도 서비스는 동작한다.

**Independent Test**: HTML 태그·주소·여러 줄을 넣은 소개를 저장해 블로그 상단 표시를 확인한다.

**Acceptance Scenarios**:

1. **Given** `<script>alert(1)</script>`이 든 소개, **When** 블로그 상단에 보이면, **Then** 실행되지 않고 글자 그대로 보인다.
2. **Given** 200자 초과 또는 5줄 이상, **When** 저장하면, **Then** "소개는 200자까지 쓸 수 있어요" 또는 "소개는 4줄까지 쓸 수 있어요"로 거부된다.
3. **Given** 빈 줄이 연달아 있는 소개, **When** 저장하면, **Then** 빈 줄이 하나로 줄어든다.
4. **Given** 소개에 쓴 웹 주소, **When** 보이면, **Then** 링크로 바뀌지 않는다.
5. **Given** 금칙어가 든 소개, **When** 저장하면, **Then** 거부된다(예약어 검사는 하지 않는다).
6. **Given** 빈 소개나 이모지가 든 소개, **When** 저장하면, **Then** 허용된다.

### User Story 4 - 프로필 사진 (Priority: P2)

회원이 사진을 골라 정사각형으로 자르고 저장한다. 사진이 없으면 닉네임 첫 글자가 들어간 기본 아이콘이 보인다. 소셜 가입자는 가입할 때 소셜 사진을 우리 저장소로 복사해 쓸 수 있다.

**Why this priority**: 작성자를 알아보기 쉽게 하지만 기본 아이콘으로도 서비스가 동작한다.

**Independent Test**: 사진을 올려 연결 → 다른 사진으로 교체 → 기본 이미지로 되돌리기를 하며, 연결된 사진이 정리되지 않고 이전 사진만 7일 뒤 정리되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** jpg·png·gif·webp 중 10MB 이하 파일, **When** 고르면, **Then** 브라우저에서 정사각형으로 자르고(위치·확대 조정) 256×256 WebP로 바꿔 위치 정보 없이 올린다. GIF는 첫 장면만 쓴다.
2. **Given** 올린 사진, **When** [저장]을 누르지 않고 떠나면, **Then** 프로필은 바뀌지 않고 그 사진은 24시간 뒤 정리된다.
3. **Given** 256×256이 아니거나 1MB를 넘는 사진, 남이 올린 사진, 글용 사진, 삭제된 사진, **When** 프로필에 연결하면, **Then** 연결되지 않는다.
4. **Given** 연결된 프로필 사진, **When** 사진 정리 작업이 돌면, **Then** 지워지지 않는다. 다른 사진으로 바꾸거나 [기본 이미지로]를 누른 이전 사진은 7일 뒤 정리된다.
5. **Given** 회원 한 명, **When** 프로필 사진을 여러 번 바꾸면, **Then** 현재 프로필 사진은 항상 하나다.
6. **Given** 사진이 없는 회원, **When** 화면에 보이면, **Then** 닉네임 첫 글자(영문은 대문자)와 블로그 주소로 정해진 배경색의 동그란 아이콘이 보이고, 라이트·다크 모드 모두 글자 대비가 4.5:1 이상이다.
7. **Given** 이메일 인증 전 회원, **When** 프로필 사진을 올리면, **Then** 거부된다.
8. **Given** 소셜 가입 마무리 화면의 "프로필 사진 사용"(기본 체크), **When** 가입을 마치면, **Then** 계정이 만들어진 직후 소셜 사진이 우리 저장소로 복사되어 연결되고, 소셜 서비스의 주소는 저장되지 않는다.
9. **Given** 소셜 사진 복사 실패(5초 초과 등), **When** 가입을 마치면, **Then** 가입은 완료되고 기본 이미지와 "설정에서 직접 올릴 수 있어요" 안내가 보인다.
10. **Given** 가입 후 소셜 쪽 사진을 바꿈, **When** 우리 블로그를 보면, **Then** 복사본이 그대로 보인다.

### User Story 5 - 비밀번호 변경과 마지막 로그인 확인 (Priority: P2)

이메일 가입 회원이 로그인한 상태에서 현재 비밀번호를 확인하고 새 비밀번호로 바꾼다. 계정 화면에서는 마지막 로그인 일자와 로그인 방식을 보고 계정 도용을 알아챌 수 있다.

**Why this priority**: 로그인한 상태에서 비밀번호를 바꿀 유일한 방법이며 계정 보안 확인 수단이다.

**Independent Test**: 두 기기에서 로그인 → 한 기기에서 비밀번호 변경 → 다른 기기는 로그아웃, 현재 기기는 유지, 알림 메일 도착을 확인한다.

**Acceptance Scenarios**:

1. **Given** 이메일 가입 회원, **When** 현재 비밀번호와 규칙에 맞는 새 비밀번호(확인 포함)로 바꾸면, **Then** 다른 모든 기기가 로그아웃되고 지금 기기는 로그인이 유지되며 "본인이 아니라면 비밀번호 재설정" 안내 메일이 간다.
2. **Given** 새 비밀번호가 현재와 같거나 가입 비밀번호 규칙에 어긋남, **When** 저장하면, **Then** 거부된다.
3. **Given** 현재 비밀번호를 5번 연속 틀림, **When** 다시 시도하면, **Then** 15분 동안 거부된다.
4. **Given** 소셜 가입 회원, **When** 계정 화면을 보면, **Then** 비밀번호 변경 버튼이 없고, 요청을 보내도 거부된다.
5. **Given** 로그인한 회원, **When** 계정 화면을 보면, **Then** "마지막 로그인: 일자, 로그인 방식"이 보인다.

### Edge Cases

- 소셜 이름에서 닉네임을 미리 채울 때 허용되지 않는 문자를 지우고 10자로 자르며, 결과가 규칙에 맞지 않거나 이미 쓰이면 빈칸으로 둔다 (`Kim Min-seo` → `KimMinseo`, `A` → 빈칸).
- 닉네임 사용 가능 확인은 입력이 잠시 멈출 때만 하고 같은 IP 1분 30번으로 제한한다. 화면 확인은 안내용이고 저장 때 다시 검사한다.
- 소셜 사진 주소는 Google·GitHub의 정해진 사진 호스트의 보안 주소만 허용하고, 서버는 외부 사진 주소를 직접 요청하지 않는다.
- 탈퇴 유예 중인 회원의 닉네임은 묶여 있어 다른 사람이 쓸 수 없고, 익명 처리 뒤 풀린다 (021).
- 정지 회원은 로그인할 수 없으므로 프로필 수정·비밀번호 변경도 할 수 없다.

## Requirements *(mandatory)*

### Functional Requirements

**닉네임**

- **FR-001**: System MUST 닉네임 입력을 앞뒤 공백 제거·유니코드 정규화한 뒤 검사하고 정규화한 값을 저장한다.
- **FR-002**: System MUST 닉네임을 2~10자의 완성형 한글·영문·숫자로 제한하고, 한글 또는 영문을 1자 이상 요구한다 (자음·모음만, 공백, 특수문자, 이모지, 숫자만 불가).
- **FR-003**: System MUST 형식 → 글자 포함 → 예약어 → 금칙어 → 중복 순서로 검사하고, 단계마다 구분되는 안내를 준다. 가입과 프로필 수정이 같은 검사를 쓴다.
- **FR-004**: System MUST 대소문자를 무시해 닉네임 중복을 막고, 동시에 같은 닉네임을 요청해도 한 명만 성공시킨다. 화면에는 입력한 대소문자 그대로 보인다.
- **FR-005**: System MUST 금칙어를 원문·숫자 제거·숫자→영문 치환·`1`→`l` 네 가지 변형으로 검사하고 예외 목록 단어는 허용하며, 어떤 금칙어에 걸렸는지 알려 주지 않는다.
- **FR-006**: System MUST 예약어(관리자·운영자·admin·official 등)를 포함만 해도 거부하고, 금칙어와 같은 변형으로 검사한다.
- **FR-007**: System MUST 닉네임을 바꾼 뒤 30일 동안 다시 바꾸지 못하게 하고 다음 변경 가능일을 보여 준다. 가입 때 정한 닉네임은 변경으로 세지 않고, 같은 값 저장은 변경이 아니며, 대소문자만 바꾼 것은 변경이다.
- **FR-008**: System MUST 이전 닉네임을 즉시 다른 사람이 쓸 수 있게 하고, 글 상세 작성자 영역·댓글·블로그 상단에 닉네임과 `@블로그주소`를 함께 보여 준다.

**프로필 저장**

- **FR-009**: System MUST 프로필 수정 대상을 항상 로그인한 본인으로 정하고, 남의 프로필을 수정할 경로를 두지 않는다. 비회원은 로그인 화면으로 보낸다.
- **FR-010**: System MUST 닉네임·소개·프로필 사진을 한 번에 저장하고, 하나라도 실패하면 아무것도 저장하지 않으며 실패한 칸을 모두 알려 준다.
- **FR-011**: System MUST 블로그 주소와 이메일을 읽기 전용으로 보여 주고 바꿀 수 없게 한다.
- **FR-012**: System MUST 동시 저장은 나중에 저장한 쪽을 반영하고, 저장 결과를 목록·상세·댓글에 즉시 반영한다.
- **FR-013**: System MUST 이메일 인증 전 회원에게 닉네임·소개 수정은 허용하고 프로필 사진 업로드는 거부한다.

**소개**

- **FR-014**: System MUST 소개를 0~200자, 최대 4줄의 글자로만 받고(이모지 허용), 연달아 있는 빈 줄을 하나로 줄이며, 앞뒤 공백 제거·정규화 후 저장한다.
- **FR-015**: System MUST 소개를 표시할 때 HTML·Markdown을 해석하지 않고 글자로 보여 주며, 주소를 자동 링크로 바꾸지 않는다.
- **FR-016**: System MUST 소개에 닉네임과 같은 금칙어 필터를 적용한다(예약어 검사 제외).

**프로필 사진**

- **FR-017**: System MUST 프로필 사진을 jpg·png·gif·webp 10MB 이하 원본에서 브라우저가 정사각형으로 잘라 256×256 WebP(위치 정보 제거)로 만든 것만 받고, 서버는 형식·실제 파일 내용·정확한 크기·1MB 이하를 확인한다.
- **FR-018**: System MUST 본인이 올렸고, 프로필용이며, 삭제되지 않은 사진만 프로필에 연결하고, 회원당 현재 프로필 사진을 하나로 유지한다.
- **FR-019**: System MUST [저장]을 눌러야 사진을 연결하고, 연결하지 않은 업로드는 24시간 뒤, 교체·해제된 이전 사진은 7일 뒤 정리하며, 현재 연결된 프로필 사진은 정리하지 않는다.
- **FR-020**: System MUST 사진이 없으면 닉네임 첫 글자와 블로그 주소로 정해지는 8가지 배경색 중 하나로 기본 아이콘을 그리고, 라이트·다크 모드 모두 대비 4.5:1 이상을 지킨다.
- **FR-021**: System MUST 소셜 가입 때 사용자가 선택하면(기본 선택) 계정 생성 직후 브라우저가 소셜 사진을 받아 같은 규격으로 우리 저장소에 복사해 연결하고, 소셜 사진 주소는 저장하지 않는다. 복사에 실패해도 가입은 완료하고 기본 이미지로 둔다.
- **FR-022**: System MUST 소셜 사진 주소를 정해진 Google·GitHub 사진 호스트의 보안 주소일 때만 화면에 넘기고, 서버가 외부 사진 주소를 직접 요청하지 않게 한다.

**계정 설정**

- **FR-023**: 이메일 가입 회원은 현재 비밀번호를 확인한 뒤 001의 비밀번호 규칙에 맞는 새 비밀번호로 바꿀 수 있어야 한다(MUST). 현재와 같은 비밀번호는 거부한다.
- **FR-024**: System MUST 비밀번호 변경 때 현재 비밀번호를 5번 연속 틀리면 15분 잠근다.
- **FR-025**: System MUST 비밀번호를 바꾸면 다른 모든 기기를 로그아웃시키고, 지금 기기는 새 세션으로 유지하며, 알림 메일을 보낸다.
- **FR-026**: System MUST 소셜 가입 회원에게 비밀번호 변경을 보여 주지 않고 요청도 거부한다.
- **FR-027**: System MUST 본인 계정 화면에 마지막 로그인 일자와 로그인 방식을 보여 준다.

### Key Entities

- **회원 (member)**: 닉네임(대소문자 무시 유일), 닉네임 변경 일자, 소개, 블로그 주소(읽기 전용).
- **로그인 수단 (auth_identity)**: 로그인 방식, 비밀번호 해시(이메일 가입만), 마지막 로그인 일자.
- **사진 (image)**: 올린 사람, 용도(글·프로필), 상태(임시·연결), 연결 해제 시각. 회원의 현재 프로필 사진은 프로필 용도로 연결된 사진 하나다.
- **금칙어·예약어·예외 목록**: 팀이 검토해 관리하는 설정 목록. 닉네임·소개·블로그 주소가 함께 쓴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 자음·모음만, 공백, 특수문자, 이모지, 숫자만, 1자·11자 닉네임은 100% 거부되고, 분리형 한글을 붙여넣은 정상 닉네임은 100% 저장된다.
- **SC-002**: 대소문자만 다른 닉네임은 100% 중복으로 거부되고, 같은 닉네임 동시 요청 50건 중 성공은 정확히 1건이다.
- **SC-003**: 숫자를 끼워 넣거나 숫자로 글자를 바꾼 금칙어 시험 목록이 100% 거부되고, 예외 단어 목록은 100% 허용되며, 거부 문구에 걸린 단어가 0건 나타난다.
- **SC-004**: 예약어를 포함한 닉네임 시험 목록이 100% 거부된다.
- **SC-005**: 닉네임을 바꾼 뒤 30일 안의 변경 요청은 100% 거부된다.
- **SC-006**: 한 칸이라도 실패한 프로필 저장 뒤 프로필의 어떤 값도 바뀌지 않는다(0건 부분 저장). 블로그 주소·이메일을 바꾸는 경로는 0개다.
- **SC-007**: XSS 시험 문자열을 넣은 소개가 블로그 상단에서 실행되는 경우가 0건이다.
- **SC-008**: 256×256이 아닌 사진, 남의 사진, 글용 사진이 프로필에 연결되는 경우가 0건이다.
- **SC-009**: 연결된 프로필 사진이 정리 작업으로 지워지는 경우가 0건이고, 교체된 이전 사진은 7일 뒤 정리 대상이 된다.
- **SC-010**: 소셜 사진을 가져온 계정의 프로필 사진 주소는 100% 우리 저장소 주소다.
- **SC-011**: 비밀번호를 바꾸면 다른 기기는 다음 요청부터 로그아웃되고 알림 메일이 1통 간다. 소셜 계정의 비밀번호 변경 요청은 100% 거부된다.
- **SC-012**: 회원의 90% 이상이 설정 화면에서 1분 안에 프로필 변경을 마친다.

## Assumptions

- 가입·로그인·비밀번호 규칙·재설정은 [001-member-auth](../001-member-auth/spec.md)를 따르고, 이 spec은 같은 비밀번호 규칙을 재사용한다.
- 사진 업로드의 공통 흐름(직접 업로드, 사용자당 1분 20장 제한, 정리 작업)은 이미지 업로드 spec(C-IMG-1)을 따른다.
- 설정 화면의 "새 글 기본 공개 범위"는 공개 범위 spec(C-POST-4), AI 동의 철회는 AI 태그 추천 spec, 친구 최근 활동 공개 설정은 친구 관련 spec이 다룬다.
- 회원 탈퇴 버튼과 그 이후 흐름은 [021-member-withdraw](../021-member-withdraw/spec.md)가 다룬다.
- 이메일 변경, 이전 닉네임을 일정 기간 묶어 두는 기능, 소개의 외부 링크 칸, 운영자 화면에서의 금칙어 관리는 범위 밖(개인 확장 또는 이후 단계)이다.
- 금칙어 목록은 공개 비속어 목록을 팀이 검토해 쓰며, 서비스 이름이 정해지면 예약어에 추가한다.
- 2026-10-07 결정에 따라 회원 행에 프로필 사진을 직접 가리키는 값을 두지 않고, 프로필 용도로 연결된 사진으로 현재 프로필 사진을 정한다 (11 §4-4·§7의 이전 표현보다 우선).
