# Feature Specification: Markdown 글쓰기·임시저장·발행 (002-write-publish)

**Feature Branch**: `002-write-publish`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "작성자는 Markdown으로 제목과 본문을 쓰고 발행 화면과 같은 미리보기를 본다. 작성 중인 글은
자동으로 임시저장되어 나중에 이어 쓸 수 있다. 발행하면 공개/비공개를 고를 수 있고, 발행 글을 고치는 동안에도 독자는
마지막 발행본을 읽는다. 상세 규칙은 docs/04-draft-and-image.md, docs/05-publish.md, docs/06-visibility.md,
docs/12-content-sanitize.md를 따른다. MVP 자동 저장은 서버 저장과 수동 저장을 먼저 하고, 브라우저 오프라인 복구는 다음
단계로 미룬다(2026-10-07 확정)."

**관련 기능 ID**: C-POST-1, C-POST-2(서버 저장 범위), C-POST-3, C-POST-4(PUBLIC/PRIVATE)

**우선순위 단계**: MVP

**선행 기능**: `001-auth-ownership` (로그인한 본인, 소유 권한, 내 글 관리)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Markdown으로 쓰고 발행한다 (Priority: P1)

로그인한 작성자가 [새 글]을 눌러 제목과 Markdown 본문을 쓰고, 발행 화면과 똑같은 미리보기를 확인한 뒤 공개 범위를 골라
발행한다. 발행하면 그 글은 바뀌지 않는 고유 주소를 갖는다.

**Why this priority**: velog형 블로그의 본질이다. 이것만 있어도 "개발자가 Markdown으로 글을 써서 내보낸다"는 핵심 가치가
증명된다.

**Independent Test**: 새 글을 쓰고 발행해 `/@handle/posts/{번호}` 주소가 생기는지, 공개 글이면 비회원도 그 내용을 읽을 수
있는지, 미리보기와 발행 결과가 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 작성자, **When** [새 글]을 누르면, **Then** 임시글이 하나 만들어지고 에디터가 열리며 공개 범위는 본인의
   기본 공개 범위(처음엔 전체 공개)로 시작한다.
2. **Given** 본문에 제목·목록·인용·강조·취소선·링크·표·체크리스트·코드 블록을 씀, **When** 미리보기를 보면, **Then** 발행했을
   때와 똑같은 결과가 보이고 코드에는 강조 표시가 된다.
3. **Given** 제목과 본문을 채움, **When** 전체 공개로 발행하면, **Then** 글이 고유 주소를 갖고 비회원도 읽을 수 있다.
4. **Given** 제목이나 본문이 비어 있음, **When** 발행하면, **Then** 발행되지 않고 비어 있는 항목마다 이유가 표시되며 글은
   임시글로 남는다.
5. **Given** 발행 버튼, **When** 연달아 여러 번 누르거나 같은 요청이 다시 전송되면, **Then** 한 번만 발행된다.
6. **Given** 비공개로 발행, **When** 다른 사람이나 비회원이 주소를 열면, **Then** 존재하지 않는 글과 똑같이 보인다.

---

### User Story 2 - 쓰던 글을 저장하고 이어 쓴다 (Priority: P2)

작성 중인 글은 따로 누르지 않아도 서버에 자동으로 저장되고, [저장]을 누르면 즉시 저장된다. 나중에 내 글 관리에서 임시글을
다시 열어 이어 쓴다. 같은 글을 다른 탭이나 기기에서 고치면 몰래 덮어쓰지 않고 알려준다.

**Why this priority**: 저장이 없으면 긴 기술 글을 쓰기 어렵다. 다만 발행만으로도 가치가 생기므로 P1 다음이다.

**Independent Test**: 글을 쓰다가 창을 닫고 내 글 관리에서 다시 열어 마지막 자동 저장 내용이 남아 있는지, 두 탭에서 같은
글을 고쳐 충돌 안내가 뜨는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 작성 중인 글, **When** 입력을 잠시 멈추면, **Then** 바뀐 제목과 본문이 서버에 자동 저장되고 화면에 "저장 중 →
   저장됨"이 표시된다.
2. **Given** 작성 중인 글, **When** [저장]을 누르면, **Then** 그 내용이 즉시 영구 저장된다.
3. **Given** 저장된 임시글, **When** 나중에 내 글 관리에서 다시 열면, **Then** 마지막으로 저장된 내용부터 이어 쓸 수 있다.
4. **Given** 같은 글을 두 탭에서 엶, **When** 한쪽이 먼저 저장한 뒤 다른 쪽이 저장하면, **Then** 나중 쪽은 덮어쓰지 않고
   "다른 탭이나 기기에서 수정되었어요" 안내와 함께 두 내용을 나란히 비교해 보여주며, 사용자는 [편집 중인 내용으로 저장]
   (확인 문구 후) / [저장된 내용 불러오기] / [새 임시글로 따로 저장] 중에서 고른다.
5. **Given** 저장하지 않은 변경이 있음, **When** 페이지를 떠나려 하면, **Then** 안내가 뜬다.
6. **Given** 제목·본문이 모두 비어 있고 만든 지 24시간이 지난 임시글, **When** 정리 시점이 되면, **Then** 자동으로 지워진다.

---

### User Story 3 - 발행한 글을 고치는 동안 독자는 발행본을 본다 (Priority: P3)

작성자가 발행한 글을 수정하기 시작하면 고치는 내용은 별도 작업본에 저장되고, 독자는 다시 발행할 때까지 마지막 발행본을
읽는다. 다시 발행하면 주소와 최초 공개일은 그대로이고 "수정됨"이 표시된다.

**Why this priority**: 이미 공유한 글의 링크와 순서가 흔들리지 않게 하는 velog형의 차별점이지만, 첫 발행이 먼저 되어야 한다.

**Independent Test**: 발행한 글을 고쳐 저장한 상태에서 비회원으로 열어 예전 내용이 보이는지, 다시 발행한 뒤 새 내용과
"수정됨"이 보이고 주소·최초 공개일이 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 발행한 글, **When** 작성자가 고쳐 저장하면, **Then** 독자에게는 마지막 발행본이 계속 보이고 내 글 관리에는
   "수정 중"으로 표시된다.
2. **Given** 수정 중인 글, **When** 다시 발행하면, **Then** 새 내용이 보이고, 주소·최초 발행일·최초 공개일은 그대로이며,
   글에 "수정됨 · 날짜"가 표시된다.
3. **Given** 수정 중인 글, **When** [변경 취소]를 누르면, **Then** 작업본이 지워지고 발행본은 그대로다.
4. **Given** 발행한 글, **When** 임시글로 되돌리려 하면, **Then** 그런 기능은 없고 비공개로 바꾸도록 안내한다.

---

### User Story 4 - 공개 범위를 바꾼다 (Priority: P4)

작성자는 발행한 글을 다시 발행하지 않고도 전체 공개와 비공개 사이에서 바로 바꿀 수 있다.

**Why this priority**: 글을 잠시 내리는 유일한 방법이라 필요하지만, 발행 흐름이 먼저 있어야 한다.

**Independent Test**: 공개 글을 비공개로 바꿔 비회원에게 없는 글로 보이는지, 다시 공개해 목록 위치가 처음 공개한 시점
그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 전체 공개 글, **When** 비공개로 바꾸면, **Then** 다시 발행하지 않아도 즉시 작성자 외에는 없는 글로 보이고,
   "수정됨" 표시와 수정 중인 작업본은 그대로다.
2. **Given** 공개 → 비공개 → 공개로 바꾼 글, **When** 목록에 나올 때, **Then** 처음 공개한 시점의 위치에 나온다.
3. **Given** 비공개로 발행한 글, **When** 나중에 처음 공개하면, **Then** 목록에서 공개한 시점의 위치에 나온다.

---

### Edge Cases

- 남의 글을 발행·수정·저장·공개 범위 변경하려 하면? → 없는 글과 똑같이 응답하고 글은 바뀌지 않는다.
- 본문에 HTML이나 스크립트를 직접 쓰면? → 글자로 보이고 실행되지 않는다. 제목도 마찬가지다.
- 제목에 보이지 않는 글자·방향 뒤집기 문자·제어 문자가 섞이면? → 제거하고 저장한다.
- 본문에 외부 링크를 넣으면? → 새 탭으로 열리고, 검색 엔진에 대한 신뢰 표시 없이 열린다.
- 본문에 외부 이미지 주소나 남이 올린 사진 주소를 넣으면? → 이미지가 아니라 링크로 보인다.
- 본문의 `#` 제목은? → 글 제목보다 한 단계 낮은 제목으로 보인다(본문에 가장 큰 제목이 생기지 않는다).
- 목록·인용이 20단계 넘게 중첩되거나 변환이 1초를 넘으면? → 발행되지 않고 이유가 안내된다.
- 본문이 100,000자를 넘거나 제목이 100자를 넘으면? → 저장·발행되지 않고 이유가 안내된다.
- 자동 저장 중 서버 저장소가 일시적으로 멈추면? → 저장은 영구 저장소로 바로 이어지고 작성자는 계속 쓸 수 있다.
- 네트워크가 끊기면? → 이번 범위에서는 "오프라인" 상태를 표시하고 연결되면 다시 저장을 시도한다. 브라우저에 남겨 두었다가
  복구하는 기능은 다음 단계다(가정 A-1).
- 로그아웃하면? → 그 브라우저에 남은 본인의 작성 데이터가 지워진다(001과 같은 규칙).

## Requirements *(mandatory)*

### Functional Requirements

**작성·미리보기 (C-POST-1, docs/12)**

- **FR-001**: 로그인하고 001의 가입을 마친 사용자만 글을 만들 수 있어야 한다. [새 글]을 누르면 임시글을 먼저 만들고, 공개
  범위 초기값은 작성자의 기본 공개 범위여야 한다.
- **FR-002**: 본문은 Markdown 원문으로 저장해야 하며 CommonMark와 GFM(표·취소선·체크리스트·주소 자동 링크)을 지원해야 한다.
  각주·수식·Mermaid·임베드는 지원하지 않는다.
- **FR-003**: 미리보기는 발행 결과와 같은 변환 규칙으로 만들어야 한다.
- **FR-004**: 본문에 직접 쓴 HTML은 글자로 보여야 하며, 어떤 입력으로도 독자의 화면에서 스크립트가 실행되지 않아야 한다.
- **FR-005**: 링크는 `http`·`https`·`mailto`·상대 경로만 허용하고, 외부 링크는 새 탭에서 열리며 원래 페이지 정보와 신뢰
  표시를 넘기지 않아야 한다.
- **FR-006**: 이미지는 작성자 본인이 올린 우리 저장소 사진만 이미지로 보이고, 외부 이미지와 남이 올린 사진은 링크로 바뀌어야
  한다. (사진 업로드 기능 자체는 MVP 다음 단계)
- **FR-007**: 본문의 제목 단계는 한 단계씩 낮춰 보여야 하고, 코드 블록은 강조 표시가 실패해도 읽혀야 한다.
- **FR-008**: 목록·인용 중첩 20단계 초과 또는 변환 1초 초과인 본문은 발행을 거부해야 한다.
- **FR-009**: 글 제목은 글자로만 다루고, 유니코드 정규화와 보이지 않는 글자·방향 뒤집기 문자·제어 문자 제거를 거쳐야 한다.
- **FR-010**: 변환 규칙이 바뀌면 기존 발행 글을 새 규칙으로 다시 만들 수 있어야 한다.

**저장 (C-POST-2 중 MVP 범위, docs/04)**

- **FR-011**: 제목과 본문의 변경을 입력이 3초 멈추면, 계속 입력 중이면 최대 30초마다 서버에 자동 저장해야 하며, 자동 저장된
  내용은 1분 안에 영구 저장소에 반영되어야 한다. 탭이 가려지거나 페이지를 떠날 때도 저장을 시도해야 한다.
- **FR-012**: [저장]과 [발행]은 즉시 영구 저장해야 한다.
- **FR-013**: 저장 상태(저장 중·저장됨·오프라인·충돌)를 화면에 표시해야 한다.
- **FR-014**: 각 저장은 편집 버전을 확인해 오래된 내용이 새 내용을 덮어쓰지 못하게 해야 하며, 충돌하면 두 내용을 비교해
  보여주고(바뀐 부분을 색과 기호로 함께 표시) 사용자가 고른 경우에만 덮어써야 한다. 덮어쓰기 전에는 확인 문구를 띄워야 한다.
- **FR-015**: 미저장 변경이 있는 채로 페이지를 떠나면 안내해야 한다.
- **FR-016**: 제목·본문이 모두 비어 있고 만든 지와 마지막 수정 후 모두 24시간이 지난 임시글은 자동으로 완전 삭제해야 한다.
- **FR-017**: 자동 저장 대상은 제목과 본문만이다.

**발행·다시 발행 (C-POST-3, docs/05)**

- **FR-018**: 발행할 때 제목(앞뒤 공백 제거 후 1~100자)과 본문(1~100,000자)을 검증하고, 실패한 항목을 모두 한 번에 알려줘야
  한다. 실패하면 글은 임시글로 남아야 한다.
- **FR-019**: 발행된 글은 `/@handle/posts/{번호}` 주소를 가지며, 이 주소는 다시 발행해도 바뀌지 않아야 한다.
- **FR-020**: 발행할 때 요약(코드·이미지·표를 뺀 글자 앞 200자)을 자동으로 만들어야 한다.
- **FR-021**: 같은 발행 요청이 연달아 오거나 다시 전송되어도 한 번만 발행되어야 한다.
- **FR-022**: 발행한 글의 수정 내용은 별도 작업본에 저장하고, 다시 발행할 때까지 독자에게는 마지막 발행본을 보여야 한다.
  [변경 취소]는 작업본만 지워야 한다.
- **FR-023**: 다시 발행하면 주소·최초 발행일·최초 공개일·반응 수는 유지하고, 다시 발행한 일자를 기록해 "수정됨"으로
  표시해야 한다.
- **FR-024**: 발행된 글을 임시글로 되돌리는 기능은 두지 않는다.
- **FR-025**: 글 내용의 수정·발행은 작성자만 할 수 있어야 하고, 남의 요청은 없는 글과 같은 응답으로 거부해야 한다.

**공개 범위 (C-POST-4, docs/06)**

- **FR-026**: 공개 범위는 전체 공개(`PUBLIC`)와 비공개(`PRIVATE`) 두 가지다. 친구 공개는 이번 범위가 아니다.
- **FR-027**: 공개 범위는 다시 발행 없이 바로 바꿀 수 있어야 하며, 바꿔도 "수정됨" 표시·작업본·반응 기록은 그대로여야 한다.
- **FR-028**: 처음으로 "발행 + 전체 공개"가 된 시각을 한 번만 기록하고, 이후 공개 범위를 껐다 켜도 바꾸지 않아야 한다. 목록
  순서는 이 시각을 따른다.
- **FR-029**: 비공개 글은 작성자 외에는 존재하지 않는 글과 똑같이 보여야 한다(상세·링크 미리보기 포함). 목록 노출 규칙은 003이
  다룬다.

## Success Criteria *(mandatory)*
