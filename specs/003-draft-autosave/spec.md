## User Scenarios & Testing *(mandatory)*

### User Story 1 - 임시글을 만들고 다시 열어 이어 쓰기 (Priority: P1)

작성자가 [새 글]을 누르면 곧바로 본인만 보는 임시글이 생긴다. 제목·본문을 쓰다가 [저장]을 누르거나 창을 닫아도, 나중에 내 글 관리에서 그 임시글을 열어 이어 쓸 수 있다.

**Why this priority**: C-POST-2의 공통 완료 기준 "임시글을 다시 열어 이어 쓸 수 있다" 그 자체다. 이것만 있어도 글을 여러 번에 나눠 쓸 수 있다.

**Independent Test**: 테스트 회원이 새 글을 만들어 제목·본문을 입력하고 수동 저장한 뒤 로그아웃·재로그인하여 내 글 관리에서 같은 글을 열어 내용이 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 이메일 인증 회원, **When** [새 글]을 누르면, **Then** 본인 소유의 빈 임시글이 즉시 만들어지고 편집 화면이 열린다.
2. **Given** 내용을 입력한 임시글, **When** [저장]을 누르면, **Then** 내용이 그 즉시 영구 저장되고 "저장됨 + 시각"이 표시된다.
3. **Given** 저장된 임시글, **When** 다른 날 내 글 관리에서 그 글을 열면, **Then** 마지막으로 저장된 제목·본문이 그대로 나타나고 이어서 편집할 수 있다.
4. **Given** 다른 회원의 임시글, **When** 그 글의 편집·저장을 시도하면, **Then** 없는 글과 똑같이 "찾을 수 없음"으로 응답하고 내용은 바뀌지 않는다.

---

### User Story 2 - 누르지 않아도 자동 저장되고 상태가 보인다 (Priority: P2)

작성자가 [저장]을 누르지 않아도 입력이 잠깐 멈출 때마다 내용이 이 기기에, 그다음 서버에, 그다음 영구 저장소에 차례로 저장된다. 화면에는 지금 내용이 어디까지 안전한지가 글자로 표시된다.

**Why this priority**: 저장 버튼을 잊어도 글을 잃지 않는 것이 자동 저장의 존재 이유다. 상태 표시가 없으면 사용자가 안전 여부를 판단할 수 없다.

**Independent Test**: 저장 버튼을 누르지 않고 입력한 뒤 3초 기다려 상태 표시가 "저장됨"으로 바뀌는지, 1분 뒤 다른 기기에서 열어도 내용이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 편집 중, **When** 입력이 1초 멈추면, **Then** 내용이 이 기기에 저장되고 "이 기기에 저장됨 (동기화 대기)"가 표시된다.
2. **Given** 기기에만 저장된 변경, **When** 입력이 3초 멈추거나 계속 입력 중 30초가 지나면, **Then** 바뀐 내용이 있을 때만 서버로 보내지고 "저장됨 + 시각"이 표시된다.
3. **Given** 서버에 보낸 내용, **When** 1분 안에, **Then** 영구 저장소에 반영되어 서버 쪽 버퍼가 사라져도 남는다.
4. **Given** 서버로 아직 못 보낸 내용이 있는 상태, **When** 페이지를 떠나려 하면, **Then** 떠나기 전에 확인을 받는다.
5. **Given** 탭이 가려지거나 페이지를 떠날 때, **When** 미전송 내용이 있으면, **Then** 그 순간 서버 전송을 한 번 시도한다.
6. **Given** 태그를 바꾼 상태, **When** 자동 저장이 일어나면, **Then** 제목·본문만 저장되고 태그는 발행할 때 확정된다.

---

### User Story 3 - 오프라인·장애에도 글이 사라지지 않는다 (Priority: P3)

지하철에서 연결이 끊기거나 서버 일부가 고장 나도 작성자는 계속 쓸 수 있고, 연결이 돌아오면 자동으로 동기화된다.

**Why this priority**: 실제로 글을 잃는 대부분의 경우가 네트워크·서버 장애다. 핵심 저장(P1·P2)이 있어야 의미가 있으므로 그다음 순위다.

**Independent Test**: 오프라인으로 전환해 입력 → 상태 표시가 "오프라인"인지 확인 → 브라우저를 닫았다 다시 열어 내용 확인 → 온라인으로 돌리면 자동으로 "저장됨"이 되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 오프라인, **When** 계속 입력하면, **Then** 이 기기에 계속 저장되고 "오프라인 — 이 기기에 저장 중, 연결되면 자동 동기화"가 표시된다.
2. **Given** 오프라인에서 쓴 내용이 남은 채 브라우저를 닫은 경우, **When** 같은 계정으로 그 글을 다시 열면, **Then** 이 기기의 미전송 내용이 "이 기기에 저장되지 않은 변경을 불러왔어요" 안내와 함께 복구된다.
3. **Given** 서버 전송 실패, **When** 재시도하면, **Then** 2초에서 시작해 최대 60초까지 간격을 늘려 가며 무작위 지연을 섞어 재시도하고, 그동안 내용은 기기에 남는다.
4. **Given** 서버의 임시 버퍼가 고장 난 상태, **When** 자동 저장이 오면, **Then** 영구 저장소에 직접 저장되어 작성자는 차이를 느끼지 않는다.
5. **Given** 브라우저 데이터가 지워진 경우, **When** 글을 다시 열면, **Then** 서버에 최대 30초 이전까지의 내용이 남아 있다.

---

### User Story 4 - 여러 탭·기기에서 같은 글을 고쳐도 몰래 덮어쓰지 않는다 (Priority: P4)

같은 글을 노트북과 휴대폰에서 번갈아 고치면, 시스템은 어느 쪽 내용도 몰래 덮어쓰지 않고 두 내용을 나란히 비교해 보여 준 뒤 사용자가 고르게 한다.

**Why this priority**: 빈도는 낮지만 생기면 한쪽의 작업이 통째로 사라진다. 편집 버전 판정이 P1~P3 위에 얹히므로 그다음 순위다.

**Independent Test**: 같은 글을 두 탭에서 열고 A 탭에서 저장한 뒤 B 탭에서 입력해 배너·비교 창이 뜨는지, 세 선택지 각각의 결과가 설명과 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 다른 탭이 먼저 저장한 글, **When** 이 탭의 자동 저장이 오면, **Then** 저장되지 않고 편집은 막지 않은 채 "다른 탭이나 기기에서 수정되었어요(시각). 지금 내용은 이 기기에만 저장되고 있어요 [비교하기]" 배너가 뜬다.
2. **Given** 충돌 배너가 뜬 상태, **When** [비교하기]·수동 저장·발행 중 하나를 누르면, **Then** 저장된 내용과 편집 중인 내용이 줄 단위(바뀐 줄 안은 단어 단위)로 비교되어, 지운 부분은 "−", 더한 부분은 "+" 기호와 색으로 함께 표시된다. 제목이 다르면 제목도 비교한다.
3. **Given** 비교 창, **When** [편집 중인 내용으로 저장]을 누르면, **Then** "시각에 저장된 내용이 지금 편집 중인 내용으로 바뀌어요" 확인에 동의한 경우에만 덮어쓴다.
4. **Given** 비교 창, **When** [저장된 내용 불러오기]를 누르면, **Then** 편집기가 저장된 내용으로 바뀌고 편집 중이던 내용은 이 기기에 7일간 백업된다.
5. **Given** 비교 창, **When** [새 임시글로 따로 저장]을 누르면, **Then** 편집 중인 내용으로 새 임시글이 생기고 원래 글은 저장된 내용 그대로다.
6. **Given** 비교 창, **When** 닫으면, **Then** 계속 편집할 수 있고 서버 전송은 멈춘 채 배너가 유지된다.
7. **Given** 이 기기에 미전송 내용이 있고 그 내용이 서버의 현재 버전에서 출발한 경우, **When** 글을 열면, **Then** 충돌로 보지 않고 미전송 내용을 그대로 이어 쓴다. 출발 버전이 다르면 바로 비교 창을 띄운다.

---

### User Story 5 - 발행한 글을 고치는 동안의 작업본 (Priority: P5)

이미 발행한 글을 고치면 고치는 내용은 별도 작업본에 저장되고, 독자는 마지막 발행본을 계속 읽는다. 작성자는 변경을 취소할 수 있다.

**Why this priority**: 발행 글 수정은 05 발행 spec과 맞물린다. 저장 경로가 같으므로 이 spec에서 저장 규칙을 정한다.

**Independent Test**: 발행된 글을 고쳐 자동 저장되게 한 뒤 비로그인 독자로 열어 이전 내용인지 확인하고, 작성자가 다시 열면 작업본이 열리는지, 변경 취소 후 발행본만 남는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 발행된 글을 고친 상태, **When** 자동 저장·수동 저장이 영구 반영되면, **Then** 작업본에만 저장되고 독자에게는 마지막 발행본이 보인다.
2. **Given** 작업본이 있는 글, **When** 작성자가 다시 열면, **Then** 작업본이 열리고 내 글 관리에는 "수정 중"으로 표시된다.
3. **Given** 작업본이 있는 글, **When** [변경 취소]를 누르면, **Then** 작업본과 서버 버퍼가 지워지고 독자가 보던 발행본은 그대로다.

---

### User Story 6 - 공용 PC 정리와 빈 임시글 정리 (Priority: P6)

공용 PC에서 로그아웃하면 그 사람의 기기 저장 내용이 모두 지워진다. 아무것도 쓰지 않고 버려진 빈 임시글은 자동으로 정리된다.

**Why this priority**: 개인정보 보호와 데이터 정리. 핵심 흐름이 동작한 뒤에 붙는다.

**Independent Test**: 글을 쓰다 로그아웃한 뒤 같은 브라우저에서 다른 계정으로 로그인해 이전 사용자의 내용·백업이 남지 않았는지 확인한다. 빈 임시글을 만들고 24시간을 경과시킨 뒤 정리 작업 후 사라졌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기기에 작업 내용·백업이 남은 회원, **When** 로그아웃하면, **Then** 그 회원의 기기 저장 내용과 백업이 모두 지워진다.
2. **Given** 한 브라우저를 두 계정이 번갈아 쓰는 경우, **When** 각자 글을 열면, **Then** 다른 계정의 기기 저장 내용은 보이지도 섞이지도 않는다.
3. **Given** 제목·본문이 모두 비었고 만든 지·마지막 수정 후 모두 24시간이 지났고 서버 버퍼에도 내용이 없는 임시글, **When** 매일 정리 작업이 돌면, **Then** 휴지통을 거치지 않고 완전히 삭제된다.
4. **Given** 제목이나 본문 중 하나라도 있는 임시글, **When** 정리 작업이 돌면, **Then** 지워지지 않는다.

---

### Edge Cases

- 같은 순간 두 탭의 첫 자동 저장이 동시에 도착 → 하나만 받아들여지고 다른 하나는 충돌로 처리된다.
- 영구 반영 작업이 옛 버전을 늦게 반영하려 함 → 더 새로운 버전을 덮어쓰지 않는다.
- 영구 반영 도중 새 자동 저장이 들어옴 → 새 내용은 버퍼에 남아 다음 반영 때 처리된다.
- 서버 버퍼가 다시 시작됨 → 최대 약 1초 분량만 영향받고, 기기에 남은 내용으로 복구된다.
- 서버 버퍼 메모리가 가득 참 → 자동 저장 내용이 밀려 지워지지 않는다. 쓰기가 실패하면 기기에 남아 재시도한다.
- 사용자당 자동 저장이 5초에 1번을 넘거나 한 번에 1MB를 넘으면 → 거부되고, 기다릴 시간 또는 크기 초과가 안내된다. 내용은 기기에 남는다.
- 업로드가 끝나지 않은 사진 표시가 본문에 있음 → 자동 저장은 그대로 된다 (발행만 막는다, 005·004 spec).
- 영구 반영 작업이 여러 서버에서 동시에 돌려 함 → 한 번만 실행된다.
- 발행이 실패(커밋 실패)함 → 서버 버퍼 내용은 지워지지 않는다.
- 로그인하지 않았거나 이메일 인증 전인 회원 → 임시글을 만들거나 저장할 수 없다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 이메일 인증을 마친 회원은 [새 글]로 본인 소유의 임시글을 즉시 만들 수 있어야 하며, 이 글은 처음부터 편집 버전 0을 가진다.
- **FR-002**: 임시글은 작성자 본인에게만 보이고 편집·저장할 수 있어야 한다. 그 밖의 사람에게는 없는 글과 같은 "찾을 수 없음"으로 응답해야 한다. 작성자는 요청 값이 아니라 로그인 정보로만 판정한다.
- **FR-003**: 영구 저장소가 항상 원본이어야 한다. 서버 버퍼와 기기 저장은 보조이며, 버퍼의 보관 기한이 지나도 저장된 임시글은 사라지지 않아야 한다.
- **FR-004**: 시스템은 입력이 1초 멈출 때마다 제목·본문을 이 기기에 저장해야 한다 (설정값).
- **FR-005**: 시스템은 바뀐 내용이 있을 때만, 입력이 3초 멈추거나 계속 입력 중이면 최대 30초마다, 그리고 탭이 가려지거나 페이지를 떠날 때 서버로 보내야 한다 (설정값).
- **FR-006**: 한 탭은 서버 전송을 한 번에 하나씩만 보내 순서가 뒤바뀌지 않아야 한다.
- **FR-007**: 서버로 받은 자동 저장 내용은 1분 이내에 영구 저장소에 반영되어야 한다 (설정값). 서버 버퍼는 저장할 때마다 24시간 보관 기한이 갱신된다.
- **FR-008**: 수동 저장과 발행은 버퍼를 거치지 않고 즉시 영구 저장소에 반영되어야 한다.
- **FR-009**: 자동 저장 대상은 제목과 본문뿐이다. 태그는 발행할 때 확정한다.
- **FR-010**: 서버는 저장이 받아들여질 때마다 편집 버전을 1 올리고, 요청이 출발한 버전과 현재 버전이 같을 때만 저장해야 한다. 다르면 저장하지 않고 서버 쪽 최신 내용·버전·저장 시각을 돌려줘야 한다. 이 확인과 저장은 나눌 수 없는 한 동작이어야 한다.
- **FR-011**: 영구 반영 작업은 더 오래된 버전으로 새 버전을 덮어써서는 안 되며, 여러 서버에서도 한 번만 실행되어야 한다.
- **FR-012**: 임시글의 자동 저장은 글 자체에, 발행한 글의 자동 저장·수동 저장은 글당 하나인 작업본에 반영되어야 한다. 독자는 작업본이 있어도 마지막 발행본만 본다.
- **FR-013**: 작업본이 있는 글을 작성자가 열면 작업본을 불러오고, 내 글 관리에 "수정 중"으로 표시해야 한다.
- **FR-014**: [변경 취소]는 작업본과 서버 버퍼를 지우고 발행본을 그대로 두어야 한다.
- **FR-015**: 편집 화면은 저장 상태를 "저장됨 + 시각", "이 기기에 저장됨 (동기화 대기)", "오프라인 — 연결되면 자동 동기화", "다른 곳에서 수정됨 — 이 기기에만 저장 중 [비교하기]" 중 하나로, 색만이 아닌 글자로 표시해야 한다.
- **FR-016**: 전송에 실패하면 2초부터 최대 60초까지 간격을 늘리고 무작위 지연을 섞어 자동 재시도하며, 그동안 내용은 기기에 남아야 한다. 연결이 돌아오면 자동으로 동기화한다.
- **FR-017**: 미전송 내용이 있을 때 페이지를 떠나려 하면 확인을 받아야 한다.
- **FR-018**: 글을 열 때 기기에 미전송 내용이 있으면, 출발 버전이 서버 현재 버전과 같으면 안내 후 이어 쓰고, 다르면 즉시 비교 창을 띄워야 한다.
- **FR-019**: 충돌이 감지되면 편집을 막지 않고 서버 전송만 멈춘 채 기기 저장은 계속하고 배너를 띄워야 한다. 서버는 어느 쪽 내용도 몰래 덮어쓰지 않는다.
- **FR-020**: 비교 창은 저장된 내용과 편집 중인 내용을 줄·단어 단위로 비교해 기호(−/+)와 색으로 강조하고, 넓은 화면은 좌우, 좁은 화면은 위아래 합친 보기로 보여 주며, 긴 글은 이전·다음 차이로 이동하고 바뀌지 않은 긴 구간은 접어야 한다.
- **FR-021**: 비교 창은 결과를 이름에 적은 세 선택지 — [편집 중인 내용으로 저장](확인 문구 동의 후에만 덮어씀), [저장된 내용 불러오기](편집 중 내용을 기기에 7일 백업), [새 임시글로 따로 저장] — 와 닫기를 제공해야 한다.
- **FR-022**: 기기 저장 내용은 회원별로 분리되어야 하고, 로그아웃할 때 그 회원의 작업 내용·백업을 모두 지워야 한다. 인증 수단은 기기 저장소에 남기지 않는다.
- **FR-023**: 기기 저장 내용은 발행이 성공하거나, 미전송 내용 없이 편집기를 떠날 때 지워야 한다.
- **FR-024**: 발행 성공 후 서버 버퍼는 발행이 확정된 다음에만, 그리고 발행 때 확인한 버전 이하일 때만 지워야 한다 (발행 중 들어온 다른 탭의 내용 보존).
- **FR-025**: 서버는 사용자당 자동 저장을 5초에 1번, 한 번에 1MB까지만 받아야 하며, 넘으면 다시 보낼 수 있는 시점 또는 크기 초과를 알려야 한다.
- **FR-026**: 서버 버퍼가 고장 나면 자동 저장은 영구 저장소에 직접 저장하고 버전 확인도 영구 저장소 기준으로 해야 한다.
- **FR-027**: 매일 한 번, 제목·본문이 모두 비었고 만든 지와 마지막 수정 후 모두 24시간이 지났으며 서버 버퍼에도 내용이 없는 임시글을 완전히 삭제해야 한다. 작성자가 빈 임시글을 직접 지우면 휴지통 없이 바로 완전 삭제한다.

### Key Entities

- **글(post)**: 임시 상태일 때 제목·본문 원문·편집 버전·만든 시각·수정 시각을 가진다. 작성자 한 명에 속한다.
- **작업본(post_draft)**: 발행된 글을 고치는 중의 제목·본문과 편집 버전. 글당 최대 하나, 다시 발행·변경 취소 때 사라진다.
- **서버 자동 저장 버퍼**: 글별 최근 자동 저장 내용·소유자·편집 버전·저장 시각. 24시간 보관, 영구 반영 대기 목록을 함께 가진다.
- **기기 저장 항목**: 회원·글별 제목·본문·출발 버전·미전송 여부·업로드 대기 사진·수정 시각. 충돌 때 7일 백업 항목이 따로 생긴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 수동 저장한 임시글은 로그아웃·재로그인·다른 기기에서 다시 열어도 100% 같은 내용으로 열린다.
- **SC-002**: 정상 연결에서 입력을 멈춘 뒤 서버 저장 완료 표시까지 5초 이내, 영구 저장소 반영까지 90초 이내다.
- **SC-003**: 네트워크 단절·서버 버퍼 재시작·서버 버퍼 장애 각각에서, 기기가 살아 있으면 잃는 입력은 0자다. 기기 데이터가 지워진 경우에도 잃는 입력은 최대 30초 분량이다.
- **SC-004**: 같은 글을 두 탭에서 고치는 시험 100회에서 사용자 동의 없이 한쪽 내용이 덮어써지는 경우가 0회다.
- **SC-005**: 발행한 글을 고치는 동안 비로그인 독자 조회는 100% 마지막 발행본을 보여 준다.
- **SC-006**: 로그아웃 후 같은 브라우저에 남는 이전 회원의 작업 내용·백업은 0건이다.
- **SC-007**: 정리 조건을 만족한 빈 임시글은 다음 정리 작업 후 0건이고, 내용이 있는 임시글은 하나도 지워지지 않는다.
- **SC-008**: 사용자 시험에서 작성자의 90% 이상이 저장 상태 표시만 보고 "지금 내용이 서버에 안전한지"를 맞게 답한다.

## Assumptions

- 로그인·이메일 인증(C-AUTH-1)은 별도 spec이다. 이 기능은 이메일 인증을 마친 회원을 전제로 한다.
- 발행 자체(검증·렌더링·연타 방지)는 [005-post-publish](../005-post-publish/spec.md)에서, 사진 업로드·업로드 대기 사진 대기열은 [004-image-upload](../004-image-upload/spec.md)에서 다룬다. 이 spec은 본문에 남는 사진 주소만 다룬다.
- 휴지통·글 삭제(C-POST-5)는 별도 spec이다. 여기서는 빈 임시글의 완전 삭제만 다룬다.
- 저장 주기·보관 기한·요청 제한 수치는 모두 설정값이며 위 값은 초기값이다.
- 서버 버퍼의 영속 설정·복제·자동 전환 가능 여부는 배포 환경 확인 항목(52 §11.2 "배포 세부 구성")이며 이 spec의 동작 규칙을 바꾸지 않는다.
- 발행 이력 보관·과거 버전 되돌리기, 태그 자동 저장, 개인 확장(그룹·카테고리·시리즈 등)은 범위 밖이다.
