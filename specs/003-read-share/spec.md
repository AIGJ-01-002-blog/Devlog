# Feature Specification: 읽기·공유 (003-read-share)

**Feature Branch**: `003-read-share`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "방문자는 홈에서 최신 공개 글을 카드로 훑고 더 보기로 이어 본다. 작성자의 /@handle 페이지에서
그 사람의 공개 글을 모아 보고, 글 링크를 공유하면 제목·요약·대표 이미지가 미리보기로 뜬다. 비공개이거나 없는 글은 찾을 수

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 공유받은 글 링크를 열어 읽는다 (Priority: P1)

방문자가 메신저나 SNS에서 받은 글 링크를 열면 글을 읽을 수 있고, 링크를 붙여 넣은 곳에는 제목·요약·대표 이미지가 미리보기로
뜬다. 볼 수 없는 글은 없는 글과 똑같이 보인다.

**Why this priority**: "공유가 되는 블로그"의 핵심이다. 홈이 없어도 링크 공유만으로 글이 읽힌다.

**Independent Test**: 공개 글 주소를 비회원으로 열어 본문·작성자·날짜가 보이는지, 링크 미리보기 정보가 있는지, 비공개 글과
없는 번호의 글 응답이 똑같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개 글, **When** 비회원이 주소를 열면, **Then** 제목, 본문, `닉네임 @블로그주소`, 처음 공개된 날짜가 보인다.
2. **Given** 다시 발행한 글, **When** 열면, **Then** 날짜 옆에 "수정됨 · 날짜"가 보인다. 공개 범위만 바꾼 글에는 보이지 않는다.
3. **Given** 공개 글 링크, **When** 메신저·SNS에 붙여 넣으면, **Then** 제목, 요약 앞 160자, 대표 이미지(없으면 서비스 기본
   이미지)가 미리보기로 뜨고, 검색 엔진에 정규 주소가 알려진다.
4. **Given** 없는 글, 남의 비공개·임시 글, **When** 열면, **Then** 모두 같은 "찾을 수 없음" 화면·응답·미리보기 문구이고
   검색 엔진에 수집되지 않는다.
5. **Given** 볼 수 있는 글을 다른 사람의 블로그 주소로 잘못 적은 링크, **When** 열면, **Then** 올바른 주소로 이동한다. 볼 수
   없는 글이면 같은 상황에서 "찾을 수 없음"이다.
6. **Given** 작성자가 자기 임시글 주소를 엶, **When** 열면, **Then** 에디터로 이동한다.
7. **Given** 작성자가 수정 중인 자기 글을 엶, **When** 열면, **Then** 독자와 같은 마지막 발행본 위에 "수정 중인 내용이 있어요
   [이어서 수정] [변경 취소]" 안내가 보인다.
8. **Given** 작성자, **When** 자기 글을 열면, **Then** [수정]·[공개 범위] 버튼이 보이고, 다른 사람에게는 보이지 않는다.

### User Story 2 - 홈에서 최신 글을 훑는다 (Priority: P2)

방문자는 홈에서 전체 공개 글을 처음 공개된 순서의 최신순으로 카드 9개씩 보고, [더 보기]로 이어 본다.

**Why this priority**: 새 글을 발견하는 입구지만, 글이 링크로 읽히는 것이 먼저다.

**Independent Test**: 공개·비공개 글이 섞인 상태에서 홈에 공개 글만 최신순 9개가 보이는지, [더 보기]를 끝까지 눌러도 같은 글이
두 번 나오거나 빠지지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개·비공개·임시 글이 섞여 있음, **When** 홈을 열면, **Then** 발행된 전체 공개 글만 처음 공개된 시각 최신순(같으면
   번호 큰 순)으로 9개 보인다.
2. **Given** 9개보다 많은 공개 글, **When** [더 보기]를 누르면, **Then** 그다음 9개가 이어 붙고, 더 없으면 버튼이 사라진다.
   빈 결과를 받는 클릭은 없다.
3. **Given** 보는 도중 새 글이 올라오거나 글이 비공개로 바뀜, **When** [더 보기]를 누르면, **Then** 같은 글이 두 번 나오거나
   빠지지 않는다.
4. **Given** 카드, **When** 보면, **Then** 썸네일 자리, 제목 1줄, 요약 3줄, 날짜, 작성자가 보이고, 썸네일이 없어도 카드 높이가
   같다. 카드를 누르면 글로, 작성자를 누르면 그 블로그로 간다.
5. **Given** 글 상세를 보고 뒤로 감, **When** 홈으로 돌아오면, **Then** 이어 붙인 카드와 스크롤 위치가 복원된다.
6. **Given** 공개 글이 하나도 없음, **When** 홈을 열면, **Then** "아직 올라온 글이 없어요" 안내와 [글쓰기](비회원은 [로그인])가
   보인다.

### User Story 3 - 작성자의 블로그에서 글을 모아 본다 (Priority: P3)

방문자는 `/@handle`에서 그 사람의 프로필과 공개 글 목록을 본다.

**Why this priority**: "내 블로그"라는 정체성을 완성하지만, 홈과 같은 카드·목록 규칙을 재사용한다.

**Independent Test**: 작성자 A의 공개·비공개 글이 섞인 상태에서 `/@A`에 공개 글만 보이는지, A 본인이 봐도 비공개 글이 나오지
않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 작성자 A, **When** `/@A`를 열면, **Then** 상단에 닉네임·`@블로그주소`·공개 글 수가 있고, 아래에 A의 공개 글만 홈과
   같은 카드(작성자 영역 제외)·정렬·9개·[더 보기]로 보인다.
2. **Given** A 본인, **When** 자기 블로그를 열면, **Then** 비공개 글은 나오지 않는다(내 글 관리에서만 보인다).
3. **Given** 없는 블로그 주소, **When** 열면, **Then** "찾을 수 없음"이다. 대문자 주소는 소문자 주소로 이동한다.
4. **Given** 공개 글이 없는 블로그, **When** 남이 보면 "아직 공개한 글이 없어요", 본인이 보면 "첫 글을 써 보세요 [글쓰기]"가
   보인다.

### Edge Cases

- 목록 커서 값을 고치거나 다른 목록의 커서를 보내면? → 잘못된 요청으로 거부한다.
- 목록을 불러오지 못하면? → "글을 불러오지 못했어요 [다시 시도]"가 보인다.
- 글 주소의 번호 자리에 숫자가 아닌 값이 오면? → "찾을 수 없음"이다.
- 링크에 `?utm_source=…` 같은 쿼리가 붙으면? → 정규 주소에는 넣지 않는다.
- 요약이 비어 있는 글(코드만 있는 글)은? → 카드의 요약 자리는 빈 3줄 높이로 유지된다.
- 비공개 글의 응답은? → 공유 캐시에 저장되지 않는다. 모든 상세 응답은 보는 사람마다 다를 수 있어 공유 캐시에 넣지 않는다.
- 작성자 본인이 보는 비공개 글은? → 정상으로 보이되 검색 엔진에는 수집되지 않는다.
- 화면 폭이 좁으면? → 가로 스크롤이 생기지 않는다(카드 배치 개수는 각자 자유).

## Requirements *(mandatory)*

### Functional Requirements

**글 상세 (C-READ-2, docs/40)**

- **FR-001**: 글 주소는 `/@handle/posts/{번호}`이며, 볼 수 있는지 판정은 한 가지 규칙(docs/42)으로만 해야 한다.
- **FR-002**: 없는 글, 남의 비공개·임시 글은 상태·본문·미리보기 문구가 모두 같은 "찾을 수 없음"이어야 하고 검색 엔진 수집을
  막아야 한다.
- **FR-003**: 판정을 먼저 한 뒤, 볼 수 있는 글이 다른 블로그 주소로 요청되면 올바른 주소로 영구 이동시켜야 한다. 대문자가 섞인
  블로그 주소는 소문자 주소로 이동시켜야 한다.
- **FR-004**: 작성자가 자기 임시글 주소를 열면 에디터로, 수정 중인 글을 열면 마지막 발행본과 "수정 중" 안내를 보여야 한다.
- **FR-005**: 공개 글에는 처음 공개된 날짜를, 비공개 글(작성자만 봄)에는 최초 발행일을 보여야 하고, 다시 발행한 글에만
  "수정됨 · 날짜"를 보여야 한다.
- **FR-006**: 작성자 영역에 `닉네임 @블로그주소`를 보여야 한다.
- **FR-007**: [수정]·[공개 범위]는 작성자에게만 보여야 한다.
- **FR-008**: 공개 글에는 정규 주소와 링크 미리보기 정보(제목, 요약 앞 160자, 대표 이미지 또는 기본 이미지, 공개·수정 일자)를
  넣어야 하고, 그 밖의 경우는 공통 문구와 수집 거부를 넣어야 한다. 제목·요약은 안전하게 이스케이프해야 한다.
- **FR-009**: 상세 응답은 공유 캐시에 저장되지 않게 하고, 공개가 아닌 글은 어디에도 저장되지 않게 해야 한다.
- **FR-010**: 상세 화면은 인라인 스크립트 없이 동작해야 한다.

**홈 목록 (C-READ-1, docs/10)**

- **FR-011**: 홈은 발행·전체 공개·삭제 안 됨·숨김 안 됨·탈퇴 신청하지 않은 작성자의 글만 보여야 한다.
- **FR-012**: 정렬은 처음 공개된 시각 최신순, 같으면 번호 큰 순이어야 한다.
- **FR-013**: 한 번에 9개를 보여주고 [더 보기]로 이어 붙이며, 더 없으면 버튼을 없애야 한다. 마지막 판단을 위해 빈 결과 클릭이
  생기지 않아야 한다.
- **FR-014**: 목록 도중 글이 추가·삭제·비공개되어도 중복·누락이 없어야 한다(위치 기반이 아닌 커서 방식).
- **FR-015**: 커서는 내용을 알 수 없는 값이어야 하고, 고친 커서나 다른 목록의 커서는 거부해야 한다.
- **FR-016**: 카드는 썸네일 자리, 제목 1줄, 요약 3줄(짧아도 3줄 높이), 날짜(24시간 이내 "N시간 전", 이후 `2026.10.02`),
  작성자(프로필 사진 또는 기본 아이콘 + 닉네임)를 보여야 하며, 썸네일이 없어도 카드 높이가 같아야 한다.
- **FR-017**: 상세에서 뒤로 오면 카드와 스크롤 위치를 30분 동안 복원해야 한다.
- **FR-018**: 목록은 본문 원문을 읽지 않고 한 번의 조회로 만들어야 한다.
- **FR-019**: 페이지에 가로 스크롤이 생기지 않아야 한다.

**개인 블로그 (C-BLOG-1, docs/10 §5)**

- **FR-020**: `/@handle`은 상단에 프로필(사진, 닉네임, `@블로그주소`, 소개, 보는 사람 기준 공개 글 수)을, 아래에 그 사람의 공개
  글만 홈과 같은 카드(작성자 영역 제외)·정렬·9개·[더 보기]로 보여야 한다.
- **FR-021**: 작성자 본인이 봐도 비공개 글은 블로그에 나오지 않아야 한다.
- **FR-022**: 없는 블로그 주소는 "찾을 수 없음"이어야 한다.
- **FR-023**: 빈 상태는 남과 본인에게 다른 안내를 보여야 한다.

### Key Entities *(include if feature involves data)*

- **글(Post)**: 002에서 정의. 목록·상세에 제목, 요약, 썸네일, 처음 공개된 일자, 다시 발행 일자, 공개 범위, 상태를 쓴다.
- **회원(Member)**: 001에서 정의. 블로그 상단과 작성자 영역에 닉네임, 블로그 주소, 소개, 프로필 사진을 쓴다.
- **목록 커서(Cursor)**: 마지막으로 본 카드의 정렬 값과 목록 종류를 담은, 내용을 알 수 없는 값.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 공개 글 링크를 붙여 넣으면 주요 메신저·SNS에서 제목과 요약이 미리보기로 뜬다.
- **SC-002**: 볼 수 없는 글과 없는 글의 응답을 외부에서 구별할 수 있는 경우가 0건이다.
- **SC-003**: 1,000개 글을 [더 보기]로 끝까지 넘기는 동안 글을 추가·비공개해도 중복·누락이 0건이다.
- **SC-004**: 홈·블로그 첫 화면과 [더 보기]가 일반적인 회선에서 1초 안에 보인다.
- **SC-005**: 비공개 글이 홈·다른 사람이 보는 블로그·공개 글 수에 섞이는 경우가 0건이다.
- **SC-006**: docs/10 §9, docs/40 §7의 공통 완료 기준 중 이번 범위 항목이 모두 자동 테스트로 확인된다.

## Assumptions

- **A-1**: 댓글·좋아요·조회수·태그·사진 업로드는 MVP 다음 단계(Tier B)다. 그래서 카드의 댓글 수·좋아요 수, 상세의 댓글·좋아요·
  태그·조회 기록, [삭제]·[신고]·[팔로우] 버튼은 해당 기능이 들어올 때 추가한다. 썸네일은 사진 업로드 전까지 항상 빈 자리다.
- **A-2**: 관리자 숨김·회원 탈퇴는 아직 없지만, 목록 대상 조건(숨김·탈퇴 신청 작성자 제외)은 처음부터 공통 조건대로 둔다.
- **A-3**: 친구 공개는 범위 밖이라 블로그 목록 정렬은 항상 처음 공개된 시각 기준이다.
- **A-4**: 카드 배치 개수·비율·색, 썸네일 빈 자리 색은 각자 자유다(docs/10 O5).
- **A-5**: 검색·트렌딩·태그별 목록·sitemap·RSS는 이번 범위가 아니다.
