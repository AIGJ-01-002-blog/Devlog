# Feature Specification: 이메일 가입·비밀번호와 Google 로그인 (004-email-google-login)

**Feature Branch**: `004-email-google-login`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "GitHub 계정이 없는 사람도 이메일과 비밀번호로 가입하거나 Google 계정으로 로그인해 자기 블로그를 갖는다.
이메일 가입자는 메일 인증을 마쳐야 글을 쓸 수 있고, 비밀번호를 잊으면 메일로 재설정하며, 로그인한 상태에서 비밀번호를 바꿀
수 있다. 001의 GitHub 로그인과 같은 구조로 붙인다. 상세 규칙은 docs/07-auth.md, docs/08-blog-address.md,
docs/11-profile.md §6-2, docs/42-permission-matrix.md를 따른다."

**관련 기능 ID**: C-AUTH-1(이메일·Google 범위, 001에서 남은 부분), C-AUTH-2(비밀번호 변경)

**선행 기능**: `001-auth-ownership` (GitHub 가입·로그인, 로그인 유지·로그아웃, 약관 동의, 블로그 주소·닉네임 규칙)

**우선순위 단계**: MVP 직후 (Tier A 나머지)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 이메일로 가입하고 메일 인증을 마친다 (Priority: P1)

GitHub 계정이 없는 방문자가 이메일·비밀번호·닉네임·블로그 주소를 넣고 필수 약관에 동의해 가입한다. 가입 즉시 로그인은 되지만,
메일로 받은 인증 링크를 누르기 전에는 글쓰기 같은 쓰기 행동을 할 수 없다.

**Why this priority**: 개발자가 아닌 팀원·독자도 블로그를 가질 수 있게 하는 가장 큰 확장이다. 인증 전 쓰기 차단은 가짜 계정으로
글·반응을 부풀리는 것을 막는 전제다.

**Independent Test**: 새 이메일로 가입해 블로그 주소가 이메일 앞부분으로 미리 채워지는지, 인증 전에 [새 글]이 막히고 "인증 메일
다시 보내기" 안내가 보이는지, 인증 링크를 누른 뒤에는 글을 쓸 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 가입 화면, **When** 이메일 `Kim.Min-Seo+blog@naver.com`을 입력하면, **Then** 블로그 주소 칸에 `kim_min_seo`가
   미리 채워지고 "이메일 앞부분으로 미리 채웠어요. 이메일을 드러내고 싶지 않으면 바꿔 주세요."와 "블로그 주소는 가입 후 바꿀 수
   없어요" 안내가 보인다.
2. **Given** 사용자가 블로그 주소 칸을 직접 고침, **When** 이메일을 다시 바꾸면, **Then** 주소 칸은 더 이상 자동으로 바뀌지 않는다.
3. **Given** 규칙에 맞는 이메일·비밀번호·닉네임·주소와 필수 약관 2개 동의, **When** 가입하면, **Then** 계정이 만들어지고 로그인
   상태가 되며, 동의한 약관 종류·버전·일자가 기록되고, 24시간 유효한 인증 메일이 발송된다.
4. **Given** 인증 전 회원, **When** 새 글 만들기·저장·발행·변경 취소·공개 범위 변경을 시도하면, **Then** 계정 상태 때문에 할 수
   없다는 이유와 [인증 메일 다시 보내기] 안내를 받는다.
5. **Given** 인증 전 회원, **When** 자기 글 삭제·복구, 닉네임·소개 수정, 비밀번호 변경, 기본 공개 범위 변경, 내 글 관리를 하면,
   **Then** 허용된다.
6. **Given** 인증 메일의 링크, **When** 24시간 안에 처음 누르면, **Then** "인증이 완료됐어요"가 보이고 이후 쓰기 행동이 허용된다.
7. **Given** 이미 쓴 링크나 24시간이 지난 링크, **When** 누르면, **Then** "링크가 만료됐어요. [인증 메일 다시 보내기]"가 보인다.
8. **Given** 인증 메일을 다시 보냄, **When** 이전 메일의 링크를 누르면, **Then** 무효다. 재발송은 1분에 1번, 하루 10번까지다.
9. **Given** 이미 이메일 가입된 이메일, **When** 같은 이메일로 다시 가입하면, **Then** "이미 가입된 이메일이에요. [로그인]
   [비밀번호 찾기]"가 보이고 계정이 새로 생기지 않는다.

### User Story 2 - 이메일과 비밀번호로 로그인한다 (Priority: P2)

이메일 가입자는 이메일과 비밀번호로 로그인한다. 틀렸을 때는 무엇이 틀렸는지 알려주지 않고, 같은 계정으로 계속 틀리면 잠시 잠긴다.

**Why this priority**: P1으로 만든 계정을 다시 쓰려면 반드시 필요하다. 잠금은 비밀번호 추측 공격을 막는다.

**Independent Test**: 올바른 비밀번호로 로그인되고, 틀린 비밀번호를 5번 연속 넣으면 맞는 비밀번호로도 15분 동안 로그인되지 않는지,
없는 이메일과 틀린 비밀번호의 안내가 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이메일 가입 계정, **When** 대소문자·앞뒤 공백이 다른 이메일과 맞는 비밀번호로 로그인하면, **Then** 로그인된다.
2. **Given** 틀린 비밀번호 또는 가입되지 않은 이메일, **When** 로그인하면, **Then** 두 경우 모두 "이메일 또는 비밀번호가 올바르지
   않아요"로 같게 안내된다.
3. **Given** 같은 계정으로 5번 연속 실패, **When** 15분 안에 다시 로그인하면, **Then** 맞는 비밀번호여도 "잠시 후 다시 시도해
   주세요(약 15분)"로 거부된다.
4. **Given** 15분이 지남, **When** 맞는 비밀번호로 로그인하면, **Then** 로그인된다.
5. **Given** 정지된 이메일 가입 계정, **When** 맞는 비밀번호로 로그인하면, **Then** 로그인되지 않고 정지 기한과 사유가 안내된다
   (001과 같은 규칙).

### User Story 3 - 비밀번호를 잊으면 메일로 재설정한다 (Priority: P3)

비밀번호를 잊은 사람은 이메일을 넣어 재설정 링크를 받는다. 화면은 가입 여부를 드러내지 않고, 메일은 그 이메일 주인에게만 간다.
재설정하면 모든 기기에서 로그아웃된다.

**Why this priority**: 비밀번호 방식에는 꼭 필요하지만, 가입·로그인이 먼저 있어야 의미가 있다.

**Independent Test**: 가입된 이메일과 가입되지 않은 이메일로 각각 요청해 화면 안내가 같은지, 재설정 링크로 새 비밀번호를 정한 뒤
다른 기기의 로그인이 끊기는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 비밀번호 찾기 화면, **When** 어떤 이메일을 넣든, **Then** 화면에는 항상 "가입된 이메일이면 안내 메일을 보냈어요"가 보인다.
2. **Given** 이메일 가입 계정이 있는 이메일, **When** 재설정을 요청하면, **Then** 30분 유효하고 한 번만 쓸 수 있는 재설정 링크가
   메일로 간다.
3. **Given** 같은 이메일로 Google·GitHub 계정도 있음, **When** 재설정을 요청하면, **Then** 메일에 "이 이메일로 Google로 가입한
   계정도 있어요. 그 계정은 Google로 로그인하세요" 같은 안내가 함께 들어 있다.
4. **Given** 이메일 가입 계정 없이 소셜 계정만 있는 이메일, **When** 재설정을 요청하면, **Then** "이 이메일은 Google로 가입되어
   비밀번호가 없어요" 같은 안내 메일만 간다.
5. **Given** 재설정 링크, **When** 규칙에 맞는 새 비밀번호를 저장하면, **Then** 그 계정의 모든 기기에서 로그아웃된다.
6. **Given** 이미 쓴 링크나 30분이 지난 링크, **When** 누르면, **Then** 쓸 수 없다.
7. **Given** 같은 이메일로 1분 안에 두 번 요청, **When** 두 번째 요청을 보내면, **Then** 메일이 다시 가지 않는다(같은 이메일 1분에
   1번·하루 10번, 같은 IP 1시간에 20번).

### User Story 4 - Google 계정으로 가입·로그인한다 (Priority: P4)

Google 계정이 있는 사람은 [Google로 계속하기]로 가입·로그인한다. GitHub와 같은 가입 마무리 화면을 거치고 블로그 주소는 `go-`로
시작한다.

**Why this priority**: 001의 GitHub 흐름을 그대로 재사용하므로 추가 비용이 작지만, 이메일 가입보다 필요성이 낮다.

**Independent Test**: 새 Google 계정으로 가입해 `go-` 주소가 생기는지, 같은 이메일로 이메일 가입한 계정과 별도 계정이 되는지,
Google에서 이메일을 바꾼 뒤에도 같은 계정으로 로그인되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 가입한 적 없는 Google 계정, **When** Google 인증을 마치면, **Then** 계정은 아직 만들어지지 않고 가입 마무리 화면이
   열리며, 블로그 주소는 고칠 수 없는 `go-`와 이메일 앞부분으로 만든 본문(예: `kim755030@gmail.com` → `go-kim755030`)이 미리
   채워져 있다.
2. **Given** 같은 이메일로 이미 이메일 가입한 계정이 있음, **When** 그 이메일의 Google 계정으로 처음 로그인하면, **Then** 별도의
   새 계정을 만드는 가입 마무리 화면으로 간다(자동으로 합치지 않는다).
3. **Given** 이미 가입한 Google 계정, **When** Google에서 이메일을 바꾼 뒤 다시 로그인하면, **Then** 같은 계정으로 로그인된다.
4. **Given** Google 계정의 이메일이 인증되지 않음, **When** 가입하려 하면, **Then** 그 이메일은 쓰지 않는다.
5. **Given** 인증된 대표 이메일이 없는 GitHub 계정, **When** GitHub로 처음 로그인하면, **Then** 가입 마무리 화면에서 이메일을
   입력받아 이메일 가입과 같은 방식으로 인증한다(001에서 막아 두었던 경우).

---

### User Story 5 - 로그인한 상태에서 비밀번호를 바꾼다 (Priority: P5)

이메일 가입자는 설정 화면에서 현재 비밀번호를 확인한 뒤 새 비밀번호로 바꾼다. 바꾸면 다른 기기는 로그아웃되고 알림 메일이 간다.

**Why this priority**: 비밀번호를 바꿀 정상 경로가 없던 문제를 메우지만, 재설정 메일로도 대신할 수 있어 마지막이다.

**Independent Test**: 두 기기에서 로그인한 뒤 한 기기에서 비밀번호를 바꿔, 바꾼 기기는 로그인이 유지되고 다른 기기는 끊기며
알림 메일이 오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이메일 가입자, **When** 현재 비밀번호와 규칙에 맞는 새 비밀번호(확인 칸 포함)로 바꾸면, **Then** 지금 기기는 로그인이
   유지되고 다른 기기는 모두 로그아웃되며, "비밀번호가 변경됐어요. 본인이 아니라면 [비밀번호 재설정]" 알림 메일이 간다.
2. **Given** 현재 비밀번호를 틀림, **When** 바꾸려 하면, **Then** 거부되고, 5번 연속 틀리면 15분 동안 시도할 수 없다.
3. **Given** 새 비밀번호가 현재 비밀번호와 같음, **When** 바꾸려 하면, **Then** 거부되고 이유가 안내된다.
4. **Given** Google·GitHub 계정, **When** 설정 화면을 보면, **Then** [비밀번호 변경] 버튼이 없고, 요청을 직접 보내도 거부된다.

---

### Edge Cases

- 비밀번호가 17자 이상이면? → 거부되며, 안내 문구에 "최대 16자"가 분명히 적혀 있다(긴 문장형·관리자 생성 비밀번호는 쓸 수 없다).
- 비밀번호에 공백·한글이 있거나, 이메일 `@` 앞부분이 들어 있거나, 흔한 비밀번호(`Password1!`, `Qwer1234!` 등)이면? → 거부된다.
- 이메일이 254자를 넘거나 형식에 맞지 않으면? → 가입할 수 없다.
- 이메일 앞부분에 영문이 없거나 3자 미만이면(`ab@x.com`, `김민서@한국.kr`)? → `user_` + 숫자 6자리 주소를 제안한다.
- 이메일 가입인데 앞부분이 `go.kim`처럼 `go_`·`gi_`로 시작하게 되면? → 그 `_`를 지운 `gokim`을 제안하고, 직접 `go_kim`을 입력하면
  "소셜 가입 주소와 헷갈려서 `go_`·`gi_`로 시작할 수 없어요"로 거부한다.
- 이메일 가입 주소에 `-`를 입력하면? → 입력할 수 없다(`-`는 소셜 접두어 전용).
- `kim755030@naver.com`과 `kim755030@daum.net`이 차례로 이메일 가입하면? → 두 번째는 `kim755030_2`가 제안된다.
- 인증 메일 재발송을 1분 안에 또 누르거나 하루 10번을 넘기면? → 보내지 않고 다시 시도할 수 있는 때를 안내한다.
- 비밀번호 재설정 링크를 받은 뒤 다시 재설정을 요청하면? → 각 링크는 30분·한 번만 유효하다.
- 로그인 상태 저장소가 일시적으로 멈추면? → 새 로그인과 인증·재설정 링크 확인은 "잠시 후 다시 시도해 주세요"로 거부하고, 실패
  횟수·재발송 제한은 통과시킨다. 글 읽기는 계속된다.
- 로그인 화면에서 실패를 반복해 가입 여부를 알아내려 하면? → 실패 안내·비밀번호 찾기 안내가 모두 같아 알 수 없다.
- 같은 이메일로 이메일 가입·Google·GitHub 세 계정을 만들면? → 세 계정 모두 따로 존재하고 주소는 `kim755030` / `go-kim755030` /
  `gi-kim755030`처럼 겹치지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**계정과 로그인 수단 (docs/07 §2, L-1)**

- **FR-001**: 시스템은 이메일 가입·로그인과 Google 로그인을 001의 GitHub 로그인에 더해 제공해야 한다. 네이버 로그인은 제공하지 않는다.
- **FR-002**: 계정 하나는 로그인 수단 하나만 가져야 한다. 같은 이메일이라도 로그인 수단이 다르면 별도 계정이며, 자동으로 합치거나
  계정을 연결하는 기능은 두지 않아야 한다.
- **FR-003**: 같은 로그인 수단(같은 이메일 가입, 같은 Google 계정)으로는 계정이 두 개 생기지 않아야 한다. 이메일 가입은 소문자로
  바꾼 이메일, Google은 바뀌지 않는 Google 고유 사용자 번호로 식별해야 한다.

**이메일 가입·인증 (docs/07 §3, L-2·L-10)**

- **FR-004**: 이메일 가입 화면은 이메일·블로그 주소·비밀번호·비밀번호 확인·닉네임과 필수 약관 2개(이용약관·개인정보 처리방침)
  동의를 받아야 하며, 동의한 종류·버전·일자를 계정 생성과 함께 기록해야 한다.
- **FR-005**: 이메일은 일반적인 형식, 최대 254자여야 하며 소문자로 바꾸고 앞뒤 공백을 지워 저장해야 한다. 이미 이메일 가입된
  이메일이면 "이미 가입된 이메일이에요. [로그인] [비밀번호 찾기]"로 안내해야 한다.
- **FR-006**: 가입하면 인증 메일을 보내야 한다. 인증 링크는 추측할 수 없는 값이며 24시간 유효하고 한 번만 쓸 수 있어야 한다.
  만료·사용된 링크는 "링크가 만료됐어요. [인증 메일 다시 보내기]"로 안내해야 한다.
- **FR-007**: 인증 메일 재발송은 1분에 1번, 하루 10번까지 허용하고, 새 메일을 보내면 이전 링크는 무효가 되어야 한다.
- **FR-008**: 인증 전 회원도 로그인은 되어야 하지만 글쓰기(새 글·자동/수동 저장·발행·변경 취소·공개 범위 변경)·댓글·사진
  업로드·좋아요·신고는 계정 상태를 이유로 거부하고 [인증 메일 다시 보내기]를 안내해야 한다. 이 검사는 서버에서 매 요청마다 하고,
  docs/42 §3 판정 순서(로그인 → 계정 상태 → 대상을 볼 수 있나 → 행동 권한 → 업무 규칙)를 따라야 한다.
- **FR-009**: 인증 전 회원에게도 자기 글 삭제·복구·영구 삭제, 닉네임·소개 수정, 비밀번호 변경, 기본 공개 범위 변경, 내 글 관리,
  회원 탈퇴는 허용해야 한다(docs/42 §5-2·§9·§10).
- **FR-010**: 소셜 가입 계정은 가입 시점에 인증된 것으로 기록해야 한다.

**블로그 주소 생성 (docs/08 §3·§4, 이메일·Google)**

- **FR-011**: 이메일 가입과 Google 가입의 블로그 주소는 이메일 `@` 앞부분을 재료로 다음 순서로 미리 채워야 한다: `+` 뒤 버림 →
  소문자 → `.`·`-`를 `_`로 → 영문 소문자·숫자·`_` 외 문자 삭제 → 연속 `_` 하나로, 처음·끝 `_` 삭제 → 16자로 자름(끝 `_` 삭제) →
  (이메일 가입) `go_`·`gi_`로 시작하면 그 `_` 삭제 → 3자 미만이면 `user_` + 숫자 6자리 → 가입 수단 접두어(Google `go-`) →
  예약어이거나 이미 있으면 비어 있는 첫 번호로 `_2`, `_3` ….
- **FR-012**: 이메일에서 만든 주소에는 대문자와 `-`가 없어야 한다. 이메일 가입 주소 칸에는 `-`를 입력할 수 없고, 대문자 입력은
  소문자로 바꿔 보여주며, 한글 자판 상태여도 영문으로 입력되어야 한다.
- **FR-013**: 이메일 가입 화면에서 이메일을 입력하는 동안 주소 칸을 자동으로 채우되, 사용자가 주소 칸을 직접 고친 뒤로는 자동으로
  바꾸지 않아야 한다. Google 가입 마무리 화면은 `go-`를 고칠 수 없는 글자로 보여주고 본문만 고치게 해야 한다.
- **FR-014**: 접두어 없는 주소(이메일 가입)는 `go_`·`gi_`로 시작할 수 없어야 하며, 본문 3~20자·예약어·금칙어·중복 검사는 001과
  같은 규칙을 써야 한다. 입력이 0.5초 멈추면 사용 가능 여부와 대안을 보여주되(같은 IP 1분에 30번), 가입 버튼을 누를 때 서버가
  다시 검사해야 한다.

**비밀번호 규칙 (docs/07 §4, L-3)**

- **FR-015**: 비밀번호는 8~16자이고 영문 대소문자 중 1개 이상, 숫자 1개 이상, 특수문자 1개 이상을 포함해야 한다. 쓸 수 있는 문자는
  영문·숫자·docs/07 §4의 특수문자뿐이며 공백·한글은 쓸 수 없다.
- **FR-016**: 이메일 `@` 앞부분이 들어간 비밀번호와 흔한 비밀번호 목록에 있는 비밀번호는 거부해야 한다.
- **FR-017**: 비밀번호 원문은 저장하거나 기록에 남기지 않고, 되돌릴 수 없는 방식으로만 저장해야 한다.
- **FR-018**: 입력하는 동안 규칙별 충족 여부를 글자와 ✓로 보여줘야 하며(색만으로 표시하지 않음), 안내에 "최대 16자"를 분명히
  적어야 한다.

**로그인·실패 제한 (docs/07 §6, L-7)**

- **FR-019**: 로그인 실패 안내는 "이메일 또는 비밀번호가 올바르지 않아요" 하나로, 이메일과 비밀번호 중 무엇이 틀렸는지·가입되어
  있는지 알 수 없어야 한다.
- **FR-020**: 같은 계정으로 5회 연속 실패하면 15분 동안 로그인을 막고 "잠시 후 다시 시도해 주세요(약 15분)"로 안내해야 한다.
  같은 IP 1분 20회 제한(001)은 이메일 로그인에도 적용되어야 한다.
- **FR-021**: 정지·약관 재동의·로그인 유지 14일·로그인 후 이동·로그인 상태 저장소 장애 처리는 001과 같은 규칙을 이메일·Google
  로그인에도 적용해야 한다. 저장소 장애 때는 인증·재설정 링크 확인도 거부하고, 실패 횟수·재발송 제한은 통과시켜야 한다.

**비밀번호 재설정 (docs/07 §4-1, L-4)**

- **FR-022**: 비밀번호 찾기 화면은 입력한 이메일과 상관없이 항상 "가입된 이메일이면 안내 메일을 보냈어요"를 보여줘야 한다.
- **FR-023**: 이메일 가입 계정이 있으면 30분 유효하고 한 번만 쓸 수 있는 재설정 링크를 보내야 한다. 같은 이메일로 Google·GitHub
  계정이 있으면 그 수단으로 로그인하라는 안내를 함께 넣고, 소셜 계정만 있으면 비밀번호가 없다는 안내만 보내야 한다. 메일은 그
  이메일 주소로만 보내야 한다.
- **FR-024**: 재설정 요청은 같은 이메일 1분에 1번·하루 10번, 같은 IP 1시간에 20번으로 제한해야 한다.
- **FR-025**: 새 비밀번호는 FR-015·FR-016 규칙을 따라야 하며, 저장하면 그 계정의 모든 로그인 상태를 끊어 모든 기기에서 로그아웃
  시켜야 한다.

**Google·GitHub 소셜 보완 (docs/07 §5)**

- **FR-026**: Google 첫 로그인도 001과 같은 가입 마무리 화면(닉네임·블로그 주소·약관, 완료 전 계정 미생성, 소셜 인증 정보 10분
  보관)을 반드시 거쳐야 한다.
- **FR-027**: Google에서는 인증된 이메일만 써야 한다.
- **FR-028**: 인증된 대표 이메일이 없는 GitHub 계정은 가입 마무리 화면에서 이메일을 입력받아 FR-006·FR-007과 같은 방식으로
  인증해야 한다(001 가정 A-3 해소).

**비밀번호 변경 (docs/11 §6-2, R-10)**

- **FR-029**: 이메일 가입자만 로그인한 상태에서 현재 비밀번호·새 비밀번호·새 비밀번호 확인으로 비밀번호를 바꿀 수 있어야 한다.
  소셜 계정에는 버튼을 보이지 않고, 요청도 거부해야 한다.
- **FR-030**: 새 비밀번호는 FR-015·FR-016 규칙을 따라야 하고, 현재 비밀번호와 같으면 거부해야 한다.
- **FR-031**: 현재 비밀번호가 틀리면 거부하고, 로그인과 같이 5회 연속 틀리면 15분 동안 막아야 한다.
- **FR-032**: 변경 후에는 다른 기기의 로그인 상태는 모두 끊고 지금 기기는 유지하되(로그인 상태 식별값은 새로 발급), "비밀번호가
  변경됐어요. 본인이 아니라면 [비밀번호 재설정]" 알림 메일을 보내야 한다.

**메일 (docs/07 L-9)**

- **FR-033**: 인증·재설정·비밀번호 변경 알림 메일을 보낼 수 있어야 하며, 개발 환경에서는 실제로 발송하지 않고 내용을 확인할 수
  있어야 한다.

### Key Entities *(include if feature involves data)*

- **회원(Member)**: 001에서 정의. 이번에는 이메일 가입·Google 가입 회원이 더해진다.
- **로그인 수단(AuthIdentity)**: 수단 종류(이메일·Google·GitHub), 식별값(이메일 가입은 소문자 이메일, 소셜은 고유 번호), 이메일,
  이메일 인증 일자(소셜은 가입 시각), 비밀번호(이메일 가입만, 되돌릴 수 없는 형태), 마지막 로그인 일자. 회원 하나에 하나, 같은
  수단·식별값으로 하나.
- **인증 링크·재설정 링크**: 회원을 가리키는 일회용 값과 만료 시각(인증 24시간, 재설정 30분). 영구 기록이 아니라 만료되면 사라진다.
- **실패·재발송 횟수**: 계정별 로그인 실패 횟수와 잠금 시각, 인증 메일·재설정 요청 횟수. 만료되는 임시 기록이다.
- **약관 동의(MemberAgreement)**: 001에서 정의. 이메일 가입도 계정 생성과 함께 기록한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 온 사람이 이메일 가입부터 인증 완료까지 3분 안에 마칠 수 있다(메일 도착 시간 제외).
- **SC-002**: 같은 이메일로 이메일 가입을 동시에 10건 보내도 이메일 가입 계정은 정확히 1개다. 같은 이메일로 이메일·Google·GitHub
  계정을 만들면 3개 모두 별도로 존재한다.
- **SC-003**: 인증 전 회원의 글쓰기·댓글·사진 업로드·좋아요·신고 요청은 100% 거부된다.
- **SC-004**: 8자 미만, 16자 초과, 영문·숫자·특수문자 중 하나라도 없는 비밀번호로는 가입·재설정·변경이 0건 성공한다.
- **SC-005**: 같은 계정으로 5회 연속 실패하면 이후 15분 동안 맞는 비밀번호로도 로그인 성공이 0건이다.
- **SC-006**: 로그인 실패 화면과 비밀번호 찾기 화면의 응답을 비교해 가입된 이메일과 가입되지 않은 이메일을 구별할 수 없다.
- **SC-007**: 인증·재설정 링크는 두 번째 사용과 만료 후 사용이 100% 거부된다.
- **SC-008**: 비밀번호를 재설정하면 그 계정의 모든 기기, 비밀번호를 변경하면 지금 기기를 뺀 모든 기기의 로그인이 즉시 끊긴다.
- **SC-009**: docs/07 §9 공통 완료 기준 1~11, docs/08 §8의 1·2·5·8, docs/11 §8의 7 중 이번 범위 항목이 모두 자동 테스트로 확인된다.

## Assumptions

- **A-1**: 001의 GitHub 흐름(가입 마무리 화면, 약관 동의·재동의, 로그인 유지 14일, 로그아웃, 정지 계정 처리, IP 제한, 로그인 후
  이동)은 그대로 재사용하며 이 spec은 이메일·Google·비밀번호에 필요한 부분만 더한다.
- **A-2**: 소셜 가입 때 Google·GitHub 프로필 사진을 복사하는 기능은 005(프로필·설정)에서 다룬다.
- **A-3 (미결)**: 메일 발송 방식(docs/07 L-9)은 개발 환경만 정해졌고, 배포 환경 방식은 환경 확인 후 결정한다.
- **A-4 (미결)**: docs/07 §10 F-1(소셜 첫 로그인 때 같은 이메일의 다른 수단 계정이 있으면 안내)은 미결 제안이라 범위 밖이다.
- **A-5**: 탈퇴 유예 중인 계정의 같은 이메일 가입 안내("탈퇴 신청한 계정이 있어요")와 탈퇴 유예 회원의 비밀번호 재설정은 020(회원
  탈퇴)에서 다룬다.
- **A-6**: 네이버 로그인, 설정 화면의 "모든 기기에서 로그아웃" 버튼(개인 확장), 이메일 변경(불가, docs/11 R-9)은 범위 밖이다.
- **A-7**: 댓글·사진 업로드·좋아요·신고 기능은 아직 없지만, 인증 전 차단 규칙은 각 기능이 들어올 때 같은 계정 상태 검사를 쓴다.
- **A-8**: 흔한 비밀번호 목록과 금칙어·예약어 목록은 설정으로 관리하는 목록이며 내용은 팀이 준비한다.
