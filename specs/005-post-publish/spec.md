## User Scenarios & Testing *(mandatory)*

### User Story 1 - 처음 발행하기 (Priority: P1)

작성자가 쓰던 임시글을 [발행]하면 글이 고유 주소를 얻고, 공개 글이면 로그인하지 않은 독자도 읽을 수 있다.

**Why this priority**: 블로그의 핵심 가치. 이것 하나만 있어도 "쓰고 → 공개하고 → 읽힌다"가 완성된다.

**Independent Test**: 테스트 회원이 임시글을 만들어 공개로 발행한 뒤, 비로그인 상태로 글 주소를 열어 내용이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 제목·본문이 채워진 본인의 임시글, **When** 공개로 발행하면, **Then** 글은 발행 상태가 되고 `/@블로그주소/posts/{글번호}`에서 누구나 읽을 수 있다.
2. **Given** 제목 또는 본문이 비어 있는 임시글, **When** 발행하면, **Then** 발행되지 않고 비어 있는 항목마다 이유가 입력칸 옆에 표시되며 글은 임시 상태 그대로다.
3. **Given** 업로드가 끝나지 않은 사진이 본문에 있는 임시글, **When** 발행하면, **Then** 발행되지 않고 "사진 업로드가 끝나지 않았다"는 이유가 표시된다.
4. **Given** 태그를 대소문자·공백만 다르게 중복 입력, **When** 발행하면, **Then** 태그는 소문자·공백 정리된 형태로 한 번씩만 붙는다.
5. **Given** 사진이 있는 본문, **When** 발행하면, **Then** 요약(코드·사진·표를 뺀 글자 앞 200자)과 썸네일(작성자가 올린 첫 사진의 640px 썸네일)이 자동으로 정해진다.

---

### User Story 2 - 스크립트가 실행되지 않는 안전한 본문 (Priority: P1)

작성자는 Markdown으로 제목·목록·표·코드 등을 자유롭게 쓰고, 발행 전 미리보기로 독자가 볼 결과를 그대로 확인한다. 누가 본문이나 제목에 악성 코드를 넣어도 독자 화면에서는 실행되지 않는다.

**Why this priority**: C-POST-1의 공통 완료 기준 "본문의 스크립트는 실행되지 않는다". 발행된 글을 남이 읽는 순간부터 필요하므로 발행과 같은 순위다.

**Independent Test**: 12 문서의 XSS 공격 문자열 32개와 정상 문법 13개를 본문·제목에 넣어 미리보기·발행한 뒤, 브라우저에서 알림창이 뜨지 않고 정상 문법은 의도대로 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 본문·제목에 스크립트 태그·이벤트 속성·위험한 링크 주소(대소문자 섞기·엔티티·퍼센트 인코딩·참조형으로 숨긴 것 포함)를 넣은 글, **When** 발행 후 독자가 열면, **Then** 실행 가능한 스크립트가 결과에 없고 알림창이 뜨지 않는다.
2. **Given** 본문에 직접 쓴 HTML(예: `<b>굵게</b>`), **When** 독자가 보면, **Then** 서식이 아니라 글자 그대로 보인다.
3. **Given** 제목·강조·취소선·목록·인용·구분선·체크리스트·표(정렬)·코드 블록·링크·주소 자동 링크, **When** 렌더링되면, **Then** 의도대로 보이고 본문 제목은 한 단계씩 낮아져 글 제목보다 큰 제목이 본문에 생기지 않는다. 체크리스트는 읽기 전용이다.
4. **Given** 외부 사이트 링크, **When** 독자가 누르면, **Then** 새 탭으로 열리고 원래 탭을 조작할 수 없으며 검색 순위 전달이 없는 링크로 표시된다. 우리 사이트 링크는 같은 탭에서 열린다.
5. **Given** 외부 이미지 주소 또는 남이 올린 사진 주소, **When** 렌더링되면, **Then** 사진으로 불러오지 않고 "[이미지] 대체글" 링크로 바뀐다 (대체글이 없으면 주소 표시). 작성자가 올린 우리 사진만 사진으로 보인다.
6. **Given** 같은 본문, **When** 미리보기와 발행 결과를 비교하면, **Then** 두 결과가 같다.
7. **Given** 목록·인용이 20단계를 넘게 중첩되거나 렌더링이 1초를 넘는 본문, **When** 발행하면, **Then** "글 구조가 너무 복잡해요 (목록·인용은 20단계까지)" 이유로 발행되지 않는다.
8. **Given** 보이지 않는 글자·글자 방향 뒤집기 문자·제어 문자가 섞인 제목, **When** 저장·발행하면, **Then** 그 문자들은 제거되고 같은 글자는 한 가지 형태로 정규화되며, 화면에는 글자로만 표시된다.

### User Story 3 - 고쳐서 다시 발행하기 (Priority: P2)

작성자가 이미 발행한 글을 고치는 동안 독자는 마지막 발행본을 보고, 다시 발행하면 새 내용이 반영된다. 주소·최초 발행일·반응은 그대로다.

**Why this priority**: 발행 후 오타·내용 수정은 거의 모든 글에서 생긴다. 고치는 중간 상태가 독자에게 노출되면 안 된다.

**Independent Test**: 발행된 글을 수정 저장만 한 상태에서 비로그인 조회 → 이전 내용, 다시 발행 후 조회 → 새 내용 + "수정됨" 표시.

**Acceptance Scenarios**:

1. **Given** 발행된 글을 수정해 저장만 한 상태, **When** 독자가 글을 열면, **Then** 마지막으로 발행된 내용이 보인다.
2. **Given** 수정 중인 글, **When** 다시 발행하면, **Then** 새 내용이 보이고 "수정됨 · 날짜"가 표시된다.
3. **Given** 조회수·좋아요·댓글이 있는 글, **When** 다시 발행하면, **Then** 주소·최초 발행일·최초 공개일·목록 위치·조회수·좋아요·댓글은 바뀌지 않는다.
4. **Given** 수정 중인 글, **When** 작성자가 변경을 취소하면, **Then** 작업본은 사라지고 글은 마지막 발행본으로 남는다.
5. **Given** 공개로 발행된 글, **When** 다시 발행하면서 비공개로 바꾸면, **Then** 그 즉시 독자에게 없는 글과 같이 보인다.

---

### User Story 4 - 연타·동시 편집에도 안전하게 (Priority: P3)

느린 네트워크에서 [발행]을 여러 번 누르거나 재전송돼도 한 번만 발행되고, 다른 탭·기기에서 먼저 저장했다면 덮어쓰기 전에 알려 준다.

**Why this priority**: 드물지만 생기면 데이터를 잃거나 "이미 성공했는데 충돌" 같은 혼란이 생긴다.

**Independent Test**: 같은 발행 시도를 동시에 20번 보내 발행이 한 번만 반영되는지, 옛 버전으로 발행하면 비교 화면이 뜨는지 확인한다.

**Acceptance Scenarios**:

1. **Given** [발행]을 누른 직후, **When** 응답을 기다리는 동안, **Then** 버튼이 비활성화되고 "발행 중…"이 표시되어 다시 누를 수 없다.
2. **Given** 같은 [발행] 클릭에서 나온 요청 여러 건, **When** 동시에 도착하면, **Then** 발행은 한 번만 일어나고 모든 요청이 같은 성공 결과를 받는다 (아직 처리 중이면 "처리 중"을 받고 잠시 뒤 재시도).
3. **Given** 다른 탭에서 더 최근에 저장된 글, **When** 옛 탭에서 발행하면, **Then** 발행되지 않고 두 내용을 나란히 비교해 고를 수 있다 (비교 창 규칙은 003-draft-autosave).
4. **Given** 발행 처리 도중, **When** 다른 탭의 자동 저장이 들어오면, **Then** 그 자동 저장 내용은 사라지지 않는다.

---

### User Story 5 - 비공개로 발행하고 나중에 공개하기 (Priority: P4)

작성자가 글을 비공개로 먼저 발행해 두고 나중에 공개하면, 목록에서 공개한 시점의 위치에 나온다.

**Why this priority**: 공개 범위(C-POST-4)와 목록(C-READ-1)이 맞물리는 지점. 껐다 켜기로 글을 맨 위로 올리는 꼼수도 막아야 한다.

**Independent Test**: 비공개 발행 → 다른 글 발행 → 첫 글 공개 → 목록 순서 확인. 이어서 비공개·공개를 다시 반복해도 위치가 그대로인지 확인.

**Acceptance Scenarios**:

1. **Given** 비공개로 발행한 글, **When** 독자가 주소를 열면, **Then** 없는 글과 똑같이 "찾을 수 없음"이다.
2. **Given** 비공개로 발행한 글, **When** 나중에 공개하면, **Then** 목록에서 처음 공개한 시점 기준 위치에 나온다.
3. **Given** 한 번 공개됐던 글, **When** 비공개 후 다시 공개하면, **Then** 목록 위치는 처음 공개 시점 그대로다.

---

### Edge Cases

- 남의 글, 삭제된 글, 없는 글 번호로 발행 요청 → 모두 "찾을 수 없음"으로 같게 응답하고 어떤 글도 바뀌지 않는다.
- 로그인하지 않았거나 이메일 인증 전·정지된 회원의 발행 요청 → 거부된다.
- 관리자 → 남의 글 내용을 수정·발행할 수 없다 (숨김만 가능, 별도 spec).
- 제목 101자, 본문 100,001자, 태그 11개(기본값 기준), 30자 넘는 태그, 허용되지 않는 공개 범위 → 각각 이유와 함께 거부, 실패한 항목을 한꺼번에 알려 준다.
- 같은 발행 시도 식별자로 다른 내용을 보냄 → 거부된다 (클라이언트 오류).
- 중복 방지 장치가 일시적으로 고장 남 → 글 잠금과 버전 확인으로 두 번째 요청이 충돌로 막혀 중복 발행은 일어나지 않는다.
- 발행 확정이 실패 → 자동 저장 버퍼 내용은 지워지지 않고, 같은 발행 시도를 다시 할 수 있다.
- 발행 직후 알림·검색 색인 등 후속 처리가 실패 → 발행은 성공한 상태로 유지된다.
- 사진이 하나도 없는 글 → 썸네일 없이 발행되고 목록 카드는 빈 썸네일로 보인다.
- 코드 블록 안에 태그 닫기·스크립트를 넣음 → 코드 블록 밖으로 빠져나가지 못하고 글자로 보인다.
- 본문 제목에서 만든 문서 내 앵커 이름 → 페이지의 다른 요소 이름과 겹치지 않는 고유 접두어가 붙고, 같은 제목은 번호로 구분된다.
- 에디터가 WYSIWYG여도 Markdown으로 내보내야 하며, 글자 색·가운데 정렬처럼 Markdown에 없는 서식은 저장되지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**글 작성·안전한 본문 (C-POST-1)**

- **FR-001**: 시스템은 본문을 Markdown 원문으로 저장하고, 독자에게 보여 줄 안전한 HTML을 따로 만들어 보관해야 한다. 서버는 원문만 받고 브라우저가 만든 HTML은 받지 않는다.
- **FR-002**: 안전한 HTML은 서버의 단일 렌더러만 만들어야 하며, 발행·미리보기·다시 렌더링이 모두 같은 렌더러를 써야 한다.
- **FR-003**: 렌더러는 CommonMark와 GFM(표·취소선·체크리스트·주소 자동 링크)을 지원하고, 본문 제목은 한 단계씩 낮춰(최상위가 2단계) 렌더링해야 한다. 각주·수식·다이어그램·임베드는 지원하지 않는다.
- **FR-004**: 본문에 직접 쓴 HTML은 모두 글자로 표시해야 한다.
- **FR-005**: 렌더링 결과는 허용 목록 정화를 한 번 더 거쳐야 하며, 허용된 태그·속성·값 외에는 모두 제거되어야 한다 (렌더러 결함에 대한 이중 방어).
- **FR-006**: 링크는 http·https·mailto·사이트 내 상대 경로만 허용하고, 그 밖의 주소는 어떤 형태로 숨겨도 제거해야 한다. 외부 링크는 새 탭으로 열되 원래 탭 접근·참조 정보 전달·검색 순위 전달을 막아야 한다.
- **FR-007**: 본문 사진은 글 작성자가 올린 우리 저장소 사진만 사진으로 그리고, 외부 이미지·남이 올린 사진은 "[이미지] 대체글" 외부 링크로 바꿔야 한다. 우리 사진은 현재 공개 주소로 바꿔 그리고 원문은 고치지 않는다.
- **FR-008**: 목록·인용 중첩이 20단계를 넘거나 렌더링이 1초를 넘으면 "글 구조가 너무 복잡하다"는 이유로 거부해야 한다.
- **FR-009**: 글 제목은 한 가지 유니코드 형태로 정규화하고 보이지 않는 글자·방향 제어 문자·제어 문자를 제거한 뒤 길이를 검사해야 하며, 화면에는 글자로만 표시해야 한다.
- **FR-010**: 로그인한 작성자는 서버 렌더러로 만든 미리보기를 볼 수 있어야 하며(입력이 0.5초 멈추면 갱신, 사용자당 1분에 60번), 미리보기와 발행 결과는 같아야 한다.
- **FR-011**: 모든 응답에 브라우저 2차 방어(우리 출처 스크립트만 실행, 이미지는 우리 사이트·사진 저장소·기기 내 미리보기만, 다른 사이트의 틀 안에 넣기 금지, 파일 형식 추측 금지, 참조 정보 최소화)가 적용되어야 한다.
- **FR-012**: 렌더링·정화 규칙이 바뀌면 렌더링 버전을 올리고, 옛 버전으로 만든 발행 글을 일괄로 다시 렌더링해야 한다. 이때 수정 일자와 편집 버전은 바뀌지 않는다.

**발행·수정 (C-POST-3)**

- **FR-013**: 작성자는 본인의 임시글 또는 발행된 글만 발행할 수 있어야 한다. 그 밖의 경우 글의 존재 여부를 드러내지 않는 "찾을 수 없음"으로 응답해야 한다. 작성자는 로그인 정보로만 판정한다.
- **FR-014**: 시스템은 발행 전에 제목(정리 후 1~100자), 본문(앞뒤 공백 제거 후 1~100,000자), 태그(설정된 최대 개수 이하·기본 10개, 각 1~30자), 공개 범위(공개/비공개), 업로드 미완료 사진 없음을 검사하고, 실패한 항목을 모두 한 번에 알려야 한다.
- **FR-015**: 시스템은 발행할 때 요약(정화된 결과에서 코드·사진·표를 뺀 글자 앞 200자)과 썸네일(작성자가 올린 첫 사진의 640px 썸네일)을 자동으로 정해야 한다.
- **FR-016**: 시스템은 태그를 소문자·앞뒤 공백 제거로 정리하고 중복을 없앤 뒤, 글의 태그를 새 목록으로 교체해야 한다.
- **FR-017**: 발행할 때 본문에서 글 작성자가 올린 사진만 글에 연결하고, 본문에서 빠진 사진은 빠진 시각을 기록해야 한다.
- **FR-018**: 최초 발행일은 처음 발행할 때 한 번만, 최초 공개일은 처음으로 "발행 + 공개"가 된 순간 한 번만 기록하고 이후 바뀌지 않아야 한다. 공개 목록은 최초 공개일 순이다.
- **FR-019**: 다시 발행하면 "수정 일자"를 기록하고, 주소·최초 발행일·최초 공개일·조회수·좋아요·댓글은 유지해야 한다.
- **FR-020**: 발행된 글을 고치는 동안 독자에게는 마지막 발행본만 보여야 하며, 다시 발행하면 작업본은 사라진다 (작업본 저장 규칙은 003-draft-autosave).
- **FR-021**: [발행]을 누르면 응답 전까지 버튼을 비활성화하고, 같은 발행 시도(같은 시도 식별자, 10분간 기억)가 여러 번 도착해도 발행은 한 번만 일어나 뒤의 요청은 첫 결과를 그대로 받아야 한다. 처리 중이면 "처리 중"을 알리고, 같은 식별자로 다른 내용이 오면 거부한다.
- **FR-022**: 작성자가 열어 둔 버전보다 서버의 버전(버퍼·작업본·글 중 가장 최신)이 더 최신이면 발행을 거부하고, 서버 쪽 최신 내용을 돌려줘 비교·선택할 수 있게 해야 한다. 같은 글에 대한 동시 발행은 한 번에 하나씩 처리되어야 한다.
- **FR-023**: 발행 처리 중 들어온 다른 탭의 자동 저장 내용은 발행이 끝난 뒤에도 남아 있어야 하며, 자동 저장 버퍼는 발행이 확정된 뒤에만 지운다.
- **FR-024**: 발행된 글을 임시글로 되돌리는 기능은 두지 않는다. 내리고 싶으면 비공개로 바꾼다.
- **FR-025**: 최초 발행이면 "글 발행됨", 다시 발행이면 "글 수정됨" 사건을 알려, 알림·검색 등이 기존 발행 기능을 바꾸지 않고 붙을 수 있어야 한다. 이 후속 처리의 실패가 발행 결과를 바꾸면 안 된다.

### Key Entities

- **글(post)**: 제목, Markdown 원문, 안전한 HTML, 렌더링 버전, 요약, 썸네일, 상태(임시/발행), 공개 범위, 최초 발행일·최초 공개일·수정 일자, 편집 버전. 작성자 한 명에 속한다.
- **작업본(post_draft)**: 발행된 글을 고치는 중의 내용과 편집 버전. 글당 최대 하나.
- **태그(tag) / 글-태그(post_tag)**: 정리된 태그 이름, 글과 다대다.
- **글-사진(post_image)**: 본문에 쓰인, 작성자 본인이 올린 사진과의 연결. 빠진 사진은 떼어 낸 시각을 남긴다.
- **발행 시도 기록**: 시도 식별자별 요청 내용 요약과 결과. 10분 보관.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 공개로 발행한 글을 비로그인 독자가 즉시 열 수 있다 (발행 응답 직후 조회 성공률 100%).
- **SC-002**: 같은 발행 시도 20건을 동시에 보내도 발행 반영(편집 버전 증가)은 정확히 1번이다.
- **SC-003**: 남의 글에 대한 발행·수정 시도는 100% "찾을 수 없음"으로 끝나고, 글 데이터는 한 글자도 바뀌지 않는다.
- **SC-004**: 다시 발행 전후로 주소·최초 발행일·최초 공개일·조회수·좋아요·댓글 수가 모두 같고, 수정 중에는 비로그인 조회가 100% 마지막 발행본을 보여 준다.
- **SC-005**: 제목·본문이 비었거나 업로드 미완료 사진이 있는 발행 시도는 100% 거부되고 글은 임시 상태를 유지한다.
- **SC-006**: 비공개로 발행했다가 공개한 글은 목록에서 공개한 시점 위치에 나오고, 공개를 껐다 켜도 위치가 바뀌지 않는다.
- **SC-007**: XSS 회귀 목록(공격 문자열 32개)을 본문·제목에 넣어 발행해도 결과에 실행 가능한 스크립트가 0건이고, 브라우저 종단 시험에서 알림창이 0번 뜬다.
- **SC-008**: 정상 문법 회귀 목록 13개가 100% 의도대로 렌더링되고, 본문에 최상위 제목이 0개다.
- **SC-009**: 같은 본문의 미리보기와 발행 결과가 100% 같다.
- **SC-010**: 외부 링크는 100% 새 탭·보호 속성으로, 외부·남의 사진은 100% 링크로 바뀐다.
- **SC-011**: 중첩 20단계 초과 또는 렌더링 1초 초과 본문은 100% 발행되지 않고, 본문 10만 자 렌더링은 1초 제한 안에 끝난다.
- **SC-012**: 모든 응답에 브라우저 2차 방어 설정이 포함되어 있다.
- **SC-013**: 렌더링 규칙 버전을 올리면 기존 발행 글이 모두 새 규칙으로 다시 렌더링되고, 수정 일자는 바뀌지 않는다.

## Assumptions

- 로그인(C-AUTH-1)·임시저장/작업본(003-draft-autosave)·사진 업로드(004-image-upload)는 별도 spec이다. 이 기능을 먼저 만들 때는 테스트용 로그인 회원과 미리 만든 임시글로 검증한다.
- 글 주소 `/@블로그주소/posts/{글번호}`는 공통 id 기반 주소(01 Q4 표, 52 §1)를 따른다. 사람이 읽는 주소(slug)는 개인 확장이다.
- 공개 범위는 공개/비공개 두 가지만 다룬다. 친구 공개는 선택 기능이라 범위 밖이며, 재발행 없는 공개 범위 변경 자체는 C-POST-4 spec에서 다룬다.
- 발행 이력·되돌리기, 코드 복사 버튼·목차 화면·임베드·각주·수식은 개인 확장이라 범위 밖이다.
- 관리자 숨김(43 문서), 글 상세 화면 구성(40 문서), 댓글의 글자만 표시 규칙은 범위 밖이다.
- 코드 강조는 브라우저에서 하며, 스크립트가 없어도 코드는 읽힌다.
- 태그 최대 개수·요청 제한 등 수치는 설정값이며 위 값은 기본값이다.
- 발행 응답 시간의 별도 수치 목표는 근거 문서에 없어 두지 않는다 (렌더링 1초 제한만 적용).
