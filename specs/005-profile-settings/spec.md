# Feature Specification: 프로필 수정과 계정 설정 (005-profile-settings)

**Feature Branch**: `005-profile-settings`

**Created**: 2026-10-07

**Status**: Draft

블로그 주소와 이메일은 바꿀 수 없다. 상세 규칙은 docs/11-profile.md, docs/09-nickname.md, docs/42-permission-matrix.md를 따른다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 소개와 닉네임을 고쳐 한 번에 저장한다 (Priority: P1)

회원이 설정 화면에서 닉네임과 소개를 고치고 [저장]을 누른다. 하나라도 규칙에 어긋나면 아무것도 저장되지 않고 틀린 칸이 모두
표시된다. 블로그 주소와 이메일은 읽기 전용으로 보인다.

**Why this priority**: 블로그 상단에 보이는 "나"를 꾸미는 가장 기본 기능이다. 사진 없이도 소개만으로 가치가 있다.

**Independent Test**: 소개를 고쳐 저장한 뒤 내 블로그 상단에 바로 반영되는지, 소개는 맞고 닉네임이 틀린 상태로 저장하면 소개도
바뀌지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 설정 화면에 들어가면, **Then** 프로필(사진·닉네임·소개·블로그 주소 "변경할 수 없어요")과
   계정(이메일 "변경할 수 없어요"·로그인 수단·직전 로그인·기본 공개 범위·약관 보기) 영역이 보인다.
2. **Given** 소개 0~200자·4줄 이내·금칙어 없음, **When** [저장]을 누르면, **Then** 저장되고 목록·글 상세·블로그 상단에 즉시
   반영된다. 입력 중에는 "32 / 200"처럼 글자 수가 보인다.
3. **Given** 소개 201자, **When** 저장하면, **Then** "소개는 200자까지 쓸 수 있어요"로 거부된다. 5줄이면 "소개는 4줄까지 쓸 수
   있어요"로 거부된다.
4. **Given** 소개에 `<script>`나 HTML·Markdown을 씀, **When** 블로그에서 보면, **Then** 실행되거나 꾸며지지 않고 글자 그대로 보인다.
5. **Given** 소개에 주소(`https://…`)를 씀, **When** 보면, **Then** 링크로 바뀌지 않는다.
6. **Given** 소개는 맞고 닉네임이 규칙에 어긋남, **When** 함께 저장하면, **Then** 아무것도 바뀌지 않고 실패한 칸이 모두 표시된다.
7. **Given** 닉네임 변경 후 30일이 안 지남, **When** 설정 화면을 보면, **Then** 닉네임 칸이 비활성화되고 "다음 변경 가능일: 11월
   1일"이 보이며, 소개·사진은 저장된다. 같은 요청에 닉네임 변경이 들어 있으면 전체가 저장되지 않는다.
8. **Given** 비회원, **When** 설정 화면에 들어오면, **Then** 로그인 화면으로 가고 로그인 후 돌아온다.

### User Story 2 - 프로필 사진을 올리거나 기본 이미지로 되돌린다 (Priority: P2)

회원이 사진을 골라 정사각형으로 자르면 256×256 크기로 바뀌어 올라가고, [저장]을 눌러야 프로필 사진이 된다. 사진이 없으면 닉네임
첫 글자가 들어간 동그란 아이콘이 보인다.

**Why this priority**: 사람을 알아보게 하는 핵심 요소지만, 기본 이미지가 있어 P1만으로도 화면이 비지 않는다.

**Independent Test**: 사진을 올리고 저장해 블로그·글 상세에 보이는지, [기본 이미지로]를 저장하면 첫 글자 아이콘으로 바뀌는지,
올리기만 하고 저장하지 않은 사진은 하루 뒤 지워지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 10MB 이하 jpg·png·gif·webp 사진, **When** [이미지 변경]으로 골라 위치·확대를 조정하면, **Then** 정사각형 256×256
   사진으로 바뀌고(촬영 위치 등 사진 정보 제거, GIF는 첫 장면) 미리보기에 보인다.
2. **Given** 올린 사진, **When** [저장]을 누르면, **Then** 프로필 사진이 되고 이전 사진은 연결이 끊긴다.
3. **Given** 올리기만 하고 저장하지 않은 사진, **When** 24시간이 지나면, **Then** 지워진다.
4. **Given** 연결이 끊긴 이전 프로필 사진, **When** 7일이 지나면, **Then** 지워진다. 지금 프로필 사진은 지워지지 않는다.
5. **Given** [기본 이미지로], **When** 저장하면, **Then** 닉네임 첫 글자(영문은 대문자) 아이콘이 블로그 주소로 정해진 색 배경에
   보인다.
6. **Given** 256×256이 아니거나, 남이 올렸거나, 글용으로 올린 사진, **When** 그 사진을 프로필로 저장하려 하면, **Then** 거부된다.
7. **Given** 이메일 인증 전 회원, **When** 사진을 올리려 하면, **Then** 거부되고, 닉네임·소개는 고칠 수 있다.

### User Story 3 - 소셜 가입 때 소셜 프로필 사진을 가져온다 (Priority: P3)

Google·GitHub로 가입하는 사람은 가입 마무리 화면에서 "프로필 사진 사용"(기본 체크)을 그대로 두면, 가입 직후 브라우저가 소셜
사진을 받아 256×256으로 바꿔 우리 저장소에 복사한다. 소셜 사진 주소는 저장하지 않는다.

**Why this priority**: 가입 직후 블로그가 비어 보이지 않게 하지만, 실패해도 기본 이미지로 충분하다.

**Independent Test**: GitHub로 가입해 프로필 사진이 우리 저장소의 복사본으로 연결되는지, 소셜 쪽 사진을 바꿔도 우리 사진은 그대로인지,
체크를 끄면 기본 이미지인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 소셜 가입 마무리 화면, **When** 화면이 열리면, **Then** "Google(또는 GitHub) 프로필 사진 사용"이 체크된 채 미리보기와
   함께 보인다.
2. **Given** 체크한 채 가입 완료, **When** 계정이 만들어지면, **Then** 브라우저가 소셜 사진을 받아 가운데를 정사각형으로 잘라
   256×256으로 바꿔 올리고 프로필 사진으로 연결한다.
3. **Given** 소셜 사진 받기가 실패하거나 5초를 넘김, **When** 가입이 끝나면, **Then** 가입은 완료되고 기본 이미지로 두며 "소셜 사진을
   가져오지 못했어요. 설정에서 직접 올릴 수 있어요"가 안내된다.
4. **Given** 체크를 끔, **When** 가입하면, **Then** 기본 이미지다.
5. **Given** 가입 후 소셜 서비스에서 사진을 바꿈, **When** 블로그를 보면, **Then** 가입 때 복사한 사진 그대로다.

### User Story 4 - 계정 정보와 설정을 관리한다 (Priority: P4)

회원은 계정 영역에서 직전 로그인 일자·방식을 보고 계정 도용을 알아챌 수 있다. 새 글 기본 공개 범위를 고르고, AI 기능에 동의했다면
동의를 철회할 수 있다.

**Why this priority**: 안전·편의 기능으로, 프로필보다 덜 자주 쓴다.

**Independent Test**: 두 번 로그인한 뒤 계정 화면에 "방금"이 아니라 "그 전" 로그인이 보이는지, 기본 공개 범위를 비공개로 바꾼 뒤
[새 글]이 비공개로 시작하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이전에 로그인한 적이 있는 회원, **When** 다시 로그인해 계정 영역을 보면, **Then** "직전 로그인: 2026.10.07 14:03,
   Google"처럼 이번 로그인 바로 전의 일자와 로그인 방식이 보인다.
2. **Given** 처음 로그인한 회원, **When** 계정 영역을 보면, **Then** "첫 로그인"이 보인다.
3. **Given** 다른 회원, **When** 내 블로그나 프로필을 보면, **Then** 내 직전 로그인 정보는 보이지 않는다.
4. **Given** 기본 공개 범위 (●) 전체 공개, **When** ( ) 나만 보기로 바꾸면, **Then** 이후 [새 글]은 비공개로 시작하고 이미 있는 글은
   바뀌지 않는다.
5. **Given** AI 기능에 동의한 회원, **When** 설정에서 동의를 철회하면, **Then** AI 동의 기록이 지워지고 다음에 AI 기능을 쓰려면 다시
   동의해야 한다.
6. **Given** 소셜 계정, **When** 계정 영역을 보면, **Then** [비밀번호 변경]은 보이지 않는다(비밀번호 변경 자체는 004).

### Edge Cases

- 소개에 빈 줄이 연달아 있으면? → 하나로 줄여 저장한다. 앞뒤 공백은 지우고, 분리된 한글은 합친 형태로 바꾼 뒤 검사한다.
- 소개에 금칙어가 있으면? → "사용할 수 없는 단어가 들어 있어요"로 거부하고, 어떤 단어인지는 알리지 않는다. 예약어 검사는 하지 않는다.
- 소개에 이모지를 쓰면? → 허용된다.
- 같은 닉네임으로 다시 저장하면? → 아무것도 바뀌지 않고 30일 제한도 시작되지 않는다. 대소문자만 바꾸면(`kim` → `Kim`) 변경으로 본다.
- 가입할 때 정한 닉네임은? → 변경으로 세지 않아 가입 직후 한 번은 바로 바꿀 수 있다.
- 두 기기에서 동시에 프로필을 저장하면? → 나중에 저장한 쪽이 반영되고, 프로필 사진은 회원당 하나만 연결된다.
- 바꾸려는 칸만 보내면? → 보낸 칸만 바뀐다. 사진 값을 비워 보내면 기본 이미지로 돌아간다.
- 요청에 다른 회원을 지정하는 값을 넣으면? → 그런 경로가 없고, 항상 로그인한 본인의 프로필만 바뀐다.
- 소셜 사진 주소가 허용된 두 곳(Google·GitHub 사진 서버)이 아니거나 안전한 연결이 아니면? → 가입 마무리 화면에 넘기지 않고 기본
  이미지로 둔다.
- Google·GitHub 사진이 없는 계정이면? → 소셜 서비스가 주는 기본 이미지(이름 첫 글자·무늬)를 그대로 가져온다.
- 사진 업로드 요청이 1분에 20장을 넘으면? → 거부된다(사진 업로드 공통 제한).
- 기본 이미지 아이콘의 글자와 배경은? → 라이트·다크 모드 모두 명도 대비 4.5:1 이상이다.

## Requirements *(mandatory)*

### Functional Requirements

**설정 화면과 저장 (docs/11 §2·§5, R-8)**

- **FR-001**: 설정 화면(`/settings`)은 로그인한 사람만 들어올 수 있어야 하고, 비회원은 로그인 화면으로 보낸 뒤 돌아오게 해야 한다.
- **FR-002**: 프로필 수정은 로그인한 본인만 할 수 있어야 하며, 요청에 회원을 지정하는 값을 받지 않아야 한다. 이 검사는 서버에서
  매 요청마다 해야 한다.
- **FR-003**: 닉네임·소개·프로필 사진은 [저장] 한 번에 반영하고, 바꾸려는 칸만 받을 수 있어야 한다. 하나라도 검사에 실패하면
  아무것도 저장하지 않고 실패한 칸을 모두 알려줘야 한다.
- **FR-004**: 닉네임이 30일 제한 중이면 닉네임 칸만 비활성화하고 다른 칸은 저장되게 하되, 같은 요청에 닉네임 변경이 들어 있으면
  전체를 실패시켜야 한다. 닉네임 검사·변경 규칙은 001(docs/09)을 따른다.
- **FR-005**: 동시에 저장하면 나중에 저장한 쪽이 반영되어야 한다.
- **FR-006**: 저장 결과는 목록·글 상세·블로그 상단에 즉시 반영되어야 한다.
- **FR-007**: 블로그 주소와 이메일은 읽기 전용으로 보여주고 어떤 경로로도 바꿀 수 없어야 한다.

**소개 (docs/11 §3, R-1~R-3)**

- **FR-008**: 소개는 0~200자의 글자만 허용하고(HTML·Markdown 불가), 줄바꿈은 최대 4줄, 이모지는 허용해야 한다. 앞뒤 공백 제거,
  유니코드 정규화, 연속 빈 줄 하나로 줄이기를 거친 뒤 검사해야 한다.
- **FR-009**: 소개를 보여줄 때는 글자로만 보여 HTML이 실행되지 않아야 하며, 주소를 자동으로 링크로 바꾸지 않아야 한다.
- **FR-010**: 소개에는 닉네임과 같은 금칙어 필터를 적용하되 예약어 검사는 하지 않아야 한다. 오류는 "소개는 200자까지 쓸 수 있어요",
  "소개는 4줄까지 쓸 수 있어요", "사용할 수 없는 단어가 들어 있어요"로 구분해야 한다.

**프로필 사진 (docs/11 §4, R-4·R-5·R-7)**

- **FR-011**: 프로필 사진은 jpg·png·gif·webp 10MB 이하에서 고르고, 브라우저에서 정사각형으로 잘라(위치 조정·확대·축소) 256×256
  한 가지 크기로 바꾸며 사진 속 위치 정보 등을 지워야 한다. GIF는 첫 장면의 정지 사진으로 만든다.
- **FR-012**: 서버는 올라온 프로필 사진의 형식·실제 내용·정확히 256×256·1MB 이하를 다시 검사해야 하며, 프로필 사진에는 목록용
  작은 사진을 만들지 않는다.
- **FR-013**: 올린 사진은 [저장]을 눌러야 프로필에 연결되어야 한다. 저장하지 않은 사진은 24시간 뒤, 바꿔서 연결이 끊긴 이전 사진은
  7일 뒤 정리되어야 하며, 지금 연결된 프로필 사진은 정리 대상이 아니어야 한다.
- **FR-014**: 프로필로 연결할 수 있는 사진은 본인이 올렸고, 프로필 용도이며, 삭제되지 않은 사진뿐이어야 한다. 그렇지 않으면 거부해야
  한다.
- **FR-015**: 회원당 연결된 프로필 사진은 언제나 하나여야 하며, 새 사진 연결은 이전 사진 떼기와 한 번에 처리되어 동시 저장에도
  두 장이 연결되지 않아야 한다.
- **FR-016**: 사진이 없으면 닉네임 첫 글자(영문은 대문자)와 블로그 주소로 정해진 8가지 색 중 하나의 배경으로 동그란 기본 아이콘을
  그려야 하며, 파일로 저장하지 않는다. 글자와 배경은 라이트·다크 모드 모두 명도 대비 4.5:1 이상이어야 한다.
- **FR-017**: 이메일 인증 전 회원은 사진을 올릴 수 없어야 하고(docs/42 §9), 사진 업로드는 사용자당 1분에 20장으로 제한해야 한다.

**소셜 프로필 사진 복사 (docs/11 §4-2, R-6)**

- **FR-018**: 소셜 가입 마무리 화면에 "프로필 사진 사용"을 기본 체크로 보여주고, 체크하면 계정을 만든 직후 브라우저가 소셜 사진을
  5초 제한으로 받아 가운데를 정사각형으로 잘라 256×256으로 바꾼 뒤 직접 올리기와 같은 흐름으로 올려 프로필에 연결해야 한다.
- **FR-019**: 소셜 사진 주소는 Google·GitHub의 사진 서버 두 곳의 안전한 연결 주소만 가입 마무리 화면에 넘겨야 하고, 그 두 곳의
  사진은 가입 마무리 화면에서만 불러올 수 있어야 한다(다른 화면에서는 불러오지 않는다).
- **FR-020**: 서버는 외부 사진 주소를 직접 요청하지 않아야 하며, 소셜 사진 주소를 저장하지 않아야 한다. 복사는 가입할 때 한 번이다.
- **FR-021**: 복사에 실패해도 가입은 완료하고 기본 이미지로 두며 설정에서 직접 올릴 수 있다고 안내해야 한다.

**계정 설정 (docs/11 §6)**

- **FR-022**: 이메일과 로그인 수단은 읽기 전용으로 보여줘야 한다. [비밀번호 변경]은 이메일 가입 계정에만 보여야 한다(동작은 004).
- **FR-023**: 계정 영역에 이번 로그인 바로 전의 로그인 일자와 로그인 방식을 "직전 로그인: 일자, 로그인 방식"으로 보여줘야 하며, 첫
  로그인이면 "첫 로그인"으로 보여줘야 한다. 이 정보는 본인에게만 보여야 한다.
- **FR-024**: 새 글 기본 공개 범위를 전체 공개(`PUBLIC`)·나만 보기(`PRIVATE`) 중에서 본인만 바꿀 수 있어야 하며, 바꾼 값은 이후
  [새 글]의 공개 범위 초기값이 되어야 한다. 이미 있는 글은 바뀌지 않는다.
- **FR-025**: AI 동의를 한 회원은 설정 화면에서 철회할 수 있어야 하며, 철회하면 AI 동의 기록을 지워 다음 사용 때 다시 동의를 받아야
  한다. 필수 약관(이용약관·개인정보 처리방침) 동의는 철회 대상이 아니다.
- **FR-026**: 설정 화면에서 이용약관·개인정보 처리방침 문서를 볼 수 있어야 한다.

**권한·연동 (docs/42 §9, docs/20)**

- **FR-027**: 닉네임·소개 수정과 기본 공개 범위 변경은 이메일 인증 전 회원에게도 허용하고, 프로필 사진 변경만 막아야 한다. 정지
  회원은 로그인할 수 없으므로 이 기능을 쓸 수 없다.
- **FR-028**: 프로필 변경은 새 사건을 발행하지 않는다. 닉네임·사진은 보여줄 때마다 현재 값을 읽어 반영한다.

### Key Entities *(include if feature involves data)*

- **회원(Member)**: 001에서 정의. 이번에 소개(0~200자), 닉네임 마지막 변경 일자, 기본 공개 범위를 쓴다. 회원은 사진을 직접 가리키지
  않는다.
- **사진(Image)**: 올린 사람, 용도(글·프로필), 상태(임시·연결됨), 연결이 끊긴 일자, 크기. 지금 프로필 사진은 "본인이 올린 프로필
  용도의 연결됨 상태이고 연결이 끊기지 않은 사진" 하나로 판별한다.
- **로그인 수단(AuthIdentity)**: 001·004에서 정의. 마지막 로그인 일자를 직전 로그인 표시에 쓴다.
- **약관 동의(MemberAgreement)**: 001에서 정의. 이번에는 AI 동의 철회 때 AI 종류의 기록을 지운다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 회원이 설정 화면에서 소개와 사진을 바꿔 저장하기까지 1분 안에 끝낼 수 있고, 저장 직후 블로그 상단에 반영된다.
- **SC-002**: 검사에 실패한 저장 요청 뒤 프로필의 모든 값이 요청 전과 같다(100%).
- **SC-003**: 소개에 docs/12의 공격 문자열을 넣어도 블로그·글 상세에서 스크립트가 하나도 실행되지 않는다.
- **SC-004**: 같은 회원이 동시에 서로 다른 사진으로 10번 저장해도 연결된 프로필 사진은 정확히 1장이다.
- **SC-005**: 256×256이 아닌 사진, 남의 사진, 글용 사진을 프로필로 연결하는 요청은 100% 거부된다.
- **SC-006**: 소셜 가입에서 사진 복사가 실패해도 가입 완료율이 떨어지지 않는다(복사 실패 때 가입 실패 0건).
- **SC-007**: 계정 화면의 직전 로그인은 언제나 방금 한 로그인이 아니라 그 전 로그인이다.
- **SC-008**: docs/11 §8 공통 완료 기준 1~6·8과 docs/09 §11의 6이 모두 자동 테스트로 확인된다.

## Assumptions

- **A-1**: 비밀번호 변경(docs/11 §6-2)은 004에서 다룬다. 이 spec은 버튼을 이메일 가입 계정에만 보이는 것까지다.
- **A-2**: "최근 활동을 친구에게 보이기" 설정(docs/11 §6-4 R-12)은 친구 기능과 함께 008에서 다룬다.
- **A-3**: 프로필 사진 업로드는 사진 업로드 공통 흐름(업로드 주소 발급 → 직접 업로드 → 완료 검사, 정리 배치)을 쓴다. 글 사진 업로드
  (`009-image-upload`, Tier B)보다 먼저 들어오면 프로필 용도에 필요한 부분을 이 기능이 먼저 갖추고, 009가 같은 흐름을 넓혀 쓴다.
- **A-4**: AI 동의를 받는 화면과 AI 기능 자체는 Tier C(`018-ai-tag-suggest`)다. 그 전에는 철회할 동의가 없으므로 철회 항목은 AI 동의 기록이
  있을 때만 보인다.
- **A-5**: 기본 공개 범위의 `FRIENDS` 선택지는 친구 공개를 선택 구현한 경우에만 있으며 008에서 다룬다.
- **A-6**: 회원 탈퇴 버튼과 흐름은 020에서 다룬다.
- **A-7**: 소개의 외부 링크 칸은 개인 확장으로 범위 밖이다.
