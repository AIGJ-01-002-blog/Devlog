# Feature Specification: 브라우저 저장과 오프라인 복구 (006-offline-autosave)

**Feature Branch**: `006-offline-autosave`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "작성 중인 글을 입력이 1초 멈출 때마다 그 기기의 브라우저에 남겨, 네트워크가 끊기거나 창이 닫혀도
다시 열면 이어 쓸 수 있게 한다. 연결되면 서버로 자동 동기화하고, 다른 곳에서 고친 내용과 부딪치면 이 기기 내용을 7일 동안 백업해
둔다. 공용 PC를 위해 로그아웃하면 브라우저에 남은 작성 데이터를 모두 지운다. 002의 서버 자동 저장 위에 얹는다. 상세 규칙은
docs/04-draft-and-image.md를 따른다."

**관련 기능 ID**: C-POST-2(002에서 남은 브라우저 저장·오프라인 복구 범위)

**선행 기능**: `002-write-publish` (서버 자동 저장·수동 저장·편집 버전·충돌 비교 창)

**우선순위 단계**: MVP 직후 (Tier A 나머지)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 네트워크가 끊겨도 계속 쓰고, 연결되면 자동으로 저장된다 (Priority: P1)

작성자가 지하철에서 글을 쓰다 네트워크가 끊겨도 에디터는 멈추지 않는다. 입력은 그 기기에 1초 단위로 남고, 연결이 돌아오면 쓴
내용이 서버로 자동 동기화된다.

**Why this priority**: "쓴 글이 사라지지 않는다"는 약속의 마지막 빈틈(오프라인)을 메운다. 002는 오프라인 상태 표시만 했다.

**Independent Test**: 글을 쓰다 네트워크를 끊고 몇 분 더 쓴 뒤 다시 연결해, 끊긴 동안 쓴 내용이 빠짐없이 서버에 저장되는지와 화면
상태 표시가 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 작성 중인 글, **When** 입력이 1초 멈추면, **Then** 제목과 본문이 서버 요청 없이 그 기기에 저장된다.
2. **Given** 기기에만 있고 서버로 아직 못 보낸 내용, **When** 화면을 보면, **Then** "● 이 기기에 저장됨 (동기화 대기)"가 글자로 보인다.
3. **Given** 네트워크가 끊김, **When** 계속 쓰면, **Then** 편집은 막히지 않고 "⚠ 오프라인 — 이 기기에 저장 중, 연결되면 자동 동기화"가
   보인다.
4. **Given** 서버 저장 실패, **When** 시간이 지나면, **Then** 2초 → 4초 → 8초 … 최대 60초 간격(무작위 지연 포함)으로 다시 시도하고,
   그동안 내용은 기기에 남아 있다.
5. **Given** 연결이 돌아옴, **When** 다시 시도가 성공하면, **Then** "✓ 저장됨 14:03"으로 바뀌고 기기의 미전송 표시가 풀린다.
6. **Given** 미전송 내용이 있음, **When** 페이지를 떠나려 하면, **Then** 확인창이 뜬다.

---

### User Story 2 - 창이 닫히거나 기기가 꺼져도 다시 열면 이어 쓴다 (Priority: P2)

작성자가 오프라인 상태에서 창을 닫거나 배터리가 꺼져도, 같은 기기에서 그 글을 다시 열면 서버로 못 보낸 내용을 불러와 이어 쓴다.

**Why this priority**: P1의 기기 저장을 실제 복구로 이어 준다.

**Independent Test**: 오프라인에서 글을 고친 뒤 창을 닫고, 연결된 상태에서 같은 글을 다시 열어 미전송 내용이 불러와지고 안내가 보이는지
확인한다.

**Acceptance Scenarios**:

1. **Given** 기기에 미전송 내용이 있고 그 내용이 출발한 서버 버전이 지금 서버 버전과 같음, **When** 그 글을 다시 열면, **Then** 충돌로
   보지 않고 기기 내용을 불러오며 "이 기기에 저장되지 않은 변경을 불러왔어요"가 보이고 이어서 편집·동기화된다.
2. **Given** 기기에 미전송 내용이 있지만 그 사이 다른 곳에서 서버 내용이 바뀜, **When** 그 글을 다시 열면, **Then** 바로 비교 창이 뜬다.
3. **Given** 미전송 내용이 없음, **When** 에디터를 떠나면, **Then** 그 글의 기기 데이터는 지워진다.
4. **Given** 발행 성공, **When** 발행이 끝나면, **Then** 그 글의 기기 데이터는 지워진다.

---

### User Story 3 - 다른 곳의 수정과 부딪쳐도 이 기기 내용을 잃지 않는다 (Priority: P3)

같은 글을 다른 탭·기기에서 먼저 저장했으면, 이 기기는 타이핑을 막지 않고 서버 전송만 멈춘 채 기기에 계속 저장한다. 작성자가
[저장된 내용 불러오기]를 고르면 편집 중이던 내용은 이 기기에 7일 동안 백업된다.

**Why this priority**: 002의 충돌 비교 창에 "기기 쪽 내용 보존"을 더해 어떤 선택에서도 글이 사라지지 않게 한다.

**Independent Test**: 두 탭에서 같은 글을 고쳐 한쪽에서 충돌을 만들고, [저장된 내용 불러오기]를 고른 뒤 편집 중이던 내용이 백업으로
남아 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 자동 저장이 "다른 곳에서 먼저 저장됨"으로 거절됨, **When** 작성자가 계속 타이핑하면, **Then** 창이 뜨지 않고 편집이 계속되며
   서버 전송만 멈추고 기기에는 계속 저장된다.
2. **Given** 충돌 상태, **When** 화면을 보면, **Then** 에디터 위에 "⚠ 다른 탭이나 기기에서 이 글이 수정되었어요(14:03). 지금 내용은 이
   기기에만 저장되고 있어요. [비교하기]" 배너가 있다.
3. **Given** 충돌 상태, **When** [비교하기]·[저장]·[발행] 중 하나를 누르면, **Then** 002의 비교 창이 뜬다.
4. **Given** 비교 창, **When** [저장된 내용 불러오기]를 고르면, **Then** 에디터는 서버 내용으로 바뀌고 편집 중이던 내용은 이 기기에 7일
   동안 백업된다는 안내가 보인다.
5. **Given** 비교 창, **When** 닫기(X)를 누르면, **Then** 편집은 계속되고 서버 전송은 멈춘 채 배너가 남는다.

---

### User Story 4 - 오프라인에서 넣은 사진은 연결되면 올라간다 (Priority: P4)

오프라인이거나 업로드에 실패한 사진은 기기에 대기열로 남고, 본문에는 임시 표시가 들어가 화면에서는 정상으로 보인다. 연결되면 자동으로
올라가 진짜 주소로 바뀐다. 임시 표시가 남은 글은 발행할 수 없다.

**Why this priority**: 사진 업로드(`009-image-upload`, Tier B)가 있어야 의미가 있어 마지막이다. 이 spec은 대기열 규칙을 정하고, 실제 연결은 009와 함께
완성한다.

**Independent Test**: 오프라인에서 사진을 붙여넣어 화면에 보이는지, 발행이 막히는지, 연결 뒤 자동으로 올라가 본문의 임시 표시가 진짜
주소로 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 오프라인, **When** 사진을 붙여넣으면, **Then** 사진은 기기 대기열에 저장되고 본문에는 "업로드 대기" 임시 표시가 들어가며
   화면에는 사진이 정상으로 보인다.
2. **Given** 임시 표시가 있는 본문, **When** 자동 저장 시점이 되면, **Then** 그대로 저장된다.
3. **Given** 임시 표시가 남은 글, **When** 발행하면, **Then** 거부되고 업로드가 끝나지 않은 사진이 있다고 안내된다.
4. **Given** 연결이 돌아옴, **When** 다시 시도가 성공하면, **Then** 임시 표시가 진짜 사진 주소로 바뀐다.

---

### User Story 5 - 공용 PC에서 로그아웃하면 작성 흔적이 남지 않는다 (Priority: P5)

로그아웃하면 그 브라우저에 남은 본인의 작성 데이터·백업·사진 대기열이 모두 지워진다. 같은 브라우저를 다른 계정이 써도 서로 섞이지 않는다.

**Why this priority**: 001이 정한 "로그아웃 시 임시 데이터 삭제"를 이 기능이 만든 데이터 전체로 넓힌다.

**Independent Test**: 오프라인 내용·백업·대기 사진이 있는 상태에서 로그아웃한 뒤 브라우저 저장소에 그 사용자의 데이터가 남지 않는지,
다른 계정으로 로그인해 앞 사람의 내용이 보이지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기기에 작성 데이터·백업·대기 사진이 있음, **When** 로그아웃하면, **Then** 그 사용자의 것이 모두 지워진다.
2. **Given** 한 브라우저를 두 계정이 번갈아 씀, **When** 각자 에디터를 열면, **Then** 다른 계정의 기기 데이터는 보이지 않는다.

---

### Edge Cases

- 브라우저 데이터가 지워지면? → 서버에 30초 이내 내용이 있어 최대 30초 분량만 잃는다.
- 탭이 가려지거나 페이지를 떠나는 순간에 미전송 내용이 있으면? → 그 순간에도 서버로 보내기를 시도하고(002), 실패해도 기기에 남는다.
- 한 탭에서 서버 요청이 응답을 기다리는 중에 또 저장 시점이 오면? → 요청은 한 번에 하나만 보내 순서가 뒤바뀌지 않는다.
- 백업한 지 7일이 지나면? → 백업은 지워진다.
- 사진 대기열의 사진이 큰데 기기 저장 공간이 부족하면? → 문서에 규정이 없다(가정 A-4).
- 오프라인 동안 다른 탭에서 그 글을 휴지통으로 옮기면? → 다시 연결됐을 때 서버는 없는 글로 응답한다. 기기 내용 처리 방식은 가정 A-5.
- 기기 저장소를 쓸 수 없는 환경(사생활 보호 창 등)이면? → 002의 서버 자동 저장만으로 동작한다(가정 A-6).
- 로그인 정보(로그인 상태 값·비밀번호 등)가 기기 저장소에 남는가? → 남기지 않는다.
- 태그도 기기에 저장되는가? → 자동 저장 대상은 제목과 본문뿐이다(태그는 발행할 때 확정).

## Requirements *(mandatory)*

### Functional Requirements

**기기 저장 (docs/04 §2-1·§2-2, D-2)**

- **FR-001**: 에디터는 입력이 1초 멈출 때마다 제목과 본문을 그 기기의 브라우저 저장소에 서버 요청 없이 저장해야 한다. 저장하는 동안
  화면이 멈추지 않는 저장 방식을 써야 한다.
- **FR-002**: 기기 데이터는 회원과 글별로 구분해 다른 계정·다른 글의 데이터와 섞이지 않아야 한다. 각 데이터는 제목·본문·그 내용이
  출발한 서버 편집 버전·미전송 여부·업로드 대기 사진·저장 일자를 가져야 한다.
- **FR-003**: 기기 저장소에는 로그인 정보를 저장하지 않아야 한다.
- **FR-004**: 서버 전송(002의 3초·최대 30초 규칙)은 미전송 내용이 있을 때만 하고, 한 탭에서는 요청을 한 번에 하나만 보내 응답을 받은
  뒤 다음 요청을 보내야 한다.
- **FR-005**: 서버 저장이 실패하면 2초 → 4초 → 8초 … 최대 60초 간격에 무작위 지연을 섞어 다시 시도해야 하며, 그동안 내용은 기기에
  남아 있어야 한다. 연결이 돌아오면 자동으로 동기화해야 한다.
- **FR-006**: 미전송 내용이 있는데 페이지를 떠나려 하면 확인창을 띄워야 한다.

**저장 상태 표시 (docs/04 §2-2)**

- **FR-007**: 저장 상태를 색만이 아니라 글자로도 구분해 보여줘야 한다: "✓ 저장됨 14:03"(서버 반영), "● 이 기기에 저장됨 (동기화
  대기)"(기기에만 있음), "⚠ 오프라인 — 이 기기에 저장 중, 연결되면 자동 동기화"(오프라인), "⚠ 다른 곳에서 수정됨 — 이 기기에만
  저장 중 [비교하기]"(충돌).

**다시 열기·지우기 (docs/04 §2-2·§2-7)**

- **FR-008**: 에디터를 열 때 기기 데이터와 서버 내용을 비교해야 한다. 미전송 내용이 있고 출발 버전이 서버 버전과 같으면 충돌이 아니므로
  기기 내용을 불러와 "이 기기에 저장되지 않은 변경을 불러왔어요"를 안내하고, 출발 버전이 다르면 바로 비교 창을 띄워야 한다.
- **FR-009**: 그 글의 기기 데이터는 발행이 성공했을 때, 또는 미전송 내용이 없는 상태로 에디터를 떠날 때 지워야 한다.

**충돌 중 기기 보존 (docs/04 §2-7)**

- **FR-010**: 자동 저장이 편집 버전 충돌로 거절되면 편집을 막거나 창을 띄우지 않고, 서버 전송만 멈춘 채 기기에는 계속 저장하며 에디터
  위에 배너("⚠ 다른 탭이나 기기에서 이 글이 수정되었어요(시각). 지금 내용은 이 기기에만 저장되고 있어요. [비교하기]")를 보여줘야 한다.
- **FR-011**: [비교하기]를 누르거나 충돌 상태에서 [저장]·[발행]을 누르면 002의 비교 창을 띄워야 한다. 비교 창을 닫으면 편집은 계속되고
  서버 전송은 멈춘 채 배너가 남아야 한다.
- **FR-012**: [저장된 내용 불러오기]를 고르면 편집 중이던 내용을 그 기기에 7일 동안 백업하고 "편집 중인 내용은 이 기기에 7일 동안
  백업돼요."를 안내해야 한다. 7일이 지난 백업은 지워야 한다.
- **FR-013**: 어떤 경우에도 서버나 기기가 작성자 모르게 한쪽 내용을 덮어쓰지 않아야 한다.

**사진 업로드 대기열 (docs/04 §4-3, 009와 연결)**

- **FR-014**: 오프라인이거나 업로드에 실패한 사진은 원본을 기기 대기열에 저장하고, 본문에는 "업로드 대기" 임시 표시를 넣으며, 화면에는
  기기에 있는 사진으로 정상 표시해야 한다.
- **FR-015**: 연결되면 대기 사진을 자동으로 다시 올리고, 성공하면 본문의 임시 표시를 진짜 사진 주소로 바꿔야 한다.
- **FR-016**: 임시 표시가 있어도 자동 저장은 해야 하지만, 임시 표시가 남은 글의 발행은 거부해야 한다(다른 사람은 볼 수 없는 주소가
  공개 글에 들어가지 않게).

**로그아웃·권한 (docs/04 §2-2·§6-2 결정 4, docs/07 §7, docs/42 §5-2)**

- **FR-017**: 로그아웃하면 그 사용자의 기기 작성 데이터·충돌 백업·사진 대기열을 모두 지워야 한다.
- **FR-018**: 기기에서 서버로 보내는 모든 저장은 002와 같은 권한 검사(로그인, 이메일 인증, 작성자 본인, 휴지통 글 아님)를 서버에서
  매번 거쳐야 하며, 기기 데이터가 있다는 사실만으로 저장이 허용되지 않아야 한다.

### Key Entities *(include if feature involves data)*

- **기기 작성 데이터**: 회원·글별 하나. 제목, 본문, 출발 서버 편집 버전, 미전송 여부, 업로드 대기 사진 목록, 저장 일자. 그 브라우저에만
  있다.
- **충돌 백업**: 회원·글별, [저장된 내용 불러오기] 때 편집 중이던 제목·본문. 7일 보관.
- **업로드 대기 사진**: 기기에 있는 사진 원본과 본문 임시 표시의 짝.
- **글(Post)·작업본(PostDraft)**: 002에서 정의. 편집 버전으로 기기 내용과 서버 내용의 출발점을 비교한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 10분 동안 오프라인으로 쓴 내용이 연결 후 서버에 100% 반영된다(잃는 글자 0).
- **SC-002**: 오프라인에서 창을 닫았다가 같은 기기에서 다시 열면 마지막 1초 이전까지 입력한 내용이 모두 복구된다.
- **SC-003**: 브라우저 데이터를 지워도 잃는 내용은 마지막 30초 이내 입력뿐이다.
- **SC-004**: 충돌 상황에서 작성자가 고른 경우를 빼고 어느 쪽 내용도 사라지는 경우가 0건이고, [저장된 내용 불러오기] 뒤 7일 동안
  편집 중이던 내용을 되찾을 수 있다.
- **SC-005**: 로그아웃 뒤 그 브라우저에 그 사용자의 작성 데이터·백업·대기 사진이 0건 남는다.
- **SC-006**: 임시 사진 표시가 남은 글이 발행되는 경우가 0건이다.
- **SC-007**: docs/04 §2-6 실패 상황 표(네트워크 끊김·브라우저 데이터 삭제·여러 탭 편집)와 docs/07 §9의 2(로그아웃 시 임시 데이터
  삭제)가 자동 테스트로 확인된다.

## Assumptions

- **A-1**: 서버 자동 저장(3초·최대 30초·1분 반영), 수동 저장, 편집 버전 확인, 비교 창과 세 버튼은 002가 이미 제공하며 이 spec은 그
  위에 기기 저장·복구·백업·대기열을 더한다.
- **A-2**: 사진 업로드 대기열은 사진 업로드(`009-image-upload`, Tier B)와 연결된다. 009 전에는 대기열의 동작 규칙만 정해 두고, 업로드·발행 거부의
  실제 검증은 009와 함께 완성한다.
- **A-3**: 저장 간격(1초·재시도 최대 60초·백업 7일)은 설정으로 바꿀 수 있는 초기값이다.
- **A-4**: 기기 저장 공간이 모자랄 때의 처리는 문서에 정해져 있지 않다. 저장에 실패하면 서버 자동 저장으로 계속하고 상태를 알린다고 본다.
- **A-5**: 오프라인 동안 그 글이 다른 곳에서 휴지통으로 옮겨진 경우는 문서에 정해져 있지 않다. 기기 내용은 지우지 않고 작성자에게 알린다고
  본다.
- **A-6**: 기기 저장소를 쓸 수 없는 브라우저 환경에서는 002의 서버 자동 저장만으로 동작한다.
