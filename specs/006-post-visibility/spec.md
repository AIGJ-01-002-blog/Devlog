## User Scenarios & Testing *(mandatory)*

### User Story 1 - 나만 보는 글은 밖으로 새지 않는다 (Priority: P1)

작성자는 회고나 메모처럼 남에게 보이고 싶지 않은 글을 "나만 보기"로 발행한다. 그 글은 작성자 본인만 상세로 볼 수 있고, 다른 사람에게는 없는 글과 똑같이 보이며, 홈·블로그·태그·검색·sitemap·글 수 어디에도 드러나지 않는다.

**Why this priority**: 이 기능의 핵심 목표("친구나 나만 보려고 쓴 글이 밖으로 새지 않는다") 그 자체다. 이것이 깨지면 공개 범위 선택이 의미가 없다.

**Independent Test**: 나만 보기 글 하나와 전체 공개 글 하나를 만든 뒤, 비회원·다른 회원·작성자·관리자로 상세와 모든 노출 위치를 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 작성자가 나만 보기로 발행한 글, **When** 작성자가 상세를 열면, **Then** 글이 보이고 "나만 볼 수 있는 글" 표시가 함께 보인다.
2. **Given** 같은 글, **When** 비회원·다른 회원·관리자가 상세 주소를 열면, **Then** "찾을 수 없음(404와 같은 응답)"을 받고, 그 응답(상태·본문·링크 미리보기 문구)은 존재하지 않는 글 번호를 열었을 때와 완전히 같다.
3. **Given** 나만 보기 글, **When** 다른 사람이 홈 최신 글·인기 글·그 작성자의 블로그·태그별 목록·검색·sitemap을 보면, **Then** 그 글은 어디에도 나오지 않고 블로그 글 수·태그 글 수에도 세지 않는다.
4. **Given** 나만 보기 글, **When** 작성자 본인이 자기 블로그 페이지를 보면, **Then** 그 글은 블로그 목록에 나오지 않고 내 글 관리에서만 보인다.
5. **Given** 나만 보기 글의 주소, **When** 메신저·SNS가 링크 미리보기를 가져가면, **Then** 제목·요약·썸네일 대신 "볼 수 없는 글이에요" 공통 문구가 나오고 검색 엔진 수집 제외 표시가 붙는다.
6. **Given** 나만 보기 글에 이미 달린 댓글·좋아요, **When** 다른 사람이 그 댓글·좋아요를 보거나 새로 쓰려고 하면, **Then** 글과 같은 "찾을 수 없음" 응답을 받는다.

### User Story 2 - 발행된 글의 공개 범위를 바로 바꾼다 (Priority: P1)

작성자는 이미 발행한 글을 다시 발행하지 않고 공개 ↔ 비공개로 즉시 바꾼다. 바꾸어도 내용·수정됨 표시·수정 중 작업본·댓글·좋아요는 그대로이고, 목록 위치는 처음 공개된 시점에 고정된다.

**Why this priority**: 공개 범위는 "언제든 다시 바꿀 수 있다"는 전제로 설계됐다. 바꾸는 행동이 다른 데이터를 망가뜨리면 사용자는 공개 범위를 믿고 쓸 수 없다.

**Independent Test**: 댓글·좋아요가 있는 공개 글을 비공개 → 공개로 바꾸면서 각 단계의 상세·목록·반응 수·수정됨 표시·목록 위치를 비교하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 작성자의 전체 공개 글, **When** 나만 보기로 바꾸면, **Then** 다시 발행 없이 즉시 적용되고 "수정됨" 표시는 생기지 않는다.
2. **Given** 수정 중인 작업본이 있는 발행 글, **When** 공개 범위를 바꾸면, **Then** 작업본은 그대로 남고 변경도 성공한다.
3. **Given** 댓글 3개·좋아요 5개가 있는 공개 글, **When** 비공개로 바꿨다가 다시 공개로 바꾸면, **Then** 댓글·좋아요는 지워지지 않고 다시 모두 보인다.
4. **Given** 공개로 처음 발행된 뒤 비공개 → 공개로 바뀐 글, **When** 홈 목록을 보면, **Then** 처음 공개된 시점의 위치에 그대로 있고 맨 위로 올라오지 않는다.
5. **Given** 나만 보기로 발행해 한 번도 공개된 적 없는 글, **When** 처음으로 전체 공개로 바꾸면, **Then** 그 순간이 최초 공개 시점이 되어 홈·블로그 목록 맨 위에 나온다.
6. **Given** 현재와 같은 값, **When** 같은 공개 범위로 다시 바꾸면, **Then** 아무것도 바뀌지 않고 성공으로 응답한다.
7. **Given** 다른 사람의 글·없는 글·휴지통 글, **When** 공개 범위 변경을 요청하면, **Then** "찾을 수 없음" 응답을 받고 글은 바뀌지 않는다.
8. **Given** 임시글, **When** 공개 범위를 바꾸면, **Then** 값만 저장되어 발행할 때 그 공개 범위가 쓰인다(임시글은 여전히 작성자만 본다).

---

### User Story 3 - 새 글은 내 기본 공개 범위로 시작한다 (Priority: P2)

회원은 설정에서 "새 글 기본 공개 범위"를 정해 두고, 새 글은 그 값으로 시작한다. 발행 설정에서 글마다 바꿀 수 있다.

**Why this priority**: 매번 공개 범위를 바꾸는 수고를 줄이지만, 없어도 글마다 고를 수 있으므로 P1보다 낮다.

**Independent Test**: 기본값을 나만 보기로 바꾼 뒤 새 글을 만들어 초기 공개 범위를 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 기본 공개 범위를 바꾼 적이 없는 회원, **When** 새 글을 만들면, **Then** 공개 범위는 전체 공개로 시작한다.
2. **Given** 기본 공개 범위를 나만 보기로 바꾼 회원, **When** 새 글을 만들면, **Then** 공개 범위는 나만 보기로 시작하고 발행 설정에서 전체 공개로 바꿀 수 있다.
3. **Given** 다른 회원, **When** 남의 기본 공개 범위를 바꾸려 하면, **Then** 그런 경로가 없다(본인 설정 화면에서만 바꾼다).

---

### User Story 4 - 친구 공개 (선택 구현 규격) (Priority: P3)

친구 공개(FRIENDS)를 켠 팀원의 서비스에서는, 작성자와 상호 수락된 친구만 그 글을 본다. 켜지 않은 서비스에서는 이 값을 받지 않는다.

**Why this priority**: 공통 범위는 PUBLIC·PRIVATE이고 FRIENDS는 선택 구현이다. 다만 구현하는 사람끼리는 같은 규칙을 따라야 비교할 수 있으므로 규격을 함께 둔다.

**Independent Test**: 친구 공개를 켠 환경에서 작성자·수락된 친구·친구 아닌 회원·비회원으로 상세와 블로그 목록을 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 친구 공개를 켜지 않은 서비스, **When** 공개 범위를 친구 공개로 요청하면, **Then** 잘못된 공개 범위라는 검증 오류를 받는다.
2. **Given** 친구 공개를 켠 서비스의 친구 공개 글, **When** 수락된 친구가 상세·작성자 블로그를 보면, **Then** 글이 보이고 블로그 목록·글 수에 포함된다.
3. **Given** 같은 글, **When** 친구가 아닌 회원·비회원이 보면, **Then** "찾을 수 없음"이고 홈·태그·검색·sitemap에는 친구에게도 나오지 않는다.
4. **Given** 친구 관계를 끊은 직후, **When** 끊긴 상대가 그 글을 열면, **Then** 즉시 "찾을 수 없음"이고 블로그 목록에서도 사라진다.
5. **Given** 기본 공개 범위가 친구 공개인데 친구가 없는 작성자, **When** 발행 설정을 열면, **Then** "아직 친구가 없어서 지금은 나만 볼 수 있어요"와 친구 초대·전체 공개로 바꾸기 안내가 보인다.

---

### Edge Cases

- 휴지통에 있는 글은 공개 범위와 상관없이 작성자에게도 상세가 "찾을 수 없음"이고, 공개 범위 변경도 "찾을 수 없음"이다.
- 관리자가 숨긴 글, 작성자가 탈퇴 유예 중인 글은 공개 범위가 전체 공개여도 다른 사람의 모든 목록·상세에서 빠진다(공용 노출 조건에 함께 포함).
- 관리자(운영자)도 남의 나만 보기·친구 공개 글을 볼 수 없다.
- 볼 수 없는 글의 사진 파일은 주소를 알면 열린다(기존 결정, 친구 공개 도입 시 재검토 대상).
- 공개 범위 변경과 다른 요청이 동시에 들어와도 최초 공개 시점은 한 번만 기록된다.
- 이미 화면에 떠 있던 카드의 글이 비공개로 바뀐 뒤 누르면 "찾을 수 없음"이다.
- 친구 공개 → 전체 공개로 바뀌면 그 순간이 최초 공개 시점이 된다(친구 공개 글은 최초 공개 시점이 없다).
- 공개가 아닌 글의 응답은 공유 캐시에 저장되지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 글마다 공개 범위를 전체 공개(PUBLIC) 또는 나만 보기(PRIVATE) 중 하나로 저장해야 한다. 친구 공개(FRIENDS)는 선택 구현이며, 켜지 않은 서비스는 이 값을 검증 오류로 거절해야 한다.
- **FR-002**: System MUST 공개 범위를 발행된 글에만 적용하고, 임시글은 공개 범위와 상관없이 작성자만 보게 해야 한다(임시글의 값은 발행 때 쓸 공개 범위).
- **FR-003**: System MUST 글 하나를 읽을 수 있는지를 하나의 공통 판정으로만 결정하고, 그 판정은 삭제 여부 → 숨김 → 작성자 탈퇴 유예 → 상태·공개 범위 순으로 확인해야 한다.
- **FR-004**: System MUST 모든 공개 목록(홈 최신 글·인기 글·개인 블로그·태그·검색·sitemap·RSS·AI 추천·관련 글)과 글 수 집계에 하나의 공통 노출 조건(발행 + 전체 공개 + 미삭제 + 미숨김 + 작성자 미탈퇴)만 사용해야 한다.
- **FR-005**: System MUST 나만 보기 글의 상세를 작성자에게만 보여 주고, 그 외 모든 사람(관리자 포함)에게는 "찾을 수 없음"으로 응답해야 한다.
- **FR-006**: System MUST 볼 수 없는 글과 존재하지 않는 글에 대해 응답 상태·본문·링크 미리보기 문구("볼 수 없는 글이에요" / "친구 공개·비공개 글이거나 삭제된 글입니다.")와 검색 엔진 수집 제외 표시를 똑같이 내보내야 한다.
- **FR-007**: System MUST 작성자 본인의 블로그 페이지에서도 나만 보기 글을 표시하지 않고, 내 글 관리에서만 공개 범위 배지와 함께 보여야 한다.
- **FR-008**: Users MUST be able to 다시 발행하지 않고 자신의 글 공개 범위를 즉시 바꿀 수 있어야 하며, 수정 중 작업본이 있어도 변경이 가능해야 한다.
- **FR-009**: System MUST 공개 범위 변경 시 "수정됨" 표시(재발행 일자), 작업본, 편집 버전, 댓글, 좋아요를 바꾸거나 지우지 않아야 한다.
- **FR-010**: System MUST 볼 수 없게 된 글의 댓글·좋아요를 그 글을 읽을 수 없는 사람에게 함께 숨기고, 다시 공개되면 그대로 되돌려 보여야 한다.
- **FR-011**: System MUST 최초 공개 시점을 "발행 상태이면서 전체 공개가 된 첫 순간"에만 기록하고, 이후 공개 범위를 껐다 켜도 처음 값을 유지해야 한다.
- **FR-012**: System MUST 남의 글·없는 글·휴지통 글에 대한 공개 범위 변경 요청을 "찾을 수 없음"으로 거절하고 글을 바꾸지 않아야 한다.
- **FR-013**: System MUST 같은 공개 범위로 다시 요청하면 아무 값도 바꾸지 않고 성공으로 응답해야 한다.
- **FR-014**: System MUST 동시에 들어온 공개 범위 변경이 서로 덮어써 최초 공개 시점이 잘못 기록되지 않도록 한 글의 변경을 차례로 처리해야 한다.
- **FR-015**: System MUST 공개 범위 변경이 확정된 뒤 다른 기능(검색 색인·sitemap 갱신·알림 등)이 반응할 수 있도록 "공개 범위가 바뀜" 사건(이전 값, 새 값)을 알려야 하며, 그 후속 처리가 실패해도 변경 자체는 성공해야 한다.
- **FR-016**: System MUST 회원마다 "새 글 기본 공개 범위"(초기값 전체 공개)를 두고, 새 글을 만들 때 그 값으로 시작해야 한다. 이 설정은 본인만 바꿀 수 있다.
- **FR-017**: System MUST 전체 공개가 아닌 글의 응답을 공유 캐시에 저장되지 않게 표시하고, 검색 엔진 수집 대상과 sitemap에서 제외해야 한다.
- **FR-018**: System MUST 전체 공개 글의 링크 미리보기에는 제목·요약·썸네일을, 그 밖의 글에는 FR-006의 공통 문구만 내보내야 한다.
- **FR-019**: (친구 공개 적용 시) System MUST 친구 공개 글을 작성자와 상호 수락된 친구에게만 상세·개인 블로그 목록·블로그 글 수로 노출하고, 홈·인기·태그·검색·sitemap에는 친구에게도 노출하지 않아야 한다. 친구가 보는 블로그 목록은 발행 일자 최신순으로 정렬한다.
- **FR-020**: (친구 공개 적용 시) System MUST 친구 관계가 끊기는 즉시 상대가 친구 공개 글을 볼 수 없게 하고, 기본값이 친구 공개인데 친구가 없는 작성자에게 발행 설정에서 안내를 보여야 한다.
- **FR-021**: System MUST 화면에서 버튼을 숨기는 것과 별개로, 모든 읽기·변경 요청에서 서버가 공개 범위 권한을 판정해야 한다.

### Key Entities *(include if feature involves data)*

- **글 (post)**: 공개 범위, 상태(임시·발행), 삭제 여부, 숨김 여부, 최초 발행 일자, 최초 공개 일자, 재발행 일자(수정됨 표시)를 가진다. 공개 범위는 상태·삭제와 별개로 저장되어 복구·재공개 시 그대로 돌아온다.
- **회원 (member)**: 새 글 기본 공개 범위 설정, 탈퇴 유예 여부를 가진다.
- **친구 관계 (friendship)**: 두 회원 사이의 상호 친구 관계(요청·수락). 한 쌍에 하나만 존재한다. 공통 데이터 구조에 포함되며, 친구 공개 범위 판정에만 이 spec에서 사용한다.
- **공개 범위 변경 사건**: 어떤 글의 공개 범위가 이전 값에서 새 값으로 바뀌었다는 기록. 후속 기능이 구독한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 공개 범위(전체 공개·나만 보기, 적용 시 친구 공개) × 보는 사람(비회원·다른 회원·친구·작성자·관리자) × 노출 위치(상세·홈·블로그 목록·블로그 글 수·태그·검색·sitemap·댓글)의 모든 조합 자동 테스트가 100% 통과한다.
- **SC-002**: 나만 보기 글은 작성자 외 모든 사람에게 상세가 "찾을 수 없음"이며, 노출 위치 전수 점검에서 노출 0건, 글 수 반영 0건이다.
- **SC-003**: 볼 수 없는 글과 없는 글의 응답(상태·본문·링크 미리보기)을 비교했을 때 차이가 0건이다.
- **SC-004**: 공개 범위를 바꾼 전후로 수정됨 표시·작업본·댓글 수·좋아요 수가 100% 같다.
- **SC-005**: 공개 → 비공개 → 공개를 반복해도 최초 공개 시점과 목록 위치가 처음 값과 같다.
- **SC-006**: 비공개로 바꾼 직후 그 글의 댓글·좋아요가 다른 사람에게 보이는 경우가 0건이다.
- **SC-007**: 새 글 100%가 작성자의 기본 공개 범위로 시작한다.
- **SC-008**: 작성자는 공개 범위 변경을 한 번의 선택으로 끝내고, 결과가 즉시(새로 고침 없이 다음 요청부터) 모든 노출 위치에 반영된다.

## Assumptions

- 공통 구현 범위는 전체 공개·나만 보기다. 친구 공개는 선택 구현이며, 적용하는 사람만 공개 범위 허용 값 확장과 친구 블로그 목록용 색인을 추가한다(세부는 근거 문서 §6).
- 친구 요청·수락·끊기 기능 자체는 공통이지만 이 spec 범위가 아니다(017-follow-friend-feed에서 다룬다). 이 spec은 친구 관계를 읽기 판정에만 쓴다.
- 발행 흐름과 최초 공개 시점 기록 규칙은 005-post-publish와 공유한다. 이 spec은 공개 범위만 바꾸는 경로를 정의한다.
- 휴지통·복구는 007-post-delete-trash, 목록 화면은 008-post-list, 상세 화면은 009-post-detail, 내 글 관리와 권한 매트릭스는 010-manage-posts에서 다룬다.
- 관리자 숨김의 세부 정책은 신고·숨김 spec(020-report-hide)을 따른다. 이 spec은 숨긴 글이 공용 노출 조건에서 빠진다는 점만 전제한다.
- 비공개 글에 쓰인 사진 파일은 주소를 알면 열린다는 기존 결정을 유지한다.
- 그룹 공개·링크 공개, 여러 글 공개 범위 일괄 변경, 첫 공개 응원 알림은 개인 확장으로 범위 밖이다.
- 비공개·친구 공개 글의 외부 AI 전송 여부는 019-ai-tag-suggest의 미결 항목으로 남기며 여기서 정하지 않는다.
