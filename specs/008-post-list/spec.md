## User Scenarios & Testing *(mandatory)*

### User Story 1 - 홈에서 최신 공개 글을 훑어본다 (Priority: P1)

누구나(비회원 포함) 홈에 들어오면 처음 공개된 시점이 최근인 공개 글 9개를 카드로 본다. 카드에는 썸네일, 제목 1줄, 본문 미리보기 3줄, 발행 날짜·댓글 수, 작성자·좋아요 수가 있다.

**Why this priority**: 서비스에 들어온 사람이 가장 먼저 보는 화면이고, 글을 발견하는 기본 경로다.

**Independent Test**: 공개·비공개·임시·휴지통·숨김·탈퇴 유예 작성자의 글을 섞어 만든 뒤 홈 첫 화면의 글과 순서를 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 다양한 상태의 글, **When** 홈을 열면, **Then** 발행 + 전체 공개 + 미삭제 + 미숨김 + 작성자 미탈퇴인 글만 최초 공개 시점 최신순(같으면 글 번호 큰 순)으로 9개 보인다.
2. **Given** 비공개로 발행했다가 나중에 처음 공개한 글, **When** 홈을 열면, **Then** 처음 공개한 시점의 위치에 나온다(최초 발행 시점 기준으로 묻히지 않는다).
3. **Given** 공개 글 카드, **When** 카드를 보면, **Then** 썸네일, 제목 1줄(넘치면 말줄임), 본문 미리보기 3줄, 발행 날짜, 댓글 수, 작성자 사진·닉네임, 좋아요 수가 보이고, 댓글·좋아요가 0이어도 숫자가 표시된다.
4. **Given** 썸네일이 없는 글과 있는 글, 미리보기가 짧은 글과 긴 글, **When** 카드를 나란히 보면, **Then** 같은 줄의 카드 높이가 같다(빈 썸네일 자리와 3줄 높이가 항상 확보된다).
5. **Given** 24시간 안에 공개된 글과 그 이전 글, **When** 날짜를 보면, **Then** 1시간 이내는 "N분 전", 24시간 이내는 "N시간 전", 그 이후는 "2026.10.02" 형식이다.
6. **Given** 카드, **When** 카드를 누르면 글 상세로, 작성자 영역을 누르면 작성자 블로그로 이동하고, 키보드만으로도 두 링크에 각각 갈 수 있다.
7. **Given** 공개 글이 하나도 없는 서비스, **When** 홈을 열면, **Then** "아직 올라온 글이 없어요. 첫 글의 주인공이 되어 보세요"와 [글쓰기](비회원은 [로그인])가 보인다.

### User Story 2 - [더 보기]로 이어서 본다 (Priority: P1)

독자는 [더 보기]를 눌러 바로 앞 글보다 이전 글 9개를 아래에 이어 붙인다. 더 볼 글이 없으면 버튼이 사라진다. 보는 도중 새 글이 올라오거나 글이 삭제·비공개되어도 같은 글이 두 번 나오거나 빠지지 않는다.

**Why this priority**: 9개 이후의 글에 닿는 유일한 방법이며, 중복·누락은 목록 신뢰를 무너뜨린다.

**Independent Test**: 공개 글 20개를 만든 뒤 [더 보기]를 두 번 누르면서, 중간에 새 글 발행·기존 글 삭제·비공개 전환을 섞어 결과 목록의 중복·누락을 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 공개 글 20개, **When** 홈에서 [더 보기]를 두 번 누르면, **Then** 9·9·2개가 순서대로 이어 붙고, 마지막 2개를 받은 뒤 버튼이 사라지며 "모든 글을 다 봤어요"가 보인다.
2. **Given** 공개 글이 정확히 9개, **When** 홈을 열면, **Then** 처음부터 [더 보기]가 없다(누르면 빈 결과가 오는 버튼이 없다).
3. **Given** 첫 9개를 본 상태, **When** 새 글이 발행된 뒤 [더 보기]를 누르면, **Then** 새 글은 이어 붙는 목록에 끼어들지 않고, 새로 고치면 맨 위에 보인다.
4. **Given** 첫 9개를 본 상태, **When** 그중 한 글이나 아직 안 본 글이 삭제·비공개된 뒤 [더 보기]를 누르면, **Then** 다음 글이 빠지거나 앞 글이 다시 나오지 않는다.
5. **Given** [더 보기] 요청이 실패, **When** 화면을 보면, **Then** "불러오지 못했어요 [다시 시도]"가 보이고 다시 시도하면 같은 위치부터 이어 받는다. 불러오는 동안 버튼은 "불러오는 중…"으로 비활성화된다.
6. **Given** [더 보기]를 여러 번 누른 뒤 글을 열었다가, **When** 30분 안에 뒤로 가기로 돌아오면, **Then** 불러온 카드와 스크롤 위치가 복원된다. 30분이 지났거나 보관값이 없으면 처음 9개부터 보인다.
7. **Given** 위조되거나 손상된 이어 보기 위치 값, **When** 목록을 요청하면, **Then** 잘못된 요청이라는 검증 오류를 받는다.
8. **Given** 클라이언트가 한 번에 9개보다 많이(또는 적게) 요청, **When** 목록을 받으면, **Then** 항상 9개 단위로 받는다.

### User Story 3 - 한 사람의 블로그를 본다 (Priority: P1)

누구나 `/@블로그주소`에 들어오면 상단에 그 사람의 프로필(사진·닉네임·@블로그주소·소개·공개 글 수)이 있고, 아래에 그 사람의 공개 글이 홈과 같은 카드(작성자 영역 생략)·정렬·9개·[더 보기]로 보인다.

**Why this priority**: 1인 1블로그 서비스에서 개인 블로그는 작성자의 대표 화면이다.

**Independent Test**: 한 회원의 공개·비공개·임시·휴지통 글을 만든 뒤 비회원과 본인으로 그 블로그를 열어 목록·글 수를 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 회원의 여러 상태 글, **When** 누구든 그 블로그를 열면, **Then** 그 사람의 공개·발행 글만 홈과 같은 정렬·9개·[더 보기]로 보이고, 카드에 작성자 영역은 없다.
2. **Given** 같은 블로그, **When** 상단을 보면, **Then** 프로필 사진(없으면 기본 아이콘)·닉네임·@블로그주소·소개·보는 사람 기준 공개 글 수가 보인다.
3. **Given** 작성자 본인, **When** 자기 블로그를 열면, **Then** 비공개 글은 목록에도 글 수에도 나오지 않는다(내 글 관리에서만 보인다).
4. **Given** 공개 글이 없는 블로그, **When** 남이 보면 "아직 공개한 글이 없어요", 본인이 보면 "첫 글을 써 보세요 [글쓰기]"가 보인다.
5. **Given** 없는 블로그 주소, 탈퇴 유예·익명 처리된 회원의 블로그 주소, **When** 열면, **Then** "찾을 수 없음"이다.
6. **Given** 대문자가 섞인 블로그 주소, **When** 열면, **Then** 소문자 주소로 영구 이동된다.

### User Story 4 - 가벼운 카드로 빠르게 본다 (Priority: P2)

모바일 독자도 목록을 빠르게 본다. 카드는 원본 사진이 아니라 작은 썸네일을 쓰고, 화면에 들어올 때 불러온다. 목록 한 번에 필요한 정보만 한 번에 가져온다.

**Why this priority**: 체감 속도·데이터 사용량 문제이며, 기능 자체(P1) 다음 순위다.

**Independent Test**: 썸네일이 있는 공개 글 9개 목록을 모바일 폭에서 불러와 전송량·요청 횟수·응답 시간을 측정하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 사진이 있는 글, **When** 카드에 썸네일이 표시되면, **Then** 본문 첫 번째로 올린 사진의 가로 640px 이하 썸네일이 쓰이고(썸네일이 없는 옛 사진은 원본), 화면 밖 카드는 화면에 들어올 때 불러온다.
2. **Given** 목록 요청 한 번, **When** 서버가 처리하면, **Then** 글과 작성자 정보를 한 번에 가져오고 본문 전체는 읽지 않는다.
3. **Given** 375px 모바일부터 데스크톱까지, **When** 목록을 보면, **Then** 페이지에 가로 스크롤이 생기지 않는다.

---

### Edge Cases

- 본문이 코드 블록·사진·표로만 이루어져 미리보기 요약이 비어 있으면 빈 3줄 높이를 유지한다.
- 미리보기 요약은 코드 블록·사진·표·수식을 빼고 글자만 앞 200자로 만들고, 단어 중간에서 잘리면 그 단어 앞에서 자른다.
- 글이 수정(재발행)돼도 최초 공개 시점은 바뀌지 않으므로 목록 순서가 바뀌지 않는다.
- 관리자가 숨긴 글, 작성자가 탈퇴 유예 중인 글은 공개 상태여도 홈·블로그 목록과 글 수에서 빠진다.
- 이미 화면에 있는 카드의 글이 삭제·비공개되면 카드는 남고 누르면 "찾을 수 없음"이다. 이어 붙일 때 이미 화면에 있는 글 번호는 건너뛴다(이중 안전장치).
- 같은 시각에 공개된 글이 여럿이면 글 번호 큰 순으로 고정된다.
- 친구 공개를 적용한 서비스에서 친구가 블로그를 보면 친구 공개 글도 포함되고 발행 일자 최신순으로 정렬된다(006 규격).
- 목록을 불러오지 못하면 "글을 불러오지 못했어요 [다시 시도]"를 보여 준다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 홈 목록에 공통 공개 노출 조건(발행 + 전체 공개 + 미삭제 + 미숨김 + 작성자 미탈퇴)을 만족하는 글만 보여야 한다.
- **FR-002**: System MUST 홈·블로그 목록을 최초 공개 시점 최신순, 같으면 글 번호 큰 순으로 정렬해야 하며, 카드의 발행 날짜도 같은 최초 공개 시점을 써야 한다.
- **FR-003**: System MUST 목록을 한 번에 9개씩 제공하고, 클라이언트가 요청한 개수와 상관없이 9개로 고정해야 한다.
- **FR-004**: System MUST 다음 글이 있는지 미리 판단해, 다음 글이 없으면 [더 보기]를 보이지 않고 "모든 글을 다 봤어요"를 보여야 한다. 빈 결과를 받는 [더 보기] 클릭이 없어야 한다.
- **FR-005**: System MUST [더 보기]를 "마지막으로 받은 글의 정렬 값" 기준 이어 보기로 제공해, 보는 도중 새 글 발행·삭제·비공개 전환이 있어도 이어 붙인 목록에 중복·누락이 없어야 한다.
- **FR-006**: System MUST 이어 보기 위치 값을 사용자가 해석할 수 없는 형태로 주고, 손상·위조된 값은 검증 오류로 거절해야 한다.
- **FR-007**: System MUST 카드마다 썸네일, 제목(1줄), 본문 미리보기(3줄), 발행 날짜, 댓글 수, 작성자 사진·닉네임, 좋아요 수를 보여야 하며, 조회수는 카드에 넣지 않는다. 댓글·좋아요 수는 0이어도 표시한다.
- **FR-008**: System MUST 썸네일이 없거나 미리보기가 짧아도 같은 줄 카드의 높이를 같게 유지해야 한다(빈 썸네일 자리, 3줄 높이 확보).
- **FR-009**: System MUST 미리보기 요약을 코드 블록·사진·표·수식을 뺀 글자 앞 200자로 만들고 단어 중간에서 자르지 않아야 한다.
- **FR-010**: System MUST 날짜를 1시간 이내 "N분 전", 24시간 이내 "N시간 전", 그 이후 "YYYY.MM.DD"로 표시하고 원래 시각도 기계가 읽을 수 있게 함께 넣어야 한다.
- **FR-011**: System MUST 카드 전체는 글 상세로, 작성자 영역은 작성자 블로그로 연결하고, 두 링크 모두 키보드로 접근 가능해야 한다.
- **FR-012**: System MUST 카드 썸네일로 본문 첫 번째 업로드 사진의 가로 640px 이하 썸네일을 쓰고(없는 옛 사진은 원본), 화면에 들어올 때 불러오며, 대체 텍스트로 제목을 넣어야 한다.
- **FR-013**: System MUST 사진을 올릴 때 원본과 함께 640px 썸네일을 만들어 저장하는 공통 데이터 규칙을 따라야 한다(썸네일 생성은 공통, 표시 비율·빈 색은 개인 선택).
- **FR-014**: System MUST 개인 블로그 페이지 상단에 프로필 사진·닉네임·@블로그주소·소개·보는 사람 기준 공개 글 수를 보여야 한다.
- **FR-015**: System MUST 개인 블로그 목록에 그 사람의 공개·발행 글만 홈과 같은 카드(작성자 영역 제외)·정렬·개수·[더 보기]로 보여야 하며, 작성자 본인이 보더라도 비공개 글을 보이지 않아야 한다.
- **FR-016**: System MUST 없는 블로그 주소와 탈퇴 유예·익명 처리된 회원의 블로그 주소에 "찾을 수 없음"을 응답하고, 대문자가 섞인 주소는 소문자 주소로 영구 이동시켜야 한다.
- **FR-017**: System MUST 홈·블로그의 빈 상태, 로딩 중, 불러오기 실패와 다시 시도 상태를 각각 정해진 문구로 보여야 한다(홈 빈 상태 비회원은 [로그인], 블로그 빈 상태 본인은 [글쓰기]).
- **FR-018**: System MUST 뒤로 가기로 목록에 돌아오면 30분 이내에 한해 불러온 카드·이어 보기 위치·스크롤 위치를 복원해야 한다.
- **FR-019**: System MUST 목록 한 번을 한 번의 데이터 조회로 처리하고(작성자 정보 포함, 반응 수는 미리 저장된 값 사용), 본문 전체를 읽지 않아야 한다.
- **FR-020**: System MUST 375px 모바일부터 데스크톱까지 페이지 가로 스크롤 없이 목록을 보여야 한다. 한 줄에 놓는 카드 개수·썸네일 비율·색은 각 서비스가 정한다.
- **FR-021**: System MUST 블로그 주소·홈 페이지 응답에 링크 미리보기 정보와 올바른 "찾을 수 없음" 상태를 서버가 직접 넣어야 한다.

### Key Entities *(include if feature involves data)*

- **글 카드**: 글 번호, 글 주소, 제목, 요약(200자), 썸네일 주소, 최초 공개 시점, 댓글 수, 좋아요 수, 작성자(블로그 주소·닉네임·프로필 사진). 글(post)과 회원(member)·사진(image)에서 온다.
- **이어 보기 위치**: 마지막 카드의 (최초 공개 시점, 글 번호)를 감싼 불투명 값.
- **블로그 프로필**: 회원의 사진·닉네임·블로그 주소·소개와 보는 사람 기준 공개 글 수.
- **썸네일**: 업로드된 사진마다 원본과 별도로 저장되는 가로 640px 이하 사본.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 상태가 섞인 테스트 데이터에서 홈·블로그 목록에 공통 노출 조건을 어긴 글이 0건이고, 순서가 최초 공개 시점·글 번호 기준과 100% 일치한다.
- **SC-002**: 공개 글 N개에 대해 [더 보기]를 끝까지 눌렀을 때 받은 글이 정확히 N개이며 빈 결과를 받는 클릭이 0회다.
- **SC-003**: 보는 도중 새 글 발행·삭제·비공개 전환을 섞어도 이어 붙인 목록의 중복·누락이 0건이다.
- **SC-004**: 모든 카드에 썸네일 자리, 제목 1줄, 미리보기 3줄, 발행 날짜·댓글 수, 작성자·좋아요 수가 표시되고, 같은 줄 카드 높이 차이가 0이다.
- **SC-005**: 작성자 본인이 자기 블로그를 볼 때 비공개 글 노출이 0건이고, 블로그 글 수가 보는 사람 기준 공개 글 수와 같다.
- **SC-006**: 글 1만 건 기준 목록 응답이 300ms 이내이고, 목록 한 번에 데이터 조회가 1회이며 본문을 읽지 않는다.
- **SC-007**: 9개 카드의 썸네일 전송량이 원본 대비 크게 줄어(약 0.4MB 수준) 모바일에서도 목록이 빠르게 뜬다.
- **SC-008**: 375px~데스크톱 모든 폭에서 페이지 가로 스크롤이 0건이다.
- **SC-009**: 뒤로 가기로 30분 이내 돌아오면 불러온 카드와 스크롤 위치가 복원된다.
