## User Scenarios & Testing *(mandatory)*

### User Story 1 - 독자가 공개 글을 읽는다 (Priority: P1)

누구나 `/@블로그주소/posts/글번호`로 공개 글을 열면 제목, 작성자(닉네임 @블로그주소), 날짜, 본문, 태그, 좋아요 수·조회수, 작성자 카드, 댓글을 한 화면에서 본다.

**Why this priority**: 글을 읽는 것은 블로그의 핵심 가치이며 목록·공유·알림 모두 이 화면으로 이어진다.

**Independent Test**: 태그·댓글·사진·코드 블록이 있는 공개 글을 비회원으로 열어 각 요소가 보이는지 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 공개 발행 글, **When** 비회원이 상세를 열면, **Then** 제목(페이지의 유일한 최상위 제목), 작성자 사진·`닉네임 @블로그주소`, 날짜, 정화된 본문, 태그, 좋아요 수, 조회수, 작성자 카드(소개·블로그 가기), 댓글이 보인다.
2. **Given** 공개 글, **When** 날짜를 보면, **Then** 목록 카드와 같은 최초 공개 시점이 같은 형식(24시간 이내 "N시간 전", 이후 "YYYY.MM.DD")으로 보인다.
3. **Given** 다시 발행한 글, **When** 상세를 보면, **Then** 날짜 옆에 "수정됨 · 10월 3일"이 보이고, 공개 범위만 바꾼 글에는 보이지 않는다.
4. **Given** 태그가 여러 개인 글, **When** 상세를 보면, **Then** 작성자가 입력한 순서대로 `#이름`이 보이고 각각 그 태그 목록으로 연결된다.
5. **Given** 댓글이 많은 글, **When** 상세를 열면, **Then** 최상위 댓글 첫 20개(각 답글 처음 3개 포함)와 전체 댓글 수가 처음 화면에 함께 들어 있고, [댓글 더 보기]로 이어 본다.
6. **Given** 알림 등에서 특정 댓글로 가는 주소(댓글 지정 값 포함), **When** 열면, **Then** 그 댓글부터 보이고, 정규 주소에는 댓글 지정 값이 포함되지 않는다.
7. **Given** 본문에 GIF와 코드 블록이 있는 글, **When** 열면, **Then** GIF는 첫 장면과 재생 표시로 보이다가 누르면 재생되고, 코드 블록은 강조 표시된다. 화면은 페이지 안에 직접 쓴 스크립트 없이 동작한다.
8. **Given** 조회수가 1만 이상인 글, **When** 보면, **Then** "조회 1.2만"처럼 줄여 표시한다.

### User Story 2 - 볼 수 없는 글은 없는 글과 똑같다 (Priority: P1)

없는 글, 남의 비공개·임시 글, 휴지통 글, 숨긴 글(남이 볼 때), 탈퇴 유예 작성자의 글은 모두 같은 "찾을 수 없음" 화면과 같은 링크 미리보기 문구를 받는다. 주소를 잘못 옮겨 적은 경우 볼 수 있는 글이면 올바른 주소로 이동한다.

**Why this priority**: 존재 여부가 새면 공개 범위·삭제·숨김의 약속이 모두 깨진다.

**Independent Test**: 각 "볼 수 없는" 상태의 글과 존재하지 않는 글 번호를 여러 행위자로 열어 응답을 비교하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 없는 글, 남의 비공개·임시 글, 휴지통 글, 숨긴 글, 탈퇴 유예 작성자의 글, **When** 다른 사람이 열면, **Then** 모두 "찾을 수 없음"이고 상태·본문·링크 미리보기 문구("볼 수 없는 글이에요")가 같으며 검색 엔진 수집 제외 표시가 붙는다.
2. **Given** 볼 수 있는 글을 다른 사람의 블로그 주소로 연 경우, **When** 열면, **Then** 올바른 블로그 주소의 글로 영구 이동한다.
3. **Given** 볼 수 없는 글을 다른 블로그 주소로 연 경우, **When** 열면, **Then** 이동 없이 "찾을 수 없음"이다(누가 쓴 글인지 드러나지 않는다).
4. **Given** 글 번호 자리에 숫자가 아닌 값, **When** 열면, **Then** "찾을 수 없음"이다.
5. **Given** 대문자가 섞인 블로그 주소, **When** 열면, **Then** 소문자 주소로 영구 이동한다.

### User Story 3 - 작성자가 자기 글을 확인하고 관리한다 (Priority: P2)

작성자는 상세에서 독자와 같은 모습을 확인하고, 자기 글에만 보이는 상태 배지와 [수정]·[공개 범위]·[삭제] 버튼으로 바로 관리한다.

**Why this priority**: 작성자의 편의 기능이며, 독자 읽기(P1)가 먼저다.

**Independent Test**: 작성자로 공개·비공개·수정 중·임시·숨김·휴지통 상태의 자기 글을 각각 열어 화면을 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 작성자의 공개 글, **When** 열면, **Then** 독자와 같은 화면에 [수정]·[공개 범위 ▾]·[삭제]가 더 보이고, [좋아요]·[신고]·[팔로우] 버튼은 없다(좋아요 수만 보인다).
2. **Given** 작성자의 비공개 글, **When** 열면, **Then** 🔒 배지와 "나만 볼 수 있는 글이에요"가 보이고 날짜는 최초 발행 일자다.
3. **Given** 수정 중인 작업본이 있는 글, **When** 작성자가 열면, **Then** 독자와 같은 마지막 발행본과 "수정 중인 내용이 있어요(저장 시각) [이어서 수정] [변경 취소]" 안내가 보인다.
4. **Given** 작성자의 임시글 주소, **When** 작성자가 열면, **Then** 에디터로 이동한다.
5. **Given** 관리자가 숨긴 작성자의 글, **When** 작성자가 열면, **Then** "운영 정책에 따라 숨겨진 글이에요. 다른 사람에게는 보이지 않아요" 안내가 보인다.
6. **Given** 휴지통의 자기 글, **When** 작성자가 열면, **Then** "찾을 수 없음"이다(휴지통 목록에서만 보인다).
7. **Given** 작성자, **When** [공개 범위 ▾]로 바꾸거나 [삭제]를 누르면, **Then** 공개 범위 변경(006)·휴지통 이동 확인창(007)이 그 규칙대로 동작한다.

### User Story 4 - 다른 독자가 반응한다 (Priority: P2)

작성자가 아닌 사람에게는 [좋아요]·[신고]·[팔로우] 버튼이 보인다. 비회원·이메일 인증 전 회원도 버튼을 보지만, 누르면 로그인 또는 이메일 인증 안내를 받는다.

**Why this priority**: 반응 기능 자체는 좋아요·신고·팔로우 spec 소관이고, 이 spec은 상세 화면에서의 표시 조건만 정한다.

**Independent Test**: 비회원·인증 전 회원·회원·작성자로 같은 공개 글을 열어 버튼 표시와 누를 때의 안내를 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 작성자가 아닌 회원, **When** 공개 글을 열면, **Then** [좋아요](내가 눌렀는지 표시 포함)·[신고]·작성자 카드의 [팔로우](팔로우 중이면 [팔로잉 ✓])가 보인다.
2. **Given** 비회원, **When** [좋아요]·[신고]·[팔로우]를 누르면, **Then** 로그인 화면으로 안내되고 로그인 후 이 글로 돌아온다.
3. **Given** 이메일 인증 전 회원, **When** [좋아요]·[신고]를 누르면, **Then** 이메일 인증 안내를 받는다.

---

### User Story 5 - 공유한 링크가 제대로 미리 보인다 (Priority: P2)

공개 글의 주소를 메신저·SNS에 붙이면 제목·요약·대표 사진이 미리 보이고, 검색 엔진에는 정규 주소가 알려진다. 비공개·임시·볼 수 없는 글은 공통 문구만 나온다.

**Why this priority**: 글이 밖으로 퍼지는 경로지만 읽기 자체보다는 부차적이다.

**Independent Test**: 공개 글과 비공개 글의 주소로 링크 미리보기 정보를 가져와 비교하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 공개 글, **When** 링크 미리보기를 가져가면, **Then** 제목, 요약 앞 160자, 첫 사진의 원본(없으면 서비스 기본 이미지), 최초 공개 시점, (있으면) 수정 시점, 정규 주소가 들어 있다.
2. **Given** 비공개 글을 작성자 본인이 보는 경우를 포함한 공개가 아닌 모든 경우, **When** 미리보기 정보를 보면, **Then** 공통 문구와 검색 엔진 수집 제외 표시만 있다.
3. **Given** 제목·요약에 특수 문자가 있는 글, **When** 미리보기 정보를 만들면, **Then** 그대로 이스케이프되어 페이지 구조를 깨지 않는다.
4. **Given** 추적용 값이 붙은 주소, **When** 열면, **Then** 정규 주소에는 그 값이 포함되지 않는다.

### User Story 6 - 상세를 연다고 조회수가 부풀지 않는다 (Priority: P3)

상세 페이지를 받는 것만으로는 조회수가 오르지 않는다. 독자의 화면에 글이 1초 이상 보였을 때만 조회 기록을 따로 남기고, 작성자 본인이 보는 상세에는 조회 기록 장치를 넣지 않는다.

**Why this priority**: 조회수 집계 규칙 자체는 조회수 spec 소관이며, 이 spec은 상세 화면 쪽 연결만 책임진다.

**Independent Test**: 상세를 여러 번 받기만 했을 때와 작성자로 열었을 때 조회수와 조회 기록 장치 포함 여부를 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 공개 글, **When** 상세 응답만 받으면, **Then** 조회수는 바뀌지 않는다.
2. **Given** 작성자 본인, **When** 자기 글 상세를 열면, **Then** 조회 기록 장치가 페이지에 없다.
3. **Given** 조회 기록이 실패, **When** 독자가 글을 보면, **Then** 상세 화면은 정상으로 보이고 저장된 조회수를 그대로 표시한다.
4. **Given** 관리자, **When** 남의 공개 글 상세를 열면, **Then** [NEEDS CLARIFICATION: 관리자의 상세 열람을 조회 기록에서 제외할지 — 40 문서는 제외를 요청했으나 31 조회수 문서의 확정 제외 목록에는 관리자가 없음 (52 §11.2)]

### Edge Cases

- 수정 중 작업본이 있어도 독자는 항상 마지막 발행본만 본다.
- 상세 응답은 보는 사람마다 내용(좋아요 여부·작성자 버튼)이 달라 공유 캐시에 넣지 않고, 공개가 아닌 글은 저장 자체를 금지한다.
- 숨긴 댓글·삭제된 댓글·탈퇴한 사용자의 댓글 표시 문구는 댓글·신고 spec을 따른다.
- 작성자 사진이 없으면 기본 아이콘을 보인다. 소개는 글자만, 줄바꿈을 유지한다.
- 본문은 저장된 정화 결과를 그대로 출력하며 조회 때 다시 변환하지 않는다.
- 정지된 회원의 기존 글은 숨김 처리 전까지 그대로 보인다.
- 볼 수 있는지 판정을 주소 일치 확인보다 먼저 해서, 볼 수 없는 글에 대해 이동 응답으로 작성자가 드러나지 않게 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 글 상세를 `/@블로그주소/posts/글번호` 주소로 제공하고, 볼 수 있는지 여부는 006의 공통 읽기 판정 하나로만 결정해야 한다.
- **FR-002**: System MUST 주소 처리를 대문자 블로그 주소 소문자 이동 → 숫자가 아닌 글 번호 거절 → 읽기 판정 → 블로그 주소 불일치 이동 → 작성자 임시글 에디터 이동 → 상세 표시 순서로 해야 한다.
- **FR-003**: System MUST 없는 글, 남의 비공개·임시 글, 휴지통 글(작성자 포함), 숨긴 글(작성자·관리자 외), 탈퇴 유예 작성자의 글에 같은 "찾을 수 없음" 응답(상태·본문·링크 미리보기 문구·검색 엔진 수집 제외)을 주어야 한다.
- **FR-004**: System MUST 볼 수 있는 글을 다른 블로그 주소로 열면 올바른 주소로 영구 이동시키고, 볼 수 없는 글이면 같은 상황에서 "찾을 수 없음"을 주어야 한다.
- **FR-005**: System MUST 제목(페이지의 유일한 최상위 제목), 작성자 사진과 `닉네임 @블로그주소`, 날짜, 본문, 태그, 좋아요 수, 조회수, 작성자 카드, 댓글을 상세에 보여야 한다.
- **FR-006**: System MUST 공개 글의 표시 날짜로 최초 공개 시점을, 비공개 글(작성자만 봄)에는 최초 발행 일자를 쓰고, 다시 발행한 글에만 "수정됨" 일자를 함께 보여야 한다.
- **FR-007**: System MUST 본문을 발행 때 정화해 저장한 결과 그대로 출력하고, 제목·소개 등 사용자 글자는 이스케이프해야 한다.
- **FR-008**: System MUST 태그를 작성자가 입력한 순서대로 각 태그 목록으로 연결해 보여야 한다.
- **FR-009**: System MUST 최상위 댓글 첫 20개(각 답글 처음 3개 포함)와 전체 댓글 수를 상세 첫 응답에 포함하고, 댓글 지정 주소로 들어오면 그 댓글부터 보이게 해야 한다.
- **FR-010**: System MUST 작성자에게만 상태 배지(임시저장·🔒 비공개·수정 중·숨김 안내)와 [수정]·[공개 범위]·[삭제] 버튼을 보여야 한다.
- **FR-011**: System MUST 수정 중 작업본이 있는 글은 작성자에게도 마지막 발행본과 "수정 중" 안내([이어서 수정]·[변경 취소])를 보여야 한다.
- **FR-012**: System MUST 작성자가 자기 임시글 주소를 열면 에디터로 이동시켜야 한다.
- **FR-013**: System MUST 작성자 본인의 글에는 [좋아요]·[신고]·[팔로우] 버튼을 보이지 않고, 작성자가 아닌 사람(비회원·인증 전 회원 포함)에게는 보이되 비회원은 로그인, 인증 전 회원은 이메일 인증 안내로 연결해야 한다.
- **FR-014**: System MUST 상세 조회 자체로 조회수를 바꾸지 않고, 작성자가 아닌 독자의 상세에만 조회 기록 장치를 넣으며, 조회 기록 실패가 상세 표시에 영향을 주지 않아야 한다.
- **FR-015**: System MUST 페이지 안에 직접 쓴 스크립트 없이 조회 기록·GIF 재생·코드 강조가 동작해야 하며, 코드 강조는 코드 블록이 있을 때만 불러온다.
- **FR-016**: System MUST 모든 상세 응답을 공유 캐시에 저장하지 않게 표시하고, 공개가 아닌 글의 응답은 어디에도 저장하지 않게 표시해야 한다.
- **FR-017**: System MUST 공개 글에 정규 주소와 링크 미리보기 정보(제목, 요약 앞 160자, 첫 사진 원본 또는 기본 이미지, 최초 공개 시점, 있으면 수정 시점)를 넣고, 그 밖의 경우(작성자가 보는 비공개 글 포함)에는 공통 문구와 검색 엔진 수집 제외만 넣어야 한다.
- **FR-018**: System MUST 정규 주소에 추적용 값·댓글 지정 값을 넣지 않아야 한다.
- **FR-019**: System MUST 링크 미리보기 정보와 "찾을 수 없음" 응답 상태를 서버가 직접 넣어, 스크립트를 실행하지 않는 미리보기 수집기도 올바른 정보를 받게 해야 한다.
- **FR-020**: System MUST 상세 한 번의 데이터 조회를 정해진 소수 횟수(글·작성자, 태그, 내 좋아요 여부, 내 팔로우 여부, 작성자일 때 작업본 유무 — 최대 5회 + 댓글 첫 페이지)로 제한하고 작성 원문은 읽지 않아야 한다.

### Key Entities *(include if feature involves data)*

- **글 (post)**: 제목, 정화된 본문, 요약, 상태, 공개 범위, 최초 발행·최초 공개·재발행 일자, 반응 수(댓글·좋아요·조회).
- **수정 작업본 (post_draft)**: 발행 글을 수정 중일 때만 존재. 작성자에게 "수정 중" 안내를 띄우는 근거.
- **작성자 (member)**: 닉네임, 블로그 주소, 소개, 프로필 사진.
- **태그 연결 (post_tag)**: 입력 순서를 가진 글-태그 연결.
- **댓글 (comment)**: 상세 첫 응답에 포함되는 첫 20개와 답글.
- **보는 사람 관계**: 내가 이 글에 좋아요를 눌렀는지, 작성자를 팔로우 중인지.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 42 문서 §5-1 권한 표(글 상태 × 행위자)의 모든 칸이 자동 통합 테스트로 통과한다.
- **SC-002**: 볼 수 없는 글 5가지 상태와 없는 글의 응답(상태·본문·미리보기 문구)을 비교했을 때 차이가 0건이다.
- **SC-003**: 볼 수 있는 글을 잘못된 블로그 주소로 열면 100% 올바른 주소로 이동하고, 볼 수 없는 글은 100% "찾을 수 없음"이다.
- **SC-004**: "수정됨"은 다시 발행한 글에만 100% 표시되고, 공개 범위만 바꾼 글에는 0건 표시된다.
- **SC-005**: 작성자 버튼은 작성자에게만, 반응 버튼은 작성자가 아닌 사람에게만 보이는 것이 행위자 4종(비회원·인증 전·회원·작성자) 모두에서 확인된다.
- **SC-006**: 상세 응답만 반복 요청해도 조회수 변화가 0이고, 작성자 본인의 상세에는 조회 기록 장치가 0건 포함된다.
- **SC-007**: 공개 글 100%에 정규 주소·링크 미리보기 정보가 있고, 그 밖의 경우 100% 공통 문구와 수집 제외 표시다.
- **SC-008**: 글 1만 건 기준 상세 응답이 300ms 이내이며, 페이지 안에 직접 쓴 스크립트가 0건이다.
- **SC-009**: 댓글 지정 주소로 열면 그 댓글이 첫 화면에 보이는 비율이 100%이고, 정규 주소에 댓글 지정 값이 0건 포함된다.

## Assumptions

- 2026-10-07 결정(H6)에 따라 비회원·이메일 인증 전 회원에게도 [좋아요]·[신고] 버튼을 보이고 누르면 안내한다. 근거 문서 40 §7 #6의 "회원에게만"은 이 결정으로 대체했다.
- 2026-10-07 결정(Q2/H7, 화면 구성 방식)에 따라 글 상세는 서버가 링크 미리보기 정보와 "찾을 수 없음" 상태를 직접 넣는다.
- 읽기 판정·공통 404 문구는 006-post-visibility, 휴지통은 007-post-delete-trash, 권한 판정 순서·응답 원칙은 010-manage-posts(C-OWN-1)를 따른다.
- 댓글 쓰기·수정·삭제, 좋아요, 조회수 집계·중복 판정, 태그, 팔로우, 신고, 사진(GIF) 규칙은 각 기능 spec(011-tag·012-comment·013-like·014-view-count·017-follow-friend-feed·020-report-hide·004-image-upload) 소관이며, 이 spec은 상세 화면에서의 표시 위치와 연결만 정한다.
- 본문 렌더링·정화 규칙은 본문 정화 spec을 따른다.
- 숨김 알림을 받았을 때 상세 안내로 보낼지 관리 화면으로 보낼지는 문서 간 미결 항목(52 §11.2)으로 남기며 이 spec에서 정하지 않는다.
- 카테고리 경로, 관련 글·이전/다음 글, 사이드바, 목차·코드 복사 등은 개인 확장으로 범위 밖이다.
