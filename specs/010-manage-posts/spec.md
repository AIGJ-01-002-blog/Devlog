## User Scenarios & Testing *(mandatory)*

### User Story 1 - 내 글을 상태별로 한눈에 본다 (Priority: P1)

로그인한 작성자는 내 글 관리 화면에서 [임시글]·[발행 글]·[휴지통] 탭으로 자기 글만 본다. 각 글의 상태(임시·🌐 공개·🔒 비공개·수정 중·숨김)와 휴지통 글의 남은 보관일이 보인다.

**Why this priority**: 비공개 글·임시글·휴지통 글은 이 화면에서만 볼 수 있어, 이 화면이 없으면 작성자가 자기 글에 접근할 길이 없다.

**Independent Test**: 한 회원에게 각 상태의 글을 만들고, 다른 회원의 글도 섞은 뒤 내 글 관리 세 탭의 내용·순서·개수를 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 로그인한 작성자, **When** 내 글 관리를 열면, **Then** 기본으로 [임시글] 탭이 보이고 탭마다 글 수(예: "임시글 3 · 발행 글 24 · 휴지통 1")가 표시된다.
2. **Given** 임시글 탭, **When** 목록을 보면, **Then** 본인 임시글만 마지막 수정 시각 최신순으로 한 줄씩 보이고, 제목이 비면 "(제목 없음)", 각 줄에 "마지막 저장" 시각과 [이어 쓰기]·[삭제]가 있다. 공개 범위는 표시하지 않는다.
3. **Given** 발행 글 탭, **When** 목록을 보면, **Then** 본인 발행 글이 마지막 수정 시각 최신순으로 보이고, 각 줄에 공개 범위 표시(🌐/🔒와 화면 낭독용 글자), 수정 중이면 [수정 중] 배지, 숨긴 글이면 "운영 정책에 따라 숨겨짐" 배지, 발행 날짜·수정됨 날짜, 조회수·좋아요 수·댓글 수가 있다.
4. **Given** 발행 글 탭, **When** [공개]·[비공개] 필터를 고르면, **Then** 해당 공개 범위의 글만 보이고 [전체]로 돌아올 수 있다.
5. **Given** 휴지통 탭, **When** 목록을 보면, **Then** 최근 삭제 순으로 원래 상태("(임시글이었음)"/"(발행 글이었음)"), "삭제 10월 2일 · 27일 뒤 완전 삭제", [복구]·[영구 삭제]가 보이고, 탭 위에 "휴지통의 글은 30일 뒤 자동으로 완전히 삭제돼요" 안내가 있다.
6. **Given** 한 탭에 글이 20개를 넘음, **When** [더 보기]를 누르면, **Then** 다음 20개가 이어 붙고 같은 글이 두 번 보이지 않는다(보는 사이 자동 저장으로 순서가 바뀌어도 이미 있는 글은 건너뛴다).
7. **Given** 비회원, **When** 내 글 관리 주소로 들어오면, **Then** 로그인 화면으로 가고 로그인 후 이 화면으로 돌아온다.

### User Story 2 - 남의 글은 어떤 경로로도 보거나 바꿀 수 없다 (Priority: P1)

내 글 관리와 모든 쓰기 요청은 로그인 정보로만 "나"를 판단한다. 주소나 요청에 다른 사용자 값을 넣어도 무시되고, 남의 글에 대한 수정·삭제·발행·공개 범위 변경 요청은 "찾을 수 없음"이며 글은 그대로다. 화면에서 버튼을 숨기는 것은 보조일 뿐이다.

**Why this priority**: C-OWN-1의 핵심이며, 모든 쓰기 기능의 안전 기반이다.

**Independent Test**: 다른 회원·관리자로 남의 글 ID를 넣은 저장·발행·변경 취소·공개 범위 변경·삭제·복구·영구 삭제 요청을 보내 응답과 요청 전후 글 값을 비교하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 다른 회원의 글, **When** 회원이 그 글에 대해 저장·자동 저장·발행·다시 발행·변경 취소·공개 범위 변경·삭제·복구·영구 삭제를 요청하면, **Then** 모두 "찾을 수 없음"이고 요청 전후 글의 내용·상태·편집 버전·수정 시각이 같다.
2. **Given** 요청에 다른 사람의 작성자 값을 넣은 경우, **When** 내 글 목록이나 쓰기 요청을 보내면, **Then** 그 값은 무시되고 결과는 1과 같다(목록은 본인 글만).
3. **Given** 관리자, **When** 남의 글 내용을 수정·삭제하거나 남의 비공개 글·남의 내 글 관리 화면을 보려 하면, **Then** "찾을 수 없음"이다(관리자는 숨김만 할 수 있다).
4. **Given** 글 주인, **When** 자기 글에 달린 남의 댓글을 삭제하려 하면, **Then** "찾을 수 없음"이고 댓글은 그대로다.
5. **Given** 남의 알림 번호, **When** 누구든(관리자 포함) 읽음·삭제를 요청하면, **Then** "찾을 수 없음"이다.

### User Story 3 - 내 글을 이 화면에서 바로 처리한다 (Priority: P2)

작성자는 목록의 각 줄에서 [이어 쓰기]·[보기]·[수정]·[이어서 수정]·[변경 취소]·[공개 범위 ▾]·[삭제]·[복구]·[영구 삭제]·[새 글]을 눌러 기존 규칙대로 처리하고, 화면 전체를 새로 고치지 않고 그 줄만 바뀐다.

**Why this priority**: 각 처리의 규칙은 다른 spec에 있고, 이 화면은 그것을 모아 부르는 자리다.

**Independent Test**: 각 버튼을 눌러 확인창·결과 안내·탭 개수 변화를 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 발행 글, **When** [삭제]를 누르고 확인하면, **Then** 그 줄이 빠지고 휴지통 개수가 1 늘어난다. 빈 임시글이면 "빈 글이라 바로 삭제했어요"가 보인다.
2. **Given** 휴지통 글, **When** [복구]를 누르면, **Then** 확인창 없이 휴지통에서 빠지고 "복구했어요 [발행 글 탭에서 보기]"가 보이며 원래 탭·원래 위치로 돌아간다.
3. **Given** 휴지통 글, **When** [영구 삭제]를 누르면, **Then** 되돌릴 수 없다는 확인창 뒤 목록에서 빠진다.
4. **Given** 비공개 발행 글, **When** [공개 범위 ▾]에서 공개를 고르면, **Then** "모든 사람이 볼 수 있게 돼요" 확인 뒤 배지만 바뀌고 "수정됨"은 생기지 않는다. 공개 → 비공개는 확인창이 없다.
5. **Given** 수정 중인 발행 글, **When** [변경 취소]를 누르고 확인하면, **Then** 작업본이 사라지고 [수정 중] 배지가 없어진다.
6. **Given** 처리 실패(예: 이미 휴지통에 있는 글), **When** 결과를 보면, **Then** 그 줄 아래에 이유가 보이고 목록을 다시 불러온다.
7. **Given** [새 글], **When** 누르면, **Then** 새 임시글이 만들어지고(기본 공개 범위로 시작) 에디터로 이동한다.

### User Story 4 - 계정 상태와 행동에 따라 일관된 응답을 받는다 (Priority: P2)

모든 요청은 같은 순서(로그인 → 계정 상태 → 대상을 볼 수 있나 → 행동 권한 → 업무 규칙)로 검사되어, 같은 상황이면 어느 기능이든 같은 종류의 응답을 받는다.

**Why this priority**: 기능마다 응답이 다르면 존재 여부가 새거나 사용자가 해결 방법을 알 수 없다. 개별 기능 동작(P1) 위에 얹는 일관성 규칙이다.

**Independent Test**: 행위자(비회원·인증 전·회원·작성자·관리자·탈퇴 유예) × 대상 상태 × 행동 매트릭스를 자동 테스트로 돌리면 검증된다.

**Acceptance Scenarios**:

1. **Given** 비회원, **When** 쓰기 행동을 요청하면, **Then** 로그인 필요 응답(화면은 로그인 후 원래 페이지로 복귀)을 받는다.
2. **Given** 이메일 인증 전 회원, **When** 새 글·저장·발행·공개 범위 변경·댓글·사진 업로드·좋아요·신고를 요청하면, **Then** 계정 상태 때문에 막혔다는 응답과 "이메일 인증 필요" 이유를 받는다. 자기 글·댓글 삭제·복구, 내 글 관리 열람은 허용된다.
3. **Given** 탈퇴 유예 회원, **When** 로그인 후 어떤 요청을 보내면, **Then** 복구 화면만 보이거나 "탈퇴 신청 계정" 이유의 계정 상태 응답을 받는다.
4. **Given** 정지된 회원, **When** 로그인하려 하면, **Then** 정지 기간·사유 안내와 함께 거부되고, 정지 순간 모든 기기의 로그인이 끊긴다.
5. **Given** 볼 수 없는 대상(비공개·임시·휴지통·숨김·탈퇴 유예)과 없는 대상, **When** 요청하면, **Then** 응답이 같다.
6. **Given** 관리자 전용 주소, **When** 비회원이 있는 주소·없는 주소에 접근하면 모두 로그인 필요 응답이고, 로그인한 일반 회원이면 "찾을 수 없음"이다.
7. **Given** 작성자, **When** 자기 글에 좋아요를 누르거나 자기 것을 신고하면, **Then** 업무 규칙 위반 검증 오류를 받는다.

---

### Edge Cases

- 한 사람이 여러 행위자에 해당하면(예: 인증 전인 작성자) 판정 순서에서 먼저 걸리는 쪽이 적용된다.
- 계정 상태 응답은 대상과 무관하게 같으므로 대상의 존재를 드러내지 않는다.
- "남의 것이라 안 됨"에는 계정 상태 응답을 쓰지 않고 항상 "찾을 수 없음"을 쓴다.
- 정지 회원은 로그인할 수 없으므로 정지 기간에는 자기 글 삭제·프로필 수정도 할 수 없다.
- 숨긴 댓글은 작성자도 수정할 수 없고 누구도 답글을 달 수 없지만, 작성자의 삭제는 가능하다.
- 관리자도 자기 글에서는 작성자다.
- 탭 개수는 첫 화면에서만 계산하고 [더 보기]에서는 다시 계산하지 않는다.
- 휴지통 탭의 남은 보관일은 삭제 일자 + 30일 기준이다.

## Requirements *(mandatory)*

### Functional Requirements

**내 글 관리 (C-MANAGE-1)**

- **FR-001**: System MUST 내 글 관리 화면을 로그인한 사용자 본인의 글만으로 구성하고, 주소·요청에 사용자를 지정하는 값을 두지 않으며 다른 값이 들어와도 무시해야 한다.
- **FR-002**: System MUST [임시글]·[발행 글]·[휴지통] 세 탭을 제공하고 기본 탭은 [임시글]이어야 한다.
- **FR-003**: System MUST 임시글·발행 글 탭을 마지막 수정 시각 최신순(같으면 글 번호 큰 순), 휴지통 탭을 삭제 일자 최신순으로 정렬해야 한다.
- **FR-004**: System MUST 세 탭 모두 한 줄 목록으로 20개씩 보여 주고, 클라이언트가 요청한 개수와 상관없이 20개로 고정하며, 다음 글이 있을 때만 [더 보기]를 보여야 한다.
- **FR-005**: System MUST 각 탭에 본인 글 수를 첫 화면에서 함께 보여야 한다.
- **FR-006**: System MUST 각 글에 상태(임시·🌐 공개·🔒 비공개·수정 중·관리자 숨김)를 보이고, 공개 범위 표시에는 화면 낭독용 글자를 함께 넣어야 한다. 임시글에는 공개 범위를 표시하지 않는다.
- **FR-007**: System MUST 발행 글에 발행 날짜, (있으면) 수정됨 날짜, 조회수·좋아요 수·댓글 수를 보여야 한다.
- **FR-008**: System MUST 발행 글 탭에 [전체]·[공개]·[비공개] 필터를 제공해 해당 글만 보여야 한다.
- **FR-009**: System MUST 휴지통 글에 원래 상태, 삭제 일자, 완전 삭제까지 남은 날을 보이고, 탭 위에 30일 자동 삭제 안내를 보여야 한다.
- **FR-010**: System MUST 각 줄의 버튼으로 이어 쓰기·보기·수정·이어서 수정·변경 취소·공개 범위 변경·삭제·복구·영구 삭제를, 화면 위의 버튼으로 새 글 만들기를 제공하고, 각 처리는 003-draft-autosave·005-post-publish·006·007 spec의 규칙과 확인창 문구를 그대로 따라야 한다.
- **FR-011**: System MUST 처리 결과를 화면 전체를 새로 고치지 않고 해당 줄과 탭 개수에만 반영하고, 실패 시 그 줄 아래에 이유를 보이며 목록을 다시 불러와야 한다.
- **FR-012**: System MUST [더 보기] 중 순서가 바뀌어도(다른 탭의 자동 저장 등) 같은 글이 두 번 보이지 않게 해야 한다.
- **FR-013**: System MUST 비회원이 내 글 관리에 들어오면 로그인 화면으로 보내고 로그인 후 돌아오게 해야 한다.
- **FR-014**: System MUST 목록 조회에서 본문을 읽지 않고, 목록 1회 + (첫 화면만) 개수 1회의 조회로 처리해야 한다.

**본인 소유 권한 (C-OWN-1)**

- **FR-015**: System MUST 현재 사용자를 로그인 정보에서만 얻고, 작성자 값을 요청으로 받지 않아야 한다.
- **FR-016**: System MUST 모든 요청을 로그인 필요 → 계정 상태 → 대상을 볼 수 있나 → 행동 권한 → 업무 규칙 순서로 검사하고, 처음 걸린 단계의 응답을 주어야 한다.
- **FR-017**: System MUST 응답 종류를 하나의 기준으로 통일해야 한다: 로그인 필요(비회원), 계정 상태로 막힘(인증 전·탈퇴 유예, 이유 포함), 찾을 수 없음(없음·볼 수 없음·남의 것·일반 회원의 관리자 전용 주소), 업무 규칙 위반(검증 오류), 상태 충돌. 계정 상태 응답은 "남의 것"에 쓰지 않는다.
- **FR-018**: System MUST 남의 글·댓글에 대한 수정·삭제·발행·공개 범위 변경·변경 취소·복구·영구 삭제 요청을 "찾을 수 없음"으로 거절하고, 요청 전후 대상 데이터(내용·상태·편집 버전·수정 시각)를 바꾸지 않아야 한다.
- **FR-019**: System MUST 볼 수 없는 대상(비공개·임시·휴지통·숨김·작성자 탈퇴 유예)과 없는 대상에 같은 응답을 주어야 한다.
- **FR-020**: System MUST 이메일 인증 전 회원의 새 글·저장·발행·공개 범위 변경·댓글·사진 업로드·좋아요·신고를 막고, 자기 글·댓글 삭제·복구와 내 글 관리 열람은 허용해야 한다.
- **FR-021**: System MUST 탈퇴 유예 회원에게 복구 화면만 허용하고 그 밖의 요청은 탈퇴 신청 계정 응답으로 막아야 한다.
- **FR-022**: System MUST 정지된 회원의 로그인을 거부하고, 정지 즉시 그 회원의 모든 로그인 상태를 끊어야 한다. 정지 회원은 비회원과 같게 취급하며 기존 글·댓글은 숨김 전까지 그대로 보인다.
- **FR-023**: System MUST 관리자에게 남의 글·댓글 숨김·숨김 해제만 허용하고, 남의 글·댓글 내용 수정·삭제, 남의 비공개 글·알림·내 글 관리 열람을 막아야 한다.
- **FR-024**: System MUST 관리자 전용 주소 전체를 로그인 필요로 묶어 비회원에게는 있는 주소·없는 주소 모두 로그인 필요 응답을, 로그인한 일반 회원에게는 "찾을 수 없음"을 주어야 한다.
- **FR-025**: System MUST 글 주인이라도 자기 글에 달린 남의 댓글을 수정·삭제할 수 없게 해야 한다.
- **FR-026**: System MUST 화면에서 할 수 없는 행동의 버튼을 보이지 않게 하되(작성자 버튼은 작성자에게만, 반응 버튼은 작성자가 아닌 사람에게), 이것과 별개로 서버가 모든 요청을 판정해야 한다.

### Key Entities *(include if feature involves data)*

- **행위자**: 비회원, 이메일 인증 전 회원, 회원(작성자가 아닌), 작성자, 관리자, 정지 회원(비회원과 같게 취급), 탈퇴 유예 회원. 회원(member)의 역할·상태와 로그인 수단(auth_identity)의 인증 여부로 판별한다.
- **글 (post)**: 작성자, 상태, 공개 범위, 삭제·숨김 여부, 수정 시각, 반응 수(조회·좋아요·댓글).
- **수정 작업본 (post_draft)**: "수정 중" 배지와 [이어서 수정]·[변경 취소]의 근거.
- **내 글 목록 항목**: 글 번호, 제목, 상태, 공개 범위, 수정 중 여부, 숨김 여부, 수정·발행·수정됨·삭제 일자, 완전 삭제 예정일, 반응 수.
- **탭 개수**: 본인의 임시글·발행 글·휴지통 글 수.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 42 문서 §5~§10-3의 모든 칸(행위자 × 대상 상태 × 행동)이 자동 통합 테스트로 100% 통과한다.
- **SC-002**: 남의 글·댓글에 대한 변경 요청은 100% "찾을 수 없음"이며, 요청 전후 대상 데이터 차이가 0건이다. 요청에 다른 작성자 값을 넣어도 결과가 같다.
- **SC-003**: 내 글 관리 세 탭에서 다른 사람의 글이 보이는 경우가 0건이다.
- **SC-004**: 볼 수 없는 대상과 없는 대상의 응답 차이가 0건이다.
- **SC-005**: 비회원 쓰기 요청 100%가 로그인 필요 응답, 인증 전·탈퇴 유예 회원 100%가 이유를 담은 계정 상태 응답을 받는다.
- **SC-006**: 회원을 정지하면 그 회원의 모든 로그인 상태가 즉시 끊기고 정지 기간 로그인 성공이 0건이다.
- **SC-007**: 발행 글 필터 결과의 공개 범위 불일치가 0건이고, [더 보기]로 끝까지 봤을 때 중복이 0건이다.
- **SC-008**: 모든 글에 상태 표시가 있고, 휴지통 글 100%에 남은 보관일이 표시된다.
- **SC-009**: 화면 버튼 표시가 42 문서 §11 조건과 100% 일치한다.
- **SC-010**: 내 글 관리 목록 응답이 300ms 이내이고 본문을 읽지 않는다.

## Assumptions

- 2026-10-07 결정(H6)에 따라 비회원·인증 전 회원에게도 좋아요·신고 버튼을 보이고 누르면 안내한다. 42 §11·§12 #7의 "회원·관리자에게만"은 이 결정으로 대체했다.
- 2026-10-07 결정(Q2/H7, 화면 구성·로그인 방식)에 따라 정지 계정의 쓰기는 계정 상태 응답, 로그인은 거부하고, 정지·탈퇴·비밀번호 변경 때 로그인 상태를 즉시 끊는다. 근거 문서의 "스크립트가 없으면 폼 제출로 대체" 규칙은 공통 기준에서 제외했다.
- 2026-10-07 결정에 따라 태그 자동완성은 로그인 필요다(42 §10-2의 비회원 허용 표현은 대체).
- 각 처리(저장·변경 취소는 003-draft-autosave, 발행은 005-post-publish, 공개 범위는 006, 삭제·복구·영구 삭제는 007)의 세부 규칙은 해당 spec을 따른다. 이 spec은 그 처리를 부르는 화면과, 모든 기능에 공통인 권한 판정 기준을 정한다.
- 댓글·좋아요·신고·팔로우·알림·프로필의 권한 칸은 이 spec의 권한 매트릭스 테스트 범위에 포함되지만, 각 기능의 동작은 해당 spec이 정한다.
- 자기 글 좋아요 응답은 42 기준(업무 규칙 위반 검증 오류)을 따른다. 30 좋아요 문서와의 응답 코드 차이·권한 검사 순서 대조는 52 §11.2의 문서 간 확인 항목으로, 42가 최종 기준이다.
- 관리자 숨김 알림을 받았을 때 이 화면의 해당 글로 이동할지 상세 안내로 보낼지는 52 §11.2 미결 항목으로 남긴다.
- 관리 화면 검색·일괄 처리, 작성자 통계 화면, 글 주인의 남의 댓글 삭제는 개인 확장으로 범위 밖이다.
