# Feature Specification: 태그 (010-tags)

입력(대소문자·띄어쓰기·전각 문자·맨 앞 #)은 한 태그로 합쳐지고, 전체 태그 목록과 블로그 안 태그 필터, 작성 중 자동완성을

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 발행할 때 태그를 단다 (Priority: P1)

작성자는 발행 설정 창(공개 범위를 고르는 창)에서 태그를 입력한다. Enter나 쉼표로 하나씩 추가하고, 입력하자마자 정규화된 모양이
칩으로 보인다. 발행하면 태그가 입력한 순서대로 글에 붙는다.

**Why this priority**: 태그가 붙어야 태그별 목록·전체 태그 목록이 생긴다. 이 기능의 출발점이다.

**Independent Test**: `Spring Boot`, `#JPA`, `C#`를 입력해 칩이 `#spring-boot`, `#jpa`, `#c#`로 보이는지, 발행 뒤 글 상세에
그 순서대로 보이는지, 다시 발행할 때 미리 채워지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 발행 설정 창, **When** `Spring Boot`를 입력하고 Enter를 누르면, **Then** 띄어쓰기로 나뉘지 않고 `#spring-boot` 칩
   하나가 생긴다.
2. **Given** 발행 설정 창, **When** 태그를 추가하면, **Then** "2 / 10"처럼 지금 개수와 최대 개수가 보인다.
3. **Given** `Spring`, `spring`, `#SPRING`을 차례로 입력, **When** 발행하면, **Then** 처음 것 하나만 `spring`으로 남는다.
4. **Given** 태그 3개를 단 글, **When** 발행하면, **Then** 글 상세에 입력한 순서대로 `#이름`이 보이고, 누르면 그 태그 페이지로
   간다.
5. **Given** 칩, **When** 끌거나 칩에 초점을 두고 Alt + 방향키를 누르면, **Then** 순서가 바뀐다. ×나 빈 입력칸의 Backspace로
   지울 수 있다.
6. **Given** 발행된 글을 다시 발행하려 함, **When** 발행 설정 창을 열면, **Then** 지금 달린 태그가 순서대로 미리 채워져 있다.
7. **Given** 발행된 글, **When** 태그만 바꿔 다시 발행하면, **Then** 글에 "수정됨"이 붙는다.
8. **Given** 태그를 입력하고 발행하지 않고 창을 닫음, **When** 다른 기기에서 그 글을 열면, **Then** 입력했던 태그는 서버에
   저장되지 않았으므로 보이지 않는다.

### User Story 2 - 잘못된 태그는 이유와 함께 거부된다 (Priority: P2)

허용되지 않는 문자, 금칙어, 너무 긴 태그, 너무 많은 태그는 몰래 고치지 않고 발행을 거부하며, 문제가 있는 태그를 모두 한 번에
알려준다.

**Why this priority**: 태그는 공개 페이지·목록·자동완성에 그대로 노출되므로, 이상한 태그가 생기지 않게 하는 것이 태그를 다는
것 다음으로 중요하다.

**Independent Test**: `🔥hot`, 31자 태그, 금칙어 태그를 함께 넣고 발행해 셋 다 한 번에 표시되는지, 금칙어는 어떤 단어인지
알려주지 않는지, 11번째 태그가 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** `🔥hot`, `a/b`, `c@d`처럼 허용되지 않는 문자가 든 태그, **When** 발행하면, **Then** 문자를 지우지 않고 거부되며
   해당 칩이 빨간 테두리와 글자 안내로 표시된다(색만으로 구분하지 않는다).
2. **Given** `...`, `---`, `#`처럼 한글·영문·숫자가 하나도 없는 태그, 또는 `ㅋㅋ`처럼 완성되지 않은 한글, **When** 발행하면,
   **Then** 거부된다.
3. **Given** 정규화 뒤 31자 이상인 태그, **When** 발행하면, **Then** "너무 길다"는 이유로 거부된다.
4. **Given** 금칙어가 든 태그, **When** 발행하면, **Then** 거부되지만 어떤 단어가 걸렸는지는 알려주지 않는다.
5. **Given** 중복을 지운 뒤 11개 이상의 태그, **When** 발행하면, **Then** "너무 많다"는 이유로 거부된다.
6. **Given** 여러 태그에 문제가 있음, **When** 발행하면, **Then** 문제가 있는 태그를 모두 위치와 함께 한 번에 알려주고 글은
   발행되지 않는다.

### User Story 3 - 태그로 글을 모아 본다 (Priority: P3)

독자는 글 상세의 태그나 태그 주소(`/tags/{이름}`)를 열어 그 태그가 달린 공개 글을 홈과 같은 카드로 본다. 전체 태그 목록
(`/tags`)에서는 공개 글이 많은 태그를 훑어본다.

**Why this priority**: 태그를 다는 이유가 되는 탐색 기능이지만, 태그가 먼저 정확하게 쌓여야 한다.

**Independent Test**: 공개·비공개·임시 글에 같은 태그를 단 뒤 `/tags/{이름}`에 공개 글만 최신순 9개씩 보이는지, `/tags`에 공개
글 수 많은 순으로 보이는지, 비공개 글에만 쓰인 태그가 아무도 안 쓴 태그와 똑같이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 태그 `spring-boot`가 달린 공개 글 42개, **When** `/tags/spring-boot`를 열면, **Then** 상단에 `#spring-boot · 공개
   글 42`가 있고, 홈과 같은 카드가 처음 공개된 시각 최신순(같으면 번호 큰 순)으로 9개 보이며 [더 보기]로 이어진다.
2. **Given** 태그에 비공개·임시·휴지통·관리자 숨김·탈퇴 신청 작성자의 글이 섞여 있음, **When** 태그 페이지·전체 태그 목록을
   보면, **Then** 그 글들은 목록에도 글 수에도 들어가지 않는다.
3. **Given** 형식에 맞지만 공개 글이 없는 태그(비공개 글에만 쓰였거나 아무도 안 씀), **When** 태그 페이지를 열면, **Then**
   정상 페이지로 "아직 이 태그로 공개된 글이 없어요"가 보이고 두 경우를 구별할 수 없다.
4. **Given** 형식에 맞지 않는 이름(예: 이모지), **When** 태그 주소를 열면, **Then** "찾을 수 없음"이다.
5. **Given** `/tags/Spring%20Boot`처럼 정규화되지 않은 주소, **When** 열면, **Then** `/tags/spring-boot`로 영구 이동한다.
6. **Given** `c#`, `c++`, `node.js`, `.net`, `스프링-부트` 태그, **When** 글 상세에서 누르면, **Then** 각각 올바르게 인코딩된
   주소로 열려 그 태그 페이지가 보인다.
7. **Given** 공개 글에 쓰인 태그들, **When** `/tags`를 열면, **Then** 공개 글 수 많은 순(같으면 이름 순)으로 상위 100개가 글 수와
   함께 보이고, 공개 글 수가 0인 태그는 나오지 않는다. 하나도 없으면 "아직 태그가 없어요"가 보인다.
8. **Given** [더 보기]를 누름, **When** 불러오는 중이거나 실패하면, **Then** 홈과 같이 "불러오는 중…"(비활성화) / "불러오지
   못했어요 [다시 시도]"가 보인다.

### User Story 4 - 쓰던 태그를 자동완성으로 고른다 (Priority: P4)

작성자가 발행 설정 창에서 태그를 입력하면 내가 쓴 태그와 공개 글에 쓰인 태그가 후보로 뜬다. 남의 비공개 글에만 쓰인 태그는
후보에 나오지 않는다.

**Why this priority**: 같은 뜻의 태그가 흩어지지 않게 도와주지만, 없어도 태그를 달 수 있다.

**Independent Test**: 회원 A의 비공개 글에만 쓰인 태그 `이직준비`가 회원 B의 자동완성에는 나오지 않고 A에게는 나오는지, 비회원
요청이 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 작성자, **When** `spr`을 입력하고 0.3초 멈추면, **Then** `spr`로 시작하는 태그가 내가 쓴 태그 먼저, 그다음
   공개 글 수 많은 순으로 최대 10개, 공개 글 수와 함께 보인다.
2. **Given** 다른 회원의 비공개 글에만 쓰인 태그, **When** 자동완성을 보면, **Then** 후보에 나오지 않는다. 내 비공개 글에 쓴
   태그는 나온다.
3. **Given** 한글을 조합하는 중, **When** 입력하면, **Then** 조합이 끝날 때까지 자동완성을 부르지 않는다.
4. **Given** 후보가 없거나, 불러오기에 실패하거나, 요청이 너무 잦음, **When** 입력하면, **Then** 목록을 띄우지 않고 입력을 막지
   않으며 Enter로 새 태그를 만들 수 있다.
5. **Given** 비회원, **When** 자동완성을 요청하면, **Then** 로그인이 필요하다는 응답으로 거부된다.
6. **Given** 앞선 요청의 응답이 늦게 도착함, **When** 이미 다음 입력의 결과가 보이면, **Then** 늦은 응답은 버린다.

### User Story 5 - 블로그 안에서 태그로 거른다 (Priority: P5)

독자는 개인 블로그 상단에서 그 블로그의 태그와 글 수를 보고, 하나를 눌러 그 태그의 글만 본다.

**Why this priority**: 한 사람의 글이 많아졌을 때 유용하지만, 전체 태그 페이지로도 대체할 수 있다.

**Independent Test**: 블로그 `/@A`에 A의 공개 글 태그가 글 수 많은 순으로 처음 10개 보이는지, `/@A?tag=jpa`에 그 태그의 A 공개
글만 블로그 목록과 같은 방식으로 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 작성자 A의 블로그, **When** 열면, **Then** 상단에 A의 공개 글에 쓰인 태그가 글 수와 함께 글 수 많은 순으로 처음
   10개, 그리고 [태그 더 보기]가 보인다.
2. **Given** `/@A?tag=jpa`, **When** 열면, **Then** "#jpa 글 5개"와 [필터 해제]가 보이고 A의 `jpa` 공개 글만 블로그 목록과 같은
   카드·정렬·9개·[더 보기]로 보인다.
3. **Given** `?tag=JPA`처럼 정규화되지 않은 값, **When** 열면, **Then** 정규화된 주소로 영구 이동한다.
4. **Given** A 본인, **When** 자기 블로그의 태그 줄을 보면, **Then** 비공개 글의 태그와 글 수는 들어가지 않는다.

### Edge Cases

- `ｓｐｒｉｎｇ`(전각), `Node.JS`, `.NET`, `스프링  부트`, `spring--boot-`는? → 각각 `spring`, `node.js`, `.net`, `스프링-부트`,
  `spring-boot`가 된다.
- `#spring`처럼 맨 앞 `#`은 지우지만 `c#`의 뒤 `#`은? → 남긴다.
- 보이지 않는 글자·방향 제어 문자·제어 문자가 섞이면? → 지운 뒤 검사한다.
- 터키어 설정 같은 지역 규칙에 따라 대소문자 변환 결과가 달라지는가? → 지역과 무관한 한 가지 규칙으로 소문자로 바꾼다.
- 같은 새 태그로 여러 글이 동시에 발행되면? → 태그는 하나만 생긴다.
- 태그가 달린 글을 모두 지우면? → 태그 기록은 남지만 공개 글 수가 0이 되어 목록·자동완성에 나오지 않는다.
- 태그 주소에 `#`이 들어가면? → 반드시 인코딩된 주소(`/tags/c%23`)로 만든다. `+`와 `.`은 그대로 둔다.
- `node.js` 주소의 `.js`가 확장자로 잘리는가? → 잘리지 않고 `node.js` 태그 페이지가 열린다.
- `.`이나 `..`만인 태그 주소는? → 태그가 될 수 없어 "찾을 수 없음"이고 경로 탐색 문제가 없다.
- 공개 글이 태그 페이지를 보는 도중 비공개로 바뀌면? → 홈과 같이 중복·누락 없이 이어 붙는다.
- 목록 카드에 태그가 보이는가? → 보이지 않는다(목록은 한 번의 조회 유지).

## Requirements *(mandatory)*

### Functional Requirements

**정규화 (T-1~T-5, docs/22 §2)**

- **FR-001**: 모든 태그 입력(발행, 자동완성 검색어, 태그 주소, 블로그 필터)은 같은 한 가지 정규화 규칙을 거쳐야 한다. 순서:
  ① 호환 문자 정리(전각 → 반각) ② 보이지 않는 글자·방향 제어 문자·제어 문자 제거(본문 제목과 같은 목록) ③ 앞뒤 공백 제거
  ④ 맨 앞의 `#`을 모두 지우고 다시 앞뒤 공백 제거 ⑤ 지역과 무관한 소문자 변환 ⑥ 공백 묶음을 `-` 하나로 ⑦ 연달은 `-`는 하나로,
  처음·끝의 `-` 제거 ⑧ 검사 ⑨ 금칙어 검사.
- **FR-002**: 허용 문자는 완성된 한글, 영문 소문자, 숫자와 기호 5개(`-` `_` `.` `+` `#`)뿐이며, 한글·영문·숫자가 1자 이상 있어야
  하고 길이는 1~30자(글자 단위)여야 한다.
- **FR-003**: 허용되지 않는 문자는 몰래 지우지 않고 거부해야 한다.
- **FR-004**: 금칙어는 닉네임과 같은 금칙어 필터(docs/09 §4, 변형 포함)를 적용해 거부하되 어떤 단어인지는 알려주지 않아야 한다.
- **FR-005**: 거부 이유는 "허용되지 않는 태그", "너무 긴 태그", "금칙어", "태그가 너무 많음"을 구별해야 한다.

**글에 태그 달기 (T-6·T-7, docs/22 §2-2·§3·§4, docs/05 §4)**

- **FR-006**: 태그는 발행 설정 창에서 입력하며, 발행할 때만 확정되어야 한다. 자동 저장·수동 저장 대상이 아니다(002 FR-017).
- **FR-007**: Enter 또는 쉼표로 태그를 하나 추가하고, 띄어쓰기는 나누지 않고 하이픈이 되어야 한다. 입력 즉시 정규화된 모양을
  칩으로 보여주되 이는 안내용이며 서버가 다시 검사해야 한다.
- **FR-008**: 칩은 ×와 빈 입력칸의 Backspace로 지우고, 끌기와 키보드(Alt + 방향키)로 순서를 바꿀 수 있어야 한다. 지금 개수와
  최대 개수를 보여야 한다.
- **FR-009**: 한 글의 태그는 정규화 뒤 같은 이름은 처음 나온 것만 남기고, 남은 순서를 입력 순서로 저장해야 한다.
- **FR-010**: 글당 태그는 중복을 지운 뒤 0~10개여야 하며 최대 개수는 설정값(기본 10)이어야 한다.
- **FR-011**: 발행 검증에 실패한 태그는 위치·이유와 함께 모두 한 번에 알려야 하고, 제목·본문 등 다른 검증 실패와 함께 돌려줘야
  한다. 실패하면 발행되지 않는다.
- **FR-012**: 발행할 때 그 글의 태그를 통째로 입력한 순서대로 바꿔야 하며, 같은 새 태그로 동시에 발행해도 태그는 하나만 생겨야
  한다.
- **FR-013**: 태그 기록은 쓰는 글이 없어도 지우지 않아야 한다.
- **FR-014**: 다시 발행할 때 발행 설정 창은 지금 태그를 순서대로 미리 채워야 하고, 태그만 바꿔도 다시 발행으로 "수정됨"이 붙어야
  한다.
- **FR-015**: 발행하지 않고 닫은 태그 입력은 서버에 저장하지 않아야 한다.
- **FR-016**: 태그를 붙이는 권한은 글 발행 권한을 따라야 한다(docs/42 §10-2). 남의 글에는 붙일 수 없다.
- **FR-017**: 태그 변경을 위한 별도 사건은 두지 않고, 다른 기능은 다시 발행·처음 공개 사건으로 갱신해야 한다(docs/20 §3-1).

**공개 조건 (docs/22 §5, docs/06 R-2a)**

- **FR-018**: 태그별 목록, 태그 글 수, 전체 태그 목록, 자동완성의 공개 글 수, 블로그 태그 줄에는 발행·전체 공개·휴지통 아님·관리자
  숨김 아님·작성자가 탈퇴 신청하지 않은 글만 들어가야 한다. 친구 공개를 적용하더라도 태그별 목록과 전체 태그 목록에는 전체 공개
  글만 들어가야 한다.

**태그별 목록 `/tags/{이름}` (T-8·T-10)**

- **FR-019**: 태그 페이지는 상단에 `#이름 · 공개 글 N`을, 아래에 홈과 같은 카드·9개·[더 보기]·정렬(처음 공개된 시각 최신순,
  같으면 번호 큰 순)·불러오는 중·실패 표시를 보여야 한다. 커서 규칙은 003과 같다.
- **FR-020**: 태그 주소는 이름을 경로 조각으로 인코딩해 만들어야 하며(`#`은 반드시 인코딩, `+`·`.`은 그대로), 허용 문자로 된 모든
  태그가 주소로 왕복되어야 한다.
- **FR-021**: 정규화되지 않은 태그 주소는 정규화된 주소로 영구 이동시켜야 하고, 형식에 맞지 않는 이름은 "찾을 수 없음"이어야
  한다.
- **FR-022**: 형식에 맞지만 공개 글이 없는 태그는 정상 페이지와 "아직 이 태그로 공개된 글이 없어요"를 보여야 하며, 비공개 글에만
  쓰인 태그와 아무도 안 쓴 태그의 응답이 같아야 한다.

**전체 태그 목록 `/tags` (T-8, docs/22 §6)**

- **FR-023**: 전체 태그 목록은 공개 글 수 많은 순(같으면 이름 순) 상위 100개를 글 수와 함께 보여야 하며, 공개 글 수 0인 태그는
  빼야 한다. 하나도 없으면 "아직 태그가 없어요"를 보여야 한다.
- **FR-024**: 전체 태그 목록은 10분마다 다시 계산해 둔 값을 써도 되며, 계산해 둔 값이 없으면 바로 계산해야 한다.

**자동완성 (T-9, docs/22 §7)**

- **FR-025**: 자동완성은 로그인한 회원만 쓸 수 있어야 한다(2026-10-07 확정: 비회원은 로그인 필요로 거부).
- **FR-026**: 검색어도 같은 정규화를 거치되 금칙어 검사는 빼고, 앞부분이 일치하는 태그를 찾아야 한다. 정리 결과가 비면 빈 목록이다.
- **FR-027**: 후보는 ① 내가 쓴 태그(내 모든 글, 공개 범위 무관) ② 공개 글 수 1 이상인 태그뿐이며, 남의 비공개 글에만 쓰인 태그는
  나오지 않아야 한다. 내가 쓴 태그 먼저, 그다음 공개 글 수 많은 순으로 최대 10개다.
- **FR-028**: 입력이 0.3초 멈출 때 부르고, 한글 조합 중에는 부르지 않으며, 늦게 도착한 이전 응답은 버려야 한다. 불러오는 중에는
  아무것도 띄우지 않는다.
- **FR-029**: 자동완성은 사용자당 1분에 60번으로 제한하고, 후보 없음·실패·제한 초과 때는 목록을 띄우지 않고 입력을 막지 않아야
  한다.

**블로그 안 태그 필터 (T-8, docs/22 §8)**

- **FR-030**: 개인 블로그 상단에 그 블로그 글에 쓰인 태그와 글 수를 글 수 많은 순으로 처음 10개 + [태그 더 보기]로 보여야 한다.
  대상은 블로그 목록과 같은 조건이다(본인이 봐도 비공개 글 제외).
- **FR-031**: `/@handle?tag=이름`은 그 태그의 글만 블로그 목록과 같은 카드·9개·[더 보기]로 보이고 [필터 해제]를 제공해야 한다.
  정규화되지 않은 값은 정규화된 주소로 영구 이동시켜야 한다.

**글 상세 표시 (docs/22 §9)**

- **FR-032**: 글 상세에 태그를 입력 순서대로 `#이름`으로 보이고, 누르면 인코딩된 태그 주소로 가야 한다. 목록 카드에는 태그를
  보이지 않는다.

### Key Entities *(include if feature involves data)*

- **태그(Tag)**: 정규화된 이름(고유). 쓰는 글이 없어도 남는다.
- **글 태그(PostTag)**: 글과 태그의 연결과 입력 순서. 한 글에 같은 태그 하나, 같은 순서 번호 하나.
- **글(Post)**: 002에서 정의. 태그 목록·글 수는 공개 조건을 만족하는 글만 센다.
- **목록 커서(Cursor)**: 003에서 정의. 태그별 목록·블로그 필터도 같은 형식을 쓰고, 다른 목록의 커서는 거부한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: docs/22 §2-1의 예시 입력 전체가 기대한 결과(또는 거부 이유)와 100% 일치한다. 특히 `Spring Boot`, `spring-boot`,
  `#SPRING  BOOT`, `ｓｐｒｉｎｇ ｂｏｏｔ`는 모두 같은 태그 하나가 된다.
- **SC-002**: 같은 새 태그로 동시에 10건 발행해도 그 태그는 하나만 생긴다.
- **SC-003**: 비공개·임시·휴지통·숨김·탈퇴 신청 작성자의 글이 태그별 목록·전체 태그 목록·자동완성·태그 글 수에 섞이는 경우가
  0건이다.
- **SC-004**: 비공개 글에만 쓰인 태그와 아무도 안 쓴 태그의 태그 페이지 응답을 외부에서 구별할 수 있는 경우가 0건이고, 남의
  비공개 글에만 쓰인 태그가 남의 자동완성·전체 목록에 나오는 경우가 0건이다.
- **SC-005**: `c#`, `c++`, `node.js`, `.net`, `스프링-부트` 태그 주소가 실제 보안 설정을 거쳐 모두 정상 페이지로 열린다.
- **SC-006**: 작성자가 자동완성 후보를 골라 태그 하나를 추가하는 데 키 입력 3번과 선택 1번이면 충분하다.
- **SC-007**: docs/22 §10의 공통 완료 기준 8가지와 docs/05 §4 태그 검증 항목이 모두 자동 테스트로 확인된다.

## Assumptions

- **A-1 (2026-10-07 확정)**: 자동완성은 로그인 필요다. docs/42 §10-2의 비회원 칸("공개 글의 태그")은 이 결정에 따라 수정될
  예정이다. GitHub 단독 로그인(001 A-1)이라 인증 전 회원은 없으며, 이메일 가입이 들어오면 인증 전 회원도 자동완성을 쓸 수 있다.
- **A-2**: 검색창에 `#태그`를 입력하면 태그 페이지로 이동하는 규칙(T-11)은 검색 기능이 들어올 때 함께 적용한다. AI 태그 추천도
  이 spec의 정규화 규칙을 그대로 쓰고 실패한 추천은 조용히 버린다. 둘 다 이 spec의 범위가 아니다.
- **A-3**: 기간 기준의 "최근 많이 쓰인 태그"는 트렌딩 담당이 정하며 범위 밖이다. `/tags`는 누적 공개 글 수 기준이다.
- **A-4**: 친구 공개 적용자의 블로그 태그 줄·필터는 친구가 볼 때 친구 공개 글도 포함한다(선택 구현, 범위 밖).
- **A-5**: 발행하지 않고 닫은 태그를 이 기기에 남기는 동작은 002 A-1의 이 기기 보관 기능이 들어올 때 함께 적용한다.
- **A-6**: 글 상세에서 태그의 위치(제목 아래 또는 본문 끝)는 글 상세 담당이 정한다.
- **A-7**: 태그 하나의 공개 글이 수천 개를 넘을 때의 정렬 성능 보강은 공통 비기능 기준(1만 건)에서는 필요 없다고 본다.
