## User Scenarios & Testing *(mandatory)*

### User Story 1 - 발행할 때 태그를 붙이면 같은 뜻의 태그가 하나로 모인다 (Priority: P1)

작성자는 발행 설정 창에서 공개 범위와 함께 태그를 입력한다. `Spring Boot`, `#spring-boot`, `ｓｐｒｉｎｇ ｂｏｏｔ`처럼 모양이 달라도 같은 뜻이면 같은 태그 `spring-boot`가 되고, `c++`·`c#`·`node.js`·`.net` 같은 기술 이름은 서로 구분된다. 입력한 순서가 그대로 표시 순서가 된다.

**Why this priority**: 태그가 흩어지면 태그별 목록·검색·AI 추천이 모두 쓸모없어진다. 정규화 규칙은 검색·AI 태그 추천도 그대로 쓰는 공통 기반이다.

**Independent Test**: 여러 모양의 입력으로 글을 발행한 뒤 글 상세의 태그와 저장된 태그 수를 확인한다. 태그 목록 화면이 없어도 검증된다.

**Acceptance Scenarios**:

1. **Given** 이메일 인증을 마친 작성자, **When** 태그 `Spring Boot`, `spring-boot`, `#SPRING  BOOT`, `ｓｐｒｉｎｇ ｂｏｏｔ`를 넣어 발행, **Then** 글에는 태그 `spring-boot` 하나만 붙는다.
2. **Given** 태그 입력 `C++`, `C#`, `Node.JS`, `.NET`, `스프링  부트`, **When** 발행, **Then** 태그는 입력 순서대로 `c++`, `c#`, `node.js`, `.net`, `스프링-부트`로 보인다.
3. **Given** 태그 중 `🔥hot`(허용되지 않는 문자), 31자 태그, 금칙어가 섞여 있음, **When** 발행, **Then** 발행되지 않고 문제가 있는 태그가 각각 몇 번째인지와 이유가 **모두** 함께 안내된다. 금칙어는 어떤 단어인지 알려주지 않는다.
4. **Given** 중복을 지운 뒤 태그가 최대 개수(기본 10개)를 넘음, **When** 발행, **Then** 발행되지 않고 개수 초과가 안내된다.
5. **Given** 두 작성자가 아직 없는 같은 새 태그로 동시에 발행, **When** 두 발행이 모두 끝남, **Then** 그 태그는 하나만 존재하고 두 글 모두에 붙는다.
6. **Given** 이미 발행된 글, **When** 태그만 바꿔 다시 발행, **Then** 태그가 새 목록으로 통째로 바뀌고 글에 "수정됨"이 표시된다.
7. **Given** 발행 설정 창에 태그를 입력하다가 발행하지 않고 닫음, **When** 다른 기기에서 그 임시글을 염, **Then** 서버에는 태그가 저장되어 있지 않다 (태그는 발행할 때 확정).

### User Story 2 - 태그를 눌러 그 태그의 공개 글을 모아 본다 (Priority: P2)

독자(비회원 포함)는 글 상세의 `#태그`를 누르거나 태그 주소로 들어가 그 태그가 붙은 공개 글을 최신순 카드로 본다.

**Why this priority**: C-TAG-1의 "태그별 글 목록"이 이 화면이다. 태그를 붙이는 가치가 독자에게 드러나는 곳이다.

**Independent Test**: 공개·비공개·임시·휴지통·숨김·탈퇴 신청 작성자의 글에 같은 태그를 붙여 두고 태그 페이지에 공개 글만 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 태그 `spring-boot`가 붙은 공개 글 12개, **When** 태그 페이지를 엶, **Then** 태그 이름·공개 글 수 12와 함께 최근 공개 순으로 카드 9개, [더 보기]로 나머지 3개가 중복·누락 없이 이어 붙는다.
2. **Given** 같은 태그가 비공개·임시·휴지통·관리자 숨김 글, 탈퇴 신청한 작성자의 글에도 붙어 있음, **When** 누구든 태그 페이지를 엶, **Then** 그 글들은 목록과 글 수 어디에도 나오지 않는다.
3. **Given** 비공개 글에만 쓰인 태그와 아무도 쓰지 않은 형식에 맞는 태그, **When** 각각 태그 페이지를 엶, **Then** 두 응답은 똑같이 "아직 이 태그로 공개된 글이 없어요" 빈 상태로 보인다.
4. **Given** 태그 `c#`, `c++`, `node.js`, `.net`, `스프링-부트`, **When** 글 상세의 태그 링크를 누름, **Then** 모두 해당 태그 페이지가 정상으로 열린다 (주소 왕복).
5. **Given** 정규화되지 않은 태그 주소(예: `Spring Boot`), **When** 접속, **Then** 정규화된 주소(`spring-boot`)로 영구 이동한다.
6. **Given** 태그가 될 수 없는 이름(예: 이모지만), **When** 접속, **Then** 찾을 수 없음(404와 같은 응답)이 보인다.
7. **Given** [더 보기] 불러오기 실패, **When** 화면 확인, **Then** "불러오지 못했어요 [다시 시도]"가 보이고 이미 보이는 카드는 그대로다.

### User Story 3 - 태그를 입력할 때 기존 태그를 자동완성으로 고른다 (Priority: P3)

로그인한 작성자가 발행 설정 창에서 태그를 입력하면 앞부분이 일치하는 태그를 "내가 쓴 태그 먼저, 그다음 공개 글이 많은 순"으로 최대 10개 제안받는다.

**Why this priority**: 같은 태그를 재사용하게 해 태그가 흩어지는 것을 줄인다. 다만 없어도 태그 입력·발행은 된다.

**Independent Test**: 내 비공개 글 태그, 남의 비공개 글에만 쓰인 태그, 공개 글 태그를 준비하고 자동완성 결과를 비교한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원(이메일 인증 전 포함), **When** `spr`를 입력하고 잠시 멈춤, **Then** `spr`로 시작하는 태그가 내 태그 먼저, 공개 글 수 많은 순으로 최대 10개 보인다.
2. **Given** 남의 비공개 글에만 쓰인 태그 `이직준비`, **When** 다른 회원이 `이직`을 입력, **Then** 그 태그는 후보에 나오지 않는다. 그 글의 작성자 본인에게는 나온다.
3. **Given** 비회원, **When** 자동완성을 요청, **Then** 로그인이 필요하다는 응답을 받는다.
4. **Given** 후보가 없거나 자동완성이 실패·요청 제한에 걸림, **When** 입력 계속, **Then** 목록이 뜨지 않을 뿐 입력한 이름을 Enter로 그대로 새 태그로 추가할 수 있다.
5. **Given** 한글을 조합하는 중, **When** 글자가 아직 완성되지 않음, **Then** 자동완성 요청을 보내지 않는다.

---

### User Story 4 - 전체 인기 태그와 블로그 안 태그로 글을 찾는다 (Priority: P4)

독자는 전체 태그 목록에서 공개 글이 많은 태그 상위 100개를 보고, 개인 블로그에서는 그 블로그의 태그로 글을 걸러 본다.

**Why this priority**: 발견을 돕는 탐색 화면이다. P1~P2가 있으면 없어도 핵심 가치는 유지된다.

**Independent Test**: 태그별 공개 글 수를 맞춘 데이터로 전체 목록 순서와 블로그 필터 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개 글에 쓰인 태그 여러 개, **When** 전체 태그 목록을 엶, **Then** 공개 글 수 많은 순(같으면 이름 순)으로 최대 100개가 글 수와 함께 보이고, 공개 글 수 0인 태그는 없다.
2. **Given** 공개 글에 쓰인 태그가 하나도 없음, **When** 전체 태그 목록을 엶, **Then** "아직 태그가 없어요"가 보인다.
3. **Given** 어떤 블로그, **When** 블로그를 엶, **Then** 그 블로그의 태그가 글 수 많은 순으로 처음 10개 + [태그 더 보기]로 보이고, 태그를 누르면 그 태그의 글만 블로그 목록과 같은 카드·9개씩으로 보이며 [필터 해제]로 돌아간다.
4. **Given** 블로그 태그 필터에 정규화되지 않은 값, **When** 접속, **Then** 정규화된 주소로 영구 이동한다.

---

### Edge Cases

- `...`, `---`, `#`처럼 한글·영문·숫자가 하나도 없는 입력, `ㅋㅋ`처럼 완성되지 않은 한글은 태그가 될 수 없다.
- 맨 앞의 `#`은 모두 지우지만(`##jpa` → `jpa`), 뒤의 `#`은 남긴다(`c#`).
- 보이지 않는 글자·방향 제어 문자가 섞인 입력은 그 글자를 지운 뒤 판정한다. 허용되지 않는 문자(이모지·`/`·`@`)는 몰래 지우지 않고 거부한다.
- `Spring`과 `spring`을 함께 입력하면 처음 나온 것 하나만 남고 순서는 그 자리를 따른다.
- 태그를 쓰는 글이 모두 지워져도 태그 자체는 남지만, 목록·자동완성·글 수에는 나오지 않는다.
- 글이 비공개로 바뀌거나 휴지통에 가거나 관리자에게 숨겨지면 즉시 그 태그 목록과 글 수에서 빠진다. 전체 태그 목록의 글 수는 최대 10분 늦게 반영될 수 있다.
- 작성자가 탈퇴를 신청하면 그 글들이 태그 목록에서 빠지고, 복구하면 돌아온다.
- 자동완성 응답이 늦게 와서 순서가 뒤바뀌면 이전 요청의 응답은 버린다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 모든 태그 입력(발행, 자동완성 검색어, 태그 주소, 블로그 태그 필터)을 하나의 정규화 규칙으로 처리해야 한다: 호환 문자 정규화(전각 → 반각) → 보이지 않는 글자·제어 문자 제거 → 앞뒤 공백 제거 → 맨 앞 `#` 모두 제거 → 소문자 → 공백 묶음을 `-` 하나로 → 연속 `-`는 하나로, 처음·끝의 `-` 제거.
- **FR-002**: System MUST 정규화 결과가 완성된 한글·영문 소문자·숫자와 기호 `-` `_` `.` `+` `#`만으로 이루어지고, 한글·영문·숫자를 1자 이상 포함하며, 1~30자(코드 포인트 기준)일 때만 태그로 받아들여야 한다. 그 밖은 지우지 않고 거부한다.
- **FR-003**: System MUST 발행할 때 태그에 금칙어 필터(닉네임과 같은 필터)를 적용하고, 걸리면 거부하되 어떤 단어인지는 알려주지 않아야 한다.
- **FR-004**: System MUST 한 글의 태그에서 정규화 후 같은 이름은 처음 나온 것만 남기고, 남은 순서를 표시 순서로 저장해야 한다.
- **FR-005**: System MUST 중복을 지운 뒤 태그 개수가 설정값(기본 10개)을 넘으면 발행을 거부해야 한다. 최대 개수는 팀원마다 설정으로 바꿀 수 있어야 한다.
- **FR-006**: System MUST 태그 검증에 실패하면 문제가 있는 태그를 **모두** 몇 번째 입력인지와 이유(허용되지 않는 문자 / 너무 김 / 금칙어 / 개수 초과)와 함께 한 번에 알려주고, 글은 발행하지 않아야 한다.
- **FR-007**: System MUST 태그를 발행(또는 다시 발행)할 때만 확정해야 한다. 자동 저장·임시 저장은 태그를 서버에 저장하지 않는다.
- **FR-008**: System MUST 다시 발행할 때 그 글의 태그를 새 목록으로 통째로 교체하고, 태그만 바꾼 경우에도 글에 "수정됨"을 표시해야 한다.
- **FR-009**: System MUST 같은 새 태그로 동시에 여러 글이 발행되어도 그 태그를 하나만 만들어야 한다.
- **FR-010**: System MUST 쓰는 글이 없어진 태그를 지우지 않되, 공개 글 수가 0인 태그는 목록·자동완성·글 수에 보이지 않게 해야 한다.
- **FR-011**: Users MUST be able to 태그 페이지에서 그 태그가 붙은 글 중 **발행·전체 공개·휴지통 아님·관리자 숨김 아님·작성자 탈퇴 신청 아님**인 글만, 공개 글 수와 함께, 다른 공통 목록과 같은 카드·9개씩·[더 보기]·최근 공개 순으로 볼 수 있어야 한다. 친구 공개를 적용한 서비스에서도 태그 목록에는 전체 공개 글만 나온다.
- **FR-012**: System MUST 형식에 맞지만 공개 글이 없는 태그의 페이지를, 아무도 쓰지 않은 태그와 구분할 수 없게 같은 빈 상태("아직 이 태그로 공개된 글이 없어요")로 보여야 한다.
- **FR-013**: System MUST 형식에 맞지 않는 태그 주소에는 찾을 수 없음(404와 같은 응답)을, 정규화되지 않은 태그 주소에는 정규화된 주소로 영구 이동을 응답해야 한다.
- **FR-014**: System MUST 허용 문자로 된 모든 태그(`c#`, `c++`, `node.js`, `.net`, 한글 포함)가 링크 → 주소 → 태그 페이지로 손실 없이 왕복되도록 링크를 만들어야 한다.
- **FR-015**: Users MUST be able to 전체 태그 목록에서 공개 글 수 상위 100개 태그를 글 수 많은 순(같으면 이름 순)으로 볼 수 있어야 한다. 이 목록은 최대 10분 늦게 반영될 수 있다.
- **FR-016**: System MUST 자동완성을 로그인한 회원(이메일 인증 전 포함)에게만 제공하고, 비회원 요청은 로그인이 필요하다고 응답해야 한다.
- **FR-017**: System MUST 자동완성 후보를 "정규화한 검색어로 앞부분이 일치하는 태그" 중 ① 요청한 회원이 쓴 태그(공개 범위 무관) ② 공개 글 수가 1 이상인 태그로 한정하고, 내 태그 먼저·공개 글 수 많은 순으로 최대 10개를 돌려줘야 한다. 남의 비공개 글에만 쓰인 태그는 후보에 나오지 않는다.
- **FR-018**: System MUST 자동완성 요청을 회원당 1분에 60번으로 제한하고, 실패·제한·후보 없음일 때 화면은 목록을 띄우지 않을 뿐 태그 입력을 막지 않아야 한다.
- **FR-019**: Users MUST be able to 블로그에서 그 블로그의 태그와 글 수를 보고(처음 10개 + 더 보기), 태그 하나로 블로그 글을 걸러 볼 수 있어야 한다. 대상 글은 그 블로그 목록과 같은 공개 조건을 따른다.
- **FR-020**: System MUST 글 상세에 태그를 저장된 순서대로 `#이름` 모양의 태그 페이지 링크로 보여야 한다. 목록 카드에는 태그를 보이지 않는다.
- **FR-021**: 발행 설정 창은 Enter 또는 쉼표로 태그를 추가하고, 입력하자마자 정규화한 모양을 미리 보여주며, 칩 삭제·끌어서(키보드로도) 순서 바꾸기·다시 발행 때 기존 태그 미리 채우기를 제공해야 한다. 오류 태그는 색만이 아니라 글자로도 표시한다. 화면의 정규화는 안내용이며 최종 판정은 서버가 한다.

### Key Entities *(include if feature involves data)*

- **태그 (`tag`)**: 정규화된 이름 하나로 식별되는 전역 태그. 글이 없어져도 남는다.
- **글-태그 연결 (`post_tag`)**: 글과 태그의 다대다 연결. 한 글 안에서 태그 중복이 없고, 입력한 순서(표시 순서)를 가진다.
- **글 (`post`)**: 공개 범위·상태·휴지통·숨김 여부와 최초 공개 일자로 태그 목록 노출 여부와 정렬을 결정한다 ([005-post-publish](../005-post-publish/spec.md)).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 근거 문서 §2-1의 정규화 예시(정상 10개·거부 6종) 전부가 기대한 결과와 100% 일치한다.
- **SC-002**: 허용되지 않는 문자·금칙어·31자 이상·개수 초과가 섞인 발행 요청은 100% 거부되고, 문제가 있는 태그가 빠짐없이 한 번에 안내된다.
- **SC-003**: 발행된 모든 글에서 태그는 입력 순서로 보이고 한 글에 같은 태그가 두 번 나오는 경우가 0건이다.
- **SC-004**: 태그별 목록·전체 태그 목록·자동완성·태그 글 수에 비공개·임시·휴지통·숨김·탈퇴 신청 작성자의 글이 섞이는 경우가 0건이다 (권한 매트릭스의 "태그" 열로 확인).
- **SC-005**: 비공개 글에만 쓰인 태그의 페이지와 아무도 쓰지 않은 태그의 페이지 응답을 비교했을 때 구분할 수 있는 차이가 없고, 그 태그는 남의 자동완성·전체 목록에 0건 나온다.
- **SC-006**: `c#`, `c++`, `node.js`, `.net`, `스프링-부트` 태그 링크가 실제 보안 설정을 거친 상태에서 100% 태그 페이지로 정상 왕복된다.
- **SC-007**: 정규화되지 않은 태그 주소는 100% 정규화된 주소로 영구 이동한다.
- **SC-008**: 같은 새 태그로 동시에 10건을 발행해도 그 태그는 1개만 존재한다.
- **SC-009**: 공개 글 1만 건 기준으로 태그 페이지와 자동완성 결과가 사용자가 기다림을 느끼지 않을 만큼(공통 비기능 기준 이내) 빠르게 보인다.

## Assumptions

- 글 발행·다시 발행 흐름과 공통 오류 형식은 [005-post-publish](../005-post-publish/spec.md)가 정하고, 이 spec은 그 안의 태그 검증·저장 규칙만 다룬다.
- 공개 조건(발행 + 전체 공개 + 휴지통 아님 + 숨김 아님 + 작성자 탈퇴 신청 아님)은 01 결정 기록 2026-10-07 "숨긴 글 조건"을 따른다. 22 문서 §5의 예시 조건에 숨김이 빠져 있으나 최신 결정을 우선한다.
- 자동완성은 01 결정 기록 2026-10-07에 따라 로그인 필요로 통일한다 (42 §10-2의 비회원 "공개 글의 태그" 칸은 수정 대상).
- 금칙어 목록·판정은 닉네임 spec의 필터를 재사용한다.
- 검색창에서 `#태그` 한 단어를 입력하면 태그 페이지로 이동하는 규칙(22 T-11)은 [015-search](../015-search/spec.md)가 구현하며, 같은 정규화 규칙을 쓴다.
- AI 태그 추천([019-ai-tag-suggest](../019-ai-tag-suggest/spec.md))은 이 spec의 정규화를 통과한 결과만 제안한다.
- 기간 기준 "최근 인기 태그"는 트렌딩([018-trending](../018-trending/spec.md)) 범위다. 전체 태그 목록은 누적 공개 글 수 기준이다.
- 태그 최대 개수 기본값은 10개이며 팀원별 설정값으로 바꿀 수 있다(강성찬 원안 5개 등).
- 개인 확장(카테고리·시리즈·주제 등)은 범위 밖이다.
