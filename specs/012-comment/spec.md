## User Scenarios & Testing *(mandatory)*

### User Story 1 - 글에 댓글을 남기고 오래된 순으로 읽는다 (Priority: P1)

이메일 인증을 마친 회원은 읽을 수 있는 발행 글에 1~1000자 글자 댓글을 남긴다. 독자(비회원 포함)는 글 아래에서 댓글을 오래된 순으로 20개씩 읽는다.

**Why this priority**: 댓글이 없으면 답글·수정·삭제도 의미가 없다. C-CMT-1의 최소 단위다.

**Independent Test**: 공개 글에 댓글을 25개 남기고 비회원으로 목록을 열어 20개 + [댓글 더 보기] 5개가 중복·누락 없이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이메일 인증을 마친 회원과 공개 발행 글, **When** "좋은 글이에요"를 등록, **Then** 댓글이 목록 끝에 `닉네임 @블로그주소`·작성 시각과 함께 보이고 머리말의 댓글 수가 1 늘어난다.
2. **Given** 비회원, **When** 댓글 영역을 봄, **Then** 입력칸 대신 "로그인하고 댓글을 남겨 보세요 [로그인]"이 보이고, 직접 요청하면 로그인이 필요하다는 응답을 받는다.
3. **Given** 이메일 인증 전 회원, **When** 댓글 영역을 봄, **Then** "이메일 인증 후 댓글을 쓸 수 있어요"가 보이고, 직접 요청하면 인증이 필요하다는 응답을 받는다.
4. **Given** 내용에 `<script>`, Markdown, 주소, 줄바꿈이 섞임, **When** 등록 후 봄, **Then** HTML·Markdown은 실행·변환되지 않고 쓴 글자 그대로, 주소는 링크가 아닌 글자로, 줄바꿈은 유지되어 보인다.
5. **Given** 공백만 입력하거나 1000자를 넘김, **When** 등록, **Then** "댓글 내용을 입력해 주세요" / "댓글은 1000자까지 쓸 수 있어요"가 보이고 입력한 내용은 그대로 남는다.
6. **Given** 같은 회원이 같은 글에 같은 내용을 10초 안에 여러 번(동시 포함) 보냄, **When** 모두 처리됨, **Then** 댓글은 하나만 생기고 이후 요청은 처음 댓글을 돌려받는다.
7. **Given** 최상위 댓글이 25개이고 일부가 같은 시각에 작성됨, **When** 첫 화면 후 [댓글 더 보기], **Then** 20개 + 5개가 중복·누락 없이 오래된 순으로 이어진다.
8. **Given** 글 작성자가 단 댓글, **When** 목록을 봄, **Then** 그 댓글에 [작성자] 배지가 보인다.

### User Story 2 - 답글로 대화를 이어 간다 (1단계) (Priority: P2)

회원은 댓글에 답글을 단다. 답글에 다시 답하면 같은 최상위 댓글 아래에 달리고 "@닉네임에게"로 대상이 표시된다. 답글은 처음 3개만 보이고 나머지는 [답글 N개 더 보기]로 펼친다.

**Why this priority**: C-CMT-1의 "답글"이다. 1단계 구조를 지키면서 대화 상대가 보여야 한다.

**Independent Test**: 최상위 → 답글 → 답글의 답글을 작성한 뒤 저장 구조(모두 같은 최상위 소속)와 대상 표시를 확인한다.

**Acceptance Scenarios**:

1. **Given** 최상위 댓글 A와 그 답글 B, **When** 다른 회원이 B에 답함, **Then** 새 답글은 A 아래(B와 같은 단계)에 달리고 내용 위에 "@B작성자닉네임에게"가 보인다.
2. **Given** 최상위 댓글 A, **When** A에 바로 답함, **Then** 대상 표시 없이 A 아래에 달린다. 내가 내 답글에 답해도 대상 표시는 없다.
3. **Given** 답글이 8개인 댓글, **When** 목록을 봄, **Then** 처음 3개와 [답글 5개 더 보기]가 보이고, 누르면 나머지가 20개씩 중복 없이 펼쳐진다.
4. **Given** 삭제된 자리·숨겨진 댓글·탈퇴 신청한 작성자의 댓글·다른 글의 댓글, **When** 그 댓글에 답글을 요청, **Then** "답글을 달 수 없는 댓글이에요"로 거부된다.
5. **Given** 대상 회원이 이후 탈퇴함, **When** 답글을 봄, **Then** "탈퇴한 사용자에게"로 표시된다.

### User Story 3 - 내 댓글을 고치거나 지운다 (Priority: P3)

작성자 본인만 자기 댓글을 수정·삭제한다. 글 작성자도 남의 댓글은 지울 수 없다. 답글이 달린 최상위 댓글을 지우면 "삭제된 댓글이에요"로 자리만 남아 대화가 보존된다.

**Why this priority**: "본인만 수정·삭제"와 "답글이 있으면 자리를 남김"은 C-CMT-1 완료 기준이다.

**Independent Test**: 다른 회원·글 작성자로 수정·삭제를 시도하고, 답글 있는/없는 댓글을 각각 지워 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** 내 정상 댓글, **When** 내용을 바꿈, **Then** 새 내용과 "· 수정됨"이 보인다. 정리 후 같은 내용이면 아무것도 바뀌지 않고 "수정됨"도 붙지 않는다.
2. **Given** 남의 댓글(내가 글 작성자여도), **When** 수정·삭제를 요청, **Then** 찾을 수 없음(404와 같은 응답)이고 댓글은 바뀌지 않는다.
3. **Given** 답글이 있는 내 최상위 댓글, **When** 삭제, **Then** 작성자 정보 없이 "삭제된 댓글이에요"로 자리만 남고 원래 내용은 저장소에서도 비워지며 답글은 그대로다.
4. **Given** 답글이 없는 댓글 또는 답글, **When** 삭제, **Then** 행이 사라진다. 그 답글이 "삭제된 자리"의 마지막 답글이었으면 자리도 함께 사라진다.
5. **Given** 답글 작성과 최상위 삭제가 동시에 일어남, **When** 둘 다 처리됨, **Then** 답글이 먼저면 최상위는 자리로 남고, 삭제가 먼저면 답글은 "답글을 달 수 없는 댓글이에요"로 거부된다.
6. **Given** 삭제된 댓글, **When** 복구를 찾음, **Then** 복구 기능은 없다.

---

### User Story 4 - 숨김·탈퇴·글 상태에 따라 댓글이 안전하게 보인다 (Priority: P4)

관리자가 숨긴 댓글, 탈퇴 신청한 사람의 댓글, 볼 수 없게 된 글의 댓글은 정해진 문구로 보이거나 아예 보이지 않는다.

**Why this priority**: 권한 누출을 막고 댓글 수를 정확히 유지한다. 다른 spec(신고·숨김, 탈퇴)과 맞물린다.

**Independent Test**: 숨김·삭제·탈퇴 유예·비공개 전환을 각각 만든 뒤 남/본인 시점의 표시와 댓글 수를 비교한다.

**Acceptance Scenarios**:

1. **Given** 관리자가 숨긴 댓글, **When** 다른 사람이 봄, **Then** 작성자 정보 없이 "운영 정책에 따라 숨겨진 댓글이에요"만 보이고, 작성자 본인에게는 원문 + "숨겨졌어요 (나만 보여요)"가 보인다. 숨긴 최상위의 답글은 그대로 보인다.
2. **Given** 숨겨진 내 댓글, **When** 수정·답글을 시도, **Then** "숨겨진 댓글은 수정할 수 없어요" / 답글 불가로 거부되고, 삭제는 할 수 있다.
3. **Given** 탈퇴를 신청한 회원의 댓글, **When** 남이 봄, **Then** "탈퇴한 사용자"·"탈퇴한 사용자의 댓글이에요"로 보이고 댓글 수는 그대로다. 복구하면 원래대로 돌아온다.
4. **Given** 임시글·비공개 글(남이 볼 때)·휴지통 글·없는 글·작성자 탈퇴 신청 글·관리자 숨김 글, **When** 댓글 보기·쓰기·수정을 요청, **Then** 모두 같은 찾을 수 없음(404와 같은 응답)이다. 빈 내용을 보내도 내용 오류가 아니라 찾을 수 없음이다.
5. **Given** 비공개로 바뀐 뒤 다시 공개된 글, **When** 댓글을 봄, **Then** 기존 댓글이 그대로 돌아온다.
6. **Given** 알림에서 특정 댓글로 이동, **When** 글을 엶, **Then** 그 댓글이 있는 위치까지 불러와 강조된다. 대상이 없거나 볼 수 없는 댓글이면 오류 없이 첫 페이지가 보인다.

---

### Edge Cases

- 이모지 같은 문자는 한 글자로 세어 1000자 제한을 판단한다.
- 보이지 않는 글자·제어 문자는 지우되 줄바꿈은 남기고, 연달아 있는 빈 줄은 하나로 줄인다.
- 금칙어 필터는 없다. 문제 댓글은 신고로 처리한다.
- 회원당 작성은 1분에 10개, 수정은 1분에 20번을 넘으면 "잠시 후 다시 시도해 주세요"로 거부된다. 요청 제한은 대상 글의 존재 여부를 드러내지 않는 순서로 판정한다.
- 탈퇴 30일 뒤 정리: 답글이 있는 그 회원의 최상위 댓글은 자리만, 나머지는 삭제되고 각 글의 댓글 수가 그만큼 준다. 그 회원의 글에 달린 댓글은 글과 함께 지워진다.
- 글이 완전 삭제되면 그 글의 댓글도 함께 삭제된다. 휴지통·비공개 동안에는 댓글이 보존된다.
- 등록·불러오기 실패 시 입력한 내용·이미 보이는 댓글은 그대로 두고 "불러오지 못했어요 [다시 시도]" 등으로 안내한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 로그인하고 이메일 인증을 마친(탈퇴 유예가 아닌) 회원만 댓글·답글을 작성하게 해야 한다. 비회원은 로그인 필요, 인증 전·탈퇴 유예 회원은 계정 상태 오류로 응답한다.
- **FR-002**: System MUST 지금 읽을 수 있는 발행 글에만 댓글 보기·작성·수정을 허용하고, 그 밖의 글(임시·남의 비공개·휴지통·관리자 숨김·작성자 탈퇴 유예·없는 글)은 모두 같은 찾을 수 없음(404와 같은 응답)으로 응답해야 한다.
- **FR-003**: System MUST 판정 순서를 로그인 → 계정 상태 → 요청 제한 → 글을 볼 수 있나 → 내용·대상 댓글 검사로 지켜, 볼 수 없는 글에는 내용 오류보다 찾을 수 없음을 먼저 돌려줘야 한다.
- **FR-004**: System MUST 댓글 내용을 정리(유니코드 정규화, 보이지 않는 글자 제거·줄바꿈 유지, 줄바꿈 통일, 앞뒤 공백 제거, 연속 빈 줄 하나로)한 뒤 1~1000자(코드 포인트)인지 검사해야 한다.
- **FR-005**: System MUST 댓글을 글자로만 보여야 한다: HTML·Markdown은 실행·변환하지 않고, 주소는 자동 링크로 바꾸지 않으며, 줄바꿈은 유지한다.
- **FR-006**: System MUST 답글 구조를 1단계로 유지해야 한다: 모든 답글은 최상위 댓글에 속하고, 답글에 답하면 같은 최상위 아래에 저장하며 대상 회원을 기록한다(내가 내 답글에 답하거나 최상위에 바로 답하면 대상 없음).
- **FR-007**: System MUST 답글 대상이 같은 글의 정상 상태(삭제·숨김·작성자 탈퇴 아님) 댓글이 아니면 "답글을 달 수 없는 댓글"로 거부해야 한다. 다른 글의 댓글을 부모로 지정하는 것은 저장 단계에서도 막는다.
- **FR-008**: Users MUST be able to 최상위 댓글을 오래된 순으로 20개씩 [댓글 더 보기]로, 답글은 각 최상위마다 처음 3개 + [답글 N개 더 보기](20개씩)로 중복·누락 없이 볼 수 있어야 한다.
- **FR-009**: System MUST 댓글마다 프로필 사진, 현재 `닉네임 @블로그주소`, 작성 시각(공통 날짜 형식), 내용이 바뀐 경우 "수정됨", 글 작성자의 댓글이면 [작성자] 배지, 대상이 있으면 "@닉네임에게"를 보여야 한다.
- **FR-010**: System MUST 상태 표시를 탈퇴한 사람 → 삭제된 자리 → 관리자 숨김 → 정상 순으로 하나만 적용하고, 탈퇴·삭제·(남이 보는) 숨김 상태에서는 내용과 작성자 정보를 내보내지 않아야 한다.
- **FR-011**: System MUST 버튼을 상태에 맞게 보여야 한다: [답글]은 정상 댓글에만, [수정]·[삭제]는 본인 정상 댓글에, [신고]는 남의 정상 댓글에.
- **FR-012**: Users MUST be able to 자기 정상 댓글을 언제든 수정할 수 있어야 하며, 이력은 남기지 않고 알림도 보내지 않는다. 정리 후 같은 내용이면 아무것도 바꾸지 않는다.
- **FR-013**: System MUST 남의 댓글(글 작성자 포함)에 대한 수정·삭제 요청을 찾을 수 없음으로 거부하고 댓글을 바꾸지 않아야 한다. 관리자도 댓글을 수정·삭제하지 않고 숨김만 한다.
- **FR-014**: System MUST 삭제할 때 답글이 있는 최상위 댓글은 내용을 비우고 "삭제된 댓글이에요" 자리로 남기고, 그 밖의 댓글은 행을 지우며, 마지막 답글이 지워진 자리는 함께 지워야 한다. 댓글 복구는 없다.
- **FR-015**: System MUST 최상위 댓글 삭제와 답글 작성이 동시에 일어나도 "자리 없이 답글만 남는" 상태나 답글 유실이 생기지 않게 순서를 정해야 한다.
- **FR-016**: System MUST 관리자가 숨긴 댓글을 남에게는 "운영 정책에 따라 숨겨진 댓글이에요"로, 작성자에게는 원문 + "숨겨졌어요 (나만 보여요)"로 보여야 하며, 숨긴 댓글의 수정·답글은 막고 본인 삭제는 허용해야 한다.
- **FR-017**: System MUST 글의 댓글 수를 항상 "삭제·숨김이 아닌 댓글(최상위 + 답글) 수"와 같게 유지해야 한다: 작성 +1, 삭제 −1, 숨김 −1, 해제 +1, 탈퇴 정리 −n. 탈퇴 유예 중인 댓글은 센다.
- **FR-018**: System MUST 같은 회원·같은 글·같은 내용·같은 대상 요청이 10초 안에 반복되면 새 댓글을 만들지 않고 처음 댓글을 돌려줘야 한다.
- **FR-019**: System MUST 작성은 회원당 1분에 10개, 수정은 1분에 20번으로 제한하고 넘으면 다시 시도할 시간과 함께 거부해야 한다.
- **FR-020**: System MUST 탈퇴 신청한 회원의 댓글을 유예 동안 "탈퇴한 사용자의 댓글이에요"로 보이고(복구 시 원래대로), 30일 뒤 정리 때 답글이 있는 최상위는 자리만 남기고 나머지는 지우며 댓글 수를 맞춰야 한다.
- **FR-021**: System MUST 알림에서 특정 댓글로 들어오면 그 댓글이 보이도록 해당 위치까지 불러와 강조하고, 대상이 그 글의 볼 수 있는 댓글이 아니면 오류 없이 첫 페이지를 보여야 한다(존재 여부를 드러내지 않음).
- **FR-022**: System MUST 댓글 목록 한 페이지를 고정된 적은 횟수의 조회로 그려야 한다(댓글 수에 비례해 조회가 늘지 않음).
- **FR-023**: System MUST 댓글 작성·삭제·숨김 사실을 알림 등 후속 기능이 받을 수 있게 저장이 확정된 뒤 알려야 하며(답글 대상 회원 포함), 후속 처리 실패가 댓글 작성을 막지 않아야 한다.

### Key Entities *(include if feature involves data)*

- **댓글 (`comment`)**: 글에 달린 글자 댓글. 속한 최상위 댓글(최상위면 없음), 답글 대상 회원, 내용, 작성·수정 일자, 삭제 일자(자리 표시), 관리자 숨김 정보를 가진다. 같은 글의 댓글만 부모가 될 수 있다.
- **글 (`post`)**: 댓글 수(보이는 댓글 수)를 미리 가지고 있고, 읽기 가능 여부가 댓글 접근을 결정한다.
- **회원 (`member`)**: 댓글 작성자·답글 대상. 탈퇴 유예·익명 처리 상태가 표시를 바꾼다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 비회원·이메일 인증 전 회원의 댓글 작성 시도는 100% 거부된다.
- **SC-002**: 읽을 수 없는 글(임시·비공개·휴지통·숨김·없는 글)의 댓글 보기·쓰기·수정 응답은 모든 경우에 서로 구분되지 않는다 (권한 매트릭스 "댓글" 열).
- **SC-003**: 답글 → 답글의 답글을 작성한 모든 경우에서 저장된 답글은 100% 최상위 댓글에 속하고 대상이 표시된다.
- **SC-004**: 다른 회원·글 작성자의 남의 댓글 수정·삭제 시도는 100% 거부되고 댓글은 바뀌지 않는다.
- **SC-005**: 답글이 있는 최상위 댓글을 지우면 "삭제된 댓글이에요" 자리만 남고 원래 내용은 저장소에 남지 않으며, 마지막 답글이 지워지면 자리도 사라진다.
- **SC-006**: 공통 XSS 공격 문자열 목록을 댓글로 넣었을 때 실행되거나 변환되는 경우가 0건이고 줄바꿈은 유지된다.
- **SC-007**: 동시 작성 20건과 삭제·숨김·해제·탈퇴 정리 뒤에도 글의 댓글 수가 실제 보이는 댓글 수와 100% 같다.
- **SC-008**: 같은 내용 요청 5건을 동시에 보내도 댓글은 1개만 생긴다.
- **SC-009**: 같은 시각 댓글이 커서 경계에 있어도 [댓글 더 보기]·[답글 더 보기] 결과에 중복·누락이 0건이다.
- **SC-010**: 댓글 수와 무관하게 댓글 목록 한 페이지를 그리는 조회 횟수가 일정하다(2회).
- **SC-011**: 숨겨진 댓글의 원문은 작성자 본인 외 누구에게도 0건 노출된다.

## Assumptions

- 글 읽기 판정은 공통 글 접근 규칙 하나를 따르며 그 정의는 공개 범위·글 상세 spec이 정한다.
- 관리자 숨김·해제 동작과 권한, 신고 시 댓글 내용 보관은 [020-report-hide](../020-report-hide/spec.md)가 정한다. 이 spec은 숨김 상태의 표시·제한·댓글 수만 다룬다.
- 댓글 관련 알림(새 댓글·답글, 숨김 통지, 지운 댓글의 알림 정리)은 [016-notification](../016-notification/spec.md)이 정한다.
- 탈퇴 유예·30일 정리의 전체 순서는 회원 탈퇴 spec이 정하고, 이 spec은 댓글 단계의 결과만 정한다.
- 01 결정 기록 2026-10-07(화면 React + REST)에 따라 JS 없이 동작하는 서버 렌더링 대체 규칙은 범위에서 뺀다.
- 화면 색·배치는 각자 자유이고, 표시 정보·페이지 크기·상태 문구는 공통이다.
- 개인 확장(무제한 답글 깊이, 비밀 댓글, 댓글 좋아요, 글 작성자의 댓글 삭제 권한)은 범위 밖이다. 깊이 확장을 켜도 이 spec의 공통 기준은 그대로 통과해야 한다.
