## User Scenarios & Testing *(mandatory)*

### User Story 1 - 남의 글에 좋아요를 누르고 취소한다 (Priority: P1)

이메일 인증을 마친 회원은 읽을 수 있는 남의 발행 글에 좋아요를 누르고, 다시 누르면 취소한다. 버튼과 숫자는 누르는 즉시 바뀌고 서버 결과로 최종 숫자를 맞춘다.

**Why this priority**: C-LIKE-1의 핵심이며 트렌딩 점수의 재료다.

**Independent Test**: 회원으로 좋아요 → 취소 → 좋아요를 하고 화면의 ♡/♥, 숫자, 실제 좋아요 기록 수를 비교한다.

**Acceptance Scenarios**:

1. **Given** 이메일 인증 회원과 남의 공개 발행 글(좋아요 12), **When** 좋아요를 누름, **Then** 즉시 ♥ 13으로 바뀌고 서버도 좋아요 상태·13을 돌려준다.
2. **Given** 이미 좋아요한 글, **When** 다시 누름, **Then** ♡ 12로 취소된다.
3. **Given** 이미 좋아요 상태, **When** "좋아요 상태로" 요청을 다시 보냄, **Then** 결과는 성공이고 수는 바뀌지 않는다 (취소 요청도 같음).
4. **Given** 사용자가 버튼을 빠르게 여러 번 누름, **When** 누르기를 멈춤, **Then** 마지막 상태만 전송되고 화면은 서버의 최종 숫자로 맞춰진다.
5. **Given** 요청이 실패함, **When** 응답을 받음, **Then** 버튼과 숫자가 원래대로 돌아가고 "좋아요를 반영하지 못했어요"가 보인다.
6. **Given** 글 상세를 처음 엶, **When** 화면이 그려짐, **Then** 내가 이미 눌렀는지가 함께 표시된다.

---

### User Story 2 - 동시에 여러 번 눌러도 1건, 숫자는 항상 정확하다 (Priority: P2)

재시도·더블클릭·여러 탭에서 같은 요청이 동시에 가도 한 사람의 좋아요는 1건이고, 글의 좋아요 수는 언제나 실제 좋아요 기록 수와 같다.

**Why this priority**: "동시에 여러 번 눌러도 1건"이 C-LIKE-1 완료 기준이다.

**Independent Test**: 같은 회원이 동시에 좋아요 20번, 좋아요·취소 섞어 40번, 여러 회원 동시 요청을 보내고 수와 실제 기록을 비교한다.

**Acceptance Scenarios**:

1. **Given** 한 회원, **When** 같은 글에 좋아요 요청을 동시에 20번, **Then** 좋아요 기록 1건, 좋아요 수 1이다.
2. **Given** 한 회원, **When** 좋아요 20번과 취소 20번을 동시에 섞어 보냄, **Then** 끝난 뒤 좋아요 수는 실제 기록 수와 같다.
3. **Given** 서로 다른 50명, **When** 같은 글에 동시에 좋아요, **Then** 좋아요 수는 50이다.
4. **Given** 실제로 상태가 바뀐 요청과 이미 그 상태였던 요청, **When** 처리됨, **Then** 상태가 바뀐 요청만 "좋아요됨/취소됨" 사실을 후속 기능(알림·트렌딩)에 알린다.
5. **Given** 좋아요 수가 어떤 이유로 실제 기록 수와 어긋남, **When** 매일 보정 작업이 실행됨, **Then** 어긋난 글만 고쳐지고, 정상 상태에서는 고친 건수가 0이다(0이 아니면 경고가 남는다).

---

### User Story 3 - 누를 수 없는 사람에게는 안내하고 막는다 (Priority: P3)

비회원·이메일 인증 전 회원에게도 버튼은 보이지만 누르면 로그인 또는 이메일 인증을 안내한다. 내 글에는 버튼 대신 숫자만 보인다. 볼 수 없는 글의 좋아요는 존재 자체를 드러내지 않는다.

**Why this priority**: 트렌딩 조작과 권한 누출을 막는다.

**Independent Test**: 비회원·인증 전·작성자·회원 각각으로 볼 수 있는 글과 볼 수 없는 글에 좋아요를 요청해 응답과 수 변화를 확인한다.

**Acceptance Scenarios**:

1. **Given** 비회원, **When** 좋아요 버튼을 누름, **Then** "로그인하고 좋아요를 눌러 보세요 [로그인]"이 보이고, 로그인 후 원래 글로 돌아오지만 좋아요가 자동으로 눌리지는 않는다.
2. **Given** 이메일 인증 전 회원, **When** 누름, **Then** "이메일 인증 후 누를 수 있어요"가 보이고 수는 바뀌지 않는다.
3. **Given** 내 글, **When** 글 상세를 봄, **Then** 버튼 없이 좋아요 수만 보이고, 직접 요청해도 자기 글 좋아요는 거부된다.
4. **Given** 임시글·휴지통 글·남의 비공개 글·관리자 숨김 글·탈퇴 신청한 작성자의 글·없는 글, **When** 누구든 좋아요·취소를 요청, **Then** 다른 이유와 상관없이 같은 찾을 수 없음(404와 같은 응답)이고 수는 바뀌지 않는다.
5. **Given** 한 회원이 1분에 60번을 넘게 좋아요·취소를 요청, **When** 61번째 요청, **Then** 다시 시도할 시간과 함께 거부된다.

---

### Edge Cases

- 글이 비공개·휴지통·관리자 숨김이 되어도 좋아요 기록은 지우지 않고, 볼 수 없는 사람에게는 수와 버튼이 함께 보이지 않는다. 다시 공개·복구되면 그대로 돌아온다.
- 글이 완전 삭제되면 그 글의 좋아요도 함께 지워진다.
- 누른 사람이 탈퇴를 신청하면 유예 동안 좋아요는 그대로이고, 30일 뒤 정리 때 기록이 지워지고 그 글의 좋아요 수가 준다.
- 글을 수정하거나 다시 발행해도 좋아요는 그대로다.
- 좋아요 → 취소 → 좋아요를 반복해도 알림은 같은 사람·같은 글에 한 번만 간다 (알림 쪽 판정).
- 1만 이상은 `1.2만`처럼 소수 첫째 자리까지(내림), 그 아래는 쉼표로 보인다.
- 목록 카드에는 좋아요 수만 보이고 내가 눌렀는지는 보이지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Users MUST be able to 읽을 수 있는 남의 발행 글에 좋아요를 누르고 취소할 수 있어야 한다. 요청은 "좋아요 상태로"/"취소 상태로" 상태 지정 방식이며, 같은 요청을 여러 번 보내도 한 번 보낸 것과 결과가 같다.
- **FR-002**: System MUST 한 회원이 한 글에 남길 수 있는 좋아요를 1건으로 보장하고, 동시에 여러 요청이 와도 이를 지켜야 한다.
- **FR-003**: System MUST 실제로 좋아요 기록이 생기거나 지워진 경우에만 글의 좋아요 수를 바꾸고, 기록 변경과 수 변경을 함께 성공하거나 함께 실패하게 해야 한다.
- **FR-004**: System MUST 응답에 현재 상태(눌렀는지)와 그 시점의 좋아요 수를 돌려줘야 한다.
- **FR-005**: System MUST 비회원 요청은 로그인 필요, 이메일 인증 전 회원은 인증 필요로 거부해야 한다.
- **FR-006**: System MUST 자기 글에 대한 좋아요를 거부해야 한다. [NEEDS CLARIFICATION: 자기 글 좋아요 거부 응답 — 30 문서는 403, 42 권한 매트릭스는 400으로 적음. 업무 규칙(불가)은 같고 응답 분류만 맞추면 된다]
- **FR-007**: System MUST 지금 읽을 수 없는 글(임시·휴지통·남의 비공개·관리자 숨김·작성자 탈퇴 신청·없는 글)에 대한 좋아요·취소 요청을 다른 이유와 상관없이 같은 찾을 수 없음(404와 같은 응답)으로 거부해야 한다.
- **FR-008**: System MUST 권한을 정해진 순서로 판정해 응답이 기능마다 달라지지 않게 해야 한다. [NEEDS CLARIFICATION: 판정 순서 — 30 문서는 로그인 → 볼 수 있나(404) → 이메일 인증 → 자기 글, 42 공통 순서는 로그인 → 계정 상태(인증) → 볼 수 있나 → 업무 규칙. 42를 최종 기준으로 할지 확인 필요]
- **FR-009**: System MUST 회원당 좋아요·취소를 합쳐 1분에 60번으로 제한하고, 넘으면 다시 시도할 시간과 함께 거부해야 한다.
- **FR-010**: System MUST 실제로 상태가 바뀐 경우에만 "좋아요됨"(글·누른 사람·작성자·시각)/"좋아요 취소됨" 사실을 저장이 확정된 뒤 후속 기능에 알려야 한다. 이미 그 상태였던 요청은 알리지 않는다.
- **FR-011**: System MUST 매일 한 번, 좋아요 수가 실제 기록 수와 다른 글을 찾아 고치고, 고친 건수가 0이 아니면 경고를 남겨야 한다. 이 작업은 여러 서버에서 동시에 돌지 않아야 한다.
- **FR-012**: System MUST 글 상세에 좋아요 수와 "내가 눌렀는지"를 보여야 하며, 목록 카드에는 좋아요 수만 보여야 한다.
- **FR-013**: System MUST 비회원·이메일 인증 전 회원에게도 좋아요 버튼을 보이고, 누르면 로그인 또는 이메일 인증을 안내해야 한다. 로그인 후에는 원래 글로 돌아오되 자동으로 좋아요를 누르지 않는다.
- **FR-014**: System MUST 작성자 본인에게는 버튼 대신 좋아요 수만 보여야 한다.
- **FR-015**: 화면은 누르는 즉시 상태와 숫자를 바꾸고, 연타는 마지막 상태만 보내며, 실패하면 되돌리고 안내해야 한다. 최종 숫자는 서버 응답으로 맞춘다.
- **FR-016**: System MUST 숫자를 0~9,999는 쉼표로, 1만 이상은 소수 첫째 자리까지 내림해 `1.2만` 형식으로 보여야 한다.
- **FR-017**: 버튼은 눌림 상태를 보조 기술에 알리고("좋아요 (13)" / "좋아요 취소 (13)"), 색만이 아니라 모양(♡/♥)으로도 구분되며, 키보드로 누를 수 있어야 한다.
- **FR-018**: System MUST 글이 비공개·휴지통·숨김·수정 중이 되거나 다시 발행되어도 좋아요 기록을 보존하고, 글이 완전 삭제될 때만 함께 지워야 한다. 볼 수 없는 사람에게는 수와 버튼을 보이지 않는다.
- **FR-019**: System MUST 누른 사람의 탈퇴 유예 동안 좋아요를 유지하고, 30일 뒤 정리 때 그 회원의 좋아요를 지우고 해당 글들의 좋아요 수를 맞춰야 한다.

### Key Entities *(include if feature involves data)*

- **글 좋아요 (`post_like`)**: 회원과 글의 쌍. 한 쌍에 하나만 존재하며 누른 일자를 가진다.
- **글 (`post`)**: 미리 계산된 좋아요 수를 가진다. 트렌딩 점수의 재료다.
- **회원 (`member`)**: 누른 사람. 이메일 인증·탈퇴 상태가 좋아요 가능 여부를 정한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 같은 회원이 같은 글에 좋아요를 동시에 20번 보내도 기록은 1건이다.
- **SC-002**: 좋아요·취소를 동시에 섞어 보내는 시험을 반복해도 매번 좋아요 수가 실제 기록 수와 100% 같다.
- **SC-003**: 같은 상태 지정 요청을 여러 번 보낸 결과가 한 번 보낸 결과와 100% 같다.
- **SC-004**: 비회원·인증 전·자기 글·볼 수 없는 글의 좋아요 요청은 100% 거부되고 수는 한 번도 바뀌지 않는다.
- **SC-005**: 실제로 상태가 바뀐 요청만 후속 기능에 알려지고, 이미 그 상태였던 요청에서 알림 사실이 생기는 경우가 0건이다.
- **SC-006**: 1분에 60번을 넘는 요청은 100% 거부된다.
- **SC-007**: 정상 운영 상태에서 매일 보정 작업이 고친 건수는 0건이다.
- **SC-008**: 사용자가 버튼을 누른 즉시(서버 응답을 기다리지 않고) 화면 상태가 바뀐다.

## Assumptions

- 01 결정 기록 2026-10-07(H6)에 따라 비회원·인증 전 회원에게도 버튼을 보인다 (40·42의 "회원만 표시"는 수정 대상).
- 글 읽기 판정은 공통 글 접근 규칙 하나를 따르고, 관리자 숨김 글은 그 규칙에서 볼 수 없는 글로 처리된다 ([020-report-hide](../020-report-hide/spec.md)).
- 좋아요 알림의 묶음·중복 방지는 [016-notification](../016-notification/spec.md), 점수 반영은 [018-trending](../018-trending/spec.md)이 정한다.
- 탈퇴 30일 정리의 전체 순서는 회원 탈퇴 spec이 정한다.
- JS 없는 폼 요청 대체 규칙은 01 결정 기록 2026-10-07(화면 React + REST)에 따라 범위에서 뺀다.
- 개인 확장(좋아요한 사람 목록, 내가 좋아요한 글 목록, 댓글 좋아요)은 범위 밖이다.
