## User Scenarios & Testing *(mandatory)*

### User Story 1 - 공개 글을 검색어로 찾기 (Priority: P1)

방문자(비회원 포함)가 검색창에 단어를 입력하면, 공개·발행된 글 가운데 모든 단어가 들어간 글이 목록 카드로 9개씩 나온다. 3글자 이상 단어는 제목·태그·본문에서, 2글자 단어는 제목·태그에서만 찾고, 1글자 단어는 무시한다.

**Why this priority**: 검색의 핵심 가치이며, 공개 범위 규칙을 지키는지가 보안과 직결된다.

**Independent Test**: 공개·비공개·휴지통·숨김·탈퇴 신청 작성자 글을 섞어 두고 검색해, 공개 글만 나오고 단어 규칙대로 찾아지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개 글, 비공개 글, 친구 공개 글, 휴지통 글, 관리자 숨김 글, 탈퇴 신청한 작성자의 글에 모두 "트랜잭션"이 있다, **When** "트랜잭션"을 검색한다, **Then** 공개·발행 글만 나온다.
2. **Given** 본문에 "트랜잭션"이 있는 공개 글, **When** "트랜잭"(3글자, 단어 일부)을 검색한다, **Then** 그 글이 나온다.
3. **Given** "롬복"이 제목에 있는 글, 태그에 있는 글, 본문에만 있는 글, **When** "롬복"을 검색한다, **Then** 제목·태그에 있는 글만 나오고 결과 위에 "두 글자 단어는 제목·태그에서만 찾았어요" 안내가 보인다.
4. **Given** 검색어 "트랜잭션 정리 a", **When** 검색한다, **Then** "a"는 무시되고 "트랜잭션"과 "정리"가 모두 있는 글만 나온다.
5. **Given** 1글자 단어만 입력, **When** 검색한다, **Then** "두 글자 이상 입력해 주세요" 안내가 보이고 결과는 없다.
6. **Given** "100% 할인" 글과 "100원 할인" 글, "snake_case" 글과 "snakeXcase" 글, **When** "100% 할인" 또는 "snake_case"를 검색한다, **Then** `%`·`_`를 글자 그대로 찾아 정확히 해당 글만 나온다.
7. **Given** 일치하는 글이 없다, **When** "롬복"을 검색한다, **Then** "'롬복'에 대한 글이 없어요" 빈 결과 문구(필요하면 2글자 안내 포함)가 보인다.

### User Story 2 - 관련도순·최신순으로 이어 보기 (Priority: P1)

결과는 기본으로 관련도순(① 모든 단어가 제목에 → ② 제목 또는 태그에 → ③ 본문까지 포함해 어딘가에)이고, 단계 안에서는 최신순이다. 최신순으로 바꿀 수 있고, [더 보기]로 이어 붙여도 중복·누락이 없다.

**Why this priority**: 결과가 많을 때 쓸 수 있는 순서와 안정적인 페이지 넘기기가 없으면 검색이 쓸모없다.

**Independent Test**: 제목·태그·본문에 단어가 있는 글을 여러 개 만들어, 관련도순 단계 순서와 [더 보기] 여러 페이지의 중복·누락을 확인한다.

**Acceptance Scenarios**:

1. **Given** 제목 일치 글, 태그 일치 글, 본문 일치 글, **When** 관련도순 검색, **Then** 제목 → 태그 → 본문 단계 순서로 나오고, 같은 단계 안에서는 최초 공개 시각 최신순(같으면 나중 글 먼저)이다.
2. **Given** 한 단계의 결과가 9개 미만, **When** 첫 페이지를 본다, **Then** 같은 페이지에서 다음 단계 결과로 이어서 9개를 채운다.
3. **Given** 결과가 20개 이상, **When** [더 보기]를 계속 누른다, **Then** 모든 결과가 한 번씩만 나온다.
4. **Given** 결과 목록, **When** 최신순을 고른다, **Then** 단계 구분 없이 최초 공개 시각 최신순으로 나오고 [더 보기]도 중복·누락이 없다.
5. **Given** 변조되거나 잘못된 이어 보기 위치 값, **When** [더 보기]를 요청한다, **Then** 잘못된 요청으로 거부된다.

### User Story 3 - 결과 카드에서 검색어 주변 문장 보기 (Priority: P2)

결과 카드는 일반 목록 카드와 같고, 미리보기 자리에 검색어가 처음 나온 곳의 앞뒤 문장이 강조와 함께 보인다.

**Why this priority**: 왜 이 글이 나왔는지 알게 해 주지만, 강조가 안전하지 않으면 XSS가 된다.

**Independent Test**: 본문에 `<script>`, `<img onerror>`가 있는 글을 검색해 강조 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** 본문에 검색어가 있는 글, **When** 검색한다, **Then** 미리보기 자리에 검색어가 처음 나온 곳 앞뒤 약 40자가 보이고, 잘린 쪽에는 `…`가 붙으며, 검색어는 강조 표시된다.
2. **Given** 검색어 근처 본문에 `<script>`, `<img onerror=...>`가 있다, **When** 검색 결과를 본다, **Then** 그 HTML은 글자로만 보이고 실행되지 않으며, 결과에는 강조 표시 외 태그가 없다.
3. **Given** 본문에 검색어가 없고 제목에만 있다, **When** 결과를 본다, **Then** 제목에서 주변 문장을 만든다.

### User Story 4 - 사람 찾기 (Priority: P2)

사람 탭에서 닉네임 또는 블로그 주소로 회원을 찾는다. 회원 = 블로그이므로 블로그 검색도 이 탭이다.

**Why this priority**: 글보다 부차적이지만 블로그를 찾아가는 주요 경로다.

**Independent Test**: 같은 닉네임 일부를 가진 활동 회원과 탈퇴 신청 회원을 만들어 검색한다.

**Acceptance Scenarios**:

1. **Given** 닉네임 "김민서"인 활동 회원과 비슷한 닉네임의 탈퇴 신청 회원, **When** 사람 탭에서 "김민서"를 검색한다, **Then** 활동 회원만 나온다.
2. **Given** 닉네임·주소가 정확히 일치하는 회원과 부분 일치 회원, **When** 검색한다, **Then** 정확히 일치하는 회원이 먼저 나온다.
3. **Given** 결과 카드, **When** 본다, **Then** 프로필 사진·닉네임·블로그 주소·소개 첫 줄이 보이고 최대 20명이다.

---

### User Story 5 - 블로그 안에서 검색 (Priority: P3)

개인 블로그 페이지에서 검색하면 그 작성자의 공개 글만 같은 규칙으로 나온다.

**Why this priority**: 글 검색에 작성자 조건 하나만 더하는 작은 확장이다.

**Independent Test**: 두 작성자에게 같은 단어가 든 글을 만들고 한 블로그 안에서 검색한다.

**Acceptance Scenarios**:

1. **Given** 작성자 A와 B 모두 "트랜잭션" 글이 있다, **When** A의 블로그 안에서 검색한다, **Then** A의 공개 글만 나온다.

---

### Edge Cases

- 앞뒤 공백·여러 칸 공백·유니코드 조합형 차이는 정규화되어 같은 검색으로 취급된다.
- 50자를 넘는 입력은 50자로 자르고, 5단어를 넘으면 앞 5단어만 쓴다.
- 대소문자가 다른 검색어("SPRING"/"spring")는 같은 결과를 낸다. 태그 비교는 태그 정규화와 같은 방식(소문자, 부분 일치)이다.
- 본문의 코드 블록 안 글자도 검색된다.
- 같은 방문자가 1분에 30번을 넘게 검색하면 "요청이 너무 많다"는 응답을 받는다.
- 검색 결과 페이지는 검색 엔진 색인 대상이 아니다.
- 결과를 보는 중 글이 비공개·삭제·숨김되면 다음 요청부터 나오지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 검색을 글 탭(기본)과 사람 탭으로 제공하고, 개인 블로그 페이지 안 검색을 제공해야 한다.
- **FR-002**: System MUST 글 검색 결과에 공개 범위 공용 조건(발행 + 전체 공개 + 휴지통 아님 + 숨김 아님 + 작성자 탈퇴 신청 아님)을 만족하는 글만 포함해야 한다. 친구 공개 글은 포함하지 않는다.
- **FR-003**: System MUST 검색어를 유니코드 정규화하고 앞뒤 공백을 제거한 뒤 최대 50자로 자르고, 띄어쓰기로 나눈 단어 중 최대 5개를 사용해야 한다.
- **FR-004**: System MUST 1글자 단어는 무시하고, 2글자 단어는 제목·태그에서만, 3글자 이상 단어는 제목·태그·본문(Markdown 원문)에서 찾아야 한다.
- **FR-005**: System MUST 남은 모든 단어가 들어 있는 글만 결과로 내야 한다(AND).
- **FR-006**: System MUST 대소문자를 무시하고, `%`·`_`·`\`를 포함한 검색어를 글자 그대로 찾아야 한다.
- **FR-007**: System MUST 남은 단어가 없으면 "두 글자 이상 입력해 주세요"를, 2글자 단어가 있으면 "두 글자 단어는 제목·태그에서만 찾았어요"를 안내해야 한다.
- **FR-008**: System MUST 관련도순(기본)을 ① 제목 → ② 제목·태그 → ③ 본문 포함의 단계 순으로, 단계 안은 최초 공개 시각 최신순(같으면 ID 큰 순)으로 정렬하고 점수는 매기지 않아야 한다.
- **FR-009**: Users MUST be able to 최신순 정렬을 선택할 수 있어야 한다.
- **FR-010**: System MUST 글 결과를 9개씩 보여 주고 [더 보기]로 이어 붙일 때 중복·누락이 없어야 하며, 잘못된 이어 보기 위치는 거부해야 한다.
- **FR-011**: System MUST 결과 카드를 일반 목록 카드와 같은 정보로 보여 주되, 미리보기 자리에 검색어가 처음 나온 곳의 앞뒤 약 40자(본문에 없으면 제목)를 보여 줘야 한다.
- **FR-012**: System MUST 주변 문장 전체를 먼저 이스케이프한 뒤 검색어에 강조를 적용하여, 결과에 강조 표시 외의 HTML이 실행·삽입되지 않게 해야 한다.
- **FR-013**: System MUST 사람 검색을 닉네임·블로그 주소 대상으로 하고, 정확히 일치를 먼저, 탈퇴 신청 회원 제외, 최대 20명을 보여 줘야 한다.
- **FR-014**: System MUST 블로그 안 검색에서 해당 작성자의 글만, 글 검색과 같은 규칙으로 보여 줘야 한다.
- **FR-015**: System MUST 같은 방문자의 검색을 1분에 30번으로 제한해야 한다.
- **FR-016**: System MUST 검색 결과 페이지가 검색 엔진에 색인되지 않도록 표시해야 한다.
- **FR-017**: System MUST NOT 검색어를 회원 정보와 함께 저장해서는 안 되며, 운영 기록에는 검색어 길이와 걸린 시간만 남겨야 한다.
- **FR-018**: System MUST 최근 글 범위 크기 등 검색 수치를 설정값으로 두어야 한다.

### Key Entities *(include if feature involves data)*

- **글 (post)**: 검색 대상. 제목, Markdown 본문, 상태·공개 범위·삭제·숨김 여부, 최초 공개 시각을 가진다. 새 테이블·컬럼은 없고 검색용 색인만 더한다.
- **태그 (tag, post_tag)**: 글에 붙은 정규화된 태그 이름. 2단계(제목·태그) 일치 판정에 쓰인다.
- **회원 (member)**: 사람 탭 대상(닉네임·블로그 주소·소개 첫 줄·프로필 사진), 탈퇴 신청 여부.
- **검색 결과 항목**: 글 카드 정보 + 강조된 주변 문장 + 관련도 단계. 저장하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 비공개·친구 공개·휴지통·숨김·탈퇴 신청 작성자의 글이 검색 결과에 나오는 경우가 0건이다.
- **SC-002**: 3글자 이상의 한글 단어 일부로 본문에 그 단어가 있는 공개 글을 100% 찾는다.
- **SC-003**: 2글자 단어 검색에서 본문에만 단어가 있는 글은 0건 나오고, 안내 문구가 100% 표시된다. 1글자 단어는 결과에 영향을 주지 않는다.
- **SC-004**: 관련도순 결과가 제목 → 태그 → 본문 단계 순서, 단계 안 최신순을 100% 지킨다.
- **SC-005**: [더 보기]로 모든 페이지를 넘겼을 때 중복 0건, 누락 0건이다.
- **SC-006**: `%`·`_`가 들어간 검색어는 그 글자를 실제로 포함한 글만 반환한다.
- **SC-007**: XSS 테스트 본문(`<script>`, `<img onerror>` 등)을 포함한 검색 결과에서 실행되는 스크립트가 0건이고, 강조 표시 외 태그가 0개다.
- **SC-008**: 글 10만 개 환경에서 검색 요청의 95%가 0.5초 이내에 결과를 돌려준다.

## Assumptions

- Tier C, 출시 순서는 01 기준 미정이다 ([52 §11.2](../../docs/52-feature-summary.md) "Tier C 출시 순서").
- 공개 범위 공용 조건은 공개 범위 spec(C-POST-4)과 06 §7을 따르며, 관리자 숨김 글 제외는 2026-10-07 결정(H1)과 020-report-hide에 의존한다.
- 결과 카드·9개·[더 보기]·날짜 형식은 전체 글 목록(C-READ-1) spec을 재사용한다.
- 태그 정규화 규칙은 태그 spec(C-TAG-1)을 따른다. 검색창에 `#태그`를 입력했을 때 태그 페이지로 보낼지는 태그 쪽 결정이며 이 spec 범위 밖이다.
- 방문자 식별 키는 조회수 spec(C-VIEW-1, 31 §2-1)과 같은 키를 쓴다. 요청 제한 저장소 장애 시에는 통과시킨다(02 §2).
- 범위 밖(개인 확장): 기간·주제 조건, 의미·하이브리드 검색, 검색어 자동 완성, 인기 검색어, 별도 검색 엔진.
- 검색 색인 확장 설치에 DB 관리자 권한이 필요할 수 있으며, 배포 환경 확인이 필요하다.
