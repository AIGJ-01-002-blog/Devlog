## User Scenarios & Testing *(mandatory)*

### User Story 1 - 관심 있는 회원을 팔로우한다 (Priority: P1)

로그인한 회원은 다른 회원의 블로그나 글 상세 작성자 영역에서 [팔로우]를 눌러 승인 없이 바로 팔로우하고, 다시 눌러 언팔로우한다. 누구나 블로그에서 팔로워·팔로잉 수와 목록을 볼 수 있다.

**Why this priority**: 피드와 발견의 출발점이다. 팔로우 관계가 있어야 피드가 의미를 가진다.

**Independent Test**: 회원 A가 B를 팔로우·언팔로우하고 B 블로그의 팔로워 수·목록을 비회원으로 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원 A(이메일 인증 전 포함)와 B의 블로그, **When** A가 [팔로우]를 누름, **Then** 버튼이 즉시 [팔로잉 ✓]로 바뀌고 B의 팔로워 수가 1 늘어난다.
2. **Given** A가 B를 팔로우 중, **When** [팔로잉 ✓]를 누름, **Then** 확인 창 없이 언팔로우되고 수가 1 준다.
3. **Given** A가 이미 B를 팔로우 중, **When** 팔로우 요청을 동시에 20번 보냄, **Then** 관계는 하나이고 "새 팔로워" 사실은 한 번만 후속 기능에 알려진다.
4. **Given** 비회원, **When** [팔로우]를 누름, **Then** 로그인 화면으로 가고 로그인 후 원래 페이지로 돌아온다.
5. **Given** 내 블로그, **When** 봄, **Then** 팔로우 버튼이 없고, 직접 요청하면 "자기 자신은 팔로우할 수 없음"으로 거부된다.
6. **Given** 없는 블로그 또는 탈퇴를 신청한 회원, **When** 팔로우·목록을 요청, **Then** 찾을 수 없음(404와 같은 응답)이다.
7. **Given** 비회원, **When** B의 팔로워·팔로잉 목록을 엶, **Then** 최근 팔로우한 순으로 20개씩 프로필 사진·`닉네임 @블로그주소`·소개 첫 줄과 보는 사람 기준 팔로우 버튼이 보인다. 비어 있으면 "아직 팔로워가 없어요" / "아직 팔로우한 사람이 없어요".
8. **Given** 팔로우 요청이 실패, **When** 응답을 받음, **Then** 버튼이 원래대로 돌아가고 "잠시 후 다시 시도해 주세요"가 보인다.

### User Story 2 - 팔로우한 사람의 새 공개 글을 피드로 본다 (Priority: P2)

로그인한 회원은 상단 메뉴의 [피드]에서 팔로우한 사람의 공개 글을 홈과 같은 카드로 최신순 9개씩 본다.

**Why this priority**: 팔로우의 주된 가치다. P1이 있어야 동작한다.

**Independent Test**: 팔로우한 사람들의 공개·비공개·임시·휴지통·숨김 글과 탈퇴 신청 작성자의 글을 준비하고 피드에 공개 글만 순서대로 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 팔로우한 사람들의 공개 글 12개, **When** 피드를 엶, **Then** 최근 공개 순으로 9개 + [더 보기] 3개가 중복·누락 없이 보인다.
2. **Given** 팔로우한 사람의 비공개·임시·휴지통·관리자 숨김 글, 탈퇴를 신청한 작성자의 글, **When** 피드를 엶, **Then** 그 글들은 나오지 않는다. 친구 공개 글도 피드에는 나오지 않는다.
3. **Given** 피드를 보던 중 한 사람을 언팔로우, **When** 다음 [더 보기]·새로 고침, **Then** 그 사람의 글은 빠지고, 이미 화면에 있는 카드는 그대로다.
4. **Given** 비회원, **When** 피드에 접근, **Then** 로그인 화면으로 간다.
5. **Given** 팔로우한 사람이 없음 / 있지만 공개 글이 없음, **When** 피드를 엶, **Then** "팔로우한 사람이 없어요. 홈에서 읽고 싶은 블로그를 찾아보세요 [홈]" / "팔로우한 사람의 공개 글이 아직 없어요"가 보인다.
6. **Given** 피드에서 글을 읽고 뒤로 감, **When** 피드로 돌아옴, **Then** 카드와 스크롤 위치가 복원된다.

### User Story 3 - 친구를 맺고 끊는다 (Priority: P3)

회원은 상대 블로그에서 [친구 요청]을 보내고, 받은 사람은 "받은 친구 요청" 목록에서 수락하거나 거절한다. 거절·요청 취소·친구 끊기는 상대에게 알리지 않는다. 친구 목록은 본인만 본다.

**Why this priority**: 2026-10-07 결정으로 친구 맺기는 공통 기능이 되었다. 친구 최근 활동(P4)과 선택 기능인 친구 공개의 바탕이다.

**Independent Test**: 두 회원 사이에서 요청 → 수락 → 끊기, 요청 → 거절, 양쪽 동시 요청을 각각 수행하고 관계 상태를 확인한다.

**Acceptance Scenarios**:

1. **Given** 회원 A와 B, **When** A가 B에게 친구 요청, **Then** B의 "받은 친구 요청"에 A가 보이고 둘은 아직 친구가 아니다.
2. **Given** A의 요청이 대기 중, **When** B가 [수락], **Then** 둘은 친구가 되고 각자의 친구 목록에 서로가 보인다.
3. **Given** A의 요청이 대기 중, **When** B가 [거절], **Then** 요청이 사라지고 A에게는 아무것도 알리지 않는다.
4. **Given** A가 B에게 요청한 상태, **When** B도 A에게 요청(동시 포함), **Then** 관계는 하나만 생기고 바로 친구(수락)가 된다.
5. **Given** 이미 친구이거나 요청 중, **When** 같은 요청을 다시 보냄, **Then** 아무것도 바뀌지 않는다. 자기 자신에게는 요청할 수 없다.
6. **Given** A와 B가 친구, **When** A가 친구를 끊거나 A가 보낸 요청을 취소, **Then** 관계가 사라지고 상대에게 알리지 않는다.
7. **Given** 다른 회원, **When** A의 친구 목록을 보려 함, **Then** 볼 수 없다(본인만).
8. **Given** 친구와 팔로우, **When** 한쪽을 맺거나 끊음, **Then** 다른 쪽 관계에는 영향이 없다.

---

### User Story 4 - 친구의 최근 활동을 대략적으로 본다 (Priority: P4)

친구(수락된 관계)는 서로의 최근 활동을 "오늘·어제·N일 전·1주 이상"으로 본다. 최근 활동 공개를 끄면 남에게 내 활동이 보이지 않고, 나도 친구들의 활동을 볼 수 없다.

**Why this priority**: 2026-10-07 공통 결정이지만 친구 관계(P3) 위에 얹는 부가 표시다.

**Independent Test**: 친구·요청 중·친구 아님 관계에서 최근 활동 표시 여부를 비교하고, 공개 설정을 끈 뒤 양방향 표시를 확인한다.

**Acceptance Scenarios**:

1. **Given** A와 B가 친구이고 B가 오늘 서비스를 이용함, **When** A가 친구 목록을 봄, **Then** B 옆에 "오늘"이 보인다. 어제면 "어제", 2~6일 전이면 "N일 전", 7일 이상이면 "1주 이상".
2. **Given** 요청 중이거나 친구가 아닌 회원, **When** B의 최근 활동을 보려 함, **Then** 보이지 않는다.
3. **Given** B가 최근 활동 공개를 끔, **When** A가 친구 목록을 봄, **Then** B의 최근 활동이 보이지 않고, B도 A를 포함한 다른 친구의 최근 활동을 볼 수 없다.
4. **Given** 회원이 짧은 시간에 여러 번 요청함, **When** 최근 활동이 기록됨, **Then** 대략 한 시간에 한 번 정도만 갱신된다(표시는 날짜 단위라 차이가 드러나지 않음).
5. **Given** 탈퇴 30일 뒤 익명 처리된 회원, **When** 처리됨, **Then** 그 회원의 최근 활동 기록은 비워진다.

---

### Edge Cases

- 팔로우는 이메일 인증·인원·횟수 제한이 없다. 팔로우 → 언팔로우 반복으로 인한 알림 도배는 알림 쪽에서 같은 사람 7일 1회로 막는다.
- 탈퇴를 신청한 회원은 유예 동안 남의 팔로워·팔로잉 수·목록에서 빠지고 그 사람의 글은 피드에서 빠지며, 복구하면 돌아온다. 30일 뒤에는 팔로우 관계가 양방향 모두, 친구 관계도 모두 지워진다.
- 탈퇴를 신청한 친구가 유예 동안 친구 목록·받은 요청에서 어떻게 보이는지는 [NEEDS CLARIFICATION: 탈퇴 유예 중인 친구·요청자의 친구 목록·받은 요청·최근 활동 표시 — 24·06에 규칙 없음. 팔로우처럼 숨겼다가 복구 시 되돌릴지]
- 친구를 끊는 순간부터(친구 공개를 적용한 서비스라면) 상대는 내 친구 공개 글을 볼 수 없다.
- 피드 [더 보기] 불러오기 실패는 공통 목록과 같이 "불러오지 못했어요 [다시 시도]"로 안내한다.
- 친구 요청·수락 알림은 선택 기능이며 기본으로 꺼져 있다. 꺼져 있으면 받은 요청은 설정의 "받은 친구 요청" 목록에서만 보인다.

## Requirements *(mandatory)*

### Functional Requirements

**팔로우**

- **FR-001**: Users MUST be able to 로그인 상태(이메일 인증 여부 무관)에서 다른 회원을 승인 없이 팔로우·언팔로우할 수 있어야 한다. 요청은 상태 지정 방식이라 여러 번 보내도 결과가 같고, 응답에 팔로우 여부와 현재 팔로워 수를 돌려준다.
- **FR-002**: System MUST 한 회원이 같은 회원을 두 번 팔로우할 수 없게 하고, 동시 요청에도 관계 하나만 만들며, 실제로 관계가 생기거나 지워진 경우에만 "팔로우됨/언팔로우됨" 사실을 저장이 확정된 뒤 후속 기능에 알려야 한다.
- **FR-003**: System MUST 자기 자신을 팔로우하려는 요청을 거부하고, 없는 블로그·탈퇴 신청한 회원 대상 요청은 찾을 수 없음(404와 같은 응답)으로 거부해야 한다. 비회원 요청은 로그인 필요로 거부한다.
- **FR-004**: Users MUST be able to 비회원을 포함해 누구나 회원의 팔로워·팔로잉 수와 목록을 볼 수 있어야 한다. 목록은 최근 팔로우한 순 20개씩 [더 보기]이며 프로필 사진·`닉네임 @블로그주소`·소개 첫 줄·보는 사람 기준 팔로우 버튼을 보인다.
- **FR-005**: System MUST 팔로워·팔로잉 수와 목록에서 탈퇴를 신청한 회원을 빼고, 복구하면 다시 포함해야 한다.
- **FR-006**: System MUST 팔로우 버튼을 비회원 [팔로우](누르면 로그인 후 원래 페이지로), 팔로우 안 함 [팔로우], 팔로우 중 [팔로잉 ✓](가리키거나 초점 시 [언팔로우]), 내 블로그는 버튼 없음으로 보이고, 누르는 즉시 바꾸되 실패하면 되돌려야 한다. 상태는 색만이 아니라 글자로도 구분한다.

**피드**

- **FR-007**: Users MUST be able to 로그인 상태에서 별도 피드 화면으로 팔로우한 사람의 글 중 **발행·전체 공개·휴지통 아님·관리자 숨김 아님·작성자 탈퇴 신청 아님**인 글만, 홈과 같은 카드·9개씩·[더 보기]·최근 공개 순으로 볼 수 있어야 한다. 친구 공개 글은 피드에 넣지 않는다.
- **FR-008**: System MUST 언팔로우한 사람의 글을 다음 피드 요청부터 빼고, [더 보기]로 이어 붙일 때 중복·누락이 없어야 한다.
- **FR-009**: System MUST 비회원의 피드 접근을 로그인 화면으로 보내고, 상단 메뉴의 [피드]는 로그인한 경우에만 보여야 한다.
- **FR-010**: System MUST 피드의 빈 상태를 "팔로우한 사람이 없음"과 "팔로우한 사람의 공개 글이 없음"으로 구분해 안내하고, 뒤로 가기 때 카드·스크롤을 복원해야 한다.

**친구 관계**

- **FR-011**: Users MUST be able to 상대 블로그에서 친구 요청을 보내고, 받은 요청을 수락·거절하고, 보낸 요청을 취소하고, 친구를 끊을 수 있어야 한다. [NEEDS CLARIFICATION: 친구 요청에 필요한 계정 조건 — 로그인만으로 되는지(팔로우와 같음), 이메일 인증이 필요한지 06에 정해져 있지 않음]
- **FR-012**: System MUST 두 회원 사이에 친구 관계(요청 중 또는 친구)를 하나만 두어야 한다. 이미 친구이거나 요청 중이면 같은 요청은 아무것도 바꾸지 않고, 상대가 이미 나에게 요청한 상태에서 내가 요청하면(동시 포함) 바로 친구가 된다. 자기 자신에게는 요청할 수 없다.
- **FR-013**: System MUST 거절·요청 취소·친구 끊기 때 관계를 지우고 상대에게 알리지 않아야 한다.
- **FR-014**: System MUST 친구 목록과 받은 친구 요청 목록을 본인에게만 보여야 한다.
- **FR-015**: System MUST 친구 관계와 팔로우 관계를 서로 독립적으로 다뤄야 한다.
- **FR-016**: System MUST 친구 공개 범위와 친구 요청·수락 알림을 사용하지 않는 서비스에서도 친구 맺기·끊기가 동작해야 한다(두 선택 기능은 기본 꺼짐).

**친구 최근 활동**

- **FR-017**: System MUST 회원이 서비스를 이용할 때 최근 활동 시각을 대략 한 시간에 한 번 정도만 갱신해야 한다.
- **FR-018**: System MUST 최근 활동을 친구(수락된 관계)에게만 "오늘·어제·N일 전·1주 이상" 단위로 보여야 하며, 정확한 시각은 보이지 않는다.
- **FR-019**: Users MUST be able to 최근 활동 공개 여부를 바꿀 수 있어야 한다(기본 공개). 끄면 내 최근 활동이 친구에게 보이지 않고, 나도 다른 친구의 최근 활동을 볼 수 없다.
- **FR-020**: System MUST 탈퇴 30일 뒤 익명 처리 때 최근 활동 기록을 비워야 한다.

**탈퇴**

- **FR-021**: System MUST 회원이 탈퇴를 신청하면 유예 동안 팔로우 관계를 지우지 않고 목록·수·피드에서만 빼며, 30일 뒤 정리 때 그 회원의 팔로우 관계(양방향)와 친구 관계를 모두 지워야 한다. 친구 관계 정리는 친구 공개 적용 여부와 무관하게 항상 실행한다.

### Key Entities *(include if feature involves data)*

- **팔로우 (`follow`)**: 팔로우하는 회원 → 팔로우받는 회원의 한 방향 관계와 팔로우 일자. 한 쌍에 하나, 자기 자신 불가.
- **친구 관계 (`friendship`)**: 두 회원의 상호 관계 한 건. 요청한 회원, 상태(요청 중 / 친구), 요청·수락 일자를 가진다. 한 쌍에 하나.
- **회원 (`member`)**: 최근 활동 일자와 최근 활동 공개 여부를 가진다. 탈퇴 유예·익명 처리 상태가 목록·피드 노출을 바꾼다.
- **글 (`post`)**: 피드에 나올지를 공개 범위·상태·휴지통·숨김 여부로 정한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 같은 사람을 동시에 20번 팔로우해도 관계는 1개이고 "새 팔로워" 사실은 1번만 알려진다.
- **SC-002**: 자기 자신 팔로우·친구 요청 시도는 100% 거부된다.
- **SC-003**: 피드에 비공개·친구 공개·임시·휴지통·숨김·탈퇴 신청 작성자의 글이 섞이는 경우가 0건이다 (권한 매트릭스 "피드" 열).
- **SC-004**: 피드 [더 보기]를 이어 붙였을 때 중복·누락이 0건이다.
- **SC-005**: 언팔로우 직후의 다음 피드 요청에서 그 사람의 글이 100% 빠진다.
- **SC-006**: 비회원도 팔로워·팔로잉 수와 목록을 볼 수 있고, 탈퇴 신청한 회원은 빠졌다가 복구하면 100% 돌아온다.
- **SC-007**: 탈퇴 30일 정리 뒤 그 회원의 팔로우 관계(양방향)와 친구 관계가 0건 남는다.
- **SC-008**: 두 회원이 동시에 서로 친구 요청을 보내도 관계는 1개이고 친구 상태가 된다.
- **SC-009**: 거절·요청 취소·친구 끊기 때 상대에게 가는 알림·표시가 0건이다.
- **SC-010**: 친구가 아닌 회원이나 최근 활동 공개를 끈 회원이 남의 최근 활동을 보는 경우가 0건이다.
- **SC-011**: 팔로워 1만 명인 회원의 블로그를 열 때도 팔로워 수가 기다림 없이 보인다(공통 비기능 기준 이내).

## Assumptions

- 01 결정 기록 2026-10-07(M1, 최근 활동 표시)에 따라 친구 맺기(요청·수락)와 친구 최근 활동은 공통, 친구 공개(`FRIENDS`) 범위와 친구 요청·수락 알림은 선택 기능(기본 꺼짐)이다. 친구 공개 범위 자체는 공개 범위 spec의 선택 규격으로 다룬다.
- 같은 결정의 ① "본인 계정 화면의 마지막 로그인 표시"는 계정·프로필 spec 범위이며 이 spec에서는 다루지 않는다. 최근 활동 공개 설정이 놓일 화면 위치도 계정 설정 spec과 맞춘다.
- 최근 활동은 친구 목록(본인용)에서 보여 준다고 가정한다(52 §9 "친구 관계" 화면).
- 팔로우는 대상이 회원이다. 블로그를 "구독"이라고 부르는 개인 서비스도 저장은 회원 팔로우로 한다.
- 팔로우·친구 관련 알림(새 팔로워 묶음·7일 1회, 팔로우한 사람의 새 글)은 [016-notification](../016-notification/spec.md)이 정한다.
- 공통 목록 카드·커서·빈/오류 상태는 홈·블로그 목록 spec을 따른다.
- 팔로워 수는 그때그때 센다. 팔로워 1만 명을 넘는 회원이 생기면 미리 계산한 수를 검토한다(결정 변경 시 팀에 알림).
- 이 기능은 Tier C(공통 2차 후보)이다. [NEEDS CLARIFICATION: 출시 순서 — 01의 "2차 후보" 문장이 남아 있어 팔로우·피드·친구를 1차 완료 범위에 넣을지 후속 출시로 둘지 확정 필요 (52 §11.2)]
- JS 없는 폼 요청 대체 규칙은 01 결정 기록 2026-10-07(화면 React + REST)에 따라 범위에서 뺀다.
- 개인 확장(그룹, 그룹 공개, 피드를 미리 만들어 두는 방식, 블로그 구독 화면 문구)은 범위 밖이다.
