# Feature Specification: AI 태그 추천 (018-ai-tag-suggest)

**Feature Branch**: `018-ai-tag-suggest`

**Created**: 2026-10-07

**Status**: Draft

본문 앞부분을 보고 태그를 최대 5개 제안한다. 사용자가 누른 것만 태그에 추가되고, AI가 실패해도 글쓰기·자동 저장·발행에는 영향이
없다. 같은 내용은 저장해 둔 결과를 재사용한다. 상세 규칙은 docs/34-ai-tag-suggest.md를 따른다."

**우선순위 단계**: 이후 단계 (Tier C)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 버튼을 눌러 태그 제안을 받고 골라 붙인다 (Priority: P1)

작성자가 에디터의 [AI 태그 추천]을 누르면 글에 맞는 태그가 최대 5개 제안되고, 원하는 것만 눌러 태그에 추가한다.

**Why this priority**: 기능의 핵심 가치다. "AI는 제안만 하고 사용자가 고른다"는 원칙이 여기서 지켜져야 한다.

**Independent Test**: 동의를 마친 작성자로 충분히 긴 글에서 버튼을 눌러 제안이 5개 이하로 오고, 아무것도 누르지 않으면 태그가 그대로이며,
하나를 누르면 그것만 추가되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 에디터, **When** 작성자가 아무것도 누르지 않으면, **Then** AI는 호출되지 않는다. 버튼을 누를 때만 호출된다.
2. **Given** 동의한 작성자의 충분히 긴 글, **When** [AI 태그 추천]을 누르면, **Then** "추천: (+ 태그) …"로 최대 5개, 글당 태그 상한에서 남은
   자리만큼 제안되고 "본문 앞부분을 보고 추천했어요 · AI 제안이에요"가 보인다.
3. **Given** 제안 목록, **When** (+ 태그)를 누르면, **Then** 그 태그만 현재 태그에 추가된다. 누르지 않은 제안은 반영되지 않는다.
4. **Given** 이미 붙인 태그, 금칙어, 태그 규칙에 맞지 않는 결과, **When** 제안을 받으면, **Then** 그것들은 나오지 않는다. 대문자·공백은
   태그 규칙대로 정리되어 나온다.
5. **Given** 정리 후 100자 미만인 글, **When** 누르면, **Then** AI를 부르지 않고 "글을 조금 더 쓴 뒤 추천받아 보세요"가 보인다.
6. **Given** 걸러낸 뒤 남은 제안이 0개, **When** 결과를 받으면, **Then** "추천할 태그를 찾지 못했어요"가 보인다.
7. **Given** 버튼 옆, **When** 보면, **Then** 오늘 남은 횟수("오늘 17회 남음")가 보인다.

### User Story 2 - 처음 쓸 때 외부 전송에 동의한다 (Priority: P1)

작성자가 처음 [AI 태그 추천]을 누르면, 글 내용이 어디로 가고 어떻게 쓰일 수 있는지 안내받고 동의해야만 전송된다. 동의는 설정에서
철회할 수 있다.

**Why this priority**: 동의 없이 글 내용이 외부로 나가면 안 된다. P1과 함께 있어야 기능을 열 수 있다.

**Independent Test**: 동의하지 않은 작성자가 버튼을 누르면 동의 창만 뜨고 외부로 아무것도 전송되지 않는지, 동의 후에는 추천이 되고
설정에서 철회하면 다시 동의 창이 뜨는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 아직 동의하지 않은 작성자, **When** 버튼을 누르면, **Then** 다음 내용의 동의 창이 뜨고 아무것도 전송되지 않는다: 글 제목과
   본문 앞부분이 Google Gemini(무료 등급)로 전송됨, Google이 이 내용을 서비스 개선에 쓰고 사람이 검토할 수 있음, Gemini를 쓸 수 없을 때는
   우리 서버의 AI로 처리하며 이때는 외부로 전송되지 않음, 개인정보·비밀번호·회사 기밀이 든 글에는 쓰지 말 것. [동의하고 추천받기] [취소].
2. **Given** 동의 창, **When** [동의하고 추천받기]를 누르면, **Then** AI 동의가 문구 버전·일자와 함께 기록되고 추천이 진행된다.
3. **Given** 동의 창, **When** [취소]를 누르면, **Then** 아무것도 기록·전송되지 않는다.
4. **Given** 동의한 회원, **When** 설정에서 동의를 철회하면, **Then** 동의 기록이 지워지고 다음에 버튼을 누르면 다시 동의 창이 뜬다.
5. **Given** 동의한 문구 버전이 현재 버전과 다름, **When** 다음에 쓰려 하면, **Then** 다시 동의를 받는다.

### User Story 3 - 다시 눌러도 기다리지 않고 횟수도 줄지 않는다 (Priority: P2)

같은 글에서 버튼을 여러 번 누르거나 조금만 고친 뒤 다시 눌러도 저장해 둔 결과로 바로 응답하고, 하루 사용 횟수가 줄지 않는다.

**Why this priority**: 무료 한도와 응답 시간을 아끼는 핵심 장치지만, 추천 자체(P1)가 먼저다.

**Independent Test**: 같은 글로 두 번 누르면 두 번째는 AI를 부르지 않고 "저장된 결과"로 응답하며 남은 횟수가 그대로인지, 오타 2개를
고친 뒤에도 재사용되는지, 본문 절반을 바꾸면 새로 묻는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 같은 내용으로 이미 추천받음, **When** 다시 누르면, **Then** AI를 부르지 않고 저장된 결과로 응답하며 하루 횟수가 줄지 않는다.
2. **Given** 공백·줄바꿈이나 사진 주소만 바뀜, **When** 다시 누르면, **Then** 같은 내용으로 보고 재사용한다.
3. **Given** 태그 하나를 붙인 뒤, **When** 다시 누르면, **Then** AI를 부르지 않고 저장된 결과에서 붙인 태그만 빼고 보여 준다.
4. **Given** 같은 글에서 오타 몇 개를 고치거나 긴 글에 문장 하나를 더함, **When** 다시 누르면, **Then** 지난번 정리된 내용과 3글자 단위
   유사도가 0.9 이상이면 저장된 결과를 재사용한다.
5. **Given** 글을 많이 고침(유사도 0.9 미만), **When** 다시 누르면, **Then** 새로 묻는다.
6. **Given** 제안 목록, **When** [다시 추천]을 누르면, **Then** 비슷한 내용 재사용은 건너뛰고 새로 묻는다. 완전히 같은 내용의 저장 결과는
   쓰되, 그 결과가 우리 서버 AI가 만든 것이고 지금 Gemini를 쓸 수 있으면 Gemini로 다시 만든다.
7. **Given** 하루 실제 호출 20회를 다 씀, **When** 새 내용으로 누르면, **Then** AI를 부르지 않고 오늘 사용 횟수를 다 썼다는 안내가 보인다. 저장된
   결과로 응답할 수 있는 요청은 계속 된다.

---

### User Story 4 - 외부 AI 한도가 다 되어도 자체 AI로 계속 추천받는다 (Priority: P3)

외부 AI(Gemini 무료 등급)의 한도가 다 되거나 일시적으로 막히면 같은 요청이 우리 서버의 AI로 처리되고, 둘 다 안 되면 "지금은 추천할 수
없어요"만 보이며 글쓰기는 그대로다.

**Why this priority**: 무료 등급 한도가 자주 바뀌므로 필요하지만, 기본 흐름이 먼저다.

**Independent Test**: 외부 AI가 한도 초과를 돌려주도록 만든 뒤 같은 요청이 자체 AI로 처리되고 한도가 초기화될 때까지 계속 자체 AI가
쓰이는지, 두 공급자를 모두 멈추면 추천은 실패해도 자동 저장·발행이 성공하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 오늘 외부 AI 호출 수가 설정한 하루 한도(기본 450)에 이름, **When** 요청하면, **Then** 한도 초과를 받기 전에 미리 자체 AI로 바꾸고
   한도가 초기화될 때까지 자체 AI를 쓴다.
2. **Given** 외부 AI가 하루 한도 초과를 알림, **When** 응답을 받으면, **Then** 같은 요청을 바로 자체 AI로 처리하고 다음 초기화 시각까지 자체 AI를
   쓴다.
3. **Given** 외부 AI가 분당 한도 초과를 알림, **When** 응답을 받으면, **Then** 60초 동안 자체 AI를 쓰고 같은 요청을 바로 자체 AI로 처리한다.
   종류를 모르는 한도 초과도 60초 쉬고, 같은 날 3번 연속이면 하루 한도 소진으로 본다.
4. **Given** 외부 AI가 10초 안에 답하지 않거나 서버 오류, **When** 결과를 받으면, **Then** 60초 동안 외부 AI를 쉬고, 이 요청은 실패로 응답한다
   (자체 AI까지 더 기다리게 하지 않는다).
5. **Given** 자체 AI로 처리 중, **When** 기다리면, **Then** "자체 AI로 추천 중이라 조금 걸려요"가 보이고 30초 안에 끝나지 않으면 실패한다.
6. **Given** 자체 AI가 이미 설정한 동시 처리 수(기본 1)만큼 일하고 있음, **When** 요청하면, **Then** "잠시 후 다시 시도해 주세요"가 보인다.
7. **Given** 두 공급자 모두 실패하거나 기능이 꺼짐, **When** 요청하면, **Then** "지금은 추천할 수 없어요"만 보이고 글쓰기·자동 저장·발행은 정상이다.
   기능이 꺼져 있으면 버튼이 보이지 않는다.

---

### Edge Cases

- 남의 글에 대해 추천을 요청하면? → 볼 수 없는 리소스와 같이 거부한다(작성자 본인만).
- 이메일 인증 전 회원은? → 계정 상태 때문에 할 수 없다는 응답이다.
- 코드가 많은 글은? → 코드 블록은 언어 이름과 앞 5줄만 남겨 보낸다.
- 링크·사진이 있는 글은? → 사진 문법은 통째로 빼고, 링크는 글자만 남긴다.
- 외부 AI로는 8,000자, 자체 AI로는 2,000자를 넘으면? → 그 길이로 자르고, 잘랐다는 사실을 "본문 앞부분을 보고 추천했어요"로 알린다.
- AI가 형식에 맞지 않는 응답을 주면? → 실패로 처리하고 저장하지 않는다.
- 실패·빈 결과·모두 걸러진 결과는? → 재사용용으로 저장하지 않는다.
- 다른 사람이 똑같은 글을 올려 추천받으면? → 완전히 같은 내용의 결과는 사용자와 상관없이 재사용한다. 보관 식별값은 내용에서 만든
  값이라 내용 자체는 남지 않는다.
- 결과 보관소에 문제가 생기면? → AI는 사용할 수 없음으로 응답한다(2026-10-07 장애 정책).

## Requirements *(mandatory)*

### Functional Requirements

**범위·호출 (A-1 ~ A-4)**

- **FR-001**: 범위는 태그 추천만이어야 한다.
- **FR-002**: AI는 작성자가 [AI 태그 추천]을 누를 때만 호출되어야 한다.
- **FR-003**: 보내는 내용은 에디터의 현재 제목, 정리된 본문 앞부분, 인기 태그, "이미 붙인 태그는 제외" 정보뿐이어야 한다. 다른 사람의 글과
  이메일·닉네임 등 회원 정보는 보내지 않는다.
- **FR-004**: 제안은 최대 5개, 글당 태그 상한에서 남은 자리만큼이어야 하고, 사용자가 눌러야만 태그에 추가되어야 한다.
- **FR-005**: 화면에 "본문 앞부분을 보고 추천했어요 · AI 제안이에요"와 오늘 남은 횟수를 보여야 한다.

**입력 정리 (docs/34 §4)**

- **FR-006**: 보내기 전에 제목·강조·목록·인용 기호를 빼고, 사진 문법은 통째로 빼고, 링크는 글자만 남기고, 코드 블록은 언어 이름 + 앞 5줄만
  남기고, 연속 공백·줄바꿈을 하나로 합치고 유니코드 정규화를 하되 대소문자는 바꾸지 않아야 한다.
- **FR-007**: 정리된 본문은 외부 AI 8,000자, 자체 AI 2,000자로 잘라야 하고, 정리 후 100자 미만이면 AI를 부르지 않고 "글을 조금 더 쓴 뒤
  추천받아 보세요"를 보여야 한다.
- **FR-008**: 지시문에는 "글에 나오지 않는 기술은 넣지 마세요"와 "영어 소문자와 하이픈만, 형식대로만 답하세요"를 넣어야 한다.
- **FR-009**: 인기 태그는 상위 50개를 하루 한 번 정해 쓰고, 자체 AI에는 그중 글에 실제로 나오는 것만 보내야 한다.
- **FR-010**: 고정된 지시문을 앞에, 매번 다른 제목·본문을 뒤에 두고, 출력은 태그 목록만 짧게 받아야 한다.

**응답 검증 (A-5)**

- **FR-011**: 두 공급자 모두 정해진 형식(태그 목록, 최대 5개)으로만 답하게 해야 하고, 형식에 맞지 않으면 실패로 처리해야 한다.
- **FR-012**: 서버가 결과를 태그 규칙(소문자, 앞뒤 공백 제거, 중복 제거, 길이)으로 정규화하고, 이미 붙인 태그·금칙어(docs/09 필터)·규칙에
  맞지 않는 태그를 걸러야 한다.
- **FR-013**: 걸러낸 뒤 0개면 "추천할 태그를 찾지 못했어요"를 보여야 한다.

**공급자 전환·시간 제한 (A-6, A-9)**

- **FR-014**: 기본 공급자는 외부 AI(Gemini 무료 등급), 대체 공급자는 우리 서버의 AI여야 한다. 모델·하루 한도·시간 제한·최대 글자 수·동시
  처리 수는 설정값이어야 한다(기본: 외부 하루 450회·10초·8,000자, 자체 30초·2,000자·동시 1건).
- **FR-015**: 다음 규칙으로 공급자를 골라야 한다: 하루 한도 소진 표시가 있거나 60초 쉬는 중이면 자체 AI, 우리가 센 오늘 외부 호출 수가
  하루 한도 이상이면 소진 표시 후 자체 AI, 그 외에는 외부 AI.
- **FR-016**: 외부 AI 응답에 따라: 하루 한도 초과는 다음 초기화 시각까지 소진 표시 후 같은 요청을 자체 AI로, 분당 한도 초과는 60초 쉬고 같은
  요청을 자체 AI로, 종류를 모르는 한도 초과는 60초 쉬고 같은 날 3번 연속이면 소진으로, 시간 초과·서버 오류는 60초 쉬고 이 요청은 실패로,
  성공은 오늘 호출 수 +1 해야 한다.
- **FR-017**: 오늘 호출 수의 날짜는 외부 AI 한도가 초기화되는 기준 시간대로 계산해야 한다.
- **FR-018**: 자체 AI 동시 처리 수를 넘으면 "잠시 후 다시 시도해 주세요"로 응답해야 한다.
- **FR-019**: 자체 AI로 처리할 때 "자체 AI로 추천 중이라 조금 걸려요"를 보여야 한다.
- **FR-020**: 어느 쪽이든 실패하면 "지금은 추천할 수 없어요"만 보여야 하고, 글쓰기·자동 저장·발행에는 영향이 없어야 한다.
- **FR-021**: 기능 스위치로 끌 수 있어야 하며, 끄면 버튼을 숨기고 요청은 사용할 수 없음으로 응답해야 한다.

**결과 재사용 (A-7, A-8)**

- **FR-022**: 결과 재사용은 반드시 써야 한다. ① 정리된 입력이 완전히 같으면(프롬프트 버전 + 내용에서 만든 식별값) 30일 동안 저장된 추천을
  그대로, ② 같은 글의 지난번 정리된 입력과 3글자 단위 유사도가 0.9 이상이면 7일 동안 저장된 추천을 재사용해야 한다. ①을 먼저, 없으면 ②를,
  없으면 AI를 부르고 ①②에 저장해야 한다.
- **FR-023**: 재사용 식별값에는 이미 붙인 태그와 인기 태그 목록을 넣지 않아야 한다. 이미 붙인 태그는 응답할 때 빼고, 저장은 빼기 전 결과로
  한다. 프롬프트 형식을 바꿀 때만 프롬프트 버전을 올린다.
- **FR-024**: 저장된 결과로 응답하면 하루 횟수에서 빼지 않고, 응답에 저장된 결과임을 표시해야 한다.
- **FR-025**: [다시 추천]은 ②를 건너뛰고 새로 묻되, ①은 쓰고 그 결과가 자체 AI 것이며 지금 외부 AI를 쓸 수 있으면 외부 AI로 다시 만들어야 한다.
- **FR-026**: 실패·빈 결과·모두 걸러진 결과는 저장하지 않아야 한다. ②는 글당 1개, 정리된 입력 최대 8,000자를 7일 뒤 자동으로 지워야 한다.
- **FR-027**: 사용자당 하루 실제 AI 호출은 20회까지여야 하고, 넘으면 하루 한도 초과로 응답해야 한다.

**동의·개인정보 (A-11, docs/07 §3-1)**

- **FR-028**: 처음 쓸 때 한 번 AI 동의를 받아야 하고, 동의하지 않으면 아무것도 전송하지 않아야 한다. 동의가 필요하면 "동의 필요" 응답으로
  동의 창을 띄운다.
- **FR-029**: 동의 문구에 외부 AI 무료 등급의 데이터 사용 방식(Google이 서비스 개선에 사용, 사람이 검토 가능), 자체 AI 대체 시 외부 전송 없음,
  개인정보·비밀번호·회사 기밀 글에 쓰지 말 것을 그대로 적어야 한다.
- **FR-030**: AI 동의는 약관 동의 기록에 "AI" 종류로 문구 버전·동의 일자와 함께 저장해야 하고, 현재 문구 버전과 다르면 다시 동의를 받아야
  한다.
- **FR-031**: 설정 화면에서 동의를 철회할 수 있어야 하며, 철회하면 AI 동의 기록을 지워야 한다.
- **FR-032**: 개인정보 처리방침에 "외부 AI 서비스(Google Gemini)로의 전송"과 무료 등급의 데이터 사용 방식을 추가해야 한다.
- **FR-033**: 외부 AI 열쇠값은 환경 설정으로만 넣고 로그에 남기지 않아야 하며, 글 내용도 로그에 남기지 않아야 한다.

**권한 (docs/42)**

- **FR-034**: 추천 요청은 그 글의 작성자 본인만 할 수 있어야 하고, 남의 글이면 "찾을 수 없음"과 같이 거부해야 한다. 이메일 인증 전 회원은
  계정 상태로 거부하고, 비회원은 로그인이 필요하다는 응답이어야 한다. 서버가 매번 다시 확인한다.
- **FR-035**: 정리 후 너무 짧음, 동의 필요, 개인 하루 한도 초과, 사용할 수 없음(두 공급자 실패·자체 AI 동시 처리 초과·기능 꺼짐)은 서로 구별되는
  이유 코드로 응답해야 한다.

### Key Entities *(include if feature involves data)*

- **AI 동의(MemberAgreement, 종류 AI)**: 회원별 AI 동의 문구 버전과 동의 일자. 철회하면 지운다.
- **추천 결과 보관(같은 내용)**: 프롬프트 버전 + 정리된 입력에서 만든 식별값 → 추천 태그, 30일.
- **추천 결과 보관(같은 글)**: 글별 지난번 정리된 입력, 추천, 공급자, 일자, 7일.
- **공급자 상태**: 오늘 외부 호출 수, 하루 한도 소진 표시(다음 초기화까지), 60초 쉼 표시, 자체 AI 동시 처리 수.
- **사용자 하루 사용 횟수**: 회원별 오늘 실제 AI 호출 수(최대 20).
- **인기 태그 목록**: 하루 한 번 정하는 상위 50개.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 버튼을 누르지 않았는데 AI가 호출되거나, 사용자가 누르지 않은 제안이 태그에 추가되는 경우가 0건이다.
- **SC-002**: 동의하지 않은 회원의 글 내용이 어느 공급자로든 전송되는 경우가 0건이다.
- **SC-003**: 외부 AI 한도가 다 되거나 한도 초과가 오면 같은 요청이 100% 자체 AI로 처리되고, 한도가 초기화될 때까지 외부 AI를 부르지 않는다.
- **SC-004**: 같은 내용으로 다시 누르면 AI 호출 0번, 하루 남은 횟수 변화 0이다. 태그 하나를 붙인 뒤나 오타 2개를 고친 뒤 다시 눌러도 AI 호출 0번이다.
- **SC-005**: 이미 붙인 태그, 금칙어, 규칙에 맞지 않는 태그가 제안에 나오는 경우가 0건이다.
- **SC-006**: 두 공급자가 모두 실패해도 글쓰기·자동 저장·발행이 실패하는 경우가 0건이다.
- **SC-007**: 로그에 외부 AI 열쇠값이나 글 내용이 남는 경우가 0건이다.
- **SC-008**: 자체 AI로 정리된 2,000자 입력을 처리할 때 30초 안에 응답한다(배포 서버에서 다시 측정).
- **SC-009**: docs/34 §10의 공통 완료 기준 7개가 모두 자동 테스트로 확인된다.

## Assumptions

- **A-1**: 주제·제목·요약 추천, 관련 글, 티저, 임베딩은 개인 확장으로 범위 밖이다. 주제 추천은 같은 공급자 전환·결과 재사용을 쓸 수 있다.
- **A-2**: 2026-10-07 동의 분리 결정(E2·H9)에 따라 docs/34의 회원 행 AI 동의 일자 대신 약관 동의 기록의 "AI" 종류 + 문구 버전으로 저장하고,
  철회는 기록 삭제로 한다. docs/34의 "동의 문구 버전은 개인 확장"은 이 결정으로 공통이 되었다.
- **A-3**: 비공개·친구 공개 글은 외부 AI로 보내지 않고 자체 AI로만 처리하자는 제안(docs/34 후속 F-1)은 미결이다(미결). 확정된 공통 기능으로
  다루지 않는다.
- **A-4**: 외부 AI 무료 등급의 실제 한도와 초기화 시각은 공급자가 실시간으로 바꾸므로 구현 때 확인하고 설정값으로 둔다. 실제 모델 이름도
  설정값이다.
- **A-5**: 자체 AI 실행 성능(스레드 수는 서버의 성능 코어 수 이하)은 배포 서버에서 다시 재야 하며, 성능이 비슷하면 입력을 4,000자까지 늘릴 수
  있다. 자체 AI용 서버 자원(메모리 약 2~4GB), 외부 AI 열쇠 관리 주체, 처리방침 문구는 팀(배포) 확인 사항이다.
- **A-6**: MVP 로그인은 GitHub 단독이어서 이메일 인증 전 회원은 사실상 없지만, 인증 전 거부 규칙은 그대로 둔다.
- **A-7**: 탈퇴 30일 익명 처리 때 AI 동의 기록은 2026-10-07 결정(동의 이력 유지)에 따라 남긴다(020에서 다룸).
