## User Scenarios & Testing *(mandatory)*

### User Story 1 - 트렌딩 탭에서 요즘 반응 많은 글 보기 (Priority: P1)

방문자(비회원 포함)는 홈 상단 [최신] [트렌딩] 탭에서 트렌딩을 고르면, 최근 7일 안에 처음 공개된 공개 글 가운데 반응이 많고 새로운 글 순으로 목록 카드 9개씩을 본다.

**Why this priority**: 트렌딩의 핵심 가치이며 독립적으로 보여 줄 수 있다.

**Independent Test**: 새 글·하루 된 글·6일 된 글·8일 된 글, 비공개 글, 반응 없는 글을 만들어 트렌딩 순서와 포함 여부를 확인한다.

**Acceptance Scenarios**:

1. **Given** 같은 반응(좋아요 5)을 가진 1시간 된 글과 하루 된 글, **When** 트렌딩을 본다, **Then** 1시간 된 글이 더 위에 있다.
2. **Given** 좋아요 30개인 6일 된 글과 좋아요 100개인 8일 된 글, **When** 트렌딩을 본다, **Then** 6일 된 글은 나오고 8일 된 글은 나오지 않는다.
3. **Given** 비공개·휴지통·숨김 글, 탈퇴 신청한 작성자의 글, **When** 트렌딩을 본다, **Then** 나오지 않는다.
4. **Given** 좋아요도 남의 댓글도 없이 조회만 500인 글, **When** 트렌딩을 본다, **Then** 나오지 않는다.
5. **Given** 트렌딩 탭, **When** 본다, **Then** 일반 목록과 같은 카드(순위 숫자 없음)와 "최근 7일 동안 반응이 많은 글 · 10분마다 갱신" 설명이 보이고, 주소로 탭 상태를 공유할 수 있다. 기본 탭은 최신이다.
6. **Given** 조건에 맞는 글이 없다, **When** 트렌딩을 본다, **Then** "아직 트렌딩 글이 없어요"와 [최신 글 보기]가 보이고, 최신 글로 채우지 않는다.

---

### User Story 2 - 조작하기 어려운 순위 (Priority: P1)

작성자가 자기 글에 댓글을 계속 달거나, 한 사람이 글을 많이 써서 트렌딩을 채우는 것을 막는다.

**Why this priority**: 조작 가능한 순위는 신뢰를 잃는다.

**Independent Test**: 자기 댓글만 20개 달린 글, 같은 사람이 여러 번 댓글을 단 글, 한 작성자의 글 5개를 만들어 순위를 확인한다.

**Acceptance Scenarios**:

1. **Given** 작성자가 자기 글에 댓글 20개를 달고 남의 반응은 없다, **When** 트렌딩을 본다, **Then** 그 글은 나오지 않는다.
2. **Given** 남 3명이 각각 댓글 2개씩, 작성자가 답글 1개를 단 글, **When** 점수를 매긴다, **Then** 댓글 반응은 "서로 다른 남의 작성자 3명"으로만 센다.
3. **Given** 한 작성자의 반응 있는 최근 글 5개, **When** 트렌딩을 본다, **Then** 그 작성자의 글은 점수가 높은 3개까지만 나온다.

---

### User Story 3 - 이어 보기 중에도 같은 순위 (Priority: P2)

순위는 10분마다 상위 100개로 새로 매겨진다. 보던 사람은 [더 보기]를 눌러도 처음 본 순위 그대로 이어서 보며, 순위가 너무 오래되면 새 순위로 다시 시작하라는 안내를 받는다.

**Why this priority**: 보는 중 순위가 바뀌어 같은 글이 두 번 나오거나 빠지면 안 된다.

**Independent Test**: 첫 페이지를 본 뒤 순위를 새로 만들고, 일부 글을 비공개·휴지통으로 보낸 다음 [더 보기]를 누른다. 순위 보관 시간이 지난 뒤에도 [더 보기]를 누른다.

**Acceptance Scenarios**:

1. **Given** 첫 페이지를 본 뒤 순위가 새로 매겨졌다, **When** [더 보기]를 누른다, **Then** 처음 본 순위 그대로 이어지고 중복·누락이 없다.
2. **Given** 아직 안 본 글이 그 사이 비공개·휴지통·숨김이 됐다, **When** [더 보기]를 누른다, **Then** 그 글을 건너뛰고 다음 글로 9개를 채운다.
3. **Given** 이미 화면에 있는 카드의 글이 비공개가 됐다, **When** 그 카드를 누른다, **Then** "찾을 수 없음"이다.
4. **Given** 보던 순위의 보관 시간(30분)이 지났다, **When** [더 보기]를 누른다, **Then** "순위가 새로 바뀌었어요" 안내 후 최신 순위 처음부터 보여 준다.
5. **Given** 순위 끝(최대 100개), **When** 마지막 페이지를 본다, **Then** [더 보기]가 없다.
6. **Given** 트렌딩 목록을 보다 글로 들어갔다, **When** 뒤로 가기, **Then** 불러온 카드와 스크롤 위치가 복원된다(30분).

---

### User Story 4 - 순위 저장소 장애에도 비지 않는 탭 (Priority: P3)

순위 저장소가 멈춰도 트렌딩 탭은 그 자리에서 첫 페이지를 계산해 보여 준다.

**Why this priority**: 부가 기능 장애가 홈을 비우면 안 된다.

**Independent Test**: 순위 저장소를 멈추고 트렌딩 탭을 연다.

**Acceptance Scenarios**:

1. **Given** 순위 저장소 장애, **When** 트렌딩 탭을 연다, **Then** 첫 9개가 보이고 [더 보기]는 없다.

---

### Edge Cases

- 점수가 같으면 최초 공개 시각이 최신인 글, 그것도 같으면 나중 글이 먼저다.
- 막 공개된 글(경과 0시간)도 점수가 무한히 커지지 않는다.
- 좋아요는 자기 글에 누를 수 없고, 조회수는 작성자·봇이 제외된 값이라 별도 보정이 없다.
- 공개 범위를 바꿔도 대상 기간은 최초 공개 시각 기준이라 비공개 → 공개 재전환으로 다시 새 글이 되지 않는다.
- 여러 서버가 있어도 순위 계산은 10분마다 한 곳에서만 한다.
- 순위 계산과 화면 사이에 볼 수 없게 된 글은 보여 줄 때 다시 확인해 뺀다.
- 관리자에게 숨겨진 댓글을 댓글 작성자 수에 넣을지는 미결이다(FR-005).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 홈 상단에 [최신] [트렌딩] 탭을 두고(기본 최신), 트렌딩 탭을 비회원에게도 보여 줘야 한다.
- **FR-002**: System MUST 트렌딩 대상을 공개 범위 공용 조건(발행 + 전체 공개 + 휴지통 아님 + 숨김 아님 + 작성자 탈퇴 신청 아님)을 만족하고 최초 공개 시각이 7일 안인 글로 한정해야 한다.
- **FR-003**: System MUST 점수를 `(3 × 좋아요 수 + 2 × 작성자를 뺀 서로 다른 댓글 작성자 수 + 0.1 × 조회수) ÷ (최초 공개 후 경과 시간(시간) + 2)^1.5`로 계산하고, 동점이면 최초 공개 시각 최신 → 나중 글 순으로 정렬해야 한다.
- **FR-004**: System MUST 좋아요 1개 이상 또는 작성자 외 댓글 작성자 1명 이상인 글만 포함해야 한다.
- **FR-005**: System MUST 댓글 작성자 수에서 작성자 본인과 삭제된 댓글을 빼야 하며, 관리자 숨김 댓글은 [NEEDS CLARIFICATION: 숨김 댓글을 트렌딩 댓글 작성자 수에서 뺄지 — 32 예시는 삭제만 제외, 숨김 정책과 맞춰야 함(52 §11.2)].
- **FR-006**: System MUST 한 작성자의 글을 최대 3개까지만 포함해야 한다.
- **FR-007**: System MUST 순위를 10분마다 상위 100개로 미리 계산해 두고, 요청 때마다 전체를 계산하지 않아야 한다.
- **FR-008**: System MUST 이어 보기 위치에 처음 본 순위를 담아, 그 사이 새 순위가 생겨도 보던 순위 그대로 9개씩 이어 보여 줘야 한다.
- **FR-009**: System MUST 보여 줄 때 각 글의 공개 상태를 다시 확인해, 볼 수 없게 된 글은 건너뛰고 다음 글로 채워야 한다.
- **FR-010**: System MUST 보던 순위가 보관 시간(30분)을 넘겨 사라지면 "순위가 새로 바뀌었어요"를 안내하고 최신 순위 처음부터 보여 줘야 한다.
- **FR-011**: System MUST 트렌딩 카드를 일반 목록 카드와 같은 정보로 보여 주고 순위 숫자는 표시하지 않아야 한다.
- **FR-012**: System MUST 탭 아래에 기준 설명("최근 7일 동안 반응이 많은 글 · 10분마다 갱신")을, 빈 상태에 "아직 트렌딩 글이 없어요"와 [최신 글 보기]를 보여 줘야 하며 최신 글로 채우지 않아야 한다.
- **FR-013**: System MUST 순위 저장소 장애 시 첫 페이지를 바로 계산해 응답하고 이어 보기는 제공하지 않아야 한다.
- **FR-014**: System MUST 뒤로 가기 때 불러온 카드·이어 보기 위치·스크롤을 30분 동안 복원해야 한다.

### Key Entities *(include if feature involves data)*

- **글 (post)**: 좋아요 수, 조회수, 최초 공개 시각, 공개 상태를 이미 가진다. 새 테이블·컬럼은 없다.
- **댓글 (comment)**: 작성자를 뺀 서로 다른 댓글 작성자 수를 세는 데 쓴다.
- **트렌딩 순위 묶음(스냅샷)**: 10분마다 만든 상위 100개 글 순서. 생성 시각으로 구분되고 30분 보관된다. 영구 저장하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 트렌딩에 나온 글의 100%가 최근 7일 안에 처음 공개된 공개 글이며, 반응(좋아요 또는 남의 댓글)이 없는 글은 0건이다.
- **SC-002**: 작성자가 자기 글에 댓글을 추가해도 그 글의 점수 변화가 0이다.
- **SC-003**: 한 작성자의 글이 트렌딩 전체에 4개 이상 나오는 경우가 0건이다.
- **SC-004**: 순위가 10분마다 갱신되고, 트렌딩 요청의 95%가 0.2초 이내에 응답한다.
- **SC-005**: 보는 도중 순위가 바뀌어도 [더 보기]로 넘긴 전체 목록에 중복 0건, 누락 0건이다(그 사이 볼 수 없게 된 글 제외).
- **SC-006**: 보는 도중 비공개·삭제·숨김된 글이 다음 페이지에 나오는 경우가 0건이다.
- **SC-007**: 순위 저장소 장애 동안 트렌딩 탭이 빈 화면을 보여 주는 경우가 0건이다(조건에 맞는 글이 있을 때).

## Assumptions

- Tier C, 출시 순서는 01 기준 미정이다 ([52 §11.2](../../docs/52-feature-summary.md)).
- 좋아요 수는 좋아요 spec(C-LIKE-1), 조회수는 조회수 spec(C-VIEW-1)의 값(중복 제거·작성자·봇 제외)을 그대로 쓴다.
- 카드·9개·[더 보기]·뒤로 가기 복원은 전체 글 목록(C-READ-1) spec을 재사용한다.
- 공개 범위 공용 조건은 C-POST-4와 2026-10-07 결정(H1, 숨김 글 제외)을 따르며, 숨김은 020-report-hide에 의존한다.
- 일별 조회 통계는 트렌딩에 쓰지 않는다(작성자 통계·향후 점수식 전환 대비용으로만 유지).
- 범위 밖(개인 확장): 오늘/주/월 탭, 사이드바 인기 글 5개, 첫 글·새 작가 탭, 주제·태그별 트렌딩.
