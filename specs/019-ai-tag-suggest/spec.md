## User Scenarios & Testing *(mandatory)*

### User Story 1 - 버튼을 눌러 태그 추천받고 골라 넣기 (Priority: P1)

작성자는 에디터에서 [AI 태그 추천]을 누르면 지금 쓰고 있는 제목·본문을 바탕으로 최대 5개의 태그 후보를 보고, 원하는 것만 눌러 태그에 추가한다.

**Why this priority**: 기능의 핵심이며 "AI는 제안만, 사용자가 골라야 반영"이라는 원칙을 보여 준다.

**Independent Test**: 충분한 길이의 글에서 버튼을 눌러 후보가 나오는지, 누른 후보만 태그에 들어가는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 동의를 마친 작성자가 본문을 충분히 쓴 상태, **When** [AI 태그 추천]을 누른다, **Then** 최대 5개 후보가 "AI 제안이에요" 표시와 함께 보이고, 아직 태그에는 아무것도 추가되지 않는다.
2. **Given** 후보 목록, **When** 그중 하나를 누른다, **Then** 그 태그만 현재 태그에 추가된다.
3. **Given** 에디터를 열고 쓰기만 한다, **When** 버튼을 누르지 않는다, **Then** 추천 요청은 한 번도 일어나지 않는다.
4. **Given** 이미 태그 `spring`이 있고 글당 태그 상한까지 2자리가 남았다, **When** 추천받는다, **Then** `spring`은 후보에 없고 후보는 최대 2개다.
5. **Given** 본문이 길어 앞부분만 보냈다, **When** 후보가 나온다, **Then** "본문 앞부분을 보고 추천했어요" 안내가 보인다.
6. **Given** 정리한 본문이 100자 미만, **When** 버튼을 누른다, **Then** AI를 부르지 않고 "글을 조금 더 쓴 뒤 추천받아 보세요"가 보인다.
7. **Given** 남의 글 또는 이메일 인증 전 회원, **When** 추천을 요청한다, **Then** 거부된다.

---

### User Story 2 - 처음 쓸 때 외부 전송에 동의하기 (Priority: P1)

처음 버튼을 누르면 제목·본문 앞부분이 외부 AI 서비스로 전송되고 그 서비스가 내용을 개선에 쓰거나 사람이 검토할 수 있다는 안내를 보고 동의해야 한다. 동의는 설정에서 철회할 수 있다.

**Why this priority**: 동의 없이 글이 외부로 나가면 개인정보 문제가 된다.

**Independent Test**: 동의하지 않은 상태에서 버튼을 누르고 취소했을 때 외부 전송이 없는지, 동의 후 철회하면 다시 묻는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 동의하지 않은 회원, **When** 버튼을 누른다, **Then** 전송 내용·외부 서비스의 데이터 사용 방식·자체 서버 처리 시 외부 전송 없음·민감 정보 주의를 담은 동의 창이 뜨고, 아무것도 전송되지 않는다.
2. **Given** 동의 창, **When** [취소]를 누른다, **Then** 아무것도 전송되지 않는다.
3. **Given** 동의 창, **When** [동의하고 추천받기]를 누른다, **Then** 동의가 기록되고 추천이 진행된다.
4. **Given** 동의한 회원, **When** 설정에서 동의를 철회한다, **Then** 다음 버튼 클릭 때 다시 동의를 묻는다.
5. **Given** 동의 문구 버전이 바뀌었다, **When** 이전 버전에 동의한 회원이 버튼을 누른다, **Then** 다시 동의를 묻는다.

---

### User Story 3 - 실패해도 글쓰기는 계속 (Priority: P1)

AI 서비스가 느리거나 실패해도 작성자는 저장·자동 저장·발행을 그대로 할 수 있고, 추천 자리에만 안내가 보인다.

**Why this priority**: 부가 기능이 핵심 기능을 막으면 안 된다는 공통 원칙이다.

**Independent Test**: 두 AI 공급자를 모두 멈춘 상태에서 추천을 누른 뒤 자동 저장·발행을 한다.

**Acceptance Scenarios**:

1. **Given** 두 공급자가 모두 실패, **When** 버튼을 누른다, **Then** "지금은 추천할 수 없어요"만 보이고, 이어서 자동 저장·발행이 정상 동작한다.
2. **Given** 기능이 꺼져 있다, **When** 에디터를 연다, **Then** 추천 버튼이 보이지 않는다.
3. **Given** 응답이 형식에 맞지 않거나 모든 후보가 걸러졌다, **When** 결과를 본다, **Then** "추천할 태그를 찾지 못했어요"가 보인다.
4. **Given** 결과 재사용 저장소 장애, **When** 버튼을 누른다, **Then** 추천을 쓸 수 없다는 안내를 받고 글쓰기는 영향이 없다.

---

### User Story 4 - 같은 내용은 다시 묻지 않고, 하루 사용 한도 지키기 (Priority: P2)

같은 글에서 버튼을 여러 번 누르거나, 태그를 하나 붙이거나, 오타만 고친 뒤 다시 누르면 지난 결과를 재사용하고 하루 횟수를 줄이지 않는다. 실제 AI 호출은 하루 20회까지이며, 남은 횟수가 보인다. [다시 추천]으로 비슷한 내용 재사용을 건너뛸 수 있다.

**Why this priority**: 무료 한도와 비용을 아끼면서 응답을 빠르게 한다.

**Independent Test**: 같은 내용으로 연속 클릭, 태그 하나 추가 후 클릭, 오타 수정 후 클릭, 대폭 수정 후 클릭의 실제 호출 수와 남은 횟수를 센다.

**Acceptance Scenarios**:

1. **Given** 한 번 추천받은 글, **When** 내용을 바꾸지 않고(공백·줄바꿈·이미지 주소만 바꿔도) 다시 누른다, **Then** 지난 결과로 응답하고 남은 횟수가 줄지 않는다.
2. **Given** 추천 후 태그 하나를 붙였다, **When** 다시 누른다, **Then** AI를 다시 부르지 않고 붙인 태그만 뺀 후보를 보여 준다.
3. **Given** 오타 몇 개만 고쳤다, **When** 다시 누른다, **Then** 같은 글의 거의 같은 내용으로 보고 지난 결과를 재사용한다.
4. **Given** 본문 절반을 바꿨다, **When** 다시 누른다, **Then** 새로 추천받는다.
5. **Given** 오늘 실제 호출 20회를 썼다, **When** 다시 새 내용으로 누른다, **Then** 하루 한도 초과 안내를 받는다(재사용 응답은 계속 가능).
6. **Given** 비슷한 내용으로 재사용된 후보, **When** [다시 추천]을 누른다, **Then** 비슷한 내용 재사용을 건너뛰고 새로 묻는다.

---

### User Story 5 - 외부 AI 한도가 다 되면 자체 AI로 자동 전환 (Priority: P3)

외부 AI 서비스의 무료 한도가 다 되거나 한도 초과 응답이 오면, 같은 요청을 자체 서버 AI로 처리하고 한도가 초기화될 때까지 자체 AI를 쓴다. 자체 AI는 느리므로 "자체 AI로 추천 중이라 조금 걸려요"를 보여 준다.

**Why this priority**: 운영 안정성 요구이며 사용자에게는 투명해야 한다.

**Independent Test**: 외부 서비스가 한도 초과를 돌려주게 만들고 연속으로 추천을 요청한다.

**Acceptance Scenarios**:

1. **Given** 외부 서비스가 하루 한도 초과를 돌려준다, **When** 추천을 요청한다, **Then** 같은 요청이 자체 AI로 처리되고 한도 초기화 시각까지 자체 AI를 쓴다.
2. **Given** 우리가 센 오늘 외부 호출 수가 설정된 한도에 닿았다, **When** 추천을 요청한다, **Then** 한도 초과 응답을 받기 전에 자체 AI로 처리한다.
3. **Given** 외부 서비스가 시간 초과(10초)나 서버 오류, **When** 추천을 요청한다, **Then** 이 요청은 실패 안내로 끝나고, 60초 동안은 자체 AI를 쓴다.
4. **Given** 자체 AI가 이미 처리 중(동시 처리 한도 초과), **When** 또 요청한다, **Then** "잠시 후 다시 시도해 주세요"를 받는다.

---

### Edge Cases

- AI가 대문자·공백·한글 설명이 섞인 태그를 내놓아도 태그 정규화 규칙으로 다듬고, 규칙에 맞지 않거나 금칙어인 태그는 버린다.
- AI가 글에 없는 기술을 제안하지 않도록 지시하지만, 최종 선택은 항상 작성자가 한다.
- 같은 내용을 다른 회원이 올려도 같은 결과를 재사용할 수 있다. 재사용 키는 내용의 요약값이라 내용 자체는 키에 남지 않는다.
- 자체 AI가 만든 재사용 결과가 있고 지금 외부 서비스를 쓸 수 있으면 [다시 추천] 시 외부 서비스로 다시 만든다.
- 실패·빈 결과·모두 걸러진 결과는 재사용하지 않는다.
- 비공개·친구 공개 글을 외부 서비스로 보낼지는 미결이다(FR-016).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 작성자 본인이 [AI 태그 추천]을 누를 때만 추천을 실행해야 하며, 이메일 인증 전 회원과 남의 글에는 거부해야 한다.
- **FR-002**: System MUST 범위를 태그 추천으로 한정하고 최대 5개, 글당 태그 상한에서 남은 자리만큼만 제안해야 한다.
- **FR-003**: System MUST 제안을 사용자가 고른 경우에만 현재 태그에 추가해야 한다.
- **FR-004**: System MUST 외부 전송 전에 동의를 받아야 하며, 동의하지 않으면 아무것도 전송하지 않아야 한다. 동의 문구는 전송 내용과 외부 서비스의 데이터 사용 방식(개선 사용·사람 검토 가능)을 밝혀야 한다.
- **FR-005**: Users MUST be able to 설정에서 AI 동의를 철회할 수 있어야 하고, 동의 문구 버전이 바뀌면 다시 동의해야 한다.
- **FR-006**: System MUST 보내기 전에 본문의 Markdown 기호·이미지·링크 주소를 지우고 코드 블록은 언어와 앞 5줄만 남기며, 공급자별 최대 글자 수로 자르고, 잘랐다는 사실을 화면에 알려야 한다.
- **FR-007**: System MUST 정리한 입력이 100자 미만이면 AI를 부르지 않고 더 쓰라고 안내해야 한다.
- **FR-008**: System MUST NOT 다른 사람의 글, 이메일·닉네임 등 회원 정보를 요청에 넣어서는 안 된다.
- **FR-009**: System MUST 응답을 정해진 형식으로 받고, 태그 정규화 규칙을 적용한 뒤 이미 붙인 태그·금칙어·규칙 위반 태그를 걸러야 한다. 남은 것이 없으면 "추천할 태그를 찾지 못했어요"를 보여야 한다.
- **FR-010**: System MUST 정리된 입력이 같으면(30일), 또는 같은 글의 지난 입력과 거의 같으면(유사도 0.9 이상, 7일) 지난 결과를 재사용해야 한다. 이미 붙인 태그는 응답할 때 뺀다.
- **FR-011**: System MUST 실제 AI 호출을 사용자당 하루 20회로 제한하고, 재사용 응답은 횟수에서 빼지 않으며, 남은 횟수를 보여 줘야 한다.
- **FR-012**: Users MUST be able to [다시 추천]으로 비슷한 내용 재사용을 건너뛰고 새 추천을 받을 수 있어야 한다.
- **FR-013**: System MUST 외부 서비스의 하루 한도 도달(우리가 센 횟수 또는 한도 초과 응답) 시 같은 요청을 자체 AI로 처리하고 한도 초기화까지 자체 AI를 써야 하며, 분당 한도·시간 초과·서버 오류 시 60초 동안 자체 AI를 써야 한다. 시간 초과·서버 오류가 난 그 요청은 실패로 응답한다.
- **FR-014**: System MUST 외부 서비스는 10초, 자체 AI는 30초에서 요청을 끊고, 자체 AI 동시 처리 수를 제한해야 한다.
- **FR-015**: System MUST 추천 실패(공급자 모두 실패, 기능 꺼짐, 재사용 저장소 장애 포함)가 저장·자동 저장·발행에 영향을 주지 않아야 하며, 기능이 꺼지면 버튼을 숨겨야 한다.
- **FR-016**: System MUST 비공개·친구 공개 글의 외부 전송 여부를 [NEEDS CLARIFICATION: 비공개·친구 공개 글은 외부 서비스로 보내지 않고 자체 AI로만 처리할지 — 34 F-1 후속 미결 제안(52 §11.2)]에 따라 처리해야 한다.
- **FR-017**: System MUST 외부 서비스 키를 비밀값으로만 주입하고, 키와 글 내용을 운영 기록에 남기지 않아야 한다.
- **FR-018**: System MUST 하루 한도·공급자 한도·글자 수·시간 제한·모델 이름을 설정값으로 두어야 한다.

### Key Entities *(include if feature involves data)*

- **회원 동의 (member_agreement, 종류 AI)**: AI 외부 전송 동의 여부, 동의 시각, 동의한 문구 버전. 철회하면 동의 없음 상태가 된다.
- **추천 결과 재사용 기록**: 정리된 입력의 요약값별 결과(30일), 글별 지난 입력·결과·공급자(7일). 영구 저장하지 않는다.
- **사용 횟수·공급자 상태**: 사용자별 하루 실제 호출 수, 외부 서비스 오늘 호출 수·한도 소진·일시 중단 표시. 영구 저장하지 않는다.
- **태그 후보**: 정규화·거르기를 거친 최대 5개 태그. 고르기 전에는 글에 연결되지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 버튼을 누르지 않은 편집 세션에서 추천 요청이 0건이고, 사용자가 고르지 않은 후보가 태그에 추가되는 경우가 0건이다.
- **SC-002**: 동의하지 않은(또는 철회한) 회원의 글이 외부로 전송되는 경우가 0건이다.
- **SC-003**: 외부 서비스 한도 초과 상황에서 같은 요청이 자체 AI로 처리되어 사용자가 결과를 받는 비율이 100%이며(자체 AI 정상 시), 한도 초기화 전까지 외부 서비스 호출이 0건이다.
- **SC-004**: 같은 내용으로 다시 누르거나 태그 하나만 붙이고 다시 누른 경우 실제 AI 호출이 0건이고 남은 횟수가 줄지 않는다.
- **SC-005**: 이미 붙인 태그·금칙어·규칙 위반 태그가 후보에 나오는 경우가 0건이다.
- **SC-006**: 두 공급자가 모두 실패한 상태에서도 자동 저장·발행 성공률이 정상 상태와 같다.
- **SC-007**: 운영 기록에서 외부 서비스 키와 글 내용이 발견되는 경우가 0건이다.
- **SC-008**: 자체 AI로 2,000자 입력을 처리할 때 대부분의 추천이 30초 안에 끝난다(배포 서버에서 다시 측정).

## Assumptions

- Tier C, 출시 순서는 01 기준 미정이다 ([52 §11.2](../../docs/52-feature-summary.md)).
- AI 동의 저장은 2026-10-07 결정(동의 분리: 종류 AI + 버전)을 따르며, 34의 회원 컬럼 저장 표현은 이 결정으로 대체된다. 동의·재동의 흐름 자체는 인증·계정 spec(C-AUTH-1/2)에 의존한다.
- 태그 정규화·글당 상한·인기 태그는 태그 spec(C-TAG-1)을, 금칙어는 닉네임 금칙어 필터(09)를 따른다.
- 결과 재사용 저장소 장애 시 AI는 쓸 수 없음으로 응답한다(01 결정 2026-10-07 H8, 02 §2).
- 개인정보 처리방침에 외부 AI 서비스로의 전송과 데이터 사용 방식을 추가하는 것은 운영 문서 작업이다.
- 자체 AI 서버 자원, 외부 서비스 키 관리 주체는 배포 단계에서 정한다.
- 범위 밖(개인 확장): 주제·제목·요약 추천, 임베딩·관련 글, AI 티저.
