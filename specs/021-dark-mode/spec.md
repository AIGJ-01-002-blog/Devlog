# Feature Specification: 다크 모드 (021-dark-mode)

**Feature Branch**: `021-dark-mode`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "방문자는 헤더 맨 오른쪽 버튼으로 시스템 설정 / 라이트 / 다크를 고르고, 처음에는 기기 설정을 따른다.
선택은 그 기기의 브라우저에 남아 새로 고치거나 다른 페이지로 가도 유지되고, 페이지를 열 때 밝은 화면이 번쩍이지 않는다. 세 사람이
같은 색 이름 목록을 써서 화면 코드에 색 값을 직접 쓰지 않는다. 상세 규칙은 docs/45-dark-mode.md를 따른다."

**관련 기능 ID**: 다크 모드 (docs/01 §2-3 Tier C)

**선행 기능**: `003-read-share` (헤더·홈·블로그·글 상세 화면)

**우선순위 단계**: 이후 단계 (Tier C)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기기 설정대로 보고, 원하면 고정한다 (Priority: P1)

방문자는 처음 방문하면 기기 설정(라이트/다크)대로 보고, 헤더 버튼을 눌러 시스템 → 라이트 → 다크 순으로 바꿀 수 있다. 고른 것은 새로 고치거나
다른 페이지로 가도 유지된다.

**Why this priority**: 다크 모드의 핵심 가치다. 비회원도 쓸 수 있어야 한다.

**Independent Test**: 기기를 다크로 둔 비회원이 처음 방문해 다크로 보이는지, 버튼을 눌러 라이트로 고정한 뒤 새로 고침·다른 페이지 이동에도
라이트가 유지되는지, 로그아웃해도 선택이 남는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 처음 방문, **When** 기기가 다크이면, **Then** 다크로, 라이트이면 라이트로 보인다.
2. **Given** 헤더, **When** 어느 페이지에서나 보면, **Then** 맨 오른쪽에 테마 버튼이 있고 지금 상태를 아이콘(🖥/☀️/🌙)과 글자 설명(읽기 도구용 이름,
   툴팁)으로 보여 준다.
3. **Given** 테마 버튼, **When** 누를 때마다, **Then** 시스템 → 라이트 → 다크 → 시스템 순으로 바뀌고 화면에 즉시 반영된다.
4. **Given** 라이트나 다크로 고정함, **When** 새로 고치거나 다른 페이지로 가면, **Then** 그대로 유지된다.
5. **Given** 라이트나 다크로 고정함, **When** 기기 설정이 바뀌면, **Then** 고정한 테마가 그대로다.
6. **Given** "시스템"을 고름, **When** 기기 설정을 바꾸면, **Then** 새로 고치지 않아도 따라 바뀐다.
7. **Given** 테마를 고른 로그인 회원, **When** 로그아웃하면, **Then** 테마 선택은 지워지지 않는다.
8. **Given** 다른 기기, **When** 열면, **Then** 그 기기의 선택(없으면 기기 설정)을 따른다. 기기 간 동기화는 하지 않는다.

---

### User Story 2 - 페이지를 열 때 밝은 화면이 번쩍이지 않는다 (Priority: P2)

다크로 설정한 사용자가 페이지를 열거나 이동할 때, 화면이 그려지기 전에 테마가 정해져 밝은 화면이 잠깐도 보이지 않는다.

**Why this priority**: 깜빡임은 다크 모드 사용 경험을 가장 크게 해치지만, 테마 선택(P1)이 먼저 있어야 한다.

**Independent Test**: 다크로 고정한 상태에서 여러 페이지를 열고 느린 회선을 흉내 내도 첫 화면이 밝게 그려지는 순간이 없는지, 보안 정책 위반
기록 없이 동작하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 다크로 설정함, **When** 페이지를 열면, **Then** 밝은 화면이 잠깐도 보이지 않는다.
2. **Given** 인라인 스크립트를 막는 보안 정책(docs/12 §8), **When** 페이지를 열면, **Then** 정책 위반 없이 테마가 정해진다(인라인 스크립트를 쓰지 않는다).
3. **Given** 테마를 바꿈, **When** 색이 바뀌면, **Then** 서서히 바뀌는 애니메이션 없이 바로 바뀐다.
4. **Given** 브라우저가 저장소 접근을 막은 환경(사생활 보호 모드 등), **When** 페이지를 열면, **Then** 오류 없이 기기 설정만 따른다.
5. **Given** 스크립트가 꺼진 브라우저, **When** 페이지를 열면, **Then** 기기 설정에 맞는 테마로 보이고 테마 버튼은 숨겨진다.

---

### User Story 3 - 다크에서도 모든 화면이 잘 읽힌다 (Priority: P3)

라이트·다크 모두 본문·보조 글자·테두리·아이콘이 충분한 명도 대비를 갖고, 코드 강조·표·인용·배지·입력칸이 테마에 맞게 보인다.

**Why this priority**: 품질 기준이지만, 테마 전환(P1~P2)이 있어야 검사할 수 있다.

**Independent Test**: 자동 검사 도구로 홈·블로그·글 상세·에디터·설정 화면을 라이트·다크 각각 검사해 대비 기준 위반이 없는지, 썸네일 빈 영역 색이
라이트 `#F1F3F5`, 다크 `#2B2F33`인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 라이트·다크, **When** 주요 화면을 검사하면, **Then** 본문 글자는 배경 대비 4.5 : 1 이상, 큰 글자·아이콘·입력칸 테두리는 3 : 1 이상이다.
2. **Given** 다크, **When** 페이지 배경을 보면, **Then** 순수 검정이 아닌 `#121212`다.
3. **Given** 썸네일 없는 카드, **When** 보면, **Then** 빈 영역이 라이트 `#F1F3F5`, 다크 `#2B2F33`이다.
4. **Given** 본문 사진·썸네일·프로필 사진, **When** 다크로 보면, **Then** 색을 뒤집거나 어둡게 하지 않고 그대로 보인다.
5. **Given** 기본 프로필 아이콘, **When** 다크로 보면, **Then** 8가지 배경색 모두 글자와 4.5 : 1 이상이다.
6. **Given** 코드 블록, **When** 테마를 바꾸면, **Then** 코드 강조 색도 라이트용·다크용으로 함께 바뀐다.
7. **Given** 본문 표·인용·체크리스트, **When** 다크로 보면, **Then** 공통 색 이름의 테두리·보조 글자 색으로 보인다.
8. **Given** 상태 배지(🌐/🔒/수정 중 등), **When** 보면, **Then** 색만으로 구분하지 않고 글자·아이콘이 함께 있다.
9. **Given** 스크롤바·기본 입력칸 같은 브라우저 기본 요소, **When** 다크로 보면, **Then** 테마를 따른다.

---

### Edge Cases

- 에디터가 다크 테마를 지원하지 않으면? → 에디터만 라이트로 두고 주변은 다크로 둔다. 지원하면 같은 테마로 켠다(각자).
- 링크 미리보기 이미지와 메일은? → 테마와 무관하게 라이트 기준이다.
- 동작 줄이기를 켠 사용자는? → 테마 전환에 애니메이션이 없으므로 불편이 없다.
- 저장된 값이 알 수 없는 값이면? → "시스템"으로 보고 기기 설정을 따른다.
- 개인 서비스가 강조색을 바꾸면? → 이름은 그대로 두고 값만 바꾸며, 배경 대비 4.5 : 1(글자)과 강조 버튼 배경 위 흰 글자 4.5 : 1을 각자 확인한다.

## Requirements *(mandatory)*

### Functional Requirements

**선택과 저장 (T-1 ~ T-4, T-8)**

- **FR-001**: 테마 선택지는 시스템 설정 / 라이트 / 다크 3가지여야 하고, "시스템"으로 되돌릴 수 있어야 한다.
- **FR-002**: 처음 기본값은 시스템 설정(기기의 라이트/다크 설정)이어야 한다.
- **FR-003**: 선택은 그 기기의 브라우저에 저장해야 한다. 비회원도 쓸 수 있어야 하고 서버·계정에는 저장하지 않는다(기기마다 따로).
- **FR-004**: 전환 버튼은 모든 페이지 헤더 맨 오른쪽에 두고, 누를 때마다 시스템 → 라이트 → 다크 순으로 바꾸며, 아이콘(🖥/☀️/🌙)과 글자 설명(읽기
  도구용 이름, 툴팁)을 함께 보여야 한다.
- **FR-005**: 버튼을 누르면 선택을 저장하고 즉시 화면 테마를 바꿔야 한다.
- **FR-006**: "시스템" 상태에서 기기 설정이 바뀌면 새로 고치지 않아도 따라 바뀌어야 하고, 라이트·다크로 고정한 상태에서는 기기 설정 변화를 무시해야
  한다.
- **FR-007**: 로그아웃해도 테마 선택은 지우지 않아야 한다(로그아웃 때는 임시 글 데이터만 지운다).

**깜빡임 방지 (T-5, docs/12 §8)**

- **FR-008**: 화면을 그리기 전에 테마가 정해져야 한다. 이를 위해 페이지 머리 부분에서 우리 서버의 작은 별도 스크립트 파일(1KB 미만)을 지연 없이
  먼저 실행해야 한다.
- **FR-009**: 인라인 스크립트를 쓰지 않아야 하며, 보안 정책(우리 서버 스크립트만 허용) 위반이 없어야 한다. 서버 화면이든 단일 페이지 화면이든 같은 방식을
  써야 한다.
- **FR-010**: 브라우저 저장소 접근이 막힌 환경에서는 오류 없이 기기 설정만 따라야 한다.
- **FR-011**: 스크립트가 꺼져 있으면 스타일만으로 기기 설정을 따라야 하고, 테마 버튼은 숨겨야 한다.
- **FR-012**: 테마가 바뀔 때 색이 서서히 바뀌는 애니메이션을 넣지 않아야 한다.

**색 이름 목록 (T-6, docs/45 §3)**

- **FR-013**: 화면 코드는 공통 색 이름(토큰)만 쓰고 색 값을 직접 쓰지 않아야 한다. 이름은 docs/45 §3을 따르고 세 사람이 같은 이름을 쓴다. 개인
  서비스는 값만 바꿀 수 있고 이름은 바꿀 수 없다.
- **FR-014**: 공통 기본값은 다음과 같아야 한다(라이트 / 다크): 페이지 배경 `#FFFFFF` / `#121212`, 카드·헤더·상자 `#FFFFFF` / `#1E1E1E`, 본문 글자
  `#212529` / `#E9ECEF`, 날짜·보조 글자 `#6C757D` / `#ADB5BD`, 구분선·카드 테두리 `#DEE2E6` / `#343A40`, 삭제·오류 `#C92A2A` / `#FF6B6B`, 썸네일
  빈 영역 `#F1F3F5` / `#2B2F33`, 코드 블록 배경 `#F8F9FA` / `#1A1B1E`, 키보드 초점 테두리 `#1C7ED6` / `#74C0FC`. 링크·강조 글자와 흰 글자가 올라가는
  버튼 배경은 각자 정하되 다크에서는 더 밝게 한다.
- **FR-015**: 다크 배경은 순수 검정이 아닌 `#121212`여야 한다.

**명도 대비와 요소별 규칙 (T-7, docs/45 §4)**

- **FR-016**: 라이트·다크 모두 본문 글자는 4.5 : 1 이상, 큰 글자·아이콘·입력칸 테두리는 3 : 1 이상이어야 한다(WCAG 2.2 AA). 각자 정한 강조색도
  배경 대비 4.5 : 1(글자), 강조 버튼 배경 위 흰 글자 4.5 : 1을 만족해야 한다.
- **FR-017**: 본문 사진·썸네일·프로필 사진은 다크에서도 색을 뒤집거나 어둡게 하지 않아야 한다.
- **FR-018**: 기본 프로필 아이콘 8가지 배경색은 다크에서도 글자와 4.5 : 1 이상이어야 한다(docs/11 §4-3).
- **FR-019**: 코드 강조 색은 테마에 맞춰 라이트용·다크용을 바꿔 적용해야 한다.
- **FR-020**: 본문 표·인용·체크리스트는 공통 색 이름(테두리, 보조 글자)만 써야 한다.
- **FR-021**: 에디터가 다크 테마를 지원하면 같은 테마로 켜고, 지원하지 않으면 에디터만 라이트로 두되 주변은 다크여야 한다.
- **FR-022**: 상태 배지는 색만으로 구분하지 않고 글자·아이콘을 함께 보여야 한다.
- **FR-023**: 링크 미리보기와 메일은 테마와 무관하게 라이트 기준이어야 한다.
- **FR-024**: 페이지에 "라이트와 다크를 모두 지원함"을 브라우저에 알려 스크롤바·기본 입력칸 등 브라우저 요소도 테마를 따르게 해야 한다.

**권한·연동**

- **FR-025**: 테마 변경은 비회원·회원·관리자 모두 같게 쓸 수 있어야 하며, 권한 검사나 서버 데이터가 필요 없다(docs/42 권한 대상 아님).
- **FR-026**: 테마 기능은 사건을 만들거나 받지 않는다.

### Key Entities *(include if feature involves data)*

- **테마 선택(Theme Choice)**: 기기 브라우저에 남는 값(시스템 / 라이트 / 다크, 없으면 시스템). 서버·계정에는 없다.
- **색 이름 목록(Color Tokens)**: docs/45 §3의 공통 이름과 라이트·다크 기본값.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 방문하면 100% 기기 설정(라이트/다크)을 따른다.
- **SC-002**: 버튼으로 시스템·라이트·다크를 고를 수 있고, 새로 고침·다른 페이지 이동 뒤에도 100% 유지된다.
- **SC-003**: 다크로 설정한 상태에서 페이지를 열 때 밝은 화면이 잠깐이라도 보이는 경우가 0건이다.
- **SC-004**: 보안 정책(인라인 스크립트 금지) 위반 기록이 0건이다.
- **SC-005**: "시스템" 상태에서 기기 설정을 바꾸면 새로 고치지 않아도 따라 바뀐다.
- **SC-006**: 자동 검사 도구로 주요 화면을 라이트·다크 각각 검사해 본문 글자 4.5 : 1, 테두리·아이콘 3 : 1 미만이 0건이다.
- **SC-007**: 썸네일 빈 영역이 라이트 `#F1F3F5`, 다크 `#2B2F33`이다.
- **SC-008**: 스크립트가 꺼져 있어도 기기 설정에 맞는 테마로 보인다.
- **SC-009**: 화면 코드에 색 값을 직접 쓴 곳이 0곳이다(공통 색 이름만 사용).
- **SC-010**: docs/45 §5의 공통 완료 기준 8개가 모두 자동 테스트 또는 자동 검사로 확인된다.

## Assumptions

- **A-1**: 테마를 계정에 저장해 기기 간 동기화하는 것은 개인 확장으로 범위 밖이다.
- **A-2**: 2026-10-07 화면 방식 결정(React + 서버 API)에 따라 테마를 정하는 작은 스크립트는 React 빌드의 시작 페이지 머리 부분에 넣는다. 같은 파일을
  서버 화면에서도 쓸 수 있다.
- **A-3**: 링크·강조 글자와 강조 버튼 배경의 실제 색 값, 색·글꼴·배치 스타일은 각자 자유다(docs/01 결정 O5).
- **A-4**: 각자 쓰는 에디터의 다크 테마 지원 여부는 담당자 확인 사항이다.
- **A-5**: docs/45는 상태가 "초안(항목 확인 중)"이며, 이 spec은 문서의 결정 사항(T-1~T-8)을 확정된 것으로 본다.
- **A-6**: 대비 검사 대상 "주요 화면"은 홈, 개인 블로그, 글 상세, 에디터, 설정으로 본다.
