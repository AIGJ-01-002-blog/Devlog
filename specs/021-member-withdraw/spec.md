## User Scenarios & Testing *(mandatory)*

### User Story 1 - 탈퇴 신청하기 (Priority: P1)

회원이 설정 맨 아래 [회원 탈퇴]로 들어가, 한 화면에서 탈퇴하면 잃게 되는 것을 숫자로 확인하고, 확인 체크와 본인 확인을 한 뒤 탈퇴한다. 즉시 모든 기기에서 로그아웃되고 블로그와 글이 다른 사람에게 보이지 않는다.

**Why this priority**: 탈퇴는 개인정보 권리이며, 나머지 흐름(복구·익명 처리)은 탈퇴 신청이 있어야 시작된다.

**Independent Test**: 두 기기에서 로그인한 시험 회원으로 탈퇴 → 두 기기 모두 로그아웃, 다른 사람이 블로그·글을 열면 찾을 수 없음, 댓글은 가려져 보임, 접수 메일 도착을 확인한다.

**Acceptance Scenarios**:

1. **Given** 탈퇴 화면, **When** 열면, **Then** 내 글 수(휴지통 포함), 남의 글에 쓴 댓글 수, 받은 좋아요 수, 복구 기한(날짜·시각), "블로그 주소는 다른 사람도, 나도 다시 쓸 수 없어요" 안내가 보인다.
2. **Given** 확인 체크를 하지 않았거나 본인 확인 칸이 비어 있음, **When** 화면을 보면, **Then** [탈퇴하기]가 비활성화되어 있고, 요청을 직접 보내도 서버가 거부한다.
3. **Given** [탈퇴하기] 버튼, **When** 화면이 열리면, **Then** 기본 선택(포커스)이 아니어서 Enter로 바로 눌리지 않는다.
4. **Given** 이메일 가입 회원, **When** 비밀번호를 틀리면 거부되고, **When** 5번 연속 틀리면, **Then** 15분 동안 탈퇴를 시도할 수 없다.
5. **Given** 소셜 가입 회원, **When** "탈퇴"가 아닌 글자를 입력하면, **Then** 거부된다.
6. **Given** 관리자 권한이 있는 회원, **When** 탈퇴하면, **Then** "관리자 권한을 해제한 뒤 탈퇴할 수 있어요"로 거부된다.
7. **Given** 탈퇴 성공, **When** 처리되면, **Then** 모든 기기가 로그아웃되고, 완료 화면에 복구 기한이 보이며, 브라우저의 임시 글 데이터가 지워지고, 이메일이 있는 계정에는 복구 기한이 적힌 접수 메일이 간다.
8. **Given** 탈퇴 직후, **When** 다른 사람이 그 블로그·글을 열면, **Then** 찾을 수 없음(없는 글과 같은 응답)이고 홈·블로그·태그·검색·피드 목록에서 사라지며, 그 사람이 남의 글에 쓴 댓글은 "탈퇴한 사용자의 댓글이에요"로 가려진다.
9. **Given** 탈퇴 유예 회원, **When** 다른 사람의 행동이 생기면, **Then** 그 회원에게 새 알림이 만들어지지 않고, 그 회원의 행동으로도 알림이 만들어지지 않는다.
10. **Given** 탈퇴 사유, **When** 탈퇴하면, **Then** 사유를 묻지 않는다.

### User Story 2 - 유예 중 복구하기 (Priority: P1)

탈퇴를 신청한 사람이 30일 안에 로그인하면 복구 화면만 보인다. [복구하기]를 누르면 블로그·글·댓글이 탈퇴 전과 똑같이 돌아온다. 로그인만으로는 복구되지 않는다.

**Why this priority**: 실수나 세션 탈취로 인한 탈퇴를 되돌릴 수 있어야 30일 유예의 의미가 있다.

**Independent Test**: 탈퇴 → 다시 로그인해 다른 주소로 이동 시도(복구 화면으로 되돌아옴) → [복구하기] → 블로그·글·댓글·반응 수가 탈퇴 전과 같은지 비교한다.

**Acceptance Scenarios**:

1. **Given** 유예 중인 회원, **When** 로그인하면, **Then** "탈퇴 신청한 계정이에요"와 복구 기한·남은 날짜, [로그아웃]·[복구하기]만 있는 복구 화면이 보인다.
2. **Given** 복구 화면, **When** 다른 주소로 가거나 다른 기능을 요청하면, **Then** 복구 화면으로 되돌아오거나 계정 상태 사유로 거부된다.
3. **Given** 복구 화면, **When** [복구하기]를 누르면, **Then** 블로그·글·댓글·좋아요·팔로우 관계가 탈퇴 전과 같고, 복구 완료 메일이 가며, 홈에서 "다시 오신 걸 환영해요"가 보인다.
4. **Given** 복구 화면, **When** [로그아웃]을 누르면, **Then** 로그아웃만 되고 유예는 계속된다.
5. **Given** 유예 중 비밀번호를 잊음, **When** 비밀번호 찾기를 하면, **Then** 재설정할 수 있다.
6. **Given** 유예 중인 이메일, **When** 같은 이메일로 이메일 가입을 시도하면, **Then** "탈퇴 신청한 계정이 있어요. 로그인하면 복구할 수 있어요"가 보인다.
7. **Given** 유예 중, **When** 다른 사람이 그 닉네임이나 블로그 주소를 쓰려 하면, **Then** 쓸 수 없다.

### User Story 3 - 30일 뒤 익명 처리 (Priority: P2)

복구하지 않고 30일이 지나면 그 회원의 개인 데이터가 정리되고 회원은 블로그 주소만 남은 익명 껍데기가 된다. 회원 한 명의 정리는 전부 성공하거나 전부 취소된다.

**Why this priority**: 탈퇴 약속(30일 뒤 삭제)을 지키는 기능이지만, 신청·복구가 먼저 있어야 의미가 있다.

**Independent Test**: 탈퇴 시각을 30일 전으로 맞춘 시험 회원(글·댓글·답글 달린 댓글·좋아요·팔로우·알림·사진 보유)에 정리 작업을 실행하고 결과와 반응 수를 확인한다. 중간 단계에서 일부러 실패시켜 아무것도 바뀌지 않는지도 확인한다.

**Acceptance Scenarios**:

1. **Given** 탈퇴 30일이 지난 회원, **When** 매일 새벽 정리 작업이 돌면, **Then** 그 회원의 글(휴지통 포함)이 완전 삭제되고, 그 글에 남이 쓴 댓글·좋아요도 함께 사라진다.
2. **Given** 남의 글에 쓴 댓글, **When** 정리되면, **Then** 답글이 달린 댓글은 내용 없이 "탈퇴한 사용자의 댓글이에요" 자리만 남고, 답글이 없는 댓글은 삭제되며, 그 글의 댓글 수가 실제 댓글 수와 같다.
3. **Given** 남의 글에 누른 좋아요, **When** 정리되면, **Then** 삭제되고 그 글의 좋아요 수가 실제 좋아요 수와 같다.
4. **Given** 팔로우·친구 관계, 받은 알림, 묶음 알림, **When** 정리되면, **Then** 관계는 양방향 모두 삭제되고, 받은 알림은 삭제되며, 남의 묶음 알림에서는 그 회원이 빠진 채 다시 계산된다.
5. **Given** 그 회원의 콘텐츠에 대한 처리 대기 신고, **When** 정리되면, **Then** "대상 없음"으로 종료된다.
6. **Given** 프로필 사진과 올린 사진, **When** 익명 처리가 끝나면, **Then** 그다음 사진 정리 작업 때 삭제된다.
7. **Given** 익명 처리된 회원, **When** 회원 정보를 보면, **Then** 블로그 주소 외에 이메일·로그인 수단·닉네임·소개·사진·최근 활동·AI 동의·정지 사유가 남지 않는다. 약관 동의 기록과 정지 이력은 증빙으로 남는다.
8. **Given** 익명 처리 뒤, **When** 다른 사람이 그 닉네임을 쓰려 하면, **Then** 쓸 수 있다. **When** 옛 블로그 주소로 접속하면, **Then** 찾을 수 없음이고, 누구도 그 주소로 가입할 수 없다.
9. **Given** 익명 처리 뒤 남은 댓글, **When** 보이면, **Then** 작성자는 "탈퇴한 사용자", 내용은 "탈퇴한 사용자의 댓글이에요", 사진은 기본 회색 아이콘이다.
10. **Given** 같은 이메일, **When** 익명 처리 뒤 다시 가입하면, **Then** 새 계정이 만들어지고 옛 주소는 예약되어 있어 `kim755030_2` 같은 다른 주소가 된다.
11. **Given** 정리 중 한 단계가 실패, **When** 작업이 끝나면, **Then** 그 회원의 앞 단계 처리까지 모두 취소되고 다음 날 다시 시도되며, 다른 회원 처리는 영향을 받지 않는다.
12. **Given** 정리 작업이 끝남, **When** 정리가 확정되면, **Then** 그 회원의 남은 로그인 세션·인증 링크·실패·요청 횟수 기록도 지워진다.

### Edge Cases

- 탈퇴 유예 회원이 다른 기기에서 이전 세션으로 요청하면, 세션은 이미 끊겨 있어 로그인이 필요하다.
- 유예 중에도 그 회원이 누른 좋아요는 남아 반응 수가 그대로다. 숫자는 익명 처리 때 맞춘다.
- 유예 회원의 콘텐츠는 공용 공개 조건(작성자 탈퇴 여부 포함)으로 이미 가려지므로 각 목록 기능이 따로 처리하지 않아도 된다.
- 복구 기한 마지막 순간에 [복구하기]와 정리 작업이 겹치면, 대상 조건(아직 탈퇴 상태이고 30일 경과)을 처리 시점에 다시 확인해 둘 중 하나만 적용된다.
- 정리 단계에 새 모듈을 추가할 때 기존 단계 순서를 바꾸지 않고 사이에 끼워 넣는다.
- 1차 출시에 이 기능을 포함할지는 미결이다 (FR-024).

## Requirements *(mandatory)*

### Functional Requirements

**탈퇴 신청**

- **FR-001**: System MUST 로그인한 본인만 설정 화면에서 탈퇴 화면으로 들어가게 하고, 비회원은 로그인 필요로 거부한다.
- **FR-002**: System MUST 한 화면 안에서 영향 안내·확인 체크 → 본인 확인 → [탈퇴하기] 순서로 보여 주고, 화면을 열 때 내 글 수(휴지통 포함)·남의 글에 쓴 댓글 수·받은 좋아요 수·복구 기한과 주소 재사용 불가 안내를 계산해 보여 준다.
- **FR-003**: System MUST 확인 체크와 본인 확인(이메일 가입은 비밀번호, 소셜 가입은 "탈퇴" 직접 입력)이 모두 있어야 탈퇴를 받아들이고, 화면의 버튼 비활성화와 별개로 서버에서도 검사한다.
- **FR-004**: System MUST 탈퇴 본인 확인에서 비밀번호를 5번 연속 틀리면 15분 동안 탈퇴 시도를 막는다.
- **FR-005**: System MUST 관리자 권한이 있는 회원의 탈퇴를 거부하고 권한 해제를 안내한다.
- **FR-006**: System MUST 탈퇴 사유를 받지 않는다.
- **FR-007**: System MUST 탈퇴를 받아들이는 즉시 회원을 탈퇴 유예 상태로 바꾸고 신청 시각을 기록하며, 모든 기기의 세션을 끊는다.
- **FR-008**: System MUST 탈퇴 직후부터 그 회원의 블로그와 글을 다른 사람에게 찾을 수 없음으로 보이게 하고 모든 공개 목록에서 빼며, 그 회원의 댓글은 행을 지우지 않고 "탈퇴한 사용자의 댓글이에요"로 가려 보여 준다.
- **FR-009**: System MUST 탈퇴가 확정된 뒤 탈퇴 사실을 다른 기능에 알리고, 이메일이 있는 계정에 복구 기한이 적힌 접수 메일을 보낸다.
- **FR-010**: System MUST 유예 중인 회원에게 새 알림을 만들지 않고, 그 회원의 행동으로도 알림을 만들지 않는다.

**유예와 복구**

- **FR-011**: System MUST 유예 회원이 로그인하면 복구 화면만 보여 주고, 다른 화면·기능 요청은 복구 화면으로 돌려보내거나 계정 상태 사유로 거부한다. 비밀번호 재설정은 허용한다.
- **FR-012**: System MUST 로그인만으로 복구하지 않고, 사용자가 [복구하기]를 눌러야 회원을 활동 상태로 되돌리고 신청 시각을 지운다.
- **FR-013**: System MUST 복구하면 블로그·글·댓글·좋아요·관계가 탈퇴 전과 같게 보이게 하고, 복구 사실을 다른 기능에 알리며, 복구 완료 메일을 보낸다.
- **FR-014**: System MUST 유예 중 그 회원의 닉네임과 블로그 주소를 다른 사람이 쓰지 못하게 묶어 둔다.
- **FR-015**: System MUST 유예 중인 이메일로 이메일 가입을 시도하면 탈퇴 신청 계정이 있다고 안내한다.

**30일 뒤 정리**

- **FR-016**: System MUST 매일 한 번, 탈퇴 상태이고 아직 익명 처리되지 않았으며 신청 뒤 30일이 지난 회원을 찾아 회원 한 명씩 정리하고, 여러 서버가 있어도 한 곳에서만 실행한다.
- **FR-017**: System MUST 회원 한 명의 정리를 하나의 원자적 작업으로 처리해 한 단계라도 실패하면 그 회원의 모든 단계를 취소하고 다음 날 다시 시도한다.
- **FR-018**: System MUST 정리를 정해진 순서로 실행한다: 글 완전 삭제 → 남의 글에 쓴 댓글 정리 → 누른 좋아요 정리 → 사진 연결 해제 → 로그인 수단 삭제 → 친구 관계 삭제 → 팔로우 관계 삭제 → 알림 정리 → 대기 신고 종료 → 회원 익명화. 각 기능은 자기 정리 단계를 제공하고, 새 단계는 기존 순서를 바꾸지 않고 사이에 들어간다.
- **FR-019**: System MUST 답글이 달린 댓글은 내용을 비우고 탈퇴 안내 자리만 남기며, 답글이 없는 댓글은 삭제하고, 정리 뒤 댓글 수·좋아요 수가 실제 행 수와 같게 한다.
- **FR-020**: System MUST 익명화 때 블로그 주소만 남기고 닉네임·소개·닉네임 변경 일자·최근 활동·AI 동의·정지 상태 정보를 비우며, 약관 동의 기록과 정지 이력은 남긴다.
- **FR-021**: System MUST 익명 처리된 회원의 사진을 익명 처리 뒤 다음 사진 정리 작업 때 삭제한다.
- **FR-022**: System MUST 익명 처리된 블로그 주소를 영구히 다시 쓸 수 없게 하고, 비워진 닉네임은 바로 다른 사람이 쓸 수 있게 하며, 로그인 수단 삭제로 같은 이메일의 새 가입을 허용한다.
- **FR-023**: System MUST 정리가 확정된 뒤 그 회원의 세션·인증 링크·실패 및 요청 횟수 기록을 지운다. 30일 뒤 정리는 별도 알림 이벤트를 만들지 않는다.

**범위**

### Key Entities

- **회원 (member)**: 상태(활동·정지·탈퇴), 탈퇴 신청 시각, 익명 처리 시각, 블로그 주소(영구 보존). 익명 처리 뒤에는 블로그 주소만 남은 껍데기.
- **로그인 수단 (auth_identity)**: 익명 처리 때 삭제되어 이메일이 풀린다.
- **동의 기록 (member_agreement)·정지 이력 (member_suspension)**: 익명 처리 뒤에도 증빙으로 남는다.
- **회원이 남긴 데이터**: 글(post), 댓글(comment), 좋아요(post_like), 사진(image), 팔로우(follow), 친구(friendship), 알림(notification), 신고 사건(report_case). 각 기능의 정리 단계 대상이다.
- **탈퇴·복구 사실**: 탈퇴 확정·복구 확정 때 다른 기능에 알리는 사건. 30일 뒤 정리는 사건을 만들지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 확인 체크나 본인 확인이 빠진 탈퇴 요청은 100% 거부된다.
- **SC-002**: 비밀번호를 5번 연속 틀린 뒤 15분 동안 탈퇴 요청이 100% 거부된다.
- **SC-003**: 탈퇴 직후 그 회원의 모든 기기가 다음 요청부터 로그아웃 상태이고, 완료 화면에 복구 기한이 보인다.
- **SC-004**: 탈퇴 직후 다른 사람이 그 블로그·글을 열면 100% 찾을 수 없음이고, 공개 목록에 그 회원의 글이 0건 나온다.
- **SC-005**: 유예 중 로그인한 회원이 복구 화면 밖의 기능을 쓰는 경우가 0건이다.
- **SC-006**: [복구하기] 뒤 블로그·글·댓글·반응 수가 탈퇴 전과 100% 같다.
- **SC-007**: 관리자 권한이 있는 회원의 탈퇴는 100% 거부된다.
- **SC-008**: 회원 한 명의 30일 뒤 정리는 전부 성공하거나 전부 취소되며, 일부러 중간 단계를 실패시키면 바뀐 데이터가 0건이다.
- **SC-009**: 정리 뒤 영향을 받은 모든 글의 댓글 수·좋아요 수가 실제 행 수와 100% 같다.
- **SC-010**: 정리 뒤 회원 정보에 블로그 주소 외 개인 정보(이메일·닉네임·소개·사진·최근 활동·AI 동의·정지 사유)가 0건 남는다.
- **SC-011**: 익명 처리된 블로그 주소로 가입·접속에 성공하는 경우가 0건이고, 같은 이메일로 다시 가입하면 100% 새 계정이 만들어진다.
- **SC-012**: 답글이 달린 댓글만 탈퇴 안내 자리로 남고, 답글 없는 댓글은 0건 남는다.

## Assumptions

- 가입 화면의 탈퇴 유예 안내와 비밀번호 재설정은 [001-member-auth](../001-member-auth/spec.md), 설정 화면의 진입 버튼은 [002-profile-nickname](../002-profile-nickname/spec.md)과 함께 동작한다.
- 각 정리 단계의 세부(댓글·좋아요·사진·팔로우·알림·신고 정리 방법)는 해당 기능 spec과 근거 문서가 정한다. 이 spec은 순서와 원자성, 결과만 정한다.
- 글 완전 삭제 방식은 글 삭제 spec(C-POST-5)과 같다.
- 탈퇴 전 글 내보내기, 메일로만 탈퇴 여부를 알리는 방식은 범위 밖(개인 확장)이다.
- 유예 기간 30일과 정리 작업 실행 시각(매일 새벽)은 근거 문서의 결정값을 따르며, 팀 정책 차이가 생기면 설정값으로 둔다.
- 가입 화면에서 이메일만으로 탈퇴 신청 여부가 드러나는 것은 팀이 감수하기로 했다 (44 결정 기록 2026-10-06).
- 이메일이 없는 계정에는 접수·복구 메일을 보내지 않는다.
