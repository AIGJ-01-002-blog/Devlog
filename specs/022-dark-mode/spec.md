## User Scenarios & Testing *(mandatory)*

### User Story 1 - 처음부터 기기 설정에 맞는 테마로 보기 (Priority: P1)

방문자(비회원 포함)가 처음 사이트를 열면 기기의 라이트/다크 설정을 따른 테마로 보이고, 페이지를 여는 순간 반대 테마 화면이 잠깐 번쩍이지 않는다.

**Why this priority**: 아무 조작 없이 모든 사용자가 바로 얻는 가치이며, 번쩍임은 가장 눈에 띄는 결함이다.

**Independent Test**: 기기를 다크로 설정한 브라우저에서 저장값 없이 여러 페이지를 열어 테마와 첫 화면을 확인한다.

**Acceptance Scenarios**:

1. **Given** 기기 설정이 다크이고 저장된 선택이 없다, **When** 처음 방문한다, **Then** 다크 테마로 보인다(기기 설정이 라이트면 라이트).
2. **Given** 다크로 보이는 상태, **When** 페이지를 새로 열거나 다른 페이지로 이동한다, **Then** 밝은 화면이 잠깐도 보이지 않는다.
3. **Given** 보안 정책상 페이지 안에 직접 쓴 스크립트는 막혀 있다, **When** 테마가 적용된다, **Then** 보안 정책 위반 없이 동작한다.
4. **Given** 테마 선택을 기기에 저장할 수 없는 환경(저장소 접근 차단), **When** 페이지를 연다, **Then** 오류 없이 기기 설정을 따른다.
5. **Given** 다크 테마, **When** 스크롤바·기본 입력칸을 본다, **Then** 브라우저 기본 요소도 테마를 따른다.

---

### User Story 2 - 헤더에서 테마 고르고 유지하기 (Priority: P1)

사용자는 어느 페이지에서나 헤더 맨 오른쪽 버튼을 눌러 시스템 → 라이트 → 다크 → 시스템 순으로 바꾼다. 선택은 이 기기에 저장되어 새로 고침·페이지 이동·로그아웃 뒤에도 유지된다.

**Why this priority**: 사용자가 원하는 테마를 고정할 수 있어야 기능이 완성된다.

**Independent Test**: 버튼을 순환시키며 각 선택이 즉시 반영되는지, 새로 고침·이동·로그아웃 뒤 유지되는지, "시스템" 선택 중 기기 설정 변경을 따라가는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 시스템 선택, **When** 버튼을 누른다, **Then** 라이트로, 다시 누르면 다크로, 다시 누르면 시스템으로 바뀌고 즉시 화면에 반영된다.
2. **Given** 다크를 골랐다, **When** 새로 고치거나 다른 페이지로 이동한다, **Then** 다크가 유지된다.
3. **Given** "시스템"을 고른 상태, **When** 기기 설정을 라이트에서 다크로 바꾼다, **Then** 새로 고치지 않아도 화면이 따라 바뀐다.
4. **Given** 라이트 또는 다크로 고정, **When** 기기 설정이 바뀐다, **Then** 화면은 고정한 테마 그대로다.
5. **Given** 테마를 고른 회원, **When** 로그아웃한다, **Then** 테마 선택은 지워지지 않는다.
6. **Given** 두 기기, **When** 한 기기에서 테마를 바꾼다, **Then** 다른 기기에는 영향이 없다.
7. **Given** 전환 버튼, **When** 화면 낭독기·마우스 올림으로 확인한다, **Then** 아이콘과 함께 현재 선택을 설명하는 글자 이름이 있다.
8. **Given** 테마가 바뀔 때, **When** 화면이 다시 그려진다, **Then** 색이 서서히 바뀌는 애니메이션은 없다.

---

### User Story 3 - 두 테마 모두 읽기 쉽고 콘텐츠 색은 그대로 (Priority: P2)

라이트·다크 모두 본문 글자와 테두리·아이콘이 충분한 명도 대비를 가지며, 글 사진·썸네일·프로필 사진은 색을 바꾸지 않고, 코드 강조는 테마에 맞는 색으로 바뀐다.

**Why this priority**: 다크 모드에서 흔한 "회색 글자가 안 읽힘" 문제와 사진 왜곡을 막는다.

**Independent Test**: 주요 화면(홈·글 상세·에디터·설정)을 두 테마에서 자동 대비 검사 도구로 확인하고, 사진·코드 블록을 눈으로 비교한다.

**Acceptance Scenarios**:

1. **Given** 라이트·다크 각각, **When** 주요 화면을 검사한다, **Then** 본문 글자는 배경 대비 4.5 : 1 이상, 큰 글자·아이콘·입력칸 테두리는 3 : 1 이상이다.
2. **Given** 다크 테마, **When** 글 사진·썸네일·프로필 사진을 본다, **Then** 색이 뒤집히거나 어두워지지 않는다.
3. **Given** 코드 블록이 있는 글, **When** 테마를 바꾼다, **Then** 코드 강조 색도 그 테마용으로 바뀐다.
4. **Given** 사진 없는 기본 프로필 아이콘, **When** 다크 테마로 본다, **Then** 아이콘 글자와 배경 대비가 4.5 : 1 이상이다.
5. **Given** 공개 범위·수정 중 등 상태 표시, **When** 어느 테마로 보든, **Then** 색만이 아니라 글자·아이콘으로도 구분된다.
6. **Given** 에디터가 다크 테마를 지원하지 않는다, **When** 다크 테마에서 글을 쓴다, **Then** 에디터만 라이트로 보이고 주변은 다크다.
7. **Given** 링크 미리보기·메일, **When** 생성된다, **Then** 테마와 무관하게 라이트 기준이다.

---

### User Story 4 - 공통 화면 상태를 같은 문구로 (Priority: P3)

어느 테마에서든, 세 서비스 어디서든, 불러오는 중·빈 목록·불러오기 실패와 다시 시도·볼 수 없는 페이지(404)·저장 상태·로그인/이메일 인증 안내는 같은 정보와 문구로 보인다. 색·글꼴·배치는 각 서비스가 정한다.

**Why this priority**: 상태 문구는 공통 규칙이지만 각 상태의 세부는 해당 기능 spec이 소유하므로, 여기서는 일관성만 보장한다.

**Independent Test**: 목록 [더 보기] 로딩·실패, 빈 홈, 없는 글 주소, 자동 저장 상태, 비회원의 댓글 입력을 두 테마에서 확인한다.

**Acceptance Scenarios**:

1. **Given** 목록 [더 보기], **When** 불러오는 중이다, **Then** 버튼이 "불러오는 중…"으로 바뀌고 비활성화된다. 실패하면 "불러오지 못했어요 [다시 시도]"가 보인다.
2. **Given** 없는 글 또는 볼 수 없는 글, **When** 주소를 연다, **Then** 같은 "볼 수 없는 페이지예요" 화면이 보인다.
3. **Given** 공개 글이 하나도 없다, **When** 홈을 연다, **Then** 정해진 빈 상태 문구와 행동 버튼(회원 [글쓰기], 비회원 [로그인])이 보인다.
4. **Given** 자동 저장 중인 에디터, **When** 저장 상태가 바뀐다, **Then** 색만이 아니라 글자로 상태(저장됨·이 기기에 저장됨·오프라인·충돌)가 보인다.
5. **Given** 비회원 또는 이메일 인증 전 회원, **When** 회원 전용 행동을 시도한다, **Then** 로그인 또는 이메일 인증 안내가 같은 방식으로 보인다.

---

### Edge Cases

- 저장값이 알 수 없는 값이면 "시스템"으로 취급한다.
- 테마 저장소 접근이 막힌 비공개 창에서는 버튼으로 바꾼 테마가 그 페이지에서만 적용되고 저장되지 않을 수 있다.
- 다크 배경은 순수 검정 대신 약간 밝은 어두운 색을 써서 흰 글자가 번져 보이지 않게 한다(정확한 값은 각 서비스 선택).
- 각 서비스가 강조 색(브랜드 색)을 정할 때도 대비 기준을 만족해야 한다.
- 썸네일 없는 카드의 빈 영역도 다크에서 어두운 색으로 바뀐다(정확한 색은 각 서비스 선택).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 테마 선택지로 시스템 설정 / 라이트 / 다크 세 가지를 제공하고, 처음 기본값은 시스템 설정이어야 한다.
- **FR-002**: System MUST 모든 페이지의 헤더 같은 자리에 전환 버튼을 두고, 누를 때마다 시스템 → 라이트 → 다크 → 시스템 순으로 바꾸며, 아이콘과 글자 이름(화면 낭독기·툴팁)을 함께 제공해야 한다.
- **FR-003**: System MUST 선택을 기기(브라우저)에 저장해 새로 고침·페이지 이동 뒤 유지하고, 비회원도 쓸 수 있어야 하며, 로그아웃 때 지우지 않아야 한다. 계정·서버에는 저장하지 않는다.
- **FR-004**: System MUST "시스템" 선택 중 기기 설정이 바뀌면 새로 고침 없이 따라가고, 라이트·다크로 고정하면 기기 설정 변경을 무시해야 한다.
- **FR-005**: System MUST 화면을 그리기 전에 테마를 정해 첫 화면에서 반대 테마가 잠깐 보이지 않게 해야 한다.
- **FR-006**: System MUST 콘텐츠 보안 정책(인라인 스크립트 금지)을 어기지 않고 테마를 적용해야 하며, 테마 저장소 접근이 막히면 기기 설정만 따라야 한다.
- **FR-007**: System MUST 브라우저 기본 요소(스크롤바·입력칸)도 테마를 따르도록 알려야 한다.
- **FR-008**: System MUST 화면 색을 공통 이름의 색 토큰 목록으로만 정의하고 라이트·다크 값을 둬야 한다. 토큰 이름은 공통, 값은 각 서비스가 바꿀 수 있다.
- **FR-009**: System MUST 두 테마 모두 본문 글자 대비 4.5 : 1 이상, 큰 글자·아이콘·입력칸 테두리 3 : 1 이상을 만족해야 한다.
- **FR-010**: System MUST NOT 글 사진·썸네일·프로필 사진의 색을 테마에 따라 바꿔서는 안 된다.
- **FR-011**: System MUST 코드 강조 색을 현재 테마에 맞는 것으로 바꿔야 한다.
- **FR-012**: System MUST 상태 표시(공개 범위·저장 상태·안 읽음 등)를 색만으로 구분하지 않고 글자·아이콘을 함께 써야 한다.
- **FR-013**: System MUST 테마 전환 시 색 전환 애니메이션을 쓰지 않아야 한다.
- **FR-014**: System MUST 링크 미리보기·메일을 테마와 무관하게 라이트 기준으로 만들어야 한다.
- **FR-015**: System MUST 로딩·빈 목록·불러오기 실패와 다시 시도·404·저장 상태·로그인/이메일 인증 안내를 각 기능 spec이 정한 공통 정보·문구로 보여 줘야 하며, 색·글꼴·배치만 서비스별로 달라질 수 있다.

### Key Entities *(include if feature involves data)*

- **테마 선택**: 시스템 / 라이트 / 다크 중 하나. 기기 브라우저에만 저장되고 서버·DB에는 저장하지 않는다.
- **색 토큰 목록**: 배경, 표면, 글자, 보조 글자, 테두리, 강조, 강조 버튼 배경, 위험, 썸네일 빈 영역, 코드 배경, 포커스 테두리. 이름은 공통, 라이트·다크 값은 기본값을 두고 서비스가 조정한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 저장값 없이 처음 방문한 사용자의 100%가 기기 설정과 같은 테마를 본다.
- **SC-002**: 시스템·라이트·다크 선택이 새로 고침·페이지 이동·로그아웃 뒤 100% 유지된다.
- **SC-003**: 다크로 설정한 상태에서 페이지를 열 때 밝은 화면이 보이는 경우가 0건이다(녹화 프레임 확인).
- **SC-004**: 테마 적용으로 인한 콘텐츠 보안 정책 위반 보고가 0건이다.
- **SC-005**: "시스템" 선택 중 기기 설정을 바꾸면 새로 고침 없이 1초 안에 화면이 따라 바뀐다.
- **SC-006**: 주요 화면(홈·글 상세·에디터·설정·알림)의 자동 대비 검사에서 두 테마 모두 기준 미달 항목이 0개다.
- **SC-007**: 다크 테마에서 색이 바뀐 사진이 0건이고, 코드 블록은 테마별 강조 색으로 보인다.
- **SC-008**: 공통 화면 상태(로딩·빈 목록·실패·404·저장 상태·로그인 안내)의 문구가 두 테마에서 동일하다.

## Assumptions

- Tier C, 출시 순서는 01 기준 미정이다 ([52 §11.2](../../docs/52-feature-summary.md)).
- 화면은 브라우저 스크립트로 그리는 단일 앱이다(2026-10-07 H7). 45의 "스크립트가 꺼져 있어도 기기 설정을 따른다"(§5 #8)는 이 결정 이후 화면 자체가 그려지지 않는 상태라 이 spec의 기준에서 뺐다. 필요하면 clarify 단계에서 다시 확인한다.
- 2026-10-07 결정(O5)에 따라 색·글꼴·배치·썸네일 빈 영역 색은 서비스별 자유이므로, 45의 썸네일 빈 영역 색 값(§5 #7)과 색 토큰 값은 기본값으로만 취급하고 완료 기준에 넣지 않았다.
- 공통 화면 상태의 구체 문구는 각 기능 spec이 소유한다: 목록 로딩·실패·빈 상태(C-READ-1), 404 화면(C-READ-2·C-POST-4), 저장 상태(C-POST-2), 로그인·인증 안내(C-AUTH-1), 알림 상태(016-notification).
- 에디터의 다크 테마 지원 여부는 각 서비스가 정한다.
- 범위 밖(개인 확장): 계정별 테마 저장, 기기 간 동기화.
