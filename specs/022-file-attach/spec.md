# Feature Specification: 글 첨부파일 (022-file-attach)

**Feature Branch**: `022-file-attach`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "작성자는 글에 PDF·압축 파일·문서 같은 첨부파일을 올리고, 독자는 글 아래 첨부 목록에서 원래 파일
이름으로 내려받는다. 사진과 첨부파일은 리소스 한 곳에서 함께 관리하되, 글과는 사진·파일을 따로 연결한다. 업로드 흐름과 정리

**선행 기능**: `009-image-upload` (직접 업로드·서버 재검사·정리 배치), `002-write-publish` (발행 검증)

**우선순위 단계**: 다음 단계 (Tier B, 사진 업로드 다음)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 글에 파일을 첨부하고 발행한다 (Priority: P1)

작성자는 에디터 아래 [파일 첨부]를 눌러 파일을 고르거나 끌어 놓는다. 파일은 바로 올라가 첨부 목록에 이름·크기와 함께 나타나고,
발행하면 독자가 글 아래 첨부 목록에서 볼 수 있다.

**Why this priority**: 발표 자료·예제 코드 압축 파일을 함께 올리는 것이 개발 블로그 첨부의 핵심이다.

**Independent Test**: 3MB PDF와 1MB zip을 첨부해 발행하고, 비회원으로 글을 열어 첨부 목록에 두 파일이 원래 이름·크기로 보이는지
확인한다.

**Acceptance Scenarios**:

1. **Given** 작성 중인 글, **When** `발표.pdf`(3MB)를 첨부하면, **Then** 첨부 목록에 "발표.pdf · 3.0MB"가 나타나고 자동 저장에
   함께 반영된다.
2. **Given** 첨부가 2개인 글, **When** 발행하면, **Then** 독자에게 글 본문 아래 첨부 목록이 첨부한 순서대로 보인다.
3. **Given** 첨부 목록, **When** 작성자가 순서를 끌어 바꾸고 저장하면, **Then** 독자에게도 바뀐 순서로 보인다.
4. **Given** 허용하지 않는 형식(`.exe`) 또는 20MB를 넘는 파일, **When** 첨부하면, **Then** 올리기 전에 "pdf, zip, txt, md, csv,
   docx, xlsx, pptx 20MB 이하만 첨부할 수 있어요"로 거부된다.

---

### User Story 2 - 독자가 원래 이름으로 내려받는다 (Priority: P2)

독자는 첨부 목록의 파일 이름을 눌러 내려받는다. 저장되는 이름은 작성자가 올린 원래 파일 이름이다.

**Why this priority**: 첨부의 목적은 내려받기다. 업로드(P1)가 먼저 있어야 한다.

**Independent Test**: 한글 이름 파일(`예제 코드.zip`)을 첨부한 글에서 내려받아 저장된 파일 이름과 내용이 원본과 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개 글의 첨부, **When** 비회원이 이름을 누르면, **Then** 원래 파일 이름(한글 포함)으로 내려받는다.
2. **Given** 비공개 글의 첨부, **When** 작성자가 아닌 사람이 내려받기 주소를 요청하면, **Then** "찾을 수 없음"이다.
3. **Given** 첨부 파일, **When** 브라우저가 열면, **Then** 페이지 안에서 실행되지 않고 항상 내려받기로 처리된다.

---

### User Story 3 - 쓰지 않는 첨부는 자동으로 정리된다 (Priority: P3)

올리기만 하고 글에 남지 않은 파일, 글에서 뺀 파일은 사진과 같은 정리 배치가 지운다.

**Why this priority**: 저장 공간 보호 장치다. 사용자가 직접 보는 기능은 아니다.

**Acceptance Scenarios**:

1. **Given** 올리고 첨부 목록에서 뺀 파일, **When** 연결이 끊긴 지 7일이 지나면, **Then** 파일과 리소스 행이 지워진다.
2. **Given** 올리기만 하고 어느 글에도 연결되지 않은 파일, **When** 24시간이 지나면, **Then** 지워진다.
3. **Given** 휴지통의 글에 연결된 파일, **When** 정리 배치가 돌면, **Then** 지워지지 않는다(연결이 남아 있으므로).

---

### Edge Cases

- 같은 파일을 두 글에 첨부하면? → 리소스 하나가 두 글에 연결된다(`post_file`은 다대다). 한 글에서 빼도 다른 글의 연결이 남아
  정리되지 않는다.
- 사진 파일(`.png`)을 첨부로 올리면? → 첨부로 받지 않고 "사진은 본문에 넣어 주세요"로 안내한다. 사진은 009 흐름으로만 올린다.
- 파일 이름에 경로 문자(`../`)나 제어 문자가 있으면? → 저장 경로는 서버가 정하므로 영향이 없고, 표시·내려받기 이름에서는 그
  문자를 지운다.
- 남이 올린 파일을 내 글에 첨부하려 하면? → 거부한다(글 작성자가 올린 리소스만 연결).

## Requirements *(mandatory)*

### Functional Requirements

**업로드 (009와 같은 흐름)**

- **FR-001**: 첨부 업로드는 로그인하고 가입을 마친 회원만 할 수 있어야 한다.
- **FR-002**: 받는 형식은 pdf, zip, txt, md, csv, docx, xlsx, pptx이고 파일 하나 20MB 이하여야 한다. 확장자와 실제 내용 형식을
  모두 검사해야 한다.
- **FR-003**: 파일 데이터는 서비스 서버를 거치지 않고 파일 저장소로 바로 올라가야 하며, 업로드 허가는 5분만 유효해야 한다.
- **FR-004**: 업로드가 끝나면 서버가 파일의 존재, 실제 크기, 실제 형식을 다시 검사해야 한다.
- **FR-005**: 저장 경로는 서버가 정하고 추측할 수 없어야 한다. 원래 파일 이름은 리소스 첨부 속성(`resource_file.original_name`)에만 둔다.
- **FR-006**: 첨부 업로드는 사진 업로드와 합쳐 사용자당 1분에 20건으로 제한해야 한다.

**글 연결**

- **FR-007**: 수동 저장·자동 저장 반영·발행 때 첨부 목록을 그 글의 첨부 연결(`post_file`)과 순서(`position`)로 맞춰야 한다.
  빠진 파일은 연결이 끊긴 시각(`resource.detached_at`)을 기록한다.
- **FR-008**: 글 작성자가 올린 첨부파일만 그 글에 연결할 수 있어야 한다.
- **FR-009**: 사진은 사진 연결(`post_image`)에만, 첨부파일은 첨부 연결(`post_file`)에만 들어가야 한다. DB가 종류별 FK로 막는다.
- **FR-010**: 한 글의 첨부는 20개 이하여야 한다.

**내려받기**

- **FR-011**: 첨부를 볼 수 있는지는 글 상세와 같은 판정 규칙(docs/42)을 따라야 한다. 볼 수 없으면 "찾을 수 없음"이다.
- **FR-012**: 내려받기 응답은 `Content-Disposition: attachment`와 원래 파일 이름(RFC 5987 인코딩)을 써야 하며, 브라우저가 내용을
  해석해 실행하지 않게 `X-Content-Type-Options: nosniff`를 붙여야 한다.
- **FR-013**: 공개 글의 첨부는 짧게 유효한 서명 주소로 저장소에서 바로 내려받게 한다. 비공개 글은 작성자 확인 뒤에만 주소를 준다.

**정리**

- **FR-014**: 어느 연결(`post_image`, `post_file`, `member_profile_image`)에도 없는 리소스는 올린 지 24시간, 연결이 끊긴 지 7일이
  지나면 저장소 파일과 행을 함께 지워야 한다(009 정리 배치와 같은 작업).
- **FR-015**: 글이 완전 삭제되면 첨부 연결도 지워지고, 다른 글에서 쓰지 않는 파일은 연결이 끊긴 것으로 기록한다.

### Key Entities *(include if feature involves data)*

- **리소스(Resource)**: 사진·첨부 공통. 올린 사람, 종류(IMAGE·FILE), 저장 경로, 형식, 크기, 연결 해제 일자, 만든 일자.
- **첨부 리소스(ResourceFile)**: 첨부 전용 속성. 원래 파일 이름. `(resource_id, kind)`로 리소스를 가리켜 사진 행과 섞이지 않는다.
- **글 첨부 연결(PostFile)**: 어떤 글이 어떤 첨부를 어떤 순서로 쓰는지. 다대다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 허용 형식 20MB 이하 파일은 모두 첨부되고, 그 밖의 파일은 올리기 전에 거부된다.
- **SC-002**: 내려받은 파일의 이름과 내용이 올린 원본과 같다(한글 이름 포함).
- **SC-003**: 비공개 글의 첨부는 작성자가 아니면 내려받을 수 없다.
- **SC-004**: 사진 리소스가 첨부 연결에, 첨부 리소스가 사진 연결에 들어가는 경우가 0건이다(DB 제약으로 거부).
- **SC-005**: 정리 배치 뒤 연결 없는 리소스가 기준 기간을 넘겨 남는 경우가 0건이다.

## Assumptions

- **A-1**: 저장소는 사진과 같은 파일 저장소를 쓰고, 첨부는 `files/` 아래 별도 경로에 둔다.
- **A-2**: 바이러스 검사는 이번 범위에 넣지 않는다. 형식·크기 검사와 항상 내려받기 처리로 위험을 줄인다.
- **A-3**: 스키마는 V3(`erd/V3__normalize_schema.sql`)의 `resource`, `resource_file`, `post_file`을 쓴다.
