# Feature Specification: 텔레그램 연결 (알림 받기 + 메모로 임시글)

**Feature Branch**: `023-telegram`
**Created**: 2026-10-07
**Status**: Implemented (v1.12.0)
**근거**: 2026-10-07 민서 답변(daily/answers-2026-10-07.md): "텔레그램 챗봇 알림 + 텔레그램 AI 기능", AI 기능 1순위 추천 "메모 보내면 AI가 임시글로 다듬기"
**선행 기능**: `015-notifications`(알림), `018-ai-tags`(AI 공급자·동의), `002-write-publish`(임시글)

## User Scenarios & Testing

### User Story 1 - 내 텔레그램을 블로그 계정에 연결한다 (Priority: P1)

회원은 설정 화면에서 [텔레그램 연결]을 누르고 블로그 봇과 대화를 시작해 자기 계정에 연결한다. 비밀번호나 전화번호를 입력하지 않는다.

**Acceptance Scenarios**:
1. **Given** 로그인한 회원, **When** [텔레그램 연결]을 누르면, **Then** 10분 동안 쓸 수 있는 1회용 연결 주소(`https://t.me/<봇>?start=<코드>`)가 보인다.
2. **Given** 연결 주소를 연 회원, **When** 봇에서 [시작]을 누르면, **Then** 봇이 "○○님 블로그와 연결했어요"라고 답하고 설정 화면이 "연결됨"으로 바뀐다.
3. **Given** 만료되었거나 이미 쓴 코드, **When** 봇을 시작하면, **Then** "연결 코드가 만료됐어요. 설정에서 다시 연결해 주세요."라고 답하고 아무 계정에도 연결하지 않는다.
4. **Given** 연결된 회원, **When** 설정에서 [연결 끊기]를 누르거나 봇에 `/stop`을 보내면, **Then** 연결이 지워지고 더는 알림이 가지 않는다.

### User Story 2 - 새 알림을 텔레그램으로 받는다 (Priority: P1)

연결한 회원은 블로그 알림(댓글·답글·좋아요·새 팔로워·새 글·신고 결과·숨김)을 텔레그램 메시지로도 받는다.

**Acceptance Scenarios**:
1. **Given** 연결되고 텔레그램 알림이 켜진 회원, **When** 내 글에 댓글이 달리면, **Then** "💬 ○○님이 「제목」에 댓글을 남겼어요" + 댓글 앞부분 + 글 주소가 온다.
2. **Given** 알림 종류를 끈 회원(015 설정), **When** 그 종류의 일이 생기면, **Then** 블로그 알림이 없으므로 텔레그램도 오지 않는다.
3. **Given** 텔레그램 알림을 끈 회원, **When** 알림이 생기면, **Then** 블로그 알림만 생기고 텔레그램은 오지 않는다.
4. 좋아요·팔로워처럼 묶이는 알림은 새 묶음이 생길 때 한 번만 보낸다(같은 묶음에 사람이 더해질 때마다 보내지 않는다).

### User Story 3 - 메모를 보내면 임시글이 된다 (Priority: P1)

연결한 회원이 봇에게 글자 메시지를 보내면 내 블로그 임시글이 하나 생긴다. AI 기능에 동의했고 AI를 쓸 수 있으면 AI가 제목을 붙이고 Markdown으로 다듬는다.

**Acceptance Scenarios**:
1. **Given** AI에 동의한 회원, **When** "오늘 Redis 캐시 TTL 설정하다가 알게 된 것: ..." 메모를 보내면, **Then** 다듬어진 임시글이 생기고 봇이 "임시글로 저장했어요: 「제목」" + 편집 주소로 답한다. 발행은 하지 않는다.
2. **Given** AI 미동의·AI 꺼짐·한도 초과·AI 실패, **When** 메모를 보내면, **Then** 메모 원문 그대로(첫 줄을 제목으로) 임시글이 생기고 그 이유를 한 줄로 알린다.
3. AI는 메모에 없는 사실·코드·수치를 지어내지 않고, 메모의 코드 블록과 링크는 그대로 둔다.
4. 정지·탈퇴 신청한 회원, 이메일 인증 전 회원의 메모는 임시글을 만들지 않고 이유를 답한다.
5. 메모는 4,000자까지, 회원당 하루 20개까지 받는다.

### Edge Cases
- 연결되지 않은 대화에서 온 메시지 → 연결 방법 안내만 하고 저장하지 않는다.
- 같은 텔레그램 대화를 다른 계정에 연결하면 이전 계정과의 연결은 끊긴다(대화 하나 = 계정 하나).
- 봇이 차단되어 보내기가 실패(403)하면 그 연결을 지운다.
- 봇 토큰이 없으면 기능 전체가 꺼지고 설정 화면에 텔레그램 항목이 보이지 않는다.

## Requirements

- **FR-001**: 봇 토큰(`TELEGRAM_BOT_TOKEN`)이 있고 `TELEGRAM_ENABLED`가 꺼져 있지 않을 때만 동작한다.
- **FR-002**: 연결 코드는 추측할 수 없는 1회용 값이고 10분 뒤 만료된다. 코드에는 회원 번호가 드러나지 않는다.
- **FR-003**: 회원 하나에 대화 하나, 대화 하나에 회원 하나만 연결된다(DB 고유 제약).
- **FR-004**: 텔레그램 메시지는 블로그 알림이 실제로 만들어진 뒤(커밋 뒤)에만, 요청과 떼어 보낸다. 실패해도 블로그 동작에 영향이 없다.
- **FR-005**: 메시지에는 받는 사람이 볼 수 있는 정보만 담는다(015 알림 화면과 같은 판정).
- **FR-006**: 메모 → 임시글은 AI 동의(018)가 있어야 AI를 쓰고, 외부 AI 하루 한도는 태그 추천과 함께 센다.
- **FR-007**: 메모·AI 응답·토큰은 로그에 남기지 않는다.
- **FR-008**: 탈퇴 정리(020) 때 연결을 지운다.
- **FR-009**: 업데이트 받기는 서버가 여러 대여도 한 대만 한다(웹훅 대신 롱 폴링: 공개 https 주소 없이 동작).
