# Feature Specification: 키보드·화면 읽기 프로그램 이동 개선

**Feature Branch**: `029-keyboard-reader-a11y`
**Created**: 2026-10-08
**Status**: Implemented (v1.16.2)
**근거**: 민서 요청 "모든 기능을 최적화 해서 구현해줘"(2026-10-07). 화면 안 이동 뒤 초점이 누른 링크에 남아 화면 읽기 프로그램이 새 화면을 알리지 못했고, 키보드 사용자는 글마다 머리말 메뉴를 다시 지나야 했다.

## User Scenarios & Testing

### User Story 1 - 키보드로 본문에 바로 간다 (Priority: P1)
1. **Given** 아무 화면, **When** Tab을 처음 누르면, **Then** 왼쪽 위에 "본문으로 건너뛰기"가 보이고 Enter를 누르면 화면이 본문까지 스크롤되고 초점이 본문으로 간다.

### User Story 2 - 화면을 옮기면 새 본문부터 읽는다 (Priority: P1)
1. **Given** 화면 읽기 프로그램 사용자, **When** 링크로 다른 화면에 가면, **Then** 초점이 새 화면 본문으로 옮겨져 거기서부터 읽는다. 스크롤 위치는 지금처럼 맨 위다.
2. 글쓰기 자동 저장처럼 링크를 누르지 않은 주소 바뀜에서는 초점을 옮기지 않는다(쓰던 칸에서 초점을 빼앗지 않는다).

## Requirements
- **FR-001**: 모든 화면 맨 앞에 "본문으로 건너뛰기" 링크. 초점을 받을 때만 보이고, 누르면 본문까지 스크롤하며 초점을 옮긴다.
- **FR-002**: 화면 안 링크로 이동하면 본문 자리(모든 화면을 감싸는 `#main-content`, `tabindex="-1"`)에 스크롤 없이 초점. 화면을 불러오는 동안에도 자리는 남아 초점이 사라지지 않는다. 본문 테두리는 그리지 않는다.
