# Feature Specification: 사용자 IP 판정 다지기

**Feature Branch**: `033-client-ip-hardening`
**Created**: 2026-10-08
**Status**: Implemented (v1.16.6)
**근거**: 민서 요청 "모든 기능을 최적화 해서 구현해줘"(2026-10-07)에 따른 테스트 보강. 요청 제한의 기준인 `ClientIpResolver`의 테스트가 없었고(줄 커버리지 0~43%), 보강하며 두 가지 결함을 찾았다.

## 찾은 결함
1. `999.1.1.1`처럼 숫자가 범위를 넘는 주소를 IPv4로 보고 `InetAddress.getByName`에 넘겼다. JDK는 이를 호스트 이름으로 보고 DNS를 묻는다. 코드 주석의 "DNS 조회 없이"와 어긋난다(결과는 같은 null이지만 요청마다 DNS를 일으킬 수 있었다).
2. `TRUSTED_PROXIES`에 `10.0.0.0/33`처럼 범위를 넘는 접두사를 넣으면 시작은 되고, 요청마다 배열 범위 오류(500)가 났다.

## Requirements
- **FR-001**: IPv4는 0~255 네 덩어리만 숫자 주소로 본다. 그 밖의 값은 DNS를 묻지 않고 "숫자 주소 아님"으로 본다.
- **FR-002**: 신뢰 대역 접두사가 0 미만이거나 주소 길이(IPv4 32, IPv6 128)를 넘으면 시작할 때 막는다.
- **FR-003**: 판정 규칙(신뢰 밖에서 온 요청은 헤더 무시, 신뢰 대역이면 오른쪽부터 첫 신뢰 밖 주소)은 바뀌지 않는다.
