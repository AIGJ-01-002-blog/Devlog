# Feature Specification: 세션 저장소가 멈췄을 때 가입·로그인 응답

**Feature Branch**: `036-session-store-down`
**Created**: 2026-10-08
**Status**: Implemented (v1.16.9)
**근거**: 001 FR-020("새 로그인은 다시 시도하라는 안내로 거부"), docs/02 §2-1 세션 행. 민서 요청 "모든 기능을 최적화 해서 구현해줘"(2026-10-07)에 따른 테스트 보강 중에 찾았다.

## 찾은 문제
`ResilientSessionFilter`는 세션 저장소(Redis)를 읽지 못하면 읽기를 비로그인으로 이어 가고, 새 세션이 필요한 요청에는 `SessionUnavailableException`을 던진다.
- 이 예외를 받는 곳이 없어 공통 오류 처리기의 마지막 칸으로 떨어졌다. 가입·이메일 인증·소셜 가입 마무리처럼 컨트롤러에서 세션을 만드는 요청이 **500 INTERNAL_ERROR**로 답하고, 운영 로그에 서버 고장으로 남았다.
- 로그인 입구(`LoginGuardFilter`)는 미리 저장소를 확인해 503으로 답하므로, 같은 장애인데 요청마다 응답이 달랐다.
- 이 필터에는 테스트가 하나도 없었다.

## Requirements
- **FR-001**: 세션 저장소 장애로 새 세션을 만들 수 없으면 503 `TEMPORARILY_UNAVAILABLE` "잠시 후 다시 시도해 주세요."로 답한다. 로그인 입구와 같은 코드다.
- **FR-002**: 이 경우 서버 오류 로그(`처리하지 못한 오류`)를 남기지 않는다. 필터가 남기는 경고 한 줄로 충분하다.
- **FR-003**: 기존 동작은 그대로다. 세션을 읽기만 하는 요청은 비로그인으로 계속되고, 한 요청 안에서 저장소에 다시 묻지 않는다. 저장소 장애가 아닌 예외는 숨기지 않는다.

## 범위 밖
- 응답이 끝난 뒤 Spring Session이 세션을 저장하다 실패하는 경우는 컨트롤러 밖이라 이 처리와 무관하다.
