# Feature Specification: 잘못 들어간 텔레그램 토큰이 로그에 남지 않게

**Feature Branch**: `037-telegram-token-logs`
**Created**: 2026-10-08
**Status**: Implemented (v1.16.10)
**근거**: 023 FR-007(봇 토큰은 로그·오류 화면에 남기지 않는다). 민서 요청 "모든 기능을 최적화 해서 구현해줘"(2026-10-07)에 따라 테스트가 없던 `HttpTelegramApi`에 테스트를 붙이다가 찾았다.

## 찾은 문제
Bot API 주소에는 토큰이 들어간다. `HttpTelegramApi`는 주소를 `try` 바깥에서 만들었다.
- 비밀값 파일 끝의 줄바꿈·공백처럼 주소에 쓸 수 없는 글자가 토큰에 섞이면 `URI.create`가 `IllegalArgumentException`을 던진다. 이 예외 메시지에는 **토큰이 든 주소 전체**가 실린다.
- 업데이트 받기는 1초마다 돈다. 예외가 스케줄러까지 올라가 토큰이 든 메시지가 매초 운영 로그에 쌓이고, 실패 뒤 30초 쉬기도 건너뛴다.
- 연결 화면의 봇 이름 조회에서는 같은 예외가 공통 오류 처리기의 오류 로그에 토큰과 함께 남는다.

## Requirements
- **FR-001**: 주소를 만들 수 없으면 다른 호출 실패와 같게 처리한다. 봇 이름은 없음, 업데이트 받기는 실패(그래서 30초 쉰다), 메시지 보내기는 `FAILED`.
- **FR-002**: 이때 로그에는 예외 종류만 남고 토큰은 남지 않는다.
- **FR-003**: 정상 토큰의 동작(주소, 보내는 본문, 응답 해석, 차단·대화 없음은 `GONE`)은 그대로다.
