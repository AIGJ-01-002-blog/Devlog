# Feature Specification: 소셜 로그인 이메일을 가입과 같은 규칙으로

**Feature Branch**: `038-social-email-rules`
**Created**: 2026-10-08
**Status**: Implemented (v1.16.11)
**근거**: docs/07 §3·§5, 004 FR-005(이메일은 앞뒤 공백 제거·소문자, 최대 254자). 민서 요청 "모든 기능을 최적화 해서 구현해줘", "의도적 중복 같은 건 하지 말고"(2026-10-07)에 따라 테스트가 없던 소셜 로그인 처리에 테스트를 붙이다가 찾았다.

## 찾은 문제
소셜 인증이 준 이메일을 GitHub·Google 처리 코드가 각자 정리했고, 가입·이메일 로그인이 쓰는 `EmailAddress` 규칙과 달랐다.
- Google: 소문자로만 바꾸고 앞뒤 공백을 지우지 않았다. `email_verified`가 참인데 `email`이 없으면 NPE로 로그인이 서버 오류가 됐다.
- GitHub: 공백 제거·소문자는 했지만 형식·길이는 보지 않았다.
- 둘 다 254자 넘는 주소나 형식이 맞지 않는 값을 그대로 회원 이메일로 저장할 수 있었다. 같은 정리 코드가 세 곳(가입, GitHub, Google)에 따로 있었다.

## Requirements
- **FR-001**: 소셜 프로필의 인증 이메일은 `EmailAddress` 규칙(앞뒤 공백 제거·소문자)으로 정리한다.
- **FR-002**: 정리한 값이 규칙(형식, 254자)에 맞지 않거나 비었으면 인증 이메일이 없는 것으로 본다. 그러면 가입 마무리 화면에서 이메일을 받아 메일로 인증한다(004 FR-028).
- **FR-003**: 정리는 `SocialProfile` 한 곳에서 한다. 로그인 수단별 처리 코드는 받은 값을 넘기기만 한다.
- **FR-004**: Google은 `email_verified`가 참일 때만 이메일을 넘긴다. 이메일이 없어도 로그인 처리가 실패하지 않는다.
