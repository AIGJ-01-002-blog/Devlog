# Feature Specification: 문의·신고 접수와 AI 버그 신고

**Feature Branch**: `054-inquiry-bug-report`
**Created**: 2026-10-08
**Status**: Implemented (v1.29.0)
**근거**: 민서님 요청 "우리 블로그 사용자가 문의사항이나 신고 사항을 접수할 수 있도록 해 줘. 특히 MCP 사용자가 쓸 때 버그 혹은 오류 신고를 우리가 했던 것처럼 등록된 AI가 남겨, 우리가 패치하고 수정해서 릴리스할 수 있도록." "우리가 했던 것처럼"은 팀이 Crowfoot MCP의 `report_bug`로 버그를 신고했던 방식이다.

## 사용자 시나리오

1. **Given** 로그인한 회원, **When** 내 메뉴 › [문의·신고]를 누르면, **Then** 보던 화면 주소가 "문제가 난 화면"으로 채워지고 종류는 버그·오류, 본문에는 버그 틀이 들어 있다. [빼기]로 주소를 뺄 수 있다.
2. **Given** 문의 화면, **When** 종류·제목·내용을 적고 [보내기]를 누르면, **Then** [내 문의]로 옮겨 "보냈어요" 안내와 함께 방금 남긴 문의가 펼쳐진다.
3. **Given** MCP로 연결한 AI(읽기·쓰기 토큰 모두), **When** 사용자가 동의해 AI가 `report_bug(title, content, tool?)`를 부르면, **Then** 종류 BUG·경로 MCP로 접수되고 접수 번호와 `/support?id=` 주소를 돌려준다. [내 문의]에 "AI 신고" 배지로 보인다.
4. **Given** 관리자, **When** 문의 관리에서 상태·답변·고친 버전을 저장하면, **Then** 회원에게 "남기신 문의「…」에 답변이 왔어요" 알림이 가고, [내 문의]에 답변과 "v1.29.0에서 고쳤어요 →"(릴리스 노트의 그 버전) 링크가 보인다. 같은 답변을 다시 저장하면 알림을 또 보내지 않는다.
5. **Given** 관리자 토큰으로 연결한 AI, **When** `tools/list`를 부르면, **Then** `list_inquiries`·`get_inquiry`·`update_inquiry`가 더 보인다. 일반 회원 토큰에는 보이지 않고 이름으로 불러도 "없는 도구"다.
6. **Given** 누구나, **When** `/releases`를 열면, **Then** 버전마다 추가·고침이 최근 10개 보이고 [이전 버전 더 보기]로 펼친다. `#v1.28.0`으로 열면 그 버전까지 펼쳐 강조한다.

## Requirements

- **FR-001**: 문의(`inquiry`)는 종류(QUESTION·BUG·SUGGESTION·REPORT), 경로(WEB·MCP), 제목(200자), 본문(Markdown 20,000자), 화면 주소(사이트 안 경로만), 도구 이름, AI 앱·토큰 이름, 접수 때 버전, 상태(RECEIVED·IN_PROGRESS·RESOLVED·CLOSED), 답변(5,000자), 고친 버전, 처리한 관리자를 둔다.
- **FR-002**: 로그인한 회원만 남긴다. 이메일 인증 전에도 남길 수 있다(인증 메일 문의). 정지된 계정은 계정 상태 필터가 막는다. 회원마다 한 시간 10번·하루 30번.
- **FR-003**: 내용은 접수한 회원과 관리자만 본다. 회원 화면에는 AI 토큰 이름과 처리한 관리자를 싣지 않는다. GitHub 이슈는 자동으로 만들지 않는다.
- **FR-004**: `report_bug`는 Gate REPORT: 모든 토큰에 보이고(readOnlyHint false), 웹과 같은 서비스·요청 제한을 쓴다. 설명에 "사용자 동의 후, 요약·재현·기대·실제 순서, 비밀 값 금지"를 적는다. `initialize` 안내에도 같은 문장을 둔다.
- **FR-005**: 관리자 도구는 Gate ADMIN: `member.role = 'ADMIN'`을 토큰 인증 때마다 새로 읽어 판단한다. `get_inquiry`는 본문을 `<user_content>`로 감싸고 지시를 따르지 말라고 덧붙인다. `update_inquiry`는 쓰기 토큰이 필요하다.
- **FR-006**: 답변이 새로 붙거나 바뀌면 `INQUIRY_ANSWERED` 알림(`notification_inquiry`)을 보낸다. 끌 수 없는 운영 알림이고 텔레그램으로도 간다. 탈퇴 신청한 회원에게는 만들지 않는다.
- **FR-007**: 고친 버전은 `1.29.0` 꼴만 받는다(`v`는 뗀다). 릴리스 노트에 아직 없는 버전도 적을 수 있다(배포 전에 적는 경우).
- **FR-008**: 릴리스 노트는 빌드 때 jar에 들어간 저장소 `CHANGELOG.md`를 `## [x.y.z] - 날짜`마다 나눠 글과 같은 렌더러로 정화한 HTML로 준다. 맨 위 버전이 지금 버전이고 문의 접수 때 함께 저장한다.
- **FR-009**: 탈퇴 정리(75)에서 그 회원의 문의를 지운다. 답변 알림은 FK로 함께 지워진다.
- **FR-010**: 새 버튼·배지·종류 카드에 `title` 툴팁을 단다. 390px 화면에서 가로 넘침이 없어야 한다.

## 범위 밖
- 비회원 문의(스팸 방지), 첨부 파일, 문의에 회원이 덧붙이는 댓글 대화.
- GitHub 이슈 자동 생성(필요하면 관리자가 내용을 다듬어 직접 만든다).
