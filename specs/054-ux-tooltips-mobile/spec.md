# Feature Specification: 툴팁·모바일 아래 탭·에디터 서식 도구 (UX 점검)

**Feature Branch**: `claude/ux-tooltips-mobile-c8jvss`
**Created**: 2026-10-08
**Status**: Implemented (v1.29.0)
**근거**: 블로그 주인 요청 "UX/UI가 다른 블로그 대비 잘 되어 있는지 확인해 줘. 마우스를 올렸을 때 어떤 기능의 버튼인지 표기될 수 있도록 가시성이나 편의성을 향상시켜 줘. 모바일 환경에서 UI를 고려해 보기 편하게 만들고 항상 다음 릴리스에도 모두 고려될 수 있도록 해 줘."

## 1. 다른 블로그와 비교 (2026-10-08 점검)

로컬에서 실제 jar + PostgreSQL + Redis + 화면을 띄워 1280px·375px로 11개 화면(홈·글·블로그·에디터·설정·검색·태그·알림·글 관리·AI 연결·피드)을 찍어 보고,
velog·티스토리·브런치·Medium에서 널리 쓰는 화면 관례와 견주었다. 다른 서비스 칸은 각 서비스의 일반적인 화면 구성을 기준으로 적은 것이라 세부는 버전마다 다를 수 있다.

| 항목 | 다른 블로그의 흔한 모습 | 점검 전 devlog | 이번 변경 뒤 |
|---|---|---|---|
| 아이콘 버튼 설명 | 에디터 도구·아이콘에 툴팁을 다는 곳이 많다(티스토리·Medium 에디터 등) | 테마 버튼 하나만 브라우저 기본 title. 알림·검색·내 메뉴·좋아요는 화면 읽기 이름만 있고 마우스로는 알 수 없음 | 모든 아이콘·버튼에 같은 모양의 툴팁(마우스 0.35초, 키보드 초점 즉시, Esc로 닫힘) |
| 에디터 서식 도구 | velog·티스토리·브런치는 제목·굵게·인용·링크·코드 버튼 줄이 있다 | 없음. Markdown을 직접 쳐야 함 | H2·H3·H4·굵게·기울임·취소선·인용·목록·번호·링크·코드·코드 블록 버튼, 툴팁에 단축키 |
| 에디터 단축키 | Ctrl+B·I·K가 흔하다 | 없음. Ctrl+S는 브라우저의 "페이지 저장"이 뜸 | Ctrl(⌘)+B·I·K 서식, Ctrl(⌘)+S 바로 저장. 되돌리기(Ctrl+Z) 한 단계 |
| 모바일 이동 | 앱처럼 아래 탭을 두거나(Medium·브런치 앱), 머리말을 줄인다 | 375px 머리말에 로고·검색·피드·태그·알림·글쓰기·내 메뉴·테마 8개가 붙어 있음. 검색 26px·테마 23px 폭으로 누르기 어려움 | 640px 이하에서 홈·피드(비회원은 AI 연결)·검색·태그·내 블로그(비회원은 로그인) 아래 탭, 이름을 늘 보임. 머리말은 알림·글쓰기·내 메뉴·테마만 |
| 누르기 크기 | 44~48px 권장(애플·구글), WCAG 2.5.8 최소 24px | 26×34, 28×34, 23×34 | 머리말 아이콘 40×40 이상, 에디터 도구 40px, 아래 탭 56px 높이 |
| 에디터 모바일 | 탭·버튼이 한 줄 | "쓰기"·"미리보기"가 두 줄로 꺾이고 [발행]이 다음 줄로 밀림 | 한 줄 고정, 서식 도구는 옆으로 밀어 보기 |
| 블로그 안 검색칸 | 둥근 입력칸 | 테두리만 있는 기본 입력칸 | 다른 입력칸과 같은 높이·모서리 |
| 다크 모드·목차·읽기 시간·코드 복사 | velog·Medium과 비슷 | 이미 있음 | 그대로(아래 탭도 다크 모드 색 토큰을 씀) |

남은 차이(이번 범위 밖, 다음 릴리스 후보):
- 좁은 화면에서는 글 목차가 숨는다. 접었다 펴는 목차 버튼이 있으면 긴 글을 읽기 쉽다.
- 에디터 미리보기와 본문 스크롤 맞추기(velog 넓은 화면).
- 터치에서는 툴팁이 뜨지 않는다. 대신 아래 탭과 주요 버튼은 글자 이름을 늘 보이게 했다.

## 2. 사용자 시나리오

1. **Given** 마우스를 쓰는 사용자, **When** 머리말 알림 아이콘에 0.35초 머물면, **Then** "알림"(안 읽은 알림이 있으면 개수까지) 말풍선이 아이콘 위에 뜬다. 벗어나거나 누르거나 Esc를 누르면 닫힌다.
2. **Given** 키보드 사용자, **When** Tab으로 [피드]에 오면, **Then** 바로 "팔로우한 사람의 새 글"이 뜨고 화면 읽기 프로그램도 같은 설명을 읽는다(aria-describedby).
3. **Given** 툴팁 하나를 본 뒤, **When** 옆 버튼으로 옮기면, **Then** 기다리지 않고 바로 뜬다.
4. **Given** 휴대폰(터치), **When** 버튼을 누르면, **Then** 툴팁 없이 바로 동작한다.
5. **Given** 에디터, **When** 글자를 고르고 [B] 또는 Ctrl+B를 누르면, **Then** `**글자**`로 감싸고 같은 글자가 골라진 채로 남는다. 다시 누르면 벗긴다. Ctrl+Z 한 번에 되돌아간다.
6. **Given** 에디터 어디서든, **When** Ctrl(⌘)+S를 누르면, **Then** 브라우저 저장 창 대신 이 글이 저장된다.
7. **Given** 375px 화면, **When** 아무 읽기 화면을 열면, **Then** 아래 탭 다섯 개가 보이고 지금 화면의 탭이 강조된다. 가로 스크롤이 생기지 않는다.

## 3. Requirements

- **FR-001**: 툴팁은 `TooltipLayer` 하나가 화면 전체를 맡는다. 글은 `data-tip` > `aria-label` > `title` 순서로 읽고, 보이는 글자와 같으면 띄우지 않는다. `data-tip=""`은 끈다.
- **FR-002**: 마우스는 350ms 뒤, 키보드 초점(`:focus-visible`)은 바로 띄운다. 닫힌 지 400ms 안에 다른 대상으로 옮기면 바로 띄운다. 터치는 띄우지 않는다.
- **FR-003**: Esc·누르기·스크롤·창 크기 바꾸기·초점 잃기에서 닫는다(WCAG 1.4.13 Dismissible). 위에 자리가 없으면 아래에 두고 화면 양옆 8px 안으로 당긴다.
- **FR-004**: 툴팁이 떠 있는 동안 원래 `title`은 잠깐 옮겨 브라우저 기본 말풍선과 겹치지 않게 하고, 닫을 때 되돌린다.
- **FR-005**: 설명이 이름과 다르면 `aria-describedby`로 잇고, 닫을 때 뗀다.
- **FR-006**: 에디터 서식 도구는 고른 범위를 `insertText` 한 번으로 바꿔 되돌리기 기록을 지킨다. 지원하지 않는 환경은 값을 직접 바꾼다.
- **FR-007**: 640px 이하에서 아래 탭(`MobileNav`)을 보이고, 머리말의 검색·피드·태그는 숨긴다. 에디터·계정 복구·OAuth 동의 화면에는 아래 탭이 없다. 아이폰 홈 막대 자리(`safe-area-inset-bottom`)를 비운다.
- **FR-008**: 색은 기존 토큰만 쓴다(툴팁은 글자색·배경색을 뒤집는다). 움직임 줄이기 설정은 기존 한 곳의 규칙을 따른다.

## 4. 다음 릴리스에도 지키는 규칙

모든 릴리스에서 아래를 확인하고 머지한다. 빠뜨리지 않게 테스트와 PR 양식에 넣었다.

1. **아이콘·기호만 있는 버튼과 링크에는 이름을 단다** (`aria-label` 또는 설명이 필요하면 `data-tip`). 글자 버튼도 무슨 일이 일어나는지 한 줄 더 알려 줄 게 있으면 `data-tip`을 단다.
   - 검사: `src/lib/controlLabels.test.ts`가 모든 화면 파일(`components/`, `pages/`)을 읽어 이름 없는 아이콘 버튼·링크가 있으면 실패한다.
2. **새 화면과 바뀐 화면은 375px로 열어 본다.** 가로 스크롤이 없고, 누르는 것은 40px 안팎 이상이며, 글자가 두 줄로 꺾이지 않는지 본다. 다크 모드도 한 번 본다.
3. 손가락에는 툴팁이 없으니 모바일에서 꼭 알아야 하는 버튼은 아이콘만 두지 않고 글자를 함께 보인다.
4. PR 양식(`.github/pull_request_template.md`)의 "UX" 항목에 확인한 화면을 적는다.
