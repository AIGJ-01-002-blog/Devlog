# Feature Specification: 발행 전 점검

**Feature Branch**: `056-prepublish-check`
**Created**: 2026-10-08
**Status**: Implemented (v1.29.0)
**근거**: 054와 같은 요청. Crowfoot은 이름 중복·FK 타입 불일치 같은 설계 규칙 17종을 상시 검사한다. 블로그 글에서는 발행 직전에 놓치기 쉬운 것들이 같은 자리다.

## 사용자 시나리오

1. **Given** 소개·태그가 없고 대체글 없는 사진이 있는 글, **When** 발행 창을 열면, **Then** "발행 전 점검 · 확인할 것 N개"가 펼쳐져 있고 항목마다 ✓·⚠·ℹ 기호와 설명이 보인다.
2. **Given** 잘 갖춘 글, **When** 발행 창을 열면, **Then** 점검은 "확인할 것 없음"으로 접혀 있다.
3. **Given** 어떤 점검 결과든, **When** [발행하기]를 누르면, **Then** 점검은 발행을 막지 않는다.

## Requirements

- **FR-001**: 점검 항목: 짧은 소개(없으면 ℹ), 태그(없으면 ⚠), 대표 사진(없으면 ℹ), 사진 대체글(빠지면 ⚠), 본문 길이(코드·주소 빼고 200자 미만이면 ℹ), 본문 첫 `#` 제목이 글 제목과 같음(⚠), 닫히지 않은 코드 블록(⚠), 언어 없는 코드 블록(ℹ), 주소가 빈 링크(⚠).
- **FR-002**: 화면에서만 계산한다(`lib/prepublish.ts`). 서버 검증은 그대로다.
- **FR-003**: 색만으로 구분하지 않는다. 기호와 화면 읽기 도구용 "통과·확인 필요·참고" 글자를 붙인다. 머리줄에 마우스를 올리면 "발행을 막지 않는다"는 설명이 보인다.

## 범위 밖
- 맞춤법 검사, 깨진 바깥 링크 확인(서버가 바깥 주소를 열어야 한다), 점검 결과 저장.
