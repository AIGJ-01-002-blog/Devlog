# Feature Specification: 글 수정 이력

**Feature Branch**: `058-post-revisions`
**Created**: 2026-10-08
**Status**: Implemented (v1.33.0)
**근거**: 블로그 주인 요청 "crowfoot에 기능 중에 우리한테도 적용했을 때 좋을 거 같은 기능 우리도 추가해 줘." Crowfoot은 문서를 저장할 때마다 버전을 남기고 두 버전을 비교하거나 되돌린다. 블로그에서는 "발행한 판"이 같은 자리다.

## 사용자 시나리오

1. **Given** 두 번 발행한 글, **When** 작성자가 편집기에서 [🕘 수정 이력]을 누르면, **Then** 2판(지금 발행본)과 1판(첫 발행)이 최신순으로 보이고, 2판과 지금 편집 중인 내용의 줄 단위 비교가 바로 열린다.
2. **Given** 수정 이력 창, **When** 1판을 고르면, **Then** 1판과 지금 내용의 비교와 "+N줄 −M줄" 요약이 보인다. 제목이 다르면 제목 비교도 보인다.
3. **Given** 1판을 고른 상태, **When** [1판 불러오기]를 누르면, **Then** 편집기의 제목·본문·짧은 소개가 1판으로 바뀌고, 바로 전 내용은 이 기기 백업에 남으며, "다시 발행하면 독자에게 보여요" 안내가 뜬다. 독자가 보는 발행본은 다시 발행할 때까지 그대로다.
4. **Given** 임시글, **When** 편집기를 열면, **Then** [수정 이력] 버튼이 없다(발행한 판이 없다).
5. **Given** 남의 글, **When** 이력 API를 부르면, **Then** 404다. 로그인하지 않았으면 401이다.
6. **Given** 휴대폰 화면, **When** 수정 이력을 열면, **Then** 판 목록이 가로로 넘어가고 비교 칸이 위아래로 쌓이며 [불러오기] 버튼이 화면 아래에 늘 보인다.

## Requirements

- **FR-001**: 발행·다시 발행이 커밋될 때 그 발행본(제목·본문·짧은 소개·시각)을 한 판으로 남긴다. 발행 트랜잭션 안의 `PublishExtension`으로 붙여 발행 서비스는 고치지 않는다. 판 번호는 글마다 1부터 오른다(글 행 잠금 아래라 겹치지 않는다).
- **FR-002**: 글마다 최근 50판만 둔다. 넘치면 발행할 때 오래된 판부터 지운다.
- **FR-003**: `GET /api/posts/{id}/revisions` → `[{no, title, createdAt, length}]` 최신순. `GET /api/posts/{id}/revisions/{no}` → `{no, title, contentMd, summary, createdAt}`. 작성자 본인의 휴지통에 없는 글만, 그 밖은 404. 응답은 `no-store`.
- **FR-004**: 되돌리기는 서버에 따로 두지 않는다. 편집기가 판 내용을 불러오고 평소처럼 자동 저장·다시 발행한다(작업본·버전 충돌 규칙 그대로).
- **FR-005**: 글을 완전히 지우면 판도 함께 지운다(FK `ON DELETE CASCADE`). 휴지통 복구 때는 그대로 남는다.
- **FR-006**: 마이그레이션은 이미 발행한 글의 지금 발행본을 1판으로 채운다.
- **FR-007**: 버튼과 판 항목에 마우스를 올리면 하는 일이 보인다(`title`). 비교는 색과 함께 −/+ 기호로 구분한다.

## 범위 밖
- 판끼리 비교(지금은 판 ↔ 편집 중 내용), 판 하나만 지우기, 독자에게 "수정 이력" 공개.
- AI(MCP) 도구로 이력 읽기.
