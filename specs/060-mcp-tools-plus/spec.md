# Feature Specification: MCP 도구 강화 1차

**Feature Branch**: `060-mcp-tools-plus`
**Created**: 2026-10-08
**Status**: Implemented (v1.31.0)
**근거**: 블로그 주인 의견 "블로그에 MCP 툴이 메인 기능인 만큼 기능을 조금 더 강화해야 된다". 052·053의 MCP는 임시글을 쓰고 발행하는 데까지는 되지만, 발행한 글은 고칠 수 없고, 본문에 사진을 넣을 수 없고, 내 비공개·임시글을 찾을 수 없었다. 이번에는 이 셋을 채운다.

번호는 같은 날 다른 작업(054~056 수정 이력·내보내기·발행 전 점검, 054 UX 점검)과 겹치지 않게 060으로 잡았다.

## 사용자 시나리오

1. **Given** 발행한 글과 쓰기 토큰, **When** AI가 `update_draft`로 제목·본문을 바꾸면, **Then** 웹 편집 화면처럼 작업본(`post_draft`)에만 저장되고 독자는 그대로 발행본을 본다. 응답은 "다시 발행해야 공개된다"와 편집 화면 링크를 준다.
2. **Given** 1의 작업본, **When** "AI가 발행·삭제하도록 허용"이 꺼진 상태에서 `publish_post`를 부르면, **Then** 거절된다. 켜져 있으면 작업본으로 다시 발행되고(공개 범위·태그·요약·썸네일은 그대로) 작업본이 지워진다.
3. **Given** 고친 내용이 없는 발행 글, **When** `publish_post`를 부르면, **Then** "고친 내용이 없다"며 거절한다.
4. **Given** 쓰기 토큰, **When** AI가 `upload_image(image_base64, alt)`로 2MB 이하 jpg·png·gif를 보내면, **Then** 서버가 긴 변 1920px로 줄이고 다시 저장해 사진 정보를 지운 뒤 웹과 같은 사진 저장소에 올리고 `![alt](주소)`를 돌려준다.
5. **Given** 쓰기 토큰, **When** AI가 `create_image_upload_link`를 부르면, **Then** 10분 동안 한 번만 쓸 수 있는 주소와 `curl -T` 명령을 돌려준다. 그 주소로 사진 바이트(10MB까지)를 보내면 4와 같이 처리하고 `{url, markdown, width, height}`를 돌려준다. 같은 주소를 다시 쓰면 404다.
6. **Given** 내 비공개 글·임시글·휴지통 글과 남의 공개 글, **When** `search_posts(query, mine=true)`를 부르면, **Then** 휴지통을 뺀 내 글만 최근 수정 순으로 최대 20개 나온다. 고치는 중인 작업본의 제목·본문도 찾는다. `mine` 없이 부르면 지금처럼 공개 글만 찾는다.

## Requirements

- **FR-001**: `update_draft`는 임시글과 발행한 글을 모두 받는다. 저장은 웹 [저장]과 같은 `PostCommandService.save`라 버전 충돌·길이 규칙이 같다. 제목·본문 둘 다 없으면 거절한다.
- **FR-002**: `publish_post`는 발행한 글에 작업본이 있으면 다시 발행한다. 053의 허용 설정·쓰기 조건을 그대로 따른다. 웹 [다시 발행]과 같은 `PostCommandService.publish`를 부른다.
- **FR-003**: `upload_image`는 base64(2MB까지, `data:` 머리 허용)를 받는다. `create_image_upload_link`는 Redis에 10분짜리 표를 두고, `PUT|POST /api/mcp/uploads/{표}`가 표를 꺼내면서 지운다(GETDEL). 표가 곧 권한이라 쿠키·토큰을 보지 않고, 올릴 때 회원이 ACTIVE인지 다시 본다.
- **FR-004**: 서버 사진 처리: 형식은 파일 머리로 판단(jpg·png·gif). webp는 서버가 읽을 수 없어 거절하고 png로 바꾸거나 웹에서 올리라고 안내한다. GIF는 1920px 이하만 받고 원본 그대로 둔다. jpg·png는 긴 변 1920px로 줄여 같은 형식으로 다시 저장한다(사진 정보 제거). 썸네일은 가로 640px. 큰 사진은 읽을 때부터 건너뛰며 읽어 메모리를 아낀다. 그 뒤는 웹과 같은 `PostImages.upload`(10MB, 1분·하루 장수 제한, 1GB 저장 공간).
- **FR-005**: `search_posts(mine=true)`는 본인 글(`deleted_at IS NULL`)의 제목·본문·태그·작업본에서 띄어 쓴 단어가 모두 들어간 글을 찾는다. 공개 검색(`SearchQuery`)은 건드리지 않는다.
- **FR-006**: `initialize` 안내와 `/mcp` 도구 표·안전 문구에 새 도구와 "발행한 글을 고치면 다시 발행해야 공개된다", "사진 정보를 지운다"를 적는다.

## 범위 밖
- 다른 작업과 겹치는 것: AI 버그 신고 도구, 글 수정 이력, Markdown 내보내기, 발행 전 점검.
- 다음 차례로 미룬 것: 시리즈 묶기, 댓글·알림·조회수 읽기, 썸네일 지정, 공개 범위만 바꾸기, 인터넷 주소의 사진 가져오기(서버가 남의 주소를 대신 여는 위험이 있어 보류).
