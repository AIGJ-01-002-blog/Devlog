# Feature Specification: AI 글 제안·자정 일기

**Feature Branch**: `061-ai-journal`
**Created**: 2026-10-08
**Status**: Implemented (v1.34.0)
**근거**: 블로그 주인 의견 "MCP 연결로 하나의 주제가 끝났다고 판단하면 블로그에 작성할 것을 제안하고 범위를 추천해 주고, 일기처럼 원하면 AI 사용이 있는 날엔 매일 자정 00:00에 일기처럼 작성되는 것도 켰다 껐다 할 수 있게". 그리고 "포트폴리오용이라고 하면 기술 소개·프로젝트 설명·사진 위주로, '우리 팀이 한 일 + 제 역할' 범위를 사용자에게 한 번 더 확인받고 진행".

서버는 AI의 대화를 읽지 못한다(MCP는 AI가 도구를 부를 때만 서버에 닿는다). 그래서 "주제가 끝났다"는 판단과 하루 작업의 기록은 연결한 AI가 하고, 서버는 받은 것을 보관·정리한다.

## 사용자 시나리오

1. **Given** 쓰기 토큰, **When** AI가 한 주제를 마치고 `propose_post(title, scope, tags)`를 부르면, **Then** 제안이 남고 내 글 관리 › 임시글 탭 위 "AI가 제안한 글"에 보인다. 같은 제목의 정하지 않은 제안이 있으면 새로 만들지 않고 범위·태그를 바꾼다. 정하지 않은 제안은 20개까지.
2. **Given** 1의 제안, **When** 사용자가 [임시글로 만들기]를 누르면, **Then** 제목과 "## 쓸 범위"를 뼈대로 한 임시글이 생기고 편집 화면이 열린다. 제안한 태그는 발행 창에 미리 채워진다. 두 번 눌러도 임시글은 하나다. [넘기기]는 제안을 닫는다.
3. **Given** 1의 제안, **When** 사용자가 대화에서 쓰라고 하고 AI가 `create_draft(…, proposal_id)`로 쓰면, **Then** 제안이 "임시글로 만듦"으로 닫힌다. 이미 임시글로 만든 제안이면 거절하고 그 글을 `update_draft`로 채우라고 안내한다. `list_post_proposals`로 정하지 않은 제안과 최근 30일 안에 만든 제안을 본다.
4. **Given** 설정 › AI 연결 › "자정에 일기 쓰기"가 꺼져 있으면(기본), **Then** `add_note`는 도구 목록에 없고 이름으로 불러도 거절한다. 켜면 보이고, `initialize` 안내에 "작업 단위마다 메모"가 붙는다.
5. **Given** 켜진 상태, **When** AI가 `add_note(content, topic, tags)`를 부르면, **Then** 메모가 남는다(하루 60개, 글쓰기 한 시간 30번 한도와 따로).
6. **Given** 전날까지 남긴 메모, **When** 매일 00:00(KST) 작업이 돌면, **Then** 회원·날짜마다 "YYYY-MM-DD 개발 일기" 임시글 하나가 생긴다. 본문은 주제가 처음 나온 차례대로 `## 주제` 소제목, 그 아래 `- HH:mm 메모`. 주제 없는 메모는 끝의 "그 밖에"(주제가 하나도 없으면 "오늘 한 일"). 태그 제안은 메모 태그를 합친 것. 묶은 메모는 지운다. 메모가 없는 날·일기를 끈 회원·정지된 계정은 만들지 않는다. 두 번 돌아도(서버 여러 대) 일기는 하나다.
7. **Given** 켜진 상태와 남은 메모, **When** 끄면, **Then** 아직 묶지 않은 메모도 지운다(끌 때 한 번 묻는다). 이미 만든 일기 임시글은 남는다.
8. **Given** 사용자가 "포트폴리오용으로 써 줘"라고 하면, **Then** AI는 기술 소개·프로젝트 설명·사진 위주로 쓰고, "우리 팀이 한 일"과 "제 역할"을 나눈 범위를 먼저 보여 주고 확인받은 뒤 쓴다(`initialize` 안내와 `propose_post` 설명).

## Requirements

- **FR-001**: V18 — `member.ai_diary_enabled`(기본 false), `ai_post_proposal`(OPEN·DRAFTED·DISMISSED), `ai_note`. 회원이 지워지면 함께 지워지고, 탈퇴 정리 단계(47)도 지운다.
- **FR-002**: 일기 설정·제안 처리는 로그인 세션 + CSRF로만: `GET|PUT /api/me/ai-diary`, `GET /api/me/ai-proposals`, `POST /api/me/ai-proposals/{id}/draft|dismiss`. AI가 스스로 일기를 켜거나 제안을 정하지 못한다.
- **FR-003**: 새 Gate `DIARY` — `Caller.aiDiaryEnabled`(요청마다 DB에서 읽음)일 때만 `add_note`가 보이고 불린다.
- **FR-004**: 자정 작업은 `@Scheduled(0 0 0 * * *, Asia/Seoul)` + `JobLock("ai-diary")`. 메모는 `DELETE … RETURNING`으로 꺼내 회원 단위 트랜잭션 안에서 임시글을 만든다(실패하면 메모가 남아 다음 자정에 다시 묶는다). 7일 넘게 묶지 못한 메모는 지운다.
- **FR-005**: 일기는 서버 AI를 거치지 않는 템플릿으로 묶는다. 동의·비용이 필요 없고 결과가 늘 같다. 다듬기는 사용자 몫이다.

## 갈림길과 고른 안 (9시 보고에 남김)
- 제안을 보여 줄 곳: 설정이 아니라 **내 글 관리 › 임시글 탭 위**. 글을 쓰러 오는 곳이라서.
- 일기 정리: 서버 AI가 아니라 **템플릿**. 내 AI 동의·비용이 필요 없고, AI 연결이 그날 쓴 메모가 그대로 남는다.
- 일기 공개: 늘 **임시글**. 발행은 사용자가.
- 알림: 이번에는 보내지 않는다(일기 임시글은 내 글 관리에 바로 보인다).

## 범위 밖
- 서버가 스스로 주제 끝을 판단하기(대화를 읽을 수 없다), 일기를 서버 AI로 다듬기, 일기가 생겼다는 알림, 일기 시각 고르기.
