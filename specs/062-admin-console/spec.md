# Feature Specification: 관리자 페이지 (대시보드·글·회원 관리·매니저 권한)

**Feature Branch**: `062-admin-console`
**Created**: 2026-10-08
**Status**: Implemented (v1.35.0)
**근거**: 블로그 주인 요청 "내 계정 하나를 관리자 계정으로 만들어 주고 관리자 페이지를 만들어서 블로그의 통계를 볼 수 있도록 해줘. 대시보드 형식으로 집계, 전체적인 글 관리나 신고 목록, 유저 목록, 권한 부여, 유저의 작성한 글 통계 등 통상적인 관리자 페이지. 매니저와 관리자만 보이는 페이지 버튼."

## 사용자 시나리오

1. **Given** 실행 설정 `OWNER_HANDLE`(운영자 블로그 주소) 또는 `OWNER_GITHUB_ID`(GitHub 회원 번호), **When** 앱이 뜨면, **Then** 그 계정이 관리자(ADMIN)가 되고 기존 로그인이 끊겨 다시 로그인하면 관리자 권한을 받는다. 이미 관리자면 아무것도 하지 않는다. 운영 설정(selfhosted·nhn)은 민서님 계정 `OWNER_HANDLE=kim755030`이다.
2. **Given** 관리자·매니저, **When** 로그인하면, **Then** 머리말에 방패 아이콘(툴팁 "관리자 페이지")과 내 메뉴의 [관리자 페이지]가 보인다. 일반 회원에게는 보이지 않고, `/admin/**`와 `/api/admin/**`는 일반 회원에게 404, 비회원은 로그인으로 보낸다. 로그인 뒤 자동으로 관리자 페이지로 가지는 않는다.
3. **Given** `/admin`, **Then** 대시보드: 처리할 신고·답할 문의 수, 최근 7·30·90일 합계(조회수·새 글·가입·댓글·좋아요·신고, 이전 같은 기간 대비 %)와 활동한 회원 수, 고른 지표의 날짜별 막대그래프(막대에 마우스를 올리면 날짜·값), 많이 본 공개 글 5개, 많이 쓴 회원 5명, 전체 현황(회원·글·임시·휴지통·조회·좋아요·댓글).
4. **Given** `/admin/posts`, **Then** 발행한 글을 제목(공개 글만)·작성자 주소로 찾고 전체·공개·비공개·숨김으로 거른다. 글마다 조회·좋아요·댓글 수. 공개 글은 [숨기기…]에서 사유를 골라 바로 숨기고(작성자에게 숨김 알림, 신고 처리됨 탭에 신고 0건 사건으로 남음), 숨긴 글은 [숨김 해제]. 자기 글은 숨길 수 없다. 비공개·친구 공개 글은 관리자에게도 제목을 주지 않는다.
5. **Given** `/admin/members`, **Then** 회원을 주소·닉네임으로 찾고 권한(관리자·매니저/일반)·상태(활동·정지·탈퇴 신청)로 거른다. 새로 가입한 순, 20명씩. 가입 방식, 발행 글 수(툴팁에 임시·숨김), 댓글 수, 가입일, 최근 활동.
6. **Given** `/admin/members/{주소}`, **Then** 작성 통계(발행·임시·숨김·쓴 댓글·받은 조회수·받은 좋아요, 최근 12달 달별 새 글, 많이 본 글 5개), 권한, 정지·해제와 이력.
7. **Given** 관리자, **When** 회원을 매니저로 올리거나 일반 회원으로 내리면, **Then** 그 회원의 모든 로그인이 끊기고 다시 로그인하면 새 권한을 받는다. 관리자 권한은 줄 수 없고, 자기 권한과 운영자 계정의 권한은 바꿀 수 없다. 정지·탈퇴 신청 회원은 매니저로 올릴 수 없다. 매니저가 바꾸려 하면 403 `ADMIN_ONLY`.
8. **Given** 매니저, **Then** 관리자 페이지 전체(대시보드·글·회원·신고·문의)를 쓰지만 권한은 바꾸지 못한다. 관리자·매니저는 정지할 수 없다(매니저는 권한을 먼저 거둔다). 관리자용 MCP 도구(문의 읽기)는 지금처럼 관리자만.

## Requirements

- **FR-001**: V19 — `member.role`에 `MANAGER`를 더한다(`ck_member_role`), 직원만 색인(`ix_member_staff`).
- **FR-002**: `Role.staff()`·`MemberPrincipal.isStaff()`가 관리자·매니저를 뜻한다. 보안 설정 `/api/admin/**`는 `hasAnyRole(ADMIN, MANAGER)`, 각 관리자 API는 다시 `isStaff()`로 확인한다. 조회수 제외 대상도 직원 전체.
- **FR-003**: 새 API — `GET /api/admin/dashboard?days=7|30|90`(다른 값은 30), `GET /api/admin/members?q&role&status&page`, `GET /api/admin/members/{handle}/stats`, `PUT /api/admin/members/{handle}/role {role: USER|MANAGER}`, `GET /api/admin/posts?q&filter&author&page`, `POST /api/admin/posts/{id}/hide {reason}`, `POST /api/admin/posts/{id}/unhide`. 모두 `no-store`.
- **FR-004**: 통계는 `admin` 모듈이 SQL 없이 조립하고, 각 모듈이 자기 테이블만 센다(헌법 IV): `MemberStats`(account), `PostStats`(post.query), `CommentStats`, `LikeStats`, `ViewStats`, `AdminReportQuery.pendingCount·reportsByDay`, `InquiryService.openCount`. 날짜는 한국 시각 기준.
- **FR-005**: 바로 숨기기는 신고 0건의 HIDDEN 사건을 만들어 기존 숨김 알림·처리됨 탭·숨김 해제를 그대로 쓴다. 대기 중인 신고 사건이 있으면 그 사건을 숨김으로 닫는다. 처리됨 탭 목록은 신고 0건 사건도 싣는다(`LEFT JOIN report`).
- **FR-006**: 화면 — 관리자 페이지 공통 탭(대시보드·글·회원·신고·문의), 모든 버튼·아이콘에 툴팁, 좁은 화면에서 지표 2열·회원 표는 카드로 쌓임·그래프 높이 줄임. 그래프는 계열 하나라 범례 없이 제목이 이름이고, 화면 읽기 프로그램용 표를 함께 둔다.

## 갈림길과 고른 안 (9시 보고에 남김)
- 관리자 수: **운영자 계정 하나**(실행 설정으로 지정, 화면에서 줄 수 없음). 다른 사람은 매니저까지. 이유: 권한을 주는 권한이 여럿이면 실수로 권한이 퍼진다.
- 로그인 뒤 자동 이동: **하지 않음**. 관리자도 평소에는 블로그를 쓴다.
- 운영자 지정 방법: **블로그 주소**(가입 뒤 바뀌지 않고 탈퇴 뒤에도 남아 다른 사람이 가져갈 수 없음, 비밀 아님). 민서님 운영 계정이 이메일 가입이라 GitHub 번호만으로는 맞지 않았다. GitHub 번호 지정도 남겨 두었다. 이메일은 개인정보라 쓰지 않았다.
- 관리자에게 비공개 글 제목: **보이지 않음**(기존 원칙 "관리자는 남의 비공개 글을 못 봄"). 수와 조회수만.
- 바로 숨기기: **신고 없이도 공개 글을 숨길 수 있게** 했다. 알림·되돌리기는 신고로 숨긴 것과 같다.

## 범위 밖
- 댓글 바로 숨기기(지금은 신고로만), 통계 CSV 내보내기, 매니저별 세부 권한.
