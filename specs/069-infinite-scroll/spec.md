# 069 목록 무한 스크롤

요청: 민서님(2026-10-09) "지금 스크롤이 내려서 더보기를 눌러야 되잖아 나중에 velog 기능 처럼 무한 스크롤 할 수 있어 계속 불러오기 말이야"

velog처럼 목록 끝까지 내리면 [더 보기]를 누르지 않아도 다음 글이 이어서 붙는다.

## 바뀌는 것

### 무한 스크롤이 되는 목록
- **글 카드 목록**(공용 `Feed`): 홈 최신·트렌딩, 팔로우 피드, 태그별 글, 검색 결과(글 탭), 블로그 글 목록, 좋아요한 글.
- **알림** 전체 목록, **팔로워·팔로잉** 목록, **내 글 관리**(임시글·발행 글·휴지통).

### 동작
- 목록 끝의 표시가 화면 아래 600px 안으로 들어오면 다음 쪽을 미리 부른다. 다 읽기 전에 다음 글이 붙어 있어 멈춤이 거의 보이지 않는다.
- 부르는 동안 목록 아래에 "불러오는 중…"이 보인다(`role="status"`).
- 한 쪽을 다 받고도 끝이 여전히 화면 안이면(큰 모니터) 이어서 더 부른다.
- **실패하면 저절로 다시 부르지 않고** "글을 불러오지 못했어요 [다시 시도]"를 보인다. 목록이 아무 말 없이 멈추지 않고, 서버가 아플 때 요청을 계속 쏟지도 않는다. [다시 시도]가 성공하면 무한 스크롤이 다시 이어진다.
- 더 받을 글이 없으면 아무것도 그리지 않는다.
- IntersectionObserver가 없는 오래된 브라우저는 예전처럼 [더 보기] 버튼이 보인다.
- 이미 있던 동작은 그대로: 같은 글은 두 번 붙지 않고, 글을 보고 뒤로 오면 카드·커서·스크롤 위치를 30분 동안 복원한다. 트렌딩 순위가 바뀌어 커서가 만료되면(410) 안내 뒤 처음부터 다시 받는다.

### 그대로 두는 것
- **댓글**의 [댓글 더 보기]·[답글 N개 더 보기]: 글 아래에서 댓글이 저절로 계속 붙으면 아래쪽 이웃 글·푸터에 닿기 어렵다. 누를 때만 펼친다.
- **블로그 태그 줄의 [태그 더 보기]**, **릴리스 노트의 [이전 버전 더 보기]**: 목록 페이지가 아니라 접힌 내용을 펼치는 버튼이다.
- **관리자 화면**(신고·문의): 처리하며 한 줄씩 보는 작업 목록이라 버튼을 둔다.

## 고른 것과 이유
- **미리 부르는 거리 600px**: 카드 한 줄(약 450px)보다 조금 길게 잡아, 보통 속도로 내리면 끝에 닿기 전에 다음 쪽이 와 있다. 더 길게 잡으면 읽지도 않을 쪽까지 부른다.
- **실패 뒤 자동 재시도 대신 [다시 시도] 버튼**: 자동 재시도는 서버 장애 때 요청을 키우고, 사용자는 왜 멈췄는지 모른다. 이유를 보여 주고 사용자가 고르게 했다.
- **공용 컴포넌트 하나(`InfiniteLoader`)**: 목록마다 감시 코드를 따로 두지 않고 한 곳에서 불러오는 중·실패·옛 브라우저 처리를 맞춘다.
- **푸터 문제**: velog처럼 목록 페이지에는 아래 고정 푸터가 없다. 알림 화면의 "90일 보관" 안내는 마지막 쪽까지 받으면 보인다.

## 확인
- 화면 `npm run typecheck && npm test`(InfiniteLoader 단위 테스트 5개 추가), 백엔드 영향 없음.
- 홈을 1280px·375px·375px 다크로 열어 API를 흉내 낸 5쪽(60개)을 스크롤만으로 끝까지 받고, 중간 쪽 실패 때 [다시 시도]가 보이고 누르면 이어지는지, 가로 스크롤이 없는지 확인했다.
