# Feature Specification: AI 연결(MCP)로 전공자용 글감 추천 받기

**Feature Branch**: `075-suggest-topics`
**Created**: 2026-10-09
**Status**: Implemented (v1.51.0)
**근거**: 2026-10-09 블로그 주인 요청("글감 뽑는 기술이 괜찮은 수준이라고 판단되면 MCP 도구로도 제작해줘"). 프로젝트 대화에서 글감을 뽑아 브리프로 넘긴 방법으로 "devlog 설계 노트" 4편(글 16~19번)이 발행됐고, 글쓴이가 브리프의 경로·숫자를 고친 일이 없어 도구로 만든다.

## 사용자 시나리오

1. **Given** 읽기 토큰으로 연결한 AI, **When** 사용자가 "블로그에 쓸 거리 있어?"라고 해 `suggest_topics`를 부르면, **Then** 최근 14일의 일기 메모·AI 일기(소제목별)·정하지 않은 글 제안·최근 임시글에서 전공자 관점이 보이는 주제를 점수 순으로 5개 돌려준다. 글감마다 관점, 근거 자료(종류·번호·시각·조각), 물어볼 것이 붙는다.
2. **Given** 이미 발행한 "Redis 캐시 이야기", **When** 임시글 "Redis 캐시 무효화"가 글감으로 뽑히면, **Then** "겹치는 글: [번호] Redis 캐시 이야기 → 새 각도만"이 붙는다.
3. **Given** 자료에 `10.0.0.5`, `password=...`, 메일 주소, `Bearer ...`가 있으면, **Then** 근거 조각에는 `****`로 가려 보이고 "가릴 것" 줄이 붙는다.
4. **Given** `focus: "배포"`, **Then** 그 낱말이 들어간 주제만 돌려준다.
5. **Given** 자료가 하나도 없으면, **Then** add_note·propose_post로 자료를 남기는 방법을 알려 준다.

## Requirements

- **FR-001**: `suggest_topics {days?=14 (1~90), focus?, limit?=5 (1~10)}`는 읽기 도구다(READ 토큰으로 부를 수 있고 아무것도 저장하지 않는다). 범위 밖 숫자는 가까운 값으로 맞추고, 정수가 아니면 오류다.
- **FR-002**: 읽는 자료는 호출한 회원 본인 것뿐이다: `ai_note`(기간 안), 제목이 `YYYY-MM-DD 개발 일기`인 글의 `## 소제목` 구간(기간 안), OPEN 글 제안(기간 무관), 최근 고친 임시글(일기 제외). 같은 제목은 한 글감으로 합친다.
- **FR-003**: 관점은 서버 AI 없이 낱말 사전으로 고른다: 동시성·장애·복구·보안·성능·접근성·운영·배포·인프라·AI 하네스·설계·데이터. 관점이 하나도 없는 기록은 빼고 개수만 알린다.
- **FR-004**: 겹침은 발행한 글(일기 제외, 최근 300편)의 제목·태그 낱말과 비교한다. 두 낱말 이상 같으면(제목이 한두 낱말이면 하나) 겹친다. 겹친 글감은 빼지 않고 점수를 낮추고 "새 각도만"을 붙인다.
- **FR-005**: 근거 조각은 140자로 자르고 IP·메일 주소·비밀값(password/secret/token/api_key/비밀번호/토큰 = 값, Bearer 값)을 `****`로 바꾼다.
- **FR-006**: 결과 끝에 글로 옮길 때 규칙(실제 코드·설정 조각과 파일 경로, 비밀값 가림, 역할 문장은 사용자 확인, 고른 글감은 propose_post)을 붙인다. 연결 안내(initialize)에도 "글감을 물으면 suggest_topics, 고른 것은 propose_post"를 적는다.

## 고른 기본값 (질문 없이 정함)
- 서버 AI(태그 추천에 쓰는 모델)를 부르지 않았다. 연결한 AI가 이미 글을 다듬을 수 있고, 낱말 사전이면 결과가 늘 같고 비용·동의가 필요 없다(071 일기와 같은 이유).
- 발행한 글 본문은 자료로 읽지 않았다. 이미 쓴 주제를 다시 추천하지 않기 위해 겹침 비교에만 쓴다.
- 프로젝트 채팅·저장소 커밋처럼 devlog 밖의 자료는 서버가 읽을 수 없다. 연결한 AI가 add_note로 남긴 메모가 그 역할을 한다.
