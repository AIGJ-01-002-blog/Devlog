# Feature Specification: 디스코드 웹훅으로 블로그 알림 받기

**Feature Branch**: `078-discord-webhook`
**Created**: 2026-10-10
**Status**: Implemented (v1.54.0)
**근거**: 2026-10-10 블로그 주인 요청 "블로그 알림을 디스코드 웹훅도 사용자가 연결해서 알림 받을 수 있게 해줘". 텔레그램 알림(spec 023)과 같은 알림을 디스코드 채널로도 보낸다.

## 사용자 시나리오

1. **Given** 로그인한 회원, **When** 설정 › 알림 › 디스코드에 자기 채널의 웹훅 주소를 넣고 [연결하기]를 누르면, **Then** 서버가 디스코드에 그 웹훅이 있는지 확인하고 저장한 뒤 채널에 "devlog 알림을 이 채널로 보내 드릴게요"를 보낸다. 화면은 디스코드가 알려 준 웹훅 이름과 연결 날짜만 보이고 주소·토큰은 다시 보이지 않는다.
2. **Given** 디스코드를 연결한 회원, **When** 누가 댓글·답글·좋아요·팔로우를 하거나 팔로우한 사람이 새 글을 올리는 등 화면 알림이 생기면, **Then** 같은 문구가 디스코드 채널에도 온다. [새 알림을 디스코드로 받기]를 끄면 오지 않는다(화면 알림은 그대로).
3. **Given** 연결된 회원, **When** [시험 보내기]를 누르면 채널에 시험 메시지가 온다. [주소 바꾸기]로 다른 웹훅으로 바꾸고, [연결 끊기]로 지운다.
4. **Given** 디스코드에서 웹훅을 지운 회원, **When** 알림을 보내다 디스코드가 404·401로 답하면, **Then** 연결을 지워 더는 보내지 않는다. 설정 화면은 다시 연결 전 상태로 보인다.
5. **Given** 디스코드 웹훅 주소가 아닌 값(다른 호스트, http, 채널 주소 등), **Then** 저장하지 않고 "디스코드 웹훅 주소가 아니에요"라고 알려 준다. 화면도 보내기 전에 같은 꼴 검사로 버튼을 막는다.

## Requirements

- **FR-001**: 회원 하나에 웹훅 하나(`member_discord`). 다시 연결하면 바꾸고 알림 받기를 켠다. 서버 쪽 키는 없고 `DISCORD_NOTIFY_ENABLED=false`로만 끈다.
- **FR-002**: 받는 주소는 `https://(ptb.|canary.)discord(app).com/api(/vN)/webhooks/{번호}/{토큰}` 꼴뿐이다. 번호·토큰만 떼어 저장하고, 부를 때는 설정한 디스코드 주소(`blog.discord.base-url`)에 붙인다. 회원이 넣은 호스트로는 요청을 보내지 않는다(서버가 내부망 등 엉뚱한 곳을 부르지 않게).
- **FR-003**: 토큰은 API 응답·로그·예외 메시지에 내보내지 않는다. 응답은 `available, linked, webhookName, notifications, linkedAt`만 준다.
- **FR-004**: 알림은 커밋 뒤 따로 도는 실행기에서 보낸다(텔레그램과 같은 방식, 블로그 알림 처리를 붙잡지 않음). 문구는 텔레그램과 같은 `NotificationText`가 만든다. 볼 수 없는 글이면 제목·링크가 없다.
- **FR-005**: 보내는 메시지는 멘션을 모두 끄고(`allowed_mentions.parse=[]`, 댓글의 `@everyone`이 채널을 울리지 않게) 링크 미리보기를 끈다. 2,000자를 넘으면 자른다. 보내는 이름은 `devlog`.
- **FR-006**: 연결·시험 보내기는 합쳐 회원당 한 시간에 10번까지(429). 남의 채널로 메시지를 퍼붓는 데 쓰이지 않게 한다.
- **FR-007**: 탈퇴 정리 때 연결을 지운다(순서 44). 탈퇴 유예 동안은 보내지 않는다.

## 고른 것과 이유 (질문 없이 진행, 일일 보고에 기록)

- **회원 누구나 연결**: 텔레그램은 관리자만(봇 하나를 공유) 열려 있지만, 디스코드 웹훅은 회원이 자기 채널을 직접 만들어 넣으므로 서버 부담·공유 자원이 없다. 요청 문구("사용자가 연결해서")대로 처음부터 모든 회원에게 연다.
- **토큰은 DB에 평문**: 앱에 아직 칼럼 암호화 도구가 없고, 웹훅 토큰은 그 채널에 글을 쓰는 권한뿐이다. 화면·로그로는 나가지 않게만 막았다. 암호화는 다른 비밀값(예: 개인 접근 토큰 해시)과 같이 묶어 볼 일로 남긴다.
- **개인정보 처리방침은 그대로**: 회원이 고른 자기 채널로 회원 자신의 알림을 보내는 것이라 제3자 제공으로 보지 않았다. 텔레그램(023)도 처리방침에 따로 적지 않았다. 적으면 처리방침 버전이 올라 전 회원 재동의가 필요하다.
- **시험 보내기 버튼**: 연결 직후 첫 메시지 외에도 "지금도 잘 가는지" 확인할 방법이 있어야 해서 더했다.
