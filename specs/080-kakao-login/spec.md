# Feature Specification: 카카오 로그인

**Feature Branch**: `080-kakao-login`
**Created**: 2026-10-10
**Status**: Implemented (키를 넣으면 켜짐)
**근거**: 2026-10-10 블로그 주인 질문 "페이스북이나 인스타, 카카오톡 OAuth랑 네이버 OAuth도 넣고 싶은데 어떻게 생각해". 정책을 확인한 뒤 국내 독자에게 효과가 가장 큰 카카오부터 붙이기로 추천했다. 구글 로그인(004)과 같은 방식이다.

## 사용자 시나리오

1. **Given** 운영자가 `KAKAO_CLIENT_ID`(REST API 키)·`KAKAO_CLIENT_SECRET`을 넣은 사이트, **When** 로그인 화면을 열면, **Then** Google과 GitHub 사이에 노란 [카카오로 계속하기] 버튼이 보인다. 키가 없으면 버튼이 없다.
2. **Given** 카카오로 처음 온 사람, **When** 카카오 동의 화면을 거치면, **Then** 가입 마무리 화면에서 `ka-` 블로그 주소와 닉네임을 정하고 가입한다. 카카오 닉네임이 닉네임 칸에 미리 들어간다.
3. **Given** 카카오계정 이메일 동의를 했고 그 이메일이 유효·인증된 사람, **Then** 이메일을 다시 묻지 않는다. 이메일 동의가 없거나(비즈 앱 전 포함) 인증되지 않았으면 가입 마무리 화면에서 이메일을 받아 인증 메일을 보낸다(이메일 없는 GitHub 계정과 같음).
4. **Given** 카카오로 가입한 회원, **When** 다시 카카오로 로그인하면, **Then** 카카오 회원번호로 같은 계정에 들어온다. 카카오 이메일이 바뀌어도 같은 계정이다.
5. **Given** 카카오 기본 프로필 사진이 아닌 사진, **Then** 가입 마무리 화면에서 [카카오 프로필 사진 사용]을 고를 수 있다. 사진을 받아 오지 못하면 기본 이미지로 가입한다.

## Requirements

- **FR-001**: 등록 이름은 `kakao`, 콜백은 `{SITE_BASE_URL}/login/oauth2/code/kakao`. 인가·토큰은 `kauth.kakao.com`, 사용자 정보는 `kapi.kakao.com/v2/user/me`, 사용자 식별은 숫자 `id`. Client Secret은 요청 본문(client_secret_post)으로 보낸다.
- **FR-002**: 동의항목은 기본 `profile_nickname,profile_image,account_email`. 비즈 앱 전환 전이면 `KAKAO_SCOPES`로 이메일을 뺀다(빈 값이면 기본값).
- **FR-003**: 이메일은 `is_email_valid`와 `is_email_verified`가 둘 다 참일 때만 인증된 이메일로 쓴다. 정리 규칙은 다른 소셜과 같다(spec 038).
- **FR-004**: 블로그 주소 접두어는 `ka-`. 이메일 가입 주소는 `ka_`로 시작할 수 없다(소셜 주소와 헷갈림). DB는 `ka-` 접두어만 더 받는다.
- **FR-005**: 사진은 `https://k.kakaocdn.net`만 받는다. 예전 계정의 `http://k.kakaocdn.net` 주소는 https로 바꾸고, `is_default_image`가 참이면 넘기지 않는다. 가입 마무리 화면 CSP img-src에 같은 호스트를 더한다.
- **FR-006**: 설정 화면·메일의 로그인 수단 이름은 "카카오".
- **FR-007**: 카카오 사진 서버는 다른 사이트가 사진을 캔버스로 가공하는 걸 허락하지 않는다(CORS 헤더 없음). 가입 마무리 화면은 사진을 바로 받아 보고,
  막히면 `GET /api/auth/signup/avatar`로 서버가 대신 받은 사진을 쓴다. 서버는 가입 대기 세션의 소셜 인증이 돌려준 주소만, 허용된 사진 서버 세 곳의
  https 주소만, 넘겨주기(redirect) 없이 5초·5MB 안에서 받고, 실제 사진(jpg·png·gif·webp)일 때만 저장하지 않고 그대로 돌려준다. 가입 대기 정보가
  있어야 하므로 화면은 가입 요청보다 먼저 사진을 256×256으로 만들어 두고, 가입 뒤에 올린다. 005 FR-020("서버는 외부 사진 주소를 직접 요청하지
  않는다")의 예외이고, 사진 주소를 저장하지 않는다는 규칙은 그대로다. (2026-10-10, 민서님 제보 "카카오로 가입하면 이미지가 등록이 안 되는데")

## 고른 것과 이유 (질문 없이 진행, 일일 보고에 기록)

- **인스타그램은 넣지 않음**: Meta가 2024-12-04에 일반 사용자용 Instagram API를 닫았고, 남은 Instagram Login은 비즈니스·크리에이터 계정 전용이다.
- **페이스북·네이버는 뒤로**: 페이스북은 일반 사용자가 쓰려면 비즈니스 인증이 필요하다는 안내가 있고 개발자 독자층 수요가 낮다. 네이버는 공개 전 검수가 있어 카카오 다음 순서로 둔다.
- **DB의 `ka_` 금지는 앱에서만**: 이미 `ka_`로 시작하는 이메일 가입 주소가 있으면 DB CHECK에 넣는 순간 그 회원의 정보 수정이 모두 실패한다.
- **개인정보 처리방침은 아직 그대로**: 카카오로 받는 항목(이메일·닉네임·사진)은 이미 처리방침에 있는 항목이다. 로그인 수단 목록 문구에 "카카오"를 더하면 처리방침 버전이 올라 전 회원 재동의가 필요하므로, 카카오 키를 실제로 넣는 릴리스에서 함께 고친다.
- **이름·생일·전화번호는 받지 않음**: 사업자 정보가 있는 비즈 앱만 신청할 수 있고, 블로그 가입에 필요 없다.

## 운영자가 할 일

1. 카카오 디벨로퍼스에서 앱을 만들고 플랫폼 Web에 `https://devlog.life`를 등록한다.
2. 카카오 로그인을 켜고 Redirect URI에 `https://devlog.life/login/oauth2/code/kakao`를 넣는다. 보안 › Client Secret을 만들고 사용함으로 둔다.
3. 동의항목에서 닉네임·프로필 사진을 켠다. 본인인증 후 비즈 앱으로 전환하면 카카오계정(이메일)도 켠다.
4. GitHub Secret `KAKAO_CLIENT_ID`(REST API 키)·`KAKAO_CLIENT_SECRET`을 넣는다. 이메일을 아직 못 받으면 Variable `KAKAO_SCOPES=profile_nickname,profile_image`를 둔다.
